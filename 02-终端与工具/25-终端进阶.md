## $\rm \S \, 25.1$ WSL：在 Windows 里演练 Linux

从[第 7 章](../02-终端与工具/09-软件运行时SDK与包管理器.md)的 apt、[第 12 章](../03-计算机系统/14-SSH远程开发与服务器生存指南.md)的服务器操作到 Docker——它们默认都是 Linux 环境。**WSL**（Windows Subsystem for Linux）在 Windows 内运行完整 Linux 内核，不是虚拟机，系统调用实时翻译。

```powershell
wsl --install    # PowerShell（管理员），一行安装，重启后得 Ubuntu
```

```bash
uname -a       # Linux ... —— 真正的 Linux 内核
ls /mnt/c/     # Windows C 盘在这里
```

| 场景 | 没有 WSL | 有 WSL |
|------|---------|--------|
| Bash 脚本 | Git Bash 行为不完全一致 | 原生，和服务器一样 |
| Python 环境 | `\` 路径、CRLF、某些包不兼容 | Linux 原生，零差异 |
| Docker | Windows 路径/权限问题 | WSL 内 Docker，和部署环境一致 |

VS Code 装 WSL 扩展后，`code .` 在 WSL 里打开——GUI 在 Windows 渲染，文件系统、终端、编译全在 Linux 侧。项目文件放 `~/projects`（WSL 内部），不要跨文件系统从 `/mnt/c/` 编译。

## $\rm \S \, 25.2$ 终端快捷键

以下快捷键在 Bash/Zsh 中通用（PowerShell 部分支持）：

**行编辑**

| 快捷键 | 作用 |
|--------|------|
| `Ctrl+A` | 跳到行首 |
| `Ctrl+E` | 跳到行尾 |
| `Ctrl+U` | 删除光标到行首 |
| `Ctrl+K` | 删除光标到行尾 |
| `Ctrl+W` | 删除前一个单词 |
| `Alt+B / Alt+F` | 按单词前后移动 |

**历史搜索**

| 快捷键 | 作用 |
|--------|------|
| `Ctrl+R` | 反向搜索历史 |
| `!!` | 重新执行上一条命令 |
| `!$` | 上一条命令的最后一个参数 |

```bash
mkdir -p /very/long/path/to/project
cd !$           # = cd /very/long/path/to/project
```

**进程控制**

| 快捷键 | 信号 | 作用 |
|--------|------|------|
| `Ctrl+C` | SIGINT | 中断当前程序 |
| `Ctrl+Z` | SIGTSTP | 挂起当前程序 |
| `Ctrl+D` | EOF | 发送输入结束 |
| `Ctrl+L` | — | 清屏 |

## $\rm \S \, 25.3$ 作业控制：fg、bg 与 nohup

`Ctrl+Z` 挂起程序后：

```bash
python train.py        # 正在运行
# 按 Ctrl+Z
# [1]+  Stopped    python train.py

nvidia-smi             # 检查 GPU
fg                      # 拉回前台
bg                      # 放到后台继续
```

后台程序绑定在当前终端——关终端就死。**nohup** 让它忽略 SIGHUP（终端关闭信号）：

```bash
nohup python train.py > train.log 2>&1 &
```

什么时候用 nohup vs tmux（详见[第 12 章](../03-计算机系统/14-SSH远程开发与服务器生存指南.md)）：

| 场景 | 工具 |
|------|------|
| 一次性的后台任务 | `nohup ... &` |
| 需要偶尔看看输出、手动操作 | tmux |
| SSH 可能断 | tmux |

## $\rm \S \, 25.4$ 配置持久化：`.bashrc` 与 dotfiles

Shell 启动时读初始化脚本：

| Shell | 交互式 Shell 读 |
|-------|----------------|
| Bash | `~/.bashrc` |
| Zsh | `~/.zshrc` |
| PowerShell | `$PROFILE` |

```bash
nano ~/.bashrc         # 编辑
source ~/.bashrc       # 立即生效
```

**alias**——给长命令起短名：

```bash
alias g='git'
alias gc='git commit -m'
alias ll='ls -lah'
alias ..='cd ..'
alias activate='source venv/bin/activate'
```

**什么放 .bashrc，什么不放**：

```bash
# ✅ 放 .bashrc——每次都要的配置
export PATH="$HOME/bin:$PATH"
alias g=git

# ❌ 不放 .bashrc——项目配置
# 应该放 .env 文件（项目目录下，不进 Git）
export DATABASE_URL=postgresql://...
export API_KEY=sk-xxxxxxxx
```

**dotfiles**：把 `~/.bashrc`、`~/.gitconfig`、`~/.ssh/config` 放进 Git 仓库，换电脑时一键恢复。

## $\rm \S \, 25.5$ Shell 深度

### 引号

```bash
echo $VAR          # 无引号——空格分割，通配符展开
echo "$VAR"        # 双引号——变量展开，空格和通配符保护
echo '$VAR'        # 单引号——一切字面
```

### 子 Shell

```bash
pwd                  # /home/alice
(cd /tmp && pwd)     # /tmp——只在子 Shell 内生效
pwd                  # 还是 /home/alice
```

### `set -euo pipefail` 与 trap

```bash
#!/bin/bash
set -euo pipefail   # 任何命令失败→退出；未定义变量→报错；管道失败→整体失败

tempfile=$(mktemp)
trap "rm -f $tempfile" EXIT   # 无论怎么退出都清理临时文件
```

陷阱一：`set -e` 不捕捉管道中间命令失败（除非加 `pipefail`）。  
陷阱二：`set -e` 在 `if`/`while`/`||`/`&&` 条件位置不生效。  
陷阱三：`set -u` 下 `${VAR:-default}` 不报错（`:-` 是默认值语法）。

### tee

```bash
python train.py 2>&1 | tee train.log       # 输出到文件 + 屏幕
python train.py 2>&1 | tee -a train.log    # -a: 追加
```

### shellcheck

```bash
shellcheck script.sh   # 检查：未加引号的变量、cd 没检查返回值、未使用变量
```

## $\rm \S \, 25.6$ PowerShell 与 Bash 最小对照

| 操作 | PowerShell | Bash/Zsh |
|------|-----------|----------|
| 列出文件 | `Get-ChildItem` / `ls` | `ls` |
| 当前目录 | `Get-Location` / `pwd` | `pwd` |
| 切换目录 | `Set-Location` / `cd` | `cd` |
| 查看文件内容 | `Get-Content` / `cat` | `cat` |
| 查找文本 | `Select-String` / `sls` | `grep` |
| 环境变量 | `$env:PATH` | `$PATH` |
| 设置环境变量 | `$env:VAR = "value"` | `export VAR="value"` |
| 管道 | 传递对象 | 传递文本 |
| 脚本扩展名 | `.ps1` | `.sh` |

## $\rm \S \, 25.9$ 本章自测答案

> 先闭卷作答本章“关键概念回顾”与“应用与辨析”，再核对以下答案。

### 自测答案 · 关键概念回顾
1. WSL 是系统调用翻译层——Linux 内核运行在 Windows 内核旁边，不模拟硬件。性能接近原生，启动不到一秒。
2. Ctrl+Z 挂起程序（可恢复），Ctrl+C 请求终止。`fg` 拉回前台，`bg` 放到后台。
3. 无引号：空格分割+通配符展开。双引号：变量展开，空格保护。单引号：一切字面。
4. nohup 适合一次性后台任务；tmux 适合需要查看输出、手动交互、或 SSH 可能断的场景。

### 自测答案 · 应用与辨析
1. 登录 Shell 读 `.bash_profile`，日常终端窗口读 `.bashrc`。大部分配置放 `.bashrc` 即可。
2. 管道中间命令失败（除非 `pipefail`）、`if`/`while`/`||` 条件位置、以及 `$( )` 子 Shell 中。
