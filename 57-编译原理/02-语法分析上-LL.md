## $\rm \S \, 2.1$ 问题：记号序列的合法性谁说了算

词法器对 `id + * id` 毫无意见：它只管切词，每个词都合法。但任何写过表达式的人都知道这不是一句合法的话：`+` 后面不能直接跟 `*`。这类「词都对、连起来不对」的判断需要一个能描述「合法序列」的形式装置，而描述嵌套结构（括号任意深、运算任意多层）恰恰超出正则表达式的表达力，《形式语言与自动机》§3.1 用 ${0^n1^n}$ 论证过这件事。所以语法级换用上下文无关文法（context-free grammar，CFG）。本章全程围绕同一条四则运算文法工作，先认识它的原始形态，编号 G1：

```text
E -> E + T | T        （表达式：若干项相加）
T -> T * F | F        （项：若干因子相乘）
F -> ( E ) | id       （因子：括号或原子）
```

三个非终结符各管一个优先级层，`id + id * id` 的推导树里 `+` 在树根、`*` 在下层，优先级与左结合由文法的形状保证（两棵树的反例见《形式语言与自动机》§3.2）。判定「记号串 $w$ 是否属于 $L(G)$」这件事，学术上交给下推自动机（见《形式语言与自动机》§3.3），工程上有两条路：自顶向下（top-down，从开始符号出发猜展开，对应最左推导）与自底向上（bottom-up，从记号往回归约，第 3 章的 LR）。本章走自顶向下，目标是一个非常实际的规格：**每一步展开只许看后面一个记号就定下来**，因为真实的编译器不想回溯，回溯意味着已做的构建工作可能作废，错误定位也乱。

自顶向下逐记号前进，天然是**最左推导（leftmost derivation）**：树从根往下长、每层先长最左边的活枝。LL(1) 这个名字就是它的三张名片：从**L**eft 读入、**L**eftmost 推导、向前看 **1** 个记号。

白话：词法管「词对不对」，语法管「句子成不成立」；本章让机器拿着文法从根往下猜，而且要求每一步只偷看一个词就猜对。

> 本节小结：语法级用 CFG 回答「记号序列合法吗」；自顶向下解析即最左推导的逐步执行，LL(1) 是「零回溯、每步一个记号定夺」的最严格规格。

## $\rm \S \, 2.2$ FIRST：这个开头能走出哪些可能

猜的第一问是「哪条产生式有戏」。设 $\alpha$ 是一个符号串（终结符、非终结符混排），定义

$$
\mathrm{FIRST}(\alpha)=\{\,a:\ \alpha\Rightarrow^{*} a\beta,\ a\in\Sigma\,\}\cup\{\epsilon:\ \alpha\Rightarrow^{*}\epsilon\,\}
$$

读法：左边那半句收集「从 $\alpha$ 出发推导若干步后，句首能露出的终结符」；后半个花括号处理特例：$\alpha$ 可能整个推没（推出空串 $\epsilon$），这时它没有句首，就把 $\epsilon$ 自己记进去。计算对全体产生式做不动点迭代（与 §1.4 的子集构造同一个味道：反复套用规则直到集合不再变大）：

1. 终结符的 FIRST 是它自己；$\mathrm{FIRST}(\epsilon)=\{\epsilon\}$。
2. 产生式 ${X\to Y_1Y_2\cdots Y_k}$：依序扫过 $Y_i$，把 $\mathrm{FIRST}(Y_i)$ 去掉 $\epsilon$ 并进来；若 $Y_i$ 推得出 $\epsilon$ 就继续扫下一个，扫不住（碰到推不出 $\epsilon$ 的符号）就停；全串都推得出 $\epsilon$，才把 $\epsilon$ 添进 $\mathrm{FIRST}(X)$。
3. 有集合变化就回到第 2 步重跑，直到一轮下来集合纹丝不动。

对 G1 手推一轮验证账法：初值全为空；扫 `F -> ( E ) | id`，得 $\mathrm{FIRST}(F)=\{(, \mathrm{id}\}$；扫 `T -> T * F | F`，第二条让 $\mathrm{FIRST}(T)$ 并进 $\mathrm{FIRST}(F)$；扫 `E` 同理并进 $\mathrm{FIRST}(T)$。第二轮里 $\mathrm{FIRST}(T)$ 的更新传播给 $\mathrm{FIRST}(E)$，这就是不动点迭代的「信息逆流而上」。实验（§2.6 脚本）给出的收敛账：

| 非终结符 | FIRST | FOLLOW | FIRST 迭代 | FOLLOW 迭代 |
| --- | --- | --- | --- | --- |
| $E$ | ${(,\ \mathrm{id}}$ | ${)\ +\ \$}$ | 4 轮 | 3 轮 |
| $T$ | ${(,\ \mathrm{id}}$ | ${)\ *\ +\ \$}$ | 同上 | 同上 |
| $F$ | ${(,\ \mathrm{id}}$ | ${)\ *\ +\ \$}$ | 同上 | 同上 |

4 轮的含义是「3 轮真更新加 1 轮确认不动」；$F$ 的 FOLLOW 含 `*`，因为 $\mathrm{FIRST}(\text{后缀 } T')$ 里的 `*` 经 $\epsilon$ 传播给了 $F$（账目细节 §2.3 展开）。G1 没有任何一条产生式能推出 $\epsilon$，所以三行 FIRST 都不带 $\epsilon$；§2.5 的改写会引入 `E' -> ε`、`T' -> ε`，到那时 $\epsilon$ 传播才真正登场。

白话：FIRST 集回答「往这条路口走，最先撞见的可能是哪几种词」；算它就是让每个非终结符把「我能开出的头」沿产生式一层层抄给上游，抄到没人再更新为止。

> 本节小结：FIRST 是「句首终结符候选集」加 $\epsilon$ 特例，不动点迭代逐轮传播；G1 三层非终结符的 FIRST 全是 ${(,\ \mathrm{id}}$，实验 4 轮收敛。

## $\rm \S \, 2.3$ FOLLOW：这个位置后面合法地跟着什么

FIRST 只回答了「路口有哪几种开头」，但带 $\epsilon$ 的产生式在解析时是「隐形通道」：$A\to\epsilon$ 不吞任何记号，要不要走它，得看「$A$ 后面此刻合法地排着什么」。对非终结符 $A$ 定义

$$
\mathrm{FOLLOW}(A)=\{\,a\in\Sigma:\ S\Rightarrow^{*}\alpha A a\beta,\ a\in\Sigma\cup\{\$\}\,\}
$$

读法：从开始符号 $S$ 出发能推到的句型里，凡 $A$ 右边紧贴终结符 $a$，$a$ 入集；约定把输入结束标记 `$` 也算进 $\mathrm{FOLLOW}(S)$（表示「$A$ 是句尾」这种情形）。注意口径：FOLLOW 只对**非终结符**定义；$a$ 与 $A$ 之间允许隔着一段能推空的串，这正是「紧贴」在推导意义下的含义。规则四条，也是不动点迭代：

1. 结束标记 `$` 自动属于 $\mathrm{FOLLOW}(S)$。
2. ${A\to\alpha B\beta}$ 且 $\beta$ 推不空：$\mathrm{FIRST}(\beta)$ 去掉 $\epsilon$ 并进 $\mathrm{FOLLOW}(B)$。
3. ${A\to\alpha B\beta}$ 且 $\epsilon\in\mathrm{FIRST}(\beta)$（或 $\beta$ 本身是空）：$\mathrm{FOLLOW}(A)$ 整个并进 $\mathrm{FOLLOW}(B)$：$B$ 后面能排的，$A$ 前面也排得上。
4. 任何集合变化就重跑，直到不动。

沿 G1 把 $T$ 的 FOLLOW 算全（其余两行同法，实验逐轮打印）：产生式 `E -> E + T` 与 `E -> T` 里 $T$ 都在句尾，规则 3 把 $\mathrm{FOLLOW}(E)$ 整笔划入，得 `) + $`；再看 `T -> F T'`（改写后的文法，${T'}$ 是新变量）与 `T' -> * F T'`，$F$ 的后邻 ${T'}$ 能推空，于是 $\mathrm{FOLLOW}(F)$ 逐轮收进 $\mathrm{FOLLOW}(T')$（$F$ 的 FOLLOW 里 `*` 的来历）。`$` 能进 $\mathrm{FOLLOW}(E)$ 靠规则 1，再经 `E -> T`、`T -> F` 的规则 3 灌给 $T$ 与 $F$；`)` 的来历是 `F -> ( E )` 里 $E$ 后面紧贴着 `)`（规则 2）。

到此两件工具齐备，立一条本章的中心约定：给一条产生式 ${A\to\alpha}$ 配上「适用窗口」$\mathcal{W}(A\to\alpha)$：

$$
\mathcal{W}(A\to\alpha)=
\begin{cases}
(\mathrm{FIRST}(\alpha)\setminus\{\epsilon\})\cup\mathrm{FOLLOW}(A), & \epsilon\in\mathrm{FIRST}(\alpha) \\
\mathrm{FIRST}(\alpha), & \text{否则}
\end{cases}
$$

读法：用这条产生式展开 $A$，当且仅当向前看记号落在窗口里；$\alpha$ 推得出空串时，展开它等于什么也不吃，此时唯一能指路的只剩「$A$ 后面合法的下一个记号」，所以把 FOLLOW 接进窗口。§2.4 的表就是「每个非终结符的每条产生式该占哪几列」的总账。

白话：FOLLOW 是「下班时刻表」——隐形通道（$\epsilon$ 产生式）要不要走，看一眼后面排队的记号在不在表里；每个产生式的「适用窗口」= 自己的开头 + 推空时借用的后续。

> 本节小结：FOLLOW 从全体句型收集「$A$ 的合法后邻」，四条规则不动点迭代；两者合流成产生式的适用窗口 $\mathcal{W}$，$\epsilon$ 产生式的窗口里 FOLLOW 全权接管。

## $\rm \S \, 2.4$ LL(1) 表：把猜测变成查表

有了窗口，把「猜」变成「查」只剩一步机械劳动。分析表（parsing table）$M$ 是一张「非终结符 × 终结符」的格子表，构造：

1. 对每条产生式 ${A\to\alpha}$ 与每个 $a\in\mathcal{W}(A\to\alpha)$：往格 $M[A,a]$ 放一条 ${A\to\alpha}$。
2. 任何格子被放了**两条以上**产生式，文法就**不是** LL(1)；反之每格至多一条即 LL(1)。

冲突判定因此完全程序化，一个非终结符哪一格、被哪两条产生式抢，全部可打印。对 G1 跑构造（实验输出原样）：

| | `+` | `*` | `(` | `)` | `id` | `$` |
| --- | --- | --- | --- | --- | --- | --- |
| $E$ | | | ${E\to E+T}$ / ${E\to T}$ | | ${E\to E+T}$ / ${E\to T}$ | |
| $T$ | | | ${T\to T*F}$ / ${T\to F}$ | | ${T\to T*F}$ / ${T\to F}$ | |
| $F$ | | | ${F\to(E)}$ | | ${F\to\mathrm{id}}$ | |

G1 的表：6 个非空格，其中 **4 个冲突格**：${M[E,\ (]}$ 与 $M[E,\mathrm{id}]$ 各被 `${E\to E+T}$` 与 `${E\to T}$` 争抢，${M[T,\ (]}$、$M[T,\mathrm{id}]$ 同病。病灶一眼可见：`E -> E + T` 与 `E -> T` 两条产生式的 FIRST 全等（都以 $E$ 开头，而 $\mathrm{FIRST}(E)={ (,\ \mathrm{id}}$），窗口重叠，格子只好并列两条。这也顺带解释了 §2.1 那句「每步只看一个记号」为什么是非平凡要求：两条候选产生式开口一模一样，向前看一个记号根本分不出该走哪条。

白话：LL(1) 表是把「文法 + 预测集」压成的一张_lookup_卡：行是非终结符，列是向前看记号，格子里写着「此时该用哪条产生式」；一格两条即翻车，且翻车原因可打印到具体行列。

> 本节小结：表构造两步——按窗口填格、查重复；G1 实测 4 个冲突格，根源是左递归产生式对 FIRST 相同、窗口重叠，机器至此把「猜不动」翻译成了可定位的表格冲突。

## $\rm \S \, 2.5$ 两类病根与改写：左递归与公共前缀

冲突的病根就两类，各有标准手术。

**病根一：左递归。** 直接左递归指 ${A\to A\alpha\mid\beta}$ 形状。它为什么必炸 LL(1)：两条候选的 FIRST 都含 $\mathrm{FIRST}(A)$ 自身，窗口必重叠，冲突不可避免。手术叫**消左递归改写**，把「先递归再收口」的左生长，换成「先收口再递归」的右生长：

```text
A  -> β A'     （β 是全部非 A 开头的候选）
A' -> α A' | ε （A' 吃掉余下的 α 重复）
```

语言等价性推导给全：原式 ${A\Rightarrow A\alpha\Rightarrow A\alpha\alpha\Rightarrow\cdots\Rightarrow\beta\alpha^{n}}$（$n$ 次展开 `A -> Aα`、最后用 `A -> β`，任意 $n\ge0$）；新式 ${A\Rightarrow\beta A'\Rightarrow\beta\alpha A'\Rightarrow\cdots\Rightarrow\beta\alpha^{n}}$（${A'}$ 恰好展开 $n$ 次、最后取 $\epsilon$）。两侧都是 ${\beta\alpha^{n}}$、$n$ 任意，故 $L$ 不变。对 G1 的 `E -> E + T | T` 套用：$\beta=T$、$\alpha=$ `+ T`，得 `E -> T E'`、`E' -> + T E' | ε`；$T$ 层同法，$F$ 无左递归不动。改写后实测（§2.6）：非空格数从 6 涨到 13，**冲突格数从 4 降到 0**，格子的「行数 × 列数」翻倍换来的是每格一条，这正是 LL(1) 能用的形状。

**病根二：公共前缀。** ${A\to\alpha\beta_1\mid\alpha\beta_2}$：两条产生式前缀同为 $\alpha$，FIRST 窗口在 $\alpha$ 的头上重叠。手术叫**提左公因子**：把公共头提取出来，分岔推后：

```text
A  -> α A'
A' -> β1 | β2
```

这个改写在右递归文法 G2（`E -> T + E | T` 等，同样 4 个冲突格，见 §2.6 实验）上做：`E -> T + E` 与 `E -> T` 公共前缀为 $T$，提取后得 `E -> T E'`、`E' -> + E | ε`，$T$ 层同理。实测改写后同样 13 格 0 冲突。两台文法（G1 消左递归版、G2 提公因子版）的表**空满分布逐格一致**：对应非终结符的 FIRST/FOLLOW 实验值逐行相等，窗口并集就逐格相同；差异只在格内产生式的一个符号，`E' -> + T E'` 对 `E' -> + E`、`T' -> * F T'` 对 `T' -> * T`，同一个分岔挂在了不同的收尾变量上，语言不变。

白话：左递归是「还没看清就把自己套进去」的死循环，提公因子是「话没说完就分岔」的抢跑，手术方向相反、目的同一个：把「分岔点」挪到机器看得见记号的地方。

> 本节小结：冲突病根两类——左递归（窗口必然重叠）与公共前缀（FIRST 撞在头上）；消左递归换左生长为右生长，提公因子把分岔推后，G1、G2 改写后实测均从 4 冲突格降到 0。

## $\rm \S \, 2.6$ 表驱动解析器与递归下降：两台机器

改写后的文法叫 G3，规则如下（`E'`「E 撇」是新增的非终结符）：

```text
E  -> T E'
E' -> + T E' | ε
T  -> F T'
T' -> * F T' | ε
F  -> ( E ) | id
```

**表驱动解析器**由三样东西驱动：G3 的 LL(1) 表、一个栈、一个向前看指针。栈底先压 `$`，再压开始符号 $E$；循环四问：

1. 栈顶是终结符？与向前看记号相等就同时各消一个（弹出、前进），不等即报错。
2. 栈顶是结束标记 `$`？对上则接受。
3. 栈顶是非终结符 $X$？查 $M[X, \text{向前看记号}]$：空格即报错；有产生式 ${X\to Y_1\cdots Y_k}$ 就弹 $X$、把 $Y_k\cdots Y_1$ 逆序压入。
4. 回到 1。

对输入 `id + id * id` 的完整栈轨迹实验原样输出（**17 步**、用产生式 **11 条**，`▸` 之前是栈顶）：

```text
栈               剩余输入              动作
E $              id + id * id $        E  -> T E'
T E' $           id + id * id $        T  -> F T'
F T' E' $        id + id * id $        F  -> id
id T' E' $       id + id * id $        匹配 id（弹出、指针右移）
T' E' $          + id * id $           T' -> ε
E' $             + id * id $           E' -> + T E'
+ T E' $         + id * id $           匹配 +
T E' $           id * id $             T  -> F T'
F T' E' $        id * id $             F  -> id
id T' E' $       id * id $             匹配 id
T' E' $          * id $                T' -> * F T'
* F T' E' $      * id $                匹配 *
F T' E' $        id $                  F  -> id
id T' E' $       id $                  匹配 id
T' E' $          $                     T' -> ε
E' $             $                     E' -> ε
$ $              $                     接受
```

把「展开动作」按时间顺序抄出来，就是最左推导本身：

```text
E ⇒ T E' ⇒ F T' E' ⇒ id T' E' ⇒ id E' ⇒ id + T E'
  ⇒ id + F T' E' ⇒ id + id T' E' ⇒ id + id * F T' E'
  ⇒ id + id * id T' E' ⇒ id + id * id E' ⇒ id + id * id
```

句型下划线的位置（最左非终结符）逐步右移——表驱动的每一步展开，恰好就是最左推导的一步替换。语法树就在这份推导里：每次展开画一个节点及其子树，17 步画完，树成形。

同一份 G3 也可以「文法即代码」地写成递归下降：每个非终结符一个函数，函数体按 LL(1) 表逐行翻译，每行一个分支（`if look() == 某 FIRST 记号: ...`，$\epsilon$ 产生式写成 `else` 分支），表驱动里的「栈」由调用栈顶替。实现十几个函数、共享一个 `look()` 与 `eat()`，与表驱动共享同一份产生式序列（实验里递归下降对 `id + id * id` 与 `( id + id ) * id` 各产出与表驱动完全一致的产生式序列）。**报错实验**（两台机器同病同报）：喂 `id + * id`，两台都在记号位置 2（0 起）停机：表驱动报「${M[T,\ *]}$ 空格」（栈顶 $T$、看到 `*`），递归下降报「$F$ 不接受 `*`」。两报错误同源，即记号 2 的 `*` 无法被 $T$ 后的任何合法产生式收编；喂 `( id id )`，同报错于位置 2（栈顶 ${T'}$、看到 `id`，${M[T',\ \mathrm{id}]}$ 空格）。报错定位一致不是巧合：两台机器执行的查表逻辑相同，只是「栈」的存放位置不同。

这里有一个值得停下来算的账：改写后的 G3 为什么敢用 `T' -> ε`？看向前看记号 `+` 时：`+` 落在 $\mathcal{W}(T'\to\epsilon)=\mathrm{FOLLOW}(T')$ 里，机器据此断定「$T$ 层已读完」，放行上层。回头看 §2.2 手推的 FIRST 迭代 4 轮：无 $\epsilon$ 文法本可以更快收敛，$\epsilon$ 的出现让「推空能力」沿产生式向上游传染，迭代才需要多轮确认。

## $\rm \S \, 2.7$ 悬挂 else：改写治不了的冲突

两类病根都有手术，但 LL(1) 冲突并非全部可治。经典反例是**悬挂 else（dangling else）**：C、Java 等语言的嵌套条件句里，`else` 归属哪个 `if` 有歧义——`if a then if b then s else s2` 里，`else` 可以配内层或外层 `if`。写成已提过公因子的文法 G4：

```text
S  -> if b then S S' | a
S' -> else S | ε
```

实测 LL(1) 表：非空格 4，**冲突格 1**：${M[S',\ \mathrm{else}]}$ 同时被 ${S'\to \mathrm{else}\ S}$ 与 ${S'\to\epsilon}$ 争抢。为什么手术无效：两条候选**开口不同**（一个以 `else` 开头、一个推空），左递归手术（针对 `A -> A α` 形状）与提公因子手术（针对同头候选）都不适用于这种「一条推空、一条不推空」的窗口重叠。深层原因：《形式语言与自动机》§3.2 说过，这个语言**天然歧义**（`else` 归属有歧义），而 LL(1) 表是「每格一条产生式」的确定性机器，给它一条歧义文法必然在分岔处撞车。歧义是语言的性质，不是文法写法的性质，改写改不掉。

工程的标准解法是把歧义**变成约定**：表构造时若冲突一方是 $\epsilon$ 产生式，一律选**非 $\epsilon$** 那条，即「`else` 永远配最近的 `if`」（大多数语言的官方语义）。这不是推导出来的，是**行业约定**：C/Java 标准都这么写。选择的代价要有账：配内层时，外层 `if` 主动放弃了这个 `else`，程序员若想配外层必须自己加括号（代码块）断开，语言的表就要多一层间接。

白话：`else` 跟哪个 `if`，文法说了不算，语言手册说了算；LL(1) 机器遇到这格冲突就按「就近配对」拍板，这不是推导而是约定——所以教材会告诉你「这里选非 $\epsilon$」而不是「这里消掉冲突」。

> 本节小结：悬挂 else 的冲突格 ${M[S',\ \mathrm{else}]}$ 改写不掉，因为歧义是语言本身性质；工程解法是冲突时优先非 $\epsilon$ 产生式，即「else 配最近 if」的官方约定。

## $\rm \S \, 2.8$ 一个真实错误：照抄左递归文法的递归下降

把 G1 原封不动写成递归下降（这是初学者最常见的照抄，因为 G1 的每条产生式读起来最顺）：`E` 的函数体第一件事就是处理 `E -> E + T`，即先递归调 `E()` 自己，等它返回再判断有没有 `+`，而 `E()` 的第一件事又是调自己。无限自调用。实验证据：喂 `id + id`，**递归深度涨到 997 触发 RecursionError，记号一个都还没消费**（消费 0 个）。这印证了 §2.5 的理论账：左递归产生式在 LL(1) 表里必然冲突、在递归下降里必然死循环，同一病根的两种症状。修复就是 §2.5 的消左递归手术（G3）；修复后的递归下降能正常解析 `id + id`（§2.6 的表驱动与递归下降双跑通过）。诊断链归档：症状（RecursionError）→ 病根（左递归产生式让函数第一件事就是自调用）→ 手术（G3）→ 验证（重跑通过、与表驱动序列一致）。

> **竞赛生迁移提示**：表达式求值你写过无数遍（《形式语言与自动机》§3.5 的 `calc`），那时你天然写的是 G3 形状（`while` 吃掉同层 `+`）而不是 G1——递归下降的「每层一个循环」本来就在执行消左递归后的文法。本章把这一步从「直觉写法」升级成「可证明的机械手术」，你以后遇到任何文法都能照方抓药。

白话：递归下降不是把文法逐字抄成函数，左递归那行抄下去就是无限套娃；先动手术再抄，手术刀 §2.5 已经给过。

> 本节小结：照抄 G1 的递归下降在 `id + id` 上实测递归 997 层爆栈、记号消费 0 个；病根即左递归，修复用消左递归改写，与 §2.5 理论互证。

## $\rm \S \, 2.11$ 本章自测答案

1. 定义见 §2.2、§2.3 两个公式。$\epsilon$ 在 FIRST 里表示「这个符号串能整体推空」；FOLLOW 对非终结符定义、以「下一个合法记号」为口径，**不含** $\epsilon$，它收集的是终结符加结束标记 `$`（§2.2、§2.3）。
2. 冲突格是 ${M[E,\ (]}$、$M[E,\mathrm{id}]$、${M[T,\ (]}$、$M[T,\mathrm{id}]$ 共 4 格（§2.4 表）。病根：`E -> E + T | T` 与 `T -> T * F | F` 是左递归产生式，两条候选 FIRST 相同、窗口重叠（§2.5）。
3. 消左递归：${A\to A\alpha\mid\beta}$ 改为 ${A\to\beta A'}$、${A'\to\alpha A'\mid\epsilon}$，等价性靠两侧都生成 ${\beta\alpha^{n}}$（$n$ 任意，§2.5 给了两侧各 $n$ 步的推导）。提公因子：${A\to\alpha\beta_1\mid\alpha\beta_2}$ 改为 ${A\to\alpha A'}$、${A'\to\beta_1\mid\beta_2}$，分岔点后移故语言不变（§2.5）。
4. 四问：终结符配对消两符号 / 结束标记 `$` 配对接受 / 非终结符查表逆序压栈 / 循环。每一步展开的是句型里最左的非终结符（栈顶即当前句型的最左非终结符），故动作序列抄出来恰是最左推导（§2.6 轨迹表）。
5. 因为歧义是语言性质不是文法写法性质（§3.2 的两棵树），任何写法都存在归属二义，LL(1) 的「每格一条」装不下。工程按约定取非 $\epsilon$ 候选（else 配最近 if），这不是推导出来的正确性而是语言标准的官方裁决（§2.7）。

应用与辨析答案：

1. 调递归上限治标不治本：实验证据是深度 997 爆栈时**记号消费 0 个**（§2.8），说明死循环发生在第一次展开、与输入长度无关，调上限只是把崩溃推迟到更高的栈深度，且每个真实输入都要爆。正确修复是消左递归改写（§2.5）得 G3，改写后递归下降与表驱动对 `id + id` 双跑通过（§2.6）。
2. 推理链：① $T'\to\epsilon$ 的 $\mathrm{FIRST}(\epsilon)={\epsilon}$，含 $\epsilon$，故按 $\mathcal{W}$ 定义取第二支：$\mathcal{W}(T'\to\epsilon)=\mathrm{FOLLOW}(T')$，问题化归为求 FOLLOW；② `E -> T E'` 里 ${T'}$ 后邻 ${E'}$ 且 ${E'}$ 可推空（$E'\to\epsilon$ 在册），规则 3 给 $\mathrm{FOLLOW}(T')\supseteq\mathrm{FOLLOW}(E')$；`E' -> + T E'` 同形，再来一份同款；`T -> F T'` 里 ${T'}$ 在句尾，规则 3 给 $\mathrm{FOLLOW}(T')\supseteq\mathrm{FOLLOW}(T)$；`T' -> * F T'` 里末位 ${T'}$ 也在句尾，得 $\mathrm{FOLLOW}(T')\supseteq\mathrm{FOLLOW}(T')$（自含，无新信息）；③ 而 $\mathrm{FOLLOW}(E')=\mathrm{FOLLOW}(E)$（${E'}$ 总在句尾），$\mathrm{FOLLOW}(T)$ 比 $\mathrm{FOLLOW}(E)$ 多一个 `+`（来自 `E' -> + T E'`）；④ 四路并集中 `+` 在册，故 ${M[T',\ \mathrm{+}]}$ 填 $T'\to\epsilon$（§2.3、§2.6 表）。
3. G2 的右递归 `E -> T + E | T`、`T -> F * T | F` 里，两条候选的公共前缀分别是 $T$ 与 $F$，这正是公共前缀病根，用提公因子手术（§2.5）。G2 没有左递归（递归藏在 `+ E`、`* T` 的尾部），所以左递归手术在此无用武之地。手术后空满分布一致的原因：两个改写把 E、T 层整理出同一批产生式头（`E -> T E'`、`T -> F T'` 完全相同，`E'`、`T'` 的 FIRST/FOLLOW 实验值逐行相等），每格「填不填」由窗口并集决定，故逐格一致；格内产生式不同是因为右递归改写把余串挂在 $E$ 上、消左递归改写把余串挂在收尾变量上。窗口不重叠才能 LL(1)，重叠就冲突；两种手术殊途同归地把分岔推到机器看得见的地方。

**你现在能做什么**：给定一条中小型文法，手算 FIRST/FOLLOW、程序化生成 LL(1) 表、指出冲突格属于左递归还是公共前缀，并对改写前后的文法各跑一遍表驱动解析，报出错误位置。

LL(1) 的合同是「每格一条产生式」，靠文法改写兑现；悬挂 else 一节也露出它的边界：先天歧义它只能按约定硬压，而「向前看一个记号」天然不适合优先级靠后置的结构。下一章把方向掉头：LR 分析从记号流往回归约，把「读完再决定」交给自动机，优先级与结合性不再靠文法分层硬编码，而是一纸声明；你会看到同一份文法在 LR 手里几乎不用改写。
