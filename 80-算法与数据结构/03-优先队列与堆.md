## $\rm \S \, 3.1$ 只回答一个问题的结构

先立任务。三件日常事共享同一个形状：把 k 路各自排好序的日志流归并成一路，每步要取 k 个队头里时间戳最小的那条；任务调度器每步要取优先级最高的作业；下一节的模拟器每步要取最早发生的事件。三件事都不要求「x 在不在这集合里」「第 5 小是谁」「按序遍历一遍」，它们只反复做两个动作：插进一个元素；取走并删掉当前最小元。只承诺这两个动作的结构叫优先队列，两个操作记作 insert 与 delMin。

现有方法先顶上。把元素存进数组有两种天然口径，各把一种操作做到极便宜：

| 实现 | insert | delMin | 看一眼 min |
| --- | --- | --- | --- |
| 有序数组 | $O(n)$ | $O(1)$ | $O(1)$ |
| 无序数组 | $O(1)$ | $O(n)$ | $O(n)$ |
| 二叉堆（§3.2） | $O(\log n)$ | $O(\log n)$ | $O(1)$ |

有序数组的 insert 贵在挪位：找位置用二分只花 $\lceil\log_2 n\rceil$ 票，但插入点之后的元素要整体后移一格，平均半张表；delMin 取首元素零成本。无序数组正好倒过来：insert 追加到末尾零成本，delMin 要扫全表找最小。两张表互为镜像，便宜全给了对称操作中的一方。总账上这笔债现形：n 个元素各 insert 一次再各 delMin 一次，无论哪张表，总票都是

$$
\sum_{k=1}^{n} k \;=\; \frac{n(n-1)}{2} \;=\; \Theta(n^2)
$$

把 n 个元素装进一张表再删光，两种朴素口径付同一笔 $\Theta(n^2)$：操作组合是对称的，便宜分给谁，总账都摊不匀。要总账降到 $\Theta(n\log n)$，两种操作必须同时便宜。堆的卖点一句话：它让价格表上不再有 $O(n)$ 一栏。

平衡二叉搜索树（第 4 章）也能让两操作都是 $O(\log n)$，为什么还要堆？因为树按「还要支持任意键查找、按序遍历」的套餐定价：每个结点背两个指针外加平衡信息，等于为用不到的服务付费。堆把结构削到只剩回答「最小是谁」所需的最少信息，换来更小的常数与更省的内存。

白话：优先队列是只卖两道菜的小馆子，insert 与 delMin 都不许超过 $O(\log n)$；数组两张口径各偏科一头，堆两门都及格。

> 本节小结：优先队列只承诺 insert 与 delMin；有序/无序数组各便宜一头，n 插 n 删总账同为 $\Theta(n^2)$；堆把两头同时压到 $O(\log n)$，且不像平衡树那样为多余的服务付费。

## $\rm \S \, 3.2$ 数组里的完全二叉树

堆（heap，本章取最小堆口径）的定义分两半，两半都为「塞进数组」服务。

形状一半：完全二叉树（complete binary tree），除最底层外每层全满，最底层结点靠左连续排列。这个形状立刻给两样东西：

1. 高度可控。高为 h 的完全二叉树结点数满足 $2^h \le n \le 2^{h+1}-1$（前 h 层全满至少 $2^h$ 个，再添也添不满下一整层），两边取对数得
$$
h \;=\; \lfloor \log_2 n \rfloor
$$
树高是对数，这是本章一切 $O(\log n)$ 条款的几何来源。
2. 没有空洞。结点按层从左到右连续编号装进数组，编号 i 的两个孩子落在 $2i+1$ 与 $2i+2$，父结点落在 $\lfloor(i-1)/2\rfloor$：树整个装在数组里，一个指针都不用。

次序一半：堆有序（heap-ordered），数组每个位置的键不超过它孩子的键。这条局部规则能推的全局事实恰好够用：沿任何一条从根往下走的路径键不减，所以最小元必在 a[0]；但兄弟之间、左右子树之间没有任何次序承诺，除 a[0] 外没有谁是固定的（第二小必是 a[1] 或 a[2]，再往下就没有免费结论了）。堆不是排好序的数组，它把「有序」这个昂贵服务削减到「根最小」一条。

两个操作各配一个修复动作：

1. insert：新元素追加到末尾，然后上浮（swim）：与父结点比，更小就交换，重复到父结点不更大或到达根。每上一层付一票，至多 $\lfloor\log_2 n\rfloor$ 层。
2. delMin：记下 a[0]；末元素搬到根、长度减一；然后下沉（sink）：若有两个孩子，先花一票选出较小者，再花一票与它比较，更小就把当前元素沉下去一层，重复到孩子都不更小或沦为叶子。每层至多两票，至多 $\lfloor\log_2 n\rfloor$ 层。

带计数器的实现如下（票账实验用；生产代码请直接用标准库 heapq，§3.6 就用它）：

```python
class BinHeap:
    def __init__(self): self.a = []; self.cmp = 0
    def push(self, x):                       # 上浮：每层一票
        a = self.a; a.append(x); i = len(a) - 1
        while i > 0:
            p = (i - 1) >> 1; self.cmp += 1
            if a[i] < a[p]: a[i], a[p] = a[p], a[i]; i = p
            else: break
    def popmin(self):                        # 下沉：每层至多两票
        a = self.a; m = a[0]; last = a.pop()
        if a:
            a[0] = last; i = 0; n = len(a)
            while True:
                l = 2 * i + 1
                if l >= n: break
                r = l + 1
                if r < n:                    # 有右孩子才要选小
                    self.cmp += 1
                    if a[r] < a[l]: l = r
                self.cmp += 1
                if a[l] < a[i]: a[i], a[l] = a[l], a[i]; i = l
                else: break
        return m
```

合同条款汇总：insert 上浮 $\lfloor\log_2 n\rfloor$ 票；delMin 下沉 $2\lfloor\log_2 n\rfloor$ 票；读 min 零票。三个操作里两个对数、一个常数，§3.1 价目表的第三行至此兑了现。

白话：堆是一棵存在数组里的完全二叉树，规矩只有一条「爹不比孩子大」；插入时新元素往上冒，删除时末元素下来再往下沉，冒和沉都只走树高那么多层。

> 本节小结：完全二叉树给「高 $=\lfloor\log_2 n\rfloor$」与「数组无缝存放」两样东西；堆有序保证最小在根、此外不承诺次序；insert 上浮一票一层，delMin 下沉两票一层，条款全是 $O(\log n)$。

## $\rm \S \, 3.3$ 建堆的两条路：自底向上对逐个插入

任务：手里已有 n 个键（不是从空堆一个个长出来），要把它们变成一个堆。两条路，票账差一个 n。

路线 A，逐个 insert：第 k 个元素插入时堆里已有 k−1 个，付至多 $\lfloor\log_2 k\rfloor$ 票，总票为

$$
\sum_{k=1}^{n} \lfloor \log_2 k \rfloor
$$

对完全树 $n=2^K-1$ 这笔账可以精确结清：深度 t 恰有 $2^t$ 个位置、各付 t 票，故总和为 $\sum_{t=1}^{K-1} t\,2^t$。用 §2.2 同款错位相减：记 $S=\sum_{t=1}^{m} t\,2^t$，则 $2S=\sum_{t=2}^{m+1}(t-1)\,2^t$，两式相减后中段各项变成 $-2^t$：

$$
S \;=\; m\,2^{m+1}\;-\;(2^{m+1}-4)\;-\;2 \;=\; (m-1)\,2^{m+1}+2
$$

代 $m=K-1$ 得

$$
\sum_{t=1}^{K-1} t\,2^t \;=\; (K-2)\,2^K+2
$$

K=10（即 n=1023）给 8194 票，实测表里「Σfloorlog」一列逐位命中。

路线 B，自底向上（bottom-up）：叶子单个成堆、不用管；从最后一个内部结点（编号 $\lfloor n/2\rfloor-1$）倒着到根，逐个下沉。最坏情形（降序输入，每次下沉一路到底）的层数等于全体结点的高度之和，仍分层计票：深度 t 有 $2^t$ 个结点、各高 $K-1-t$，

$$
\sum_{t=0}^{K-1} 2^t\,(K-1-t) \;=\; 2^K-K-1 \;=\; n-K
$$

一般的 n 恰为 $n-s(n)$，其中 $s(n)$ 是 n 二进制表示里 1 的个数：上界与 n 只差一个常数项。比较票是层数的两倍，因为完全树里每个内部结点恰有两个孩子：选较小孩子一票、与结点本身比一票。降序输入正是它的最坏情形：每个被下沉的键都比下方所有键小，一路沉到底。

实测对账（exp1A，降序输入，最小堆）：

| n | 下沉层数（理论 $n-s(n)$） | 下沉法票 | 插入法票 | 插入/下沉 |
| --- | --- | --- | --- | --- |
| 1023 | 1013（1013） | 2026 | 8194 | 4.04 |
| 65535 | 65519（65519） | 131038 | 917506 | 7.00 |
| 1048575 | 1048555（1048555） | 2097110 | 18874370 | 9.00 |

完全树上层数与票数逐位命中理论；比值随 $\log_2 n$ 线性涨，规模每乘 64 比值涨 3：档位差 $n$ 对 $n\log n$ 的活体展示。一般 n 的行（1024、65536）值得停一拍：实测层数 1015 低于上界 1023，因为完全树底部参差帮了忙，有的内部结点只有独子（选小那一票免了）、有的下沉提前停（孩子不更小）；上界是合同定价，实付可以更低，2028 票恰为 $2\times 1015$ 再减 2 张独子折扣，账目能对到个位。

随机输入对照（exp1A）：下沉法收 1.88 票/元素（n=65535，最坏 2.0），几乎不动，它对什么输入都收约 2n 票；插入法从最坏 14.0 跌到 2.28 票/元素，随机键的期望上浮深度是 $O(1)$，随机输入救的是插入法。但选表比的是最坏条款：自底向上在任何输入上都是 $\Theta(n)$，插入法的合同最坏一栏写着 14 票/元素。

计时（exp1B，降序输入，min over reps）：

| n | 下沉法 | 插入法 | 倍数 |
| --- | --- | --- | --- |
| 65535 | 8.304 ms | 79.915 ms | 9.62 |
| 262143 | 37.268 ms | 388.830 ms | 10.43 |
| 1048575 | 176.942 ms | 1732.324 ms | 9.79 |

$n=2^{20}-1$ 处票数比 9.00、时间比 9.79：两个实现同是数组交换、同在解释器里跑，§1.4 的常数近乎同价，票账直接兑现成时间账。

白话：建堆别一个个往里插（那是 $n\log n$ 的冤枉钱），把现成的数组从中间倒着一个个下沉，全体只付 ${2n}$ 出头的票。

> 本节小结：逐个插入建堆最坏 $\Theta(n\log n)$（完全树精确 $(K-2)2^K+2$ 票）；自底向下沉最坏 $2(n-s(n))$ 票即 $\Theta(n)$；随机输入救插入法、救不了最坏条款；计时比 9.79 对票数比 9.00，常数同价时票账即时间账。

## $\rm \S \, 3.4$ 堆排序：一格空白的兑现

组装。升序排序用最大堆（堆序反向：父不小于孩子；全部票账镜像同款）。两步：1. 自底向上建堆，付 $2(n-s(n))$ 票；2. 反复把堆顶（当前最大元）与堆末元素交换、堆缩一格、下沉修复，堆长为 i 时付至多 $2\lfloor\log_2 i\rfloor$ 票。总账：

$$
2\,(n-s(n)) \;+\; \sum_{i=1}^{n-1} 2\lfloor\log_2 i\rfloor \;\le\; 2n + 2n\log_2 n \;=\; O(n\log n)
$$

三个条款同时兑现：全输入无条件 $O(n\log n)$，没有对抗输入可撕毁它，且 §2.3 的地板价保证这张表不可能再低一档；空间 $O(1)$ 原地，交换全在原数组内完成。第 2 章留的那格空白签上了。口径说明：本章计数器是最小堆，直接跑出的是降序；升序用最大堆，是同一张表的镜像，票账一字不差。

不稳定照旧，机理与 §2.1 快排同款：堆顶与堆末的交换跨越中间全部元素。最小反例：输入 $[2_a,\,2_b,\,1]$ 本身已是最大堆，第一轮交换就把 $2_a$ 换到末位、$2_b$ 从它头上跳过，排完得 $[1,\,2_b,\,2_a]$，相等元素的相对次序被长距搬运翻掉。多键排序要保次序时，这张表不能进 §2.1 的两步稳定排序法。

工程角色：纯堆排序少见，常当保险。C++ 的 std::sort 走 introsort 路线：快排打头（常数好、扫描顺序对缓存友好），递归深度超限就退到堆排序封死最坏，小段再用插入排序收尾。第 2 章 §2.5 那张图里「递归深度超限时退堆排序」的分支在此兑现。不让它当主力的原因在常数：下沉沿数组大步跳跃访存（下标 $0\to 2\to 6\to 13\cdots$），与快排划分的顺序扫描相反，§1.4 的常数账（缓存线）对它不利。

白话：堆排序 = 先花 2n 票把数组盘成堆，再反复「取走最大、缩一格、修一修」；合同上无可挑剔，常数上跑不过快排，所以工程里它当快排的保险丝。

> 本节小结：建堆 $2(n-s(n))$ 票加 n 轮下沉，全输入 $O(n\log n)$ 且原地，地板价封死再降的可能；跨距交换造成不稳定；introsort 用它给快排的最坏情形兜底，自己不当主力。

## $\rm \S \, 3.5$ d 叉堆：权衡怎么随 d 移动

把「两个孩子」推广成 d 个，权衡立刻现形。d 叉堆（d-ary heap）：编号 i 的孩子在 $di+1$ 到 $di+d$，父在 $\lfloor(i-1)/d\rfloor$。树更矮了，高约 $\log_d n$；但两本票账朝反向走：

1. insert 付深度票：树矮一层省一层，更便宜。
2. delMin 每层约付 d 票：先在 d 个孩子里选最小（d−1 票）再与结点比（1 票）。层数省下的，单价又赔回去。

实测插入账（exp2A，降序输入一路浮顶，n=65535，理论 $\sum_{k\le n}\text{depth}_d(k)$ 逐位命中）：

| d | 插入总票 | 票/元素 | delMin 票/次（实测） | delMin 上界 $d\cdot L$ |
| --- | --- | --- | --- | --- |
| 2 | 917506 | 14.000 | 31.01 | 30 |
| 4 | 495156 | 7.556 | 32.56 | 32 |
| 8 | 350412 | 5.347 | 41.99 | 48 |

读表三句话：

1. 插入票随 d 近乎对半砍：14.000 到 7.556 到 5.347，d 翻倍深度账就砍一截。
2. delMin 的实测 31.01 对上界 30 多出约一票，账目恰好闭合：计数器数比较、层数数交换，停机那层「比了但不用换」的票计入前者不计入后者，$2\times 15.0037+1=31.01$。d=8 实测 41.99 远低于上界 48：大键下沉常在中途停住（实测层数 5.12 对 $L=6$），上界按一路到底定价，实付更低。
3. 本负载（65535 次降序插入加 4096 次 delMin+push 更大键）里插入占票数大头（917506 对约 127000），插入票随 d 对半砍、delMin 单价上涨填不平，于是计时单调走低：d=2 用 99.86 ms，d=4 用 61.49 ms，d=8 用 47.99 ms（exp2B）。

d 没有全局最优值，最优 d 由负载配比决定：插入密集（构建期、事件源源入表）选大 d；delMin 密集且插入稀少时，大 d 的单价税越缴越多。d=2 是均衡默认，Python 标准库 heapq 就是二叉堆；大 d 叉堆在稠密图的 Dijkstra 上有名有实，第 6 章兑现这张表。

白话：d 叉堆把树压矮换插入便宜，代价是每次下沉要在更多孩子里挑 smallest；活儿以插入为主就调大 d，以删除为主就守住 d=2。

> 本节小结：d 叉堆 insert 约 $\log_d n$ 票、delMin 每层约 d 票；插入票随 d 对半砍（14.000/7.556/5.347），delMin 单价随 d 涨（31.01/32.56/41.99）；本负载计时 99.86/61.49/47.99 ms 单调降，d 的最优值由负载配比定。

## $\rm \S \, 3.6$ 事件驱动模拟：堆的最出名工地

第 38 册 §2.6 用手写事件循环给 M/M/1 的闭式解盖章，那个循环能写成两只钟（下一到达、下一离开各记一个时刻），是因为系统里只有两种事件。真实系统的事件种类一多，超时、重传、心跳、定时器，「每种事件存一个变量」就散架了。通用做法：把全部未来事件放进一张表，每步取最早的那张。这张表就是优先队列，这个用法叫事件驱动模拟（event-driven simulation）。

骨架（直接法，M/M/1，到达率 $\lambda$、服务率 $\mu$，完整实现见 exp3）：

```python
import heapq, random
rng = random.Random(20261107)
events = []                                  # 事件表：(时刻, 序号, 类型)
seq = 0
heapq.heappush(events, (rng.expovariate(lam), seq, 0)); seq += 1
while done < n_cust:
    t_now, _, kind = heapq.heappop(events)   # 取最早事件
    if kind == 0:                            # 到达：预约下一次到达
        heapq.heappush(events, (t_now + rng.expovariate(lam), seq, 0)); seq += 1
        # 服务台空闲则预约其离开并记等待，否则进入 FIFO 队列
    else:                                    # 离开：队首补位，预约其离开
        ...
```

两个细节值得钉死。其一，事件是元组，比较先看时刻、平局看序号 seq：同一时刻的到达与离开谁先入账，逐位统计会差一位；seq 让破平规则确定且可复现，这个细节在 §3.7 变成故障主角。其二，直接法只调度「下一个」未来事件，任一时刻表里至多两张票（下一到达、下一离开），实测事件表最大规模为 1（pop 之后、push 之前观测）。堆在这里从不长高，它的价值不是「大表上省 log」，而是把「取最早」做成接口：表里事件种类随便加，取最早的条款照常履行。

实测（exp3，$\lambda=0.9$，$\mu=1$，每种子 120000 位顾客，两个种子，预热前 10% 不进统计；理论 $W_q=\rho/(\mu-\lambda)=0.9/0.1=9$，$W=1/(\mu-\lambda)=10$）：

| 种子 | $W_q$ | $W$ |
| --- | --- | --- |
| 20261107 | 10.1790 | 11.1847 |
| 20261108 | 8.3777 | 9.3777 |
| 合并 | 9.2783（对理论 +3.09%） | 10.2812（对理论 +2.81%） |

诚实备注：单种子波动约 ±2%，与第 38 册 §2.6 的老话一脉相承：$\rho=0.9$ 时队长起伏的相关时间约 380 个服务时间，短种子采不到几个独立起伏；这里两个种子把误差压到 3% 量级，要更准就加种子，测量成本的账那边已算过，不重算。

白话：模拟连续时间系统，就把每种「未来要发生的事」连时刻一起扔进堆，主循环每步取最早的处理；堆保证「取最早」永远只花对数票，事件种类再多也不改条款。

> 本节小结：事件表=优先队列；元组主键时刻、序号破平；直接法表长恒小（实测最大 1），堆的价值在通用接口而非大表；$W_q$ 合并 9.2783 对理论 9、$W$ 合并 10.2812 对理论 10，误差 3% 量级与种子数自洽。

## $\rm \S \, 3.7$ 排障实录：语义分叉与票外之票

exp3b 问一个 §3.6 没答的问题：事件表本身值多少钱？最初的方案最顺手：写两份完整模拟，一份事件表用 heapq，一份用无序数组加线性扫描，计时相除。结果一份正常跑完，另一份「死」了。排查按证据走：

1. 症状：堆版几秒完成；扫描版的完成计数 ndone 卡在 203（总共 10000）不再增长。
2. 定位：faulthandler（python 加 `-X faulthandler` 启动，或代码里用 faulthandler 定时转储全部线程栈）把卡住瞬间的调用栈打了出来，指向扫描版内层 `for i in range(1, len(ev))`。栈说明不是死锁：主循环还在转，只是永远转不到完成。
3. 病根：两份实现不只是数据结构不同。堆版用序号破平，扫描版取「先扫到的最小者」，同一时刻事件的处置次序不同，业务轨迹从此分叉，扫描版那条恰好走进一个永不完结的调度死局。名义上在对比数据结构，实际在对比两套业务调度：被测变量没控住。这类故障不报错、不抛异常，只留一个看似性能问题的死循环，靠对账数字（203 对 10000）才现形。

修法是把业务整体请出实验室：预生成同一条事件时间戳流（表长记 E=200），两个被测对象只做同一件事，反复「取出最小元、插入一个新时刻」，一个用堆（heapify 后 heappop/heappush），一个用无序数组（线性扫描找最小、list.pop 移除）。10000 次操作，纯数据结构对纯数据结构：

```python
def bench(struct, times):            # 同一条预生成时间戳流，new_ts() 生成新时刻
    t = list(times)
    if struct == "heap":
        heapq.heapify(t)
        for _ in range(len(t)):
            v = heapq.heappop(t); heapq.heappush(t, v + new_ts())
    else:
        for _ in range(len(t)):
            bi = 0
            for i in range(1, len(t)):
                if t[i] < t[bi]: bi = i
            v = t.pop(bi); t.append(v + new_ts())
```

实测：堆版 2.3 ms，扫描版约 2.2 s，倍数 939.8（重跑同段得 925.3，计时波动 2% 内，量级稳定）。理论比较票比是每次取最小扫描付 $E-1\approx 199$ 票、堆付约 $\log_2 E\approx 7.6$ 票：

$$
\frac{E}{\log_2 E} \;=\; \frac{200}{7.6} \;=\; 26.2
$$

实测 939.8 约是理论的 36 倍，多出来的倍数全在票外：

1. 移位票。list.pop 取中间位平均要搬半张表，这笔 $O(E)$ 的内存搬运不进比较票账：扫描版每次操作实际付两笔 $O(E)$，比较一整遍，再搬半张表。
2. 单价票（§1.4）。扫描的 199 次比较由解释器逐条跑 Python 字节码，堆的 heappop/heappush 是标准库 C 实现；同名的「一次比较」两边单价差一个量级。若把堆换成本章手写计数堆，堆版同样要慢一个量级：939.8 是「算法差距 × 语言差距」的乘积，不是算法差距本身。
3. 理论模型没有被打脸。它预测了方向（表一大扫描必死）与量级起点（至少 26 倍），两条都兑现；它从没承诺精确倍数，§1.1 要求档位声明连同前提一起念，前提里本就写着「只数比较票、常数视作同价」。实测与理论的差值是模型口径的边界，不是模型的错：第 1 章搭的「理论对实测」那座桥（§1.3、§1.4），在此过了最重的一辆车。

> 排障教训：对比实验的口径只有一条：两个被测对象之间，除被测差异外其余一切相同。「共用同一条预生成输入、只换数据结构」把这条口径变成机械步骤，语义分叉这类病在开工前就失去了入口。

白话：想让 A 比 B 输 939 倍还是输 26 倍，取决于你数不数搬家的票、算不算单价的差；但「扫描必死」这个方向，两种口径都说对了。

> 本节小结：带业务调度的双实现会因破平规则不同而轨迹分叉（扫描版 ndone 卡 203，faulthandler 指向扫描内层）；改用共用预生成事件流的纯数据结构口径后，堆 2.3 ms 对扫描约 2.2 s，倍数 939.8 对理论 $E/\log_2 E=26.2$，差额来自 list.pop 的 $O(E)$ 移位与解释器对 C 的单价差。

## $\rm \S \, 3.10$ 本章自测答案

概念回顾答案：

1. 有序数组 insert $O(n)$（二分找位 $\lceil\log_2 n\rceil$ 票加挪位平均半表）、delMin $O(1)$；无序数组正好镜像；堆两个操作分别 $\lfloor\log_2 n\rfloor$ 与 $2\lfloor\log_2 n\rfloor$ 票。n 插 n 删时前两张表一个付「插入扫/挪半表 × n」、一个付「删除扫全表 × n」，总票同为 $\tfrac{n(n-1)}{2}=\Theta(n^2)$；堆两操作都对数，总账 $O(n\log n)$（来源：§3.1、§3.2）。
2. 完全性（除最底层外全满、最底层靠左连续）。它给两样东西：高 $h$ 满足 $2^h\le n\le 2^{h+1}-1$，两边取对数得 $h=\lfloor\log_2 n\rfloor$；以及结点按层连续编号后孩子必在 $2i+1,2i+2$、父在 $\lfloor(i-1)/2\rfloor$，位置由编号唯一决定、没有空洞，所以不需要指针（来源：§3.2）。
3. 最坏层数 = 全体结点高度之和：深度 t 有 $2^t$ 个结点、各高 $K-1-t$，求和得 $2^K-K-1=n-K$（一般 n 为 $n-s(n)$，只差常数）；比较票是层数两倍，因完全树内部结点恰有两个孩子。随机输入下下沉法约 1.88 票/元素（几乎不动），插入法从 14.0 跌到 2.28 票/元素（期望上浮 $O(1)$）：随机救的是插入法；但合同比最坏条款，插入法最坏一栏仍写着 14 票/元素，自底向上任何输入都 $\Theta(n)$，所以选它（来源：§3.3）。
4. 两票 = 在孩子里选较小者一票 + 与结点本身比一票；d 叉后选小变 d−1 票，每层约 d 票，insert 的深度票则随 d 缩水。差额那一票是停机层「比了但不用换」的比较票：计数器数比较、层数数交换，$2\times 15.0037+1=31.01$（来源：§3.2、§3.5）。
5. 建堆 $2(n-s(n))$ 票（$O(n)$）+ n 轮「堆顶换末位、缩一格、下沉」各 $2\lfloor\log_2 i\rfloor$ 票，总账 $O(n\log n)$ 对一切输入成立，§2.3 地板价封死更低档位；交换全在原数组内所以原地；堆顶与末位的跨距交换翻掉相等元素的相对次序（$[2_a,2_b,1]$ 一轮就现形）所以不稳。introsort 让它当快排的保险丝：递归深度超限才启用，主力仍是常数更优、访存顺序对缓存友好的快排（来源：§3.4）。

应用与辨析答案：

1. 理论下限：每次取最小扫描付 $E-1$ 票、堆付约 $\log_2 E$ 票，$E=10^5$ 时 $E/\log_2 E\approx 10^5/16.6\approx 6000$ 倍起步。票外更糟的两笔：list.pop 每次平均搬半张表（第二笔 $O(E)$，不进比较票账）；扫描循环跑解释器字节码、堆操作跑 C，单价差一个量级（来源：§3.7）。
2. 选大 d。insert 与 delMin 之比 1000 比 1 时，总票约 $1000\log_d n+d\log_d n$，d 增大只线性加重 delMin 一侧、却让占绝对大头的一侧按 $\log_d n$ 缩水，净赚。d=8 在 exp2B 赢，因为那个负载插入票占约 88%（917506 对约 127000）；换成 delMin 密集的负载（比如几乎只删不插），d=8 每层 8 票的单价税会让它输给 d=2。配比定 d，不是 d 定对错（来源：§3.5）。
3. 往小动。移位票从解释器的逐元素搬运换成 memmove 的一块拷贝，单价骤降但 $O(E)$ 的量不变；比较循环仍是 Python 字节码，仍是大头。倍数会明显低于 939.8 但仍远高于 26.2，具体落点由「字节码比较与 memmove 的单价比」决定，这正是 §1.4 的常数账：量（票数）没变，单价变了，总价就变。考的是「单价票」这张（来源：§3.7、§1.4）。

**你现在能做什么**：拿到任何一个「要反复取最小」的场景，你能说出三张价目表各自的价格、算出建堆与操作的比较票数并与实测对账，还能在「实测倍数远超理论」时把差额拆成移位票与单价票。

优先队列答得了「当前最小是谁」，答不了「x 在不在这张表里」「x 排第几」：它把次序信息刻意削减到只剩根。当任务需要按任意键查找与按序遍历，价目表得换成符号表。第 4 章从二叉搜索树的点名任务开张，哈希把点名再压缩成一次算术。
