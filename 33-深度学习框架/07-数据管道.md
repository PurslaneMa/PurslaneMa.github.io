## $\rm \S \, 7.1$ 一行起步：TensorDataset 与 DataLoader

要解决的问题：数据已经躺在内存里，每条是一条样本加一个标签，要按 batch 喂进训练循环，最省事的写法是什么。

```python
import torch
from torch.utils.data import TensorDataset, DataLoader

X = torch.arange(20.).reshape(10, 2)              # 10 条样本，每条 2 维
y = torch.arange(10)                              # 10 个标签
loader = DataLoader(TensorDataset(X, y), batch_size=4, shuffle=True)
for xb, yb in loader:                             # 每次迭代产出一个 batch
    print(xb.shape, yb.shape)                     # torch.Size([4, 2]) torch.Size([4])
print(len(loader))                                # 3：batch 个数，不是样本数
```

`TensorDataset` 把「第 i 条就是 `X[i]` 与 `y[i]`」写成一行，`DataLoader` 把它变成 `for xb, yb in loader:` 就能驱动的 batch 流；`shuffle=True` 让每个 epoch 的顺序重新打乱。十行不到，上一章那三行手写切片就被替掉了。

| 写法 | 说明 |
| --- | --- |
| `TensorDataset(X, y)` | 把若干张量按第 0 维绑定成数据集，一次取出一条样本对 |
| `DataLoader(ds, batch_size, shuffle)` | 把数据集包成按 batch 迭代的加载器 |
| `for xb, yb in loader:` | 迭代产出的每个 batch 是一对张量 |
| `len(loader)` | batch 个数 ${\lceil n/\mathrm{bs}\rceil}$，不是样本数，最后一批可能不满 |

**本节小结**：`TensorDataset`＋`DataLoader` 两行就把上一章的手写切片替掉了；`len(loader)` 数的是 batch 数不是样本数。下一节看数据不在内存里时怎么写自己的 Dataset。

## $\rm \S \, 7.2$ 自定义 Dataset：三个方法

要解决的问题：`TensorDataset` 只能装已经切好的张量。数据放在磁盘上、每条要现场解码或增强时，得自己规定「下标进、样本出」这一步。

```python
import numpy as np
from torch.utils.data import Dataset

class GaussianData(Dataset):                     # 继承 Dataset 即获得协议
    def __init__(self, n, d, seed=42):
        rng = np.random.default_rng(seed)        # 一次性准备放 __init__
        self.X = torch.tensor(rng.normal(size=(n, d)))
        self.y = torch.tensor((self.X[:, 0] > 0).long())
    def __len__(self):
        return len(self.X)                       # 一共多少条
    def __getitem__(self, i):
        return self.X[i], self.y[i]              # 下标进、样本对出
```

三个方法的契约：

1. `__init__` 只做一次的准备：读元数据、打开文件句柄、算出长度，不在这里把整个数据集搬进内存。
2. `__len__` 报条数：`DataLoader` 靠它算 batch 数（§7.1）。
3. `__getitem__(i)` 给第 i 条：`DataLoader` 会对它调用 n 次，每次只要一条。

把这三件事分开，是让「数据在内存、在磁盘、还是现场增强」都不影响训练循环的原因。`__getitem__` 返回单条样本或 `(样本, 标签)`，元素优先返回张量：返回裸 numpy 数组时 batch 的 dtype 会跟着 numpy 走，`np.float64` 的 X 让 batch 变成 `double`，与 float32 的模型第一次前向就撞类型错误（§7.6）。

**本节小结**：自定义 Dataset 只需守住三个方法——`__init__` 备料、`__len__` 报数、`__getitem__` 单条进出；存取细节藏在 `__getitem__` 背后，训练循环一个字不改。下一节回到 DataLoader 本身的旋钮。

## $\rm \S \, 7.3$ DataLoader 关键参数与现成数据集

要解决的问题：`batch_size` 之外还有哪些常调的旋钮，现成的数据集从哪来。签名是 `DataLoader(ds, batch_size=32, shuffle=True, num_workers=0, pin_memory=False, drop_last=False, collate_fn=None)`，常用参数列如下：

| 参数 | 一句话说明 |
| --- | --- |
| `shuffle` | 每个 epoch 是否重新打乱取样本的顺序（训练开、评估关） |
| `num_workers` | 开几个子进程预取数据，0 表示在主进程里取（§7.5） |
| `pin_memory` | 把 batch 放进锁页内存，配 GPU 时拷贝更快（第 8 章） |
| `collate_fn` | 自定义「B 条样本拼成一个 batch」的规则，变长数据靠它 |
| `drop_last` | 丢掉最后一个不满的 batch，保证每批等大 |

图像这类数据有现成件：`torchvision.transforms` 提供 `Resize`、`RandomCrop`、`ToTensor`、`Normalize` 等可组合的预处理，`torchvision.datasets.MNIST(root, train=True, download=True, transform=...)` 直接给你一个 `Dataset`，`download=True` 会自动下载并解压；训练循环对它的用法与 `TensorDataset` 完全一样。

变长文本（每句长度不同）要自定义 `collate_fn` 把一批补到同长（片段用到 `torch.nn.functional`，别名为 `F`）：

```python
def pad_collate(batch):                          # batch: [(x1, y1), (x2, y2), ...]
    xs, ys = zip(*batch)                         # 拆成样本与标签
    L = max(len(x) for x in xs)                  # 本批最长的那条
    return torch.stack([F.pad(x, (0, L - len(x))) for x in xs]), torch.stack(ys)
```

这段代码在做什么：把一批变长样本拆成样本列与标签列，找出本批最长的句子，短的用 `F.pad` 补零到同长，最后样本与标签各自 `stack` 成一个张量。

**本节小结**：常用旋钮五个——shuffle、num_workers、pin_memory、collate_fn、drop_last；变长数据是 `collate_fn` 的主场，图像与文本都有现成件可拿。下一节打开 DataLoader 的盖子。

## $\rm \S \, 7.4$ 打开盖子：三层抽象与 30 行迷你 DataLoader

不打开盖子，你会缺一块判断力：`DataLoader` 会用了，却说不清它内部哪一步在采样、哪一步在拼接，遇到变长数据或自定义顺序时不知道该把参数伸向哪里。

把「喂一个 batch」拆成三层，是为了让三个互相独立的决策各自变化而不重写彼此：

| 层 | 职责 | 迷你接口 | PyTorch 对应物 |
| --- | --- | --- | --- |
| Dataset | 单条数据怎么取、一共多少条 | `__len__` / `__getitem__` | `torch.utils.data.Dataset` |
| Sampler | 这一轮按什么顺序取下标 | `permutation` 或 `arange` | `Sampler` / `shuffle=` |
| DataLoader | 按序取一批、拼成一个张量 | `__iter__` 产 `(X, y)` | `torch.utils.data.DataLoader` |

分层的动机是组合爆炸：采样策略（顺序、随机、按类平衡）乘上批大小乘上拼接方式，若写死在循环里，每换一样就重写一遍循环。PyTorch 的 `Dataset` 是个纯协议类，只有两个方法要实现：`__len__` 报条数、`__getitem__` 给下标回样本。数据在内存里、在磁盘上、还是要现场做增强，都藏在 `__getitem__` 背后，训练循环一个字不用改；`__getitem__` 返回的东西可以现场算（增强）、现场解码（图片文件），调用方拿到的都只是「下标进、样本出」。

```python
class DataLoader:
    def __init__(self, X, y, batch_size, shuffle=False, seed=None, collate_fn=None):
        self.X, self.y, self.bs = X, y, batch_size
        self.shuffle, self.rng = shuffle, np.random.default_rng(seed)
        self.collate_fn = collate_fn or (lambda items: (
            np.stack([it[0] for it in items]),       # 样本堆成 (B, ...)
            np.array([it[1] for it in items])))      # 标签堆成 (B,)
    def __len__(self):
        return (len(self.X) + self.bs - 1) // self.bs   # batch 个数，向上取整
    def __iter__(self):
        idx = self.rng.permutation(len(self.X)) if self.shuffle else np.arange(len(self.X))
        for s in range(0, len(idx), self.bs):
            j = idx[s:s + self.bs]                     # 采样：按序号切
            yield self.collate_fn([(self.X[i], self.y[i]) for i in j])
```

三个组件都在这 30 行里：`__len__`/`__getitem__` 的精神由 `self.X[i]` 承担（内存数据集），采样是 `permutation` 与 `arange` 二选一，组批是 `collate_fn`。collate（拼接）值得点名：它把 B 条样本摞成一个张量，`np.stack` 就是默认实现；变长数据（NLP 的句子）在这里要 pad 到同长，PyTorch 允许自定义 `collate_fn` 就是为此。

**本节小结**：三层各管一件事——Dataset 管单条存取、Sampler 管顺序、DataLoader 管组批；拆层是因为三个决策独立变化，30 行迷你版把它们各归各位。下一节回答「为什么非要打乱」。

## $\rm \S \, 7.5$ 打开盖子：无偏性、打乱实验与逐数对照

不打开盖子，你会缺一块判断力：知道训练要 `shuffle=True`，却说不出凭什么，也看不出不打乱的代价落在哪个 batch 上。

SGD 的正当性来自「batch 梯度是全量梯度的无偏估计」：设 $B$ 是从训练集均匀随机抽出的下标集，则

$$
\mathbb{E}_{B}\big[g_{\mathrm{batch}}\big]
= \mathbb{E}_{B}\Big[\frac{1}{|B|}\sum_{i\in B}\nabla\ell_i\Big]
= \frac{1}{n}\sum_{i=1}^{n}\nabla\ell_i
= g_{\mathrm{full}}
$$

这个期望是对「均匀随机抽一个 batch」取的，所以它要求 batch 的成分不与样本内容相关。数据若按类别排好序，不打乱时每个 batch 全是同一类，单步梯度系统性偏向该类，条件破坏，期望不再是全量梯度；打乱恢复的正是「下标与内容无关」这条抽样前提。

实验构造最坏情况：数据按类别排序（前 200 条全类 0、后 200 条全类 1），同一个网络同一组超参，只差打不打乱。第一个 epoch 的逐 batch 损失：

| batch | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 不打乱 | 0.068 | 0.012 | 0.034 | 0.007 | 0.021 | 0.007 | **2.767** | 0.001 |
| 打乱 | 1.487 | 0.146 | 0.015 | 0.069 | 0.055 | 0.026 | 0.005 | 0.026 |

不打乱的曲线在第 7 个 batch 上跳到 2.767：前 6 个 batch 全是类 0（标签成分 `0,0,0,0,0,0,24`），参数刚学会「都猜类 0」，第一个类 1 的 batch 就摔一跤。参数在两类之间来回摆，每个 epoch 末尾停在「偏向类 1」的位置。按 epoch 看固定测试集：

| epoch | loss 打乱 | acc 打乱 | loss 不打乱 | acc 不打乱 |
| --- | --- | --- | --- | --- |
| 1 | 0.0777 | 0.98 | 0.2003 | 0.94 |
| 5 | 0.0848 | 0.99 | 0.0871 | 0.99 |
| 10 | 0.0902 | 0.99 | 0.0985 | 0.98 |
| 30 | 0.1290 | 0.97 | 0.1313 | 0.98 |

第 1 个 epoch 差 4 个百分点、loss 差近 3 倍；之后两者都收敛，这道题太容易，差异被磨平了。验证环境：WSL Ubuntu，NumPy 2.5.4，float64。打乱的价值在第 1 个 epoch 最显眼，数据越难、类别越不均，差距越持久。

对照实验：10 条样本、batch 4，固定置换 `[7, 6, 1, 3, 2, 4, 0, 9, 5, 8]` 喂两边。迷你版按置换切片；torch 版用 `DataLoader(ds, batch_size=4, sampler=FixedPermSampler(perm))`，`sampler` 参数正好是「把采样决策交给外部」的官方接口。3 个 batch 逐数对照，${\max|\mathrm{diff}|=0}$：两边产出的 batch 完全一致，验证环境 WSL PyTorch 2.14.1+cpu。

并行 worker 一句话：GPU 算一个 batch 只要毫秒，CPU 备料（读盘、解码、增强）往往更慢，数据管道成为瓶颈；`num_workers=k` 开 k 个子进程提前备好后续 batch（prefetch，预取），把「备料」与「计算」重叠起来，多进程是为了绕开 Python 的 GIL。

**本节小结**：无偏性要求 batch 成分与样本内容无关，按类排序且不打乱时这条被破坏，第 7 个 batch 的 2.767 就是代价；逐数对照证明 `sampler` 接口与手写置换产出完全一致。下一章从数据转向设备与精度。

## $\rm \S \, 7.6$ 常见错误与报错翻译

| 症状 | 原因 | 怎么改 |
| --- | --- | --- |
| 第一次前向报 `mat1 and mat2 must have the same dtype, but got Double and Float` | `__getitem__` 返回裸 numpy 数组或 Python 浮点，batch 的 dtype 跟着数据源走 | 在 `__getitem__` 里返回张量，或 `torch.tensor(..., dtype=torch.float32)`（§7.2） |
| 变长数据组 batch 抛 `ValueError: all input arrays must have the same shape` | 默认 collate 要求所有样本同形状，`np.stack` 在「第二维不相等」这一步卡住 | 自定义 `collate_fn` 做 padding（§7.3）；torch 的 `default_collate` 同样会抛 `RuntimeError: stack expects each tensor to be equal size` |
| `len(loader)` 被当成样本数，或以为每个 batch 都一样长 | `len(loader)` 数的是 batch 个数，最后一批可能不满 | 需要每批等大就设 `drop_last=True`（§7.1、§7.3） |

**本节小结**：管道报错大多出在 dtype 与形状两头——numpy 数组混进 batch 坏 dtype，变长样本坏 stack；先把 `__getitem__` 的返回统一成张量，一半的坑就此消失。

## $\rm \S \, 7.9$ 本章自测答案

### $\rm \S \, 7.9.1$ 关键概念回顾答案

1. Dataset 管单条存取、Sampler 管顺序、DataLoader 管组批与拼接；拆层是因为三个决策独立变化，写死则组合爆炸。（§7.4）
2. `__init__`、`__len__`、`__getitem__`；不可见，存取细节藏在 `__getitem__` 背后，循环只认下标。（§7.2）
3. 数的是 batch 个数（${\lceil n/\mathrm{bs}\rceil}$）；collate 把 B 条样本摞成一个张量，变长数据在 `np.stack` 处因形状不等而失败。（§7.1、§7.4）
4. batch 成分必须与样本内容无关（均匀抽样）；按类排序且不打乱时成分与类别完全相关，单步梯度有偏。（§7.5）
5. 损失跳到 2.767；前 6 个 batch 全是类 0，参数偏向「都猜类 0」，首个类 1 batch 的梯度既大又反方向。（§7.5）

### $\rm \S \, 7.9.2$ 应用与辨析答案

1. ${\lceil 400/32\rceil=13}$ 个；最后一个 16 条（${400-12\times32}$），`__len__` 的向上取整就是为它。（§7.1）
2. `ValueError`；`np.stack` 要求所有样本同形状，变长句子的第二维不相等。（§7.6）
3. 没有区别：batch 大小等于数据总量时只有一种 batch，每步就是全量梯度，采样无关紧要。（§7.5）
4. `shuffle=True` 等价于内置的随机 Sampler；按类平衡的 Sampler 每个 batch 产出一半类 0、一半类 1 的下标序列，实现 `__iter__` 即可。（§7.5）
5. 主进程跑训练循环、worker 进程读盘增强并预取 batch；多进程因为 GIL 让多线程的 Python 代码并行不了，numpy 之外的数据处理正是纯 Python。（§7.5）
