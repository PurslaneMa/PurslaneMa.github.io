# $\rm Chapter \, 7$ 数据级并行：SIMD 与向量化

前两章都在对付「多个执行者抢一份资源」：流水线抢部件，多核抢缓存行。本章换个思路扩产：让一条指令一次处理一排数据，部件只加宽不多造，控制逻辑一分摊薄。这就是**数据级并行（data-level parallelism）**，硬件形态叫 SIMD（single instruction, multiple data）。本章先算清字宽账，再真跑两个实验：同一段乘加循环在三种编译开关下从 0.744 ns/元素走到 0.047 ns/元素，以及同一个循环在小数据集上被 gcc 的一个反直觉决定拖回标量速度；最后解释为什么一个 if 就能让向量化泡汤。

> **开始前自检**：本章假设你已经会：
>
> 1. □ CPI/IPC 与超标量的说法（本书 §1.2、§4.1）；
> 2. □ 缓存行与 L3 共享的量级（本书 §5.1、§5.3）；
> 3. □ 会写 C 的 for 循环并理解「逐元素运算」（竞赛通用）；
> 4. □ 会用命令行编译与计时（操作系统册 §2.3 练过 fork+exec 的用法）。

## $\rm \S \, 7.1$ 字宽账：一条指令装几个数

标量指令一次喂一个数；SIMD 寄存器是一次装一排数的大托盘。x86 的三代托盘：SSE 的 128 位 `xmm`、AVX/AVX2 的 256 位 `ymm`、AVX-512 的 512 位 `zmm`。宽度账一笔就清：一个 float 4 字节即 32 位，所以

$$
128 \text{ 位} = 4 \text{ 个 float}, \qquad 256 \text{ 位} = 8 \text{ 个 float}, \qquad 512 \text{ 位} = 16 \text{ 个 float}
$$

一条 `vmulps` 把托盘里 8 对 float 同时相乘：取指、译码、发射的流水线成本只付一次，算力按宽度翻倍。这就是「控制成本摊薄」的账：§4.1 的超标量靠复制整条执行单元换并行，SIMD 只把 ALU 从 32 位宽改成 256 位宽，同样一条指令的取译开销不变。代价是编程模型：数据要按托盘宽度对齐摆放，分支要另外处理（§7.3）。三代托盘对照：

| 代 | 寄存器 | 位宽 | float 数 | 典型年代 |
| --- | --- | --- | --- | --- |
| SSE | `xmm` | 128 | 4 | 1999 起 |
| AVX/AVX2 | `ymm` | 256 | 8 | 2011 起 |
| AVX-512 | `zmm` | 512 | 16 | 2013 起（服务器端普及） |

RISC-V 的**向量扩展（RVV，Vector Extension）**再进一步：向量长度是运行时参数而非固定 128/256 位，同一份代码在不同硬件上自动用满各自宽度，一句话记住它即可，本书实验都走 x86。竞赛生其实早用过手工版 SIMD：`bitset` 与压位技巧把 64 个布尔装进一个 `uint64_t`，一次位运算处理 64 个「数据」，与 `vmulps` 的账是同一笔，只是工具从编译器换成了你自己的手。深度学习分册第 5 章的卷积，本质上就是这类乘加在海量数据上的堆叠，那一章的战场从本章起步。

**本节小结**：SIMD 的全部经济学在「取译开销只付一次、算力按托盘宽度翻倍」这一笔摊薄账；128/256/512 位各装 4/8/16 个 float，RVV 把宽度改成运行时参数，`bitset` 是你手写过的迷你版。下一节用真机实验验证这笔账兑现几成。

## $\rm \S \, 7.2$ 实验：自动向量化，三个编译开关的差距

实验代码是一段最普通的逐元素乘加，$n = 2^{20}$（约一百万）个 float，外层重复 100 遍；每遍给加数 $s$ 加一点增量，防止编译器发现「每遍结果相同」而把 99 遍删掉（这个坑我们真踩过：不加增量时 `-O3` 实测 0.01 ns/元素，比访存理论下限还快百倍，那是编译器在替你跑）：

```c
for (int r = 0; r < REP; r++) {
    s += 0.125f;
    for (int i = 0; i < N; i++) c[i] = a[i]*b[i] + s;
}
```

三个编译开关（WSL2、gcc 13.3.0、Intel Core Ultra 7 255H，`taskset` 绑核，各取 3 次最快）：

| 编译开关 | 生成的宽度 | 每元素耗时 | 相对加速 |
| --- | --- | --- | --- |
| `-O2 -fno-tree-vectorize` | 标量 | 0.744 ns | 1.0 倍 |
| `-O2` | 128 位（SSE） | 0.588 ns | 1.3 倍 |
| `-O3 -march=native` | 256 位（AVX2） | 0.324 ns | 2.3 倍 |

向量化确实发生了，两条证据。其一，编译器自报（`gcc -fopt-info-vec-optimized`）：

```text
simd2.c:16:18: optimized: loop vectorized using 16 byte vectors   /* -O2 */
```

其二，反汇编里 `-O3 -march=native` 的热循环是 `vmulps %ymm6,%ymm0,%ymm0`，`ymm` 即 256 位。注意 `-O2` 也向量化了：gcc 12 起在 `-O2` 就开向量化（保守的成本模型），所以「不开 `-O3` 就没有 SIMD」的老经验在这台 gcc 上不成立。实验方法照 §5.3 的口径：绑核、每组取 3 次重复的最快值、数组用静态全局（三个地址互不重叠，编译器免插运行时别名检查），全程确定性无随机。

这张表的增速远不到宽度比（8 倍宽只换来 2.3 倍），瓶颈在数据供给：三个数组合计 12 MiB，塞在 24 MiB 的 L3 里（本书 §5.1 的表），每元素流量 12 字节（读 `a`、读 `b`、写 `c` 各 4 字节），0.324 ns/元素 折算 37 GB/s，恰是单核能从 L3 拉数据的带宽量级。把工作集缩到 L1 装得下（4096 个元素 × 3 数组 = 48 KiB，重复 40000 遍），带宽墙消失，宽度账全额兑现：

| 编译开关（同一小循环） | 每元素耗时 | 相对加速 |
| --- | --- | --- |
| `-O2 -fno-tree-vectorize` | 0.369 ns | 1.0 倍 |
| `-O2`（128 位） | 0.087 ns | 4.2 倍 |
| `-O2 -march=native`（256 位） | 0.047 ns | 7.9 倍 |

4 倍宽换 4.2 倍、8 倍宽换 7.9 倍，与 §7.1 的字宽账对得上。验算拍数：0.047 ns/元素按 3.5 GHz 折 0.16 拍/元素，即每 8 元素的向量迭代约 1.3 拍，靠「两条 256 位装载 + 一条乘加 + 一条存储」在现代核心上每拍处理 6 个以上元素，与执行端口的宽度相符；0.087 ns 的 SSE 版折每 4 元素约 1.2 拍，同理成立。这张表还藏着一个反直觉的实测点：同一个 L1 版循环用 `-O3 -march=native` 编译，反而慢回 0.86 ns/元素，比标量还差。读反汇编发现 gcc 在这组常量下没向量化主循环，还给它排了一个糟糕的标量调度。教训：编译器的启发式不是法律，关键循环要用 `-fopt-info-vec` 和反汇编验货，实测多少写多少。

**本节小结**：同一段乘加循环，从标量 0.744 ns 走到 AVX2 的 0.324 ns，差距先被 L3 带宽墙打折、缩进 L1 后宽度账全额兑现（7.9 倍）；向量化是否真发生，靠 `-fopt-info-vec` 与反汇编两条证据说话，编译器启发式也会看走眼。下一节问：什么样的循环编译器根本不敢碰。

## $\rm \S \, 7.3$ 为什么一个 if 就能挡住向量化

向量化要求八对数据走同一条指令序列。循环里一旦出现 `if (a[i] > 0) c[i] = x; else c[i] = y;`，八个元素各有各的去向，一条指令给不出八个答案。硬件的解法是**掩码（mask）**：每条 SIMD 指令带一个 8 位开关，逐元素决定「本位是否写入」。走这条路的代价两层：真分支与假分支的运算都得做（算完再按掩码挑），若分支两侧各有 20 拍的重活，向量版等于全按 20 拍收费，标量版只按实际命中侧收费；分支越不均匀，掩码越亏。算一笔小账：八个 lane 只有一个命中重侧（20 拍的重活），标量版按分支预测走对时平均约 2 拍收一个元素，掩码版一律 20 拍收八个，差距近十倍；分支均匀时差距消失，gcc 的成本模型算的就是这笔账，它的拒绝理由写在 `-fopt-info-vec-missed` 的输出里，常见一句「cost model: not profitable」。

比分支更硬的钉子是**循环携带依赖（loop-carried dependence）**：本次迭代要用上次结果的循环，八 lanes 无法同时开工，向量化直接免谈：

```c
c[i] = f(c[i-1]);       /* 第 i 个 lane 要等第 i-1 个 lane 的结果 */
c[i] = a[i]*b[i] + s;   /* lane 之间互不相识，向量化友好 */
```

本章主实验属于第二行。写竞赛代码时把前缀和、递推这类带依赖的循环与纯映射的循环分开写，前者老老实实标量（或改分块算法，见 §7.6 第 4 题），后者交给编译器。

**本节小结**：向量化要求八个 lane 走同一条路，if 靠掩码硬着头皮走（分支不均匀时按重侧全额收费，近十倍地亏），循环携带依赖则直接免谈；「纯映射、无依赖」是编译器敢下手的门槛。下一节看剩下的两个后勤坑：对齐与离散访存。

## $\rm \S \, 7.4$ 对齐、gather/scatter 与一堵带宽墙

托盘装货有两个后勤问题：

1. **对齐（alignment）**：理想情况一次装载对准 32 或 64 字节边界；现代 x86 允许不对齐装载，代价是跨缓存行时多付一次行访问，编译器为对齐还要先「剥皮」（处理头部几个元素再进主循环）；
2. **离散访存**：`c[i] = a[idx[i]]` 这类按下标表跳跃取数，托盘没法一次装齐，AVX2 提供 gather 指令逐 lane 收集，AVX-512 有对称的 scatter；它们把 8 次标量装载压成 1 条指令，但每次装载仍是独立的一行，远不如连续装载合算。§5.3 的跨步实验在这里换了个说法重现：SIMD 加速的是运算，数据供给的老账（行、页、TLB）一个字都没减。

所以本章的正确读法是两句。第一句：让编译器向量化是免费的午餐，前提是循环是纯映射、无分支纠缠，这条纪律从竞赛代码到生产代码通用。第二句：SIMD 把算力抬高了 8 倍，数据供给不跟涨时，加速比按带宽的短板打折（§7.2 第一张表的 2.3 倍就是打折价），这个「算力对带宽」的比值关系下一章还会以更系统的面目出现。离散访存的行账也可以直接算：连续装载 8 个 float 占 32 字节，两条共享一行；`gather` 装 8 个散在下标表里的元素，最坏踢 8 条不同的行，按 §5.3 的每行价格付 4 倍以上的运费。深度学习分册第 5 章的卷积核正是这两句的受益者：卷积是纯映射乘加，天然向量化，引擎先把数据铺进片上缓存再喂宽托盘。

## $\rm \S \, 7.7$ 本章自测答案

> 先闭卷作答 §7.5 与 §7.6，再核对。

### $\rm \S \, 7.7.1$ 关键概念回顾答案

1. 4、8、16 个。取指译码发射每条指令只付一次，ALU 加宽后同一条指令同时算 4/8/16 对数，控制开销被摊薄。（§7.1）
2. `-O2` 生成 128 位（SSE），`-O3 -march=native` 生成 256 位（AVX2）。证据一：`-fopt-info-vec-optimized` 报「using 16 byte vectors」；证据二：反汇编热循环是 `ymm` 寄存器的 `vmulps`。（§7.2）
3. 差在数据供给：12 MiB 工作集在 L3，每元素 12 字节流量对应 37 GB/s 的单核带宽墙。L1 版工作集 48 KiB，墙消失，宽度账全额兑现。（§7.2）
4. 两侧运算都得做，再按掩码挑结果。分支高度不均匀、且重侧代价大时，全按重侧收费的掩码版比「按命中侧收费」的标量还亏。（§7.3）
5. 本次迭代要用上次的结果，八个 lane 无法同时开工。特征：`c[i]` 只依赖同下标的 `a[i]`、`b[i]`，lane 之间无数据往来。（§7.3）
6. RVV 的向量长度是运行时参数，同一份代码在不同硬件上自动用满各自宽度；x86 是固定 128/256/512 位三档。（§7.1）
7. 同一笔「一次运算摊多个数据」的控制成本账；`bitset` 是你手写的 64 位托盘、只有与或非，SIMD 是硬件的 256 位托盘、带完整乘加与掩码。（§7.1）

### $\rm \S \, 7.7.2$ 应用与辨析答案

1. 默认不敢。gcc 需要重排加法顺序才能装托盘，改变浮点结果，须显式给 `-ffast-math`（或 `#pragma omp simd`）授权；整型求和无此顾虑，`-O2` 就敢。（§7.3）
2. 跌。流量翻倍到 24 字节/元素，同样 37 GB/s 墙下每元素下限翻倍到约 0.65 ns，AVX2 版约 2 倍宽只换来约 1.5 倍，短板更短。（§7.2）
3. 掩码版两侧都算：加法必做，比较必做，乘法或清零靠掩码挑，每元素约 3 次运算。省掉的是分支指令本身与可能的预测失败，不省运算。（§7.3）
4. 第一步把「块内各自累加」写成纯映射（每 lane 累加自己的起点段），lane 间无依赖；依赖被推迟到块间修正那一步，而修正只有每块一次。（§7.3）
5. 三步：`-fopt-info-vec-missed` 看编译器拒绝的理由；反汇编看热循环有没有 `ymm`/`xmm` 向量指令；缩工作集重测，区分「没向量化」与「被带宽墙打折」。（§7.2）
