## $\rm \S \, 40.1$ 声音是什么——从物理到数字

### $\rm \S \, 40.1.1$ 声波：空气的压力变化

声音的本质是**空气的振动**——一个物体（喇叭振膜、你的声带、吉他弦）来回运动，挤压和拉稀周围的空气，形成压力波。这个压力波到达你的耳膜，耳膜跟着振动，大脑解读为声音。

用数学语言：声音是一个**时间上的连续函数**——压力随时间的起伏。一个纯音（如音叉发出的 $440 \, \text{Hz}$ A 音）是完美的正弦波。真实的声音（语音、音乐、噪音）是无数正弦波的叠加。

### $\rm \S \, 40.1.2$ 采样：把连续变成离散

计算机不能存储“连续的波形”——它只能存储离散的数字。**采样**（sampling）就是把连续波形按固定时间间隔“拍照”：

```text
连续波形： ~  ~  ~  ~  ~  ~  ~  （无限多个点）
采样后：   •  •  •  •  •  •  •  （每秒固定数量的点）
```

两个关键参数：

- **采样率**（sample rate，单位 Hz）：每秒采多少个点。CD 质量 = $44100 \, \text{Hz}$（每秒钟取 44100 个点）。电话语音 = $8000 \, \text{Hz}$（够用但音质明显差）。
- **位深度**（bit depth）：每个采样点用多少比特存储。CD 质量 = 16-bit（每个点是 0-65535 的整数）。录音室 = 24-bit 或 32-bit float。

**奈奎斯特定理**：要无失真地还原一个频率为 f 的信号，采样率必须至少是 2f。人类听觉上限约 20kHz，所以 CD 的 $44100 \, \text{Hz}$ > 2×$20000 \, \text{Hz}$——刚刚好。

### $\rm \S \, 40.1.3$ 音频文件格式

| 格式 | 压缩方式 | 典型码率 | 用途 |
|---|---|---|---|
| **WAV** | 无压缩（PCM） | ~1411 kbps (CD) | 录音、音频编辑的中间格式 |
| **FLAC** | 无损压缩 | ~700 kbps | 音乐发烧友存档——字节完美还原，约一半大小 |
| **MP3** | 有损压缩 | 128-320 kbps | 二十年前的主流——利用听觉掩蔽效应扔掉“听不到的信息” |
| **AAC** | 有损压缩 | 128-256 kbps | MP3 的继任者——同码率下音质更好。YouTube/iTunes 默认 |
| **Opus** | 有损压缩 | 6-510 kbps | 现代标准——从语音通话到 HiFi 音乐全覆盖。Discord/WhatsApp 使用 |

## $\rm \S \, 40.2$ 语音 AI：让计算机听和说

### $\rm \S \, 40.2.1$ ASR：语音转文字

**ASR**（Automatic Speech Recognition，自动语音识别）的任务：输入一段音频波形，输出这段音频对应的文字。

传统 ASR 是一个复杂的多级流水线（声学模型→发音词典→语言模型→解码器）。现代端到端 ASR（如 OpenAI **Whisper**）是一个 Transformer 模型——输入音频频谱，直接输出文字。Whisper 是一个超多语言的 ASR 模型，代码与各尺寸权重以 MIT 许可开放（训练数据未公开）——下载和商用前仍应看一眼模型卡上的许可说明。

```python
# 用 Whisper 转写音频文件
import whisper
model = whisper.load_model("base")   # tiny/base/small/medium/large
result = model.transcribe("meeting.mp3")
print(result["text"])                # "今天我们讨论论文管理器的架构..."

# Whisper 自动检测语言，支持近百种语言
```

### $\rm \S \, 40.2.2$ TTS：文字转语音

**TTS**（Text-to-Speech，文本转语音）是 ASR 的逆过程：输入文字，输出自然的人声朗读。

早期 TTS 像机器人——拼接预录的音节片段导致语调僵硬。现代神经 TTS（如 ElevenLabs、OpenAI TTS、Coqui）生成的朗读声在常见场景下已很难与真人区分——自然的语调、停顿、情感表达；但在罕见词、强情感和口音上仍会露出破绽。关键技术之一是**声码器**（vocoder）：把声学模型输出的频谱图（或声学特征）变成波形——频谱图是“每个时刻有哪些频率、各有多强”，波形才是能播放的采样序列。

### $\rm \S \, 40.2.3$ 说话人识别

**说话人识别**（speaker recognition）回答“这段语音是谁说的”——和 ASR 不同，它不关心说的是什么内容，只关心说话人的身份。它的基础技术是**声纹**（voiceprint）——每个人的声道形状、发音习惯在频谱上产生独特的特征。用一个小型神经网络从音频中提取声纹向量，比较两个声纹向量的相似度。

### $\rm \S \, 40.2.4$ 音乐信息检索

**音乐信息检索**（Music Information Retrieval, MIR）是 AI 和音乐交叉的领域：

- **音乐指纹识别**（Shazam 背后的技术）：手机录 3 秒音频片段→匹配数百万首歌曲的指纹数据库→返回歌名。原理是把频谱图中的峰值点对作为指纹，极其抗噪声。
- **音乐推荐**（Spotify Discover Weekly）：不是简单的“这首歌标签是 Rock 就推荐 Rock”。实际流程：分析每首歌的音频特征（速度、调性、能量、可跳舞性）→协同过滤（和你口味相似的人也喜欢什么）→NLP 分析用户创建的播放列表的语义。
- **自动作曲**（MuseNet、MusicGen）：用类似语言模型的架构（自回归生成）来生成音乐 token 序列。

## $\rm \S \, 40.3$ 音频工作站与工具

### $\rm \S \, 40.3.1$ DAW：数字音频工作站

**DAW**（Digital Audio Workstation，数字音频工作站）是音乐制作的“IDE”——多轨录音、MIDI 编辑、效果器、混音、母带处理。专业人士用 **Ableton Live**、**Logic Pro**、**FL Studio**、**Pro Tools**。开源替代 **Audacity**（audacityteam.org）适合简单的录音、剪辑、格式转换——它不是 DAW 但够处理日常音频编辑。

### $\rm \S \, 40.3.2$ 命令行音频工具

```bash
# FFmpeg：音频/视频万能转换工具
ffmpeg -i input.wav -codec:a libmp3lame -b:a 192k output.mp3   # WAV→MP3
ffmpeg -i input.mp3 -ac 1 -ar 16000 output.wav                  # 转单声道、16kHz
ffmpeg -i video.mp4 -vn -acodec copy audio.m4a                  # 从视频提取音频

# SoX（Sound eXchange）：音频处理的"瑞士军刀"
sox input.wav output.wav trim 0 30            # 截取前 30 秒
sox input.wav -n spectrogram                  # 生成频谱图
```

第三条 `ffmpeg -vn -acodec copy` 直接复制音频流、不重编码，只在源音频是 AAC 时适合装进 `.m4a`；源音频是 MP3/Opus 时要么改容器（如 `.mkv`），要么去掉 `copy` 让它重编码。不确定就先原样跑一遍，看它报不报错。

## $\rm \S \, 40.4$ 动手实践

### $\rm \S \, 40.4.1$ 实践一：用 Whisper 转写一段语音

起始目录与前置条件：已安装 Python 3.8+，以及 ffmpeg 并加入 PATH（Whisper 靠它解码音频）；`pip install openai-whisper`。首次运行会下载 `base` 模型权重（约 140 MB）；有 NVIDIA GPU 会自动用 CUDA，没有也能在 CPU 上跑，只是更慢。用手机录一段 30 秒中文语音，保存为当前目录的 `test.mp3`。

```bash
pip install openai-whisper
```

用手机录一段 30 秒的中文语音，保存为 `test.mp3`，用 Whisper 转写：

```python
import whisper
model = whisper.load_model("base")
result = model.transcribe("test.mp3", language="zh")
print(result["text"])
```

预期输出与判据：打印出的中文与录音内容基本一致（少量错别字、漏字正常）——能读出大意就是成功。若报 `ffmpeg not found`，先把 ffmpeg 装好并重开终端。

结束与清理：模型缓存在用户目录的 `.cache/whisper`（约 140 MB），不再用可删除；测试录音含个人信息，不要提交进 Git 仓库。

### $\rm \S \, 40.4.2$ 实践二：查看音频文件的内部结构

起始目录与前置条件：上一步生成的 `test.mp3`（或任意音频文件）在当前目录；ffprobe 已安装。

```bash
ffprobe test.mp3
# 查看：采样率（sample_rate）、声道数（channels）、码率（bit_rate）、编码格式（codec_name）
```

预期输出与判据：`Stream` 行里能同时读到 `codec_name=mp3`、`sample_rate=44100`（手机录音常是 48000）、`channels`、`bit_rate`——与 §40.1.3 的表对照一下（WAV 的 CD 码率约 1411 kbps，MP3 常见 128–320 kbps）。

结束与清理：只读，无需清理。

### $\rm \S \, 40.4.3$ 实践三：Shazam 的原理——创建音频频谱图

起始目录与前置条件：当前目录有 `test.mp3`，已安装 SoX；发行版自带的 SoX 不一定带 MP3 解码，遇到 `no handler for file extension mp3` 就先用 ffmpeg 转成 WAV（`ffmpeg -i test.mp3 test.wav`）再继续。

```bash
sox test.mp3 -n spectrogram        # 默认在当前目录生成 spectrogram.png
# 打开 spectrogram.png——横轴是时间，纵轴是频率，亮度是能量
# 这就是 Shazam 建立指纹的基础——频谱峰值点
```

预期输出与判据：生成 `spectrogram.png`，能看到随时间变化的水平/斜向能量条（人声和乐器各有形状）——这些亮点就是可被哈希成指纹的峰值。若图片是一片均匀颜色，多半是音频太短或音量太低。

结束与清理：看完删除 `spectrogram.png`；中途转换出的 `test.wav` 是无损格式、比 MP3 大一个量级，不需要时一并删除。

## $\rm \S \, 40.5$ 总结

- 声音的本质是空气振动→数字化的关键是采样率（每秒多少个点，$44100 \, \text{Hz}$ CD 标准）和位深度（每点多少 bit）。
- 音频格式：WAV（无压缩）、FLAC（无损压缩）、MP3/AAC/Opus（有损压缩，利用听觉掩蔽）。
- ASR（语音→文字）：Whisper 开源可用。TTS（文字→语音）：现代神经 TTS 在常见朗读场景下生成的声音已接近真人。
- 音乐信息检索：Shazam（频谱指纹）、Spotify 推荐（音频特征+协同过滤）、AI 作曲（自回归生成）。

## $\rm \S \, 40.8$ 本章自测答案

> 先闭卷作答本章“关键概念回顾”与“应用与辨析”，再核对以下答案。

### $\rm \S \, 40.8.1$ 自测答案 · 关键概念回顾
1. 声音是空气的压力波；计算机按固定时间间隔对连续波形采样（采样率，如 CD 的 $44100 \, \text{Hz}$），并用固定比特数存储每个采样点（位深度，如 CD 的 16-bit）。
2. 要无失真地还原频率为 f 的信号，采样率必须至少是 2f；人类听觉上限约 20kHz，44100 > 2×20000，恰好覆盖人耳。
3. WAV 无压缩；FLAC 无损压缩（字节完美还原、约一半大小）；MP3/AAC 有损压缩（利用听觉掩蔽效应扔掉“听不到的信息”）；Opus 是现代通用标准，从低码率语音到高码率音乐全覆盖。
4. ASR（自动语音识别，如 Whisper）输入音频波形、输出对应文字；TTS（文本转语音）输入文字、输出自然的朗读语音——现代神经 TTS 的声音已接近真人。

### $\rm \S \, 40.8.2$ 自测答案 · 应用与辨析
5. ASR 关心“说了什么内容”（换成谁的声音都能转写）；说话人识别关心“是谁说的”（内容不重要），它提取每个人的声纹向量，比较两个声纹向量的相似度。
6. Opus 的码率范围极宽（6-510 kbps）且延迟低：低码率下语音依然清晰，高码率下音乐质量接近无损——一个编解码器覆盖两种需求，所以即时通讯和流媒体都采用它。
