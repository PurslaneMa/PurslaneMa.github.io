## $\rm \S \, 8.1$ Shell 脚本：让命令序列可复用

第 7 章里所有的命令都是你一条条手动输入的。当你需要反复执行同一组命令时（每次改完代码→编译→运行→测试），手动输入是浪费时间且容易出错。Shell 脚本把一组命令写进文件，像程序一样执行。

先把本章要反复使用的样例文件放在同一个练习目录里（例如 Bash 下的 `~/cmdbox`、Windows 下的 `C:\Users\<你的用户名>\cmdbox`），后面各节出现这些文件名时都指这里：

`main.cpp` 就是第 1 章 §1.9.2 那个加法程序，本章的脚本会反复编译它。`papers.txt` 在第 6 章只有「标题 (年份)」，这里为了演示按列处理扩成 5 列，每行是 `标题|年份|会议|引用数|DOI`：

```text
Attention Is All You Need|2017|NeurIPS|120000|DOI: 10.48550/arXiv.1706.03762
GPT-3:  Language Models are Few-Shot Learners|2020|arXiv|100000|DOI: 10.48550/arXiv.2005.14165
Deep Residual Learning for Image Recognition|2016|CVPR|210000|DOI: 10.1109/CVPR.2016.90
```

（第二行标题里有一个多余的双空格，后面演示“压缩连续空白”时正好用上。）

`app.log` 每行是 `日期 时间 级别 状态码 说明`，四行里有两条 500 和两条 200，且相同状态码不相邻——后面演示“先排序再去重统计”时正好用上：

```text
2024-03-01 10:00:01 INFO 200 service started
2024-03-01 10:00:05 ERROR 500 upstream timeout
2024-03-01 10:00:07 INFO 200 paper fetched
2024-03-01 10:00:09 ERROR 500 upstream timeout (retry)
```

`papers.json` 是同一批论文的 JSON 版；`config.conf` 有一个空行和一个注释行，用来验证删除规则：

```json
{
  "papers": [
    {"title": "Attention Is All You Need", "year": 2017, "venue": "NeurIPS"},
    {"title": "GPT-3", "year": 2020, "venue": "arXiv"},
    {"title": "Deep Residual Learning", "year": 2016, "venue": "CVPR"}
  ]
}
```

```text
# 论文管理器配置
data=papers.txt

year_min=2017
```

各节语法速查里的 `file.txt`、`data.csv`、`data.txt` 是“换成你手头任意文本文件”的占位写法——在样例目录里换成 `papers.txt` 就能照着跑。

### $\rm \S \, 8.1.1$ 第一个脚本

```bash
#!/bin/bash
# build.sh —— 编译并运行第 1 章的加法程序
set -e          # 任何命令返回非零退出码时立即停止

echo "=== 编译 ==="
g++ -std=c++17 -Wall -Wextra -O2 main.cpp -o sum

echo "=== 运行测试 ==="
echo "2 3" | ./sum

echo "=== 完成 ==="
```

`#!`（shebang）告诉系统用哪个程序执行此脚本。`set -e` 是最重要的安全设置——没有它，编译失败后脚本会继续执行（用上一次留下的旧可执行文件运行测试）。在 Bash 中运行（当前目录就是练习目录，`build.sh` 与 `main.cpp` 同级）：

```bash
chmod +x build.sh    # 添加执行权限（Linux/macOS/WSL/Git Bash）
./build.sh           # 运行
```

成功判据：依次看到 `=== 编译 ===`、`=== 运行测试 ===`、`5`、`=== 完成 ===` 四段输出，退出码为 0。

### $\rm \S \, 8.1.2$ 变量、参数与条件

```bash
#!/bin/bash
# build2.sh —— 带参数与存在性检查的构建脚本
set -euo pipefail    # -u: 使用未定义变量时报错; -o pipefail: 管道中任一命令失败则整体失败

SRC="${1:-main.cpp}"     # 第一个参数，默认值 main.cpp
OUT="${2:-sum}"          # 第二个参数，默认值 sum

if [ ! -f "$SRC" ]; then
    echo "错误: $SRC 不存在" >&2   # >&2 = 输出到 stderr
    exit 1
fi

echo "编译 $SRC → $OUT"
g++ -std=c++17 -Wall -Wextra "$SRC" -o "$OUT"
echo "2 3" | ./"$OUT"
```

`"${1:-default}"` 是参数扩展——有参数用参数，没有用默认值。`>&2` 把错误信息输出到 stderr，和程序的退出码一起构成完整的命令行契约。把它存成 `build2.sh` 后试着用三种方式调用：`./build2.sh`（全用默认值）、`./build2.sh main.cpp myapp`（改产物名）、`./build2.sh no-such.cpp`（文件不存在，走错误分支）。

### $\rm \S \, 8.1.3$ 循环与批量处理

```bash
#!/bin/bash
# backup-all.sh —— 给练习目录里每个 .txt 文件留一份 .bak 备份
for file in *.txt; do
    cp "$file" "$file.bak"
    echo "已备份: $file → $file.bak"
done
```

`*.txt` 是第 3 章的通配符展开，Shell 先把匹配到的文件名列出来，再逐个交给循环体。成功判据：对样例目录运行后能看到 `papers.txt → papers.txt.bak`，且 `ls` 里出现了 `.bak` 文件。

### $\rm \S \, 8.1.4$ 函数：脚本内的复用

```bash
#!/bin/bash

check_data() {
    local file=$1       # local = 局部变量，不会泄漏到函数外
    if [ ! -s "$file" ]; then        # -s: 文件存在且内容非空
        echo "$file 不存在或为空" >&2
        return 1
    fi
    return 0
}

if check_data papers.txt; then
    echo "样例数据就绪"
else
    echo "请先按 §8.1 开头造出 papers.txt"
    exit 1
fi
```

函数用 `return 0/1` 报告成功或失败，调用处像用普通命令一样判断——脚本的其余部分不用关心里面怎么检查的。

### $\rm \S \, 8.1.5$ 跨平台注意事项

Bash 脚本在 WSL、Linux 和 macOS 上都能运行（假设解释器路径都是 `/bin/bash`）；在 Windows 上装了 Git 之后，Git Bash 也自带同一套 Bash 与 GNU 工具，可以直接跑本章的脚本。PowerShell 脚本（`.ps1`）可以在 Windows 原生环境和 Linux PowerShell Core 上运行。选择哪个？

| 场景 | 选择 |
|------|------|
| 目标环境只有 Linux 服务器 | Bash |
| 需要调用 Windows 系统 API（注册表、COM 等） | PowerShell |
| 团队中有人用 Windows、有人用 Linux | Bash（通过 WSL/Git Bash）或 Python 脚本 |
| CI/CD pipeline | 看 CI runner 的操作系统——GitHub Actions 的 `ubuntu-latest` 用 Bash，`windows-latest` 可用 PowerShell |

> **经验规则**：如果脚本需要在服务器上运行——写 Bash。如果只需要在你自己电脑上跑——写你熟悉的那个。不确定时，Python 作为一个跨平台脚本语言往往比 Shell 更不容易出环境差异问题。

## $\rm \S \, 8.2$ sed 与 awk：文本处理的瑞士军刀

第 7 章里 `grep` 帮你找到行。但找到之后呢？“把 100 个文件里的 `old_func` 改成 `new_func`”“取 CSV 第 3 列求平均值”“提取所有 JSON 中某个字段的值”——这些你需要 sed 和 awk。

### $\rm \S \, 8.2.1$ sed：流编辑器

sed 按行读取文本，对每一行执行你指定的操作，输出修改后的结果。**sed 默认不修改原文件**——它只是把修改后的内容输出到标准输出。

先用两条最小命令看清 `s///` 的匹配范围（Bash / Git Bash，任意目录）：

```bash
echo "book" | sed 's/o/0/'      # 预期输出：b0ok（每行只换第一次）
echo "book" | sed 's/o/0/g'     # 预期输出：b00k（g = global，每行全部换）
```

其余常用写法（`file.txt` 是占位符，在样例目录里换成 `papers.txt` 就是同一条命令）：

| 写法 | 作用 | 注意 |
|---|---|---|
| `sed 's/old/new/2' file.txt` | 每行第 2 次匹配做替换 | GNU sed 扩展；macOS 自带的 BSD sed 不支持，那里只能改用 `/g` 或 awk |
| `sed -i 's/old/new/g' file.txt` | 直接改写原文件 | 危险：先不带 `-i` 看输出，必要时 `cp file.txt file.txt.bak` 备份；Linux/Git Bash 写 `-i`，macOS 要写成 `-i ''` |
| `sed -n '5,10p' file.txt` | 打印第 5 到 10 行 | `-n` 抑制默认的整行输出，只有带 `p` 的行会出来 |
| `sed '5d' file.txt` | 删除第 5 行 | 只从输出里去掉，原文件不动 |
| `sed '1,3d' file.txt` | 删除前 3 行 | 同上 |
| `sed -n '/ERROR/p' app.log` | 打印所有含 ERROR 的行 | 等效 `grep ERROR app.log` |

**实战**：论文管理器把 JSON 里的 `venue` 字段从 `NeurIPS` 统一改为 `NeurIPS (Conference)`：

```bash
sed 's/"NeurIPS"/"NeurIPS (Conference)"/g' papers.json
# 预期输出：JSON 照原样输出，只有含 "NeurIPS" 的那一行被改写；先确认无误，再考虑加 -i 原地修改
```

**实战**：删除所有空行和注释行（样例 `config.conf` 里恰好各有一处）：

```bash
sed '/^$/d; /^#/d' config.conf
# ^$ = 空行, ^# = 以 # 开头的行
# 预期输出：只剩 data=papers.txt 和 year_min=2017 两行
```

### $\rm \S \, 8.2.2$ awk：按列处理

awk 自动把每行拆成字段——`$1` 是第一列，`$2` 是第二列，`$0` 是整行；默认按连续空白切分，`-F'|'` 表示按竖线切分。在样例 `papers.txt` 上先跑两条最小命令（Bash / Git Bash，练习目录）：

```bash
# 每行按 | 切成 5 列，打印标题和年份
awk -F'|' '{print $1, $2}' papers.txt
# 预期输出 3 行，形如：Attention Is All You Need 2017

# 过滤：第 2 列（年份）>= 2020 的行，只打印标题
awk -F'|' '$2 >= 2020 {print $1}' papers.txt
# 预期输出 1 行：GPT-3:  Language Models are Few-Shot Learners
```

其余常用写法（`file.txt`、`data.csv`、`data.txt` 都是占位符）：

| 写法 | 作用 |
|---|---|
| `awk '{print $1}' file.txt` | 按空白切分，打印第一列 |
| `awk '{print $1, $3}' file.txt` | 打印第 1 和第 3 列 |
| `awk -F',' '{print $2}' data.csv` | 逗号分隔的 CSV，取第 2 列 |
| `awk -F'|' '{print $1, $4}' papers.txt` | 竖线分隔：标题与引用数 |
| `awk '{sum += $2} END {print sum}' data.txt` | 第 2 列求和 |
| `awk -F'|' '{sum += $4; n++} END {print sum/n}' papers.txt` | 引用数列求平均值 |

**实战**：`papers.txt` 的列是 `标题|年份|会议|引用数|DOI`，统计每个会议的平均引用数：

```bash
awk -F'|' '{c[$3] += $4; n[$3]++} END {for (v in c) print v, c[v]/n[v]}' papers.txt
# 预期输出 3 行（顺序随 awk 实现而变）：NeurIPS 120000 / arXiv 100000 / CVPR 210000
```

### $\rm \S \, 8.2.3$ sed + awk 组合：Unix 哲学的体现

```bash
# 找出所有包含 ERROR 的日志行，提取第 4 列（状态码），统计每种状态码的出现次数
grep "ERROR" app.log | awk '{print $4}' | sort | uniq -c | sort -rn
# 预期输出：      2 500

# 把年份 >= 2020 的记录中的 "arXiv" 改为 "arXiv (Preprint)"
awk -F'|' '$2 >= 2020' papers.txt | sed 's/arXiv/arXiv (Preprint)/'
# 预期输出中只有 venue 那列的 arXiv 被改写，DOI 里的 arXiv 不受影响——sed 默认每行只替换第一次匹配
```

`uniq -c` 有一个容易被忽略的前提：它只统计**相邻**的重复行，所以前面必须先 `sort` 把相同内容排到一起。把中间两步拿掉试一次就能看到差别：

```bash
awk '{print $4}' app.log | uniq -c        # 相邻的重复才会合并，同一状态码可能分成多行
awk '{print $4}' app.log | sort | uniq -c # 先排序：得到 2 个 200、2 个 500
```

末尾的 `sort -rn` 是第三步：`-n` 按数值而不是字典序排，`-r` 反向（从大到小），让出现最多的状态码排在最前。

> **经验规则**：grep 找到行，sed 修改行，awk 计算列——三个工具各司其职。遇到文本处理任务时，先想“我需要哪几个”，而不是直接打开 Python。

### $\rm \S \, 8.2.4$ jq：JSON 的 sed/awk

现代开发中 JSON 远比 CSV 常见。`jq` 之于 JSON 正如 awk 之于 CSV，在样例 `papers.json` 上直接跑（jq 的安装交给系统包管理器，下一章 §9.3 统一讲）：

```bash
jq '.papers[0].title' papers.json                                     # 取第一篇标题
jq '.papers[] | select(.year >= 2020)' papers.json                    # 筛选年份
jq '.papers | group_by(.venue) | map({venue: .[0].venue, count: length})' papers.json
jq -r '.papers[].title' papers.json                                   # -r 输出纯文本（去掉 JSON 引号）
# 最后一条的预期输出 3 行：Attention Is All You Need / GPT-3 / Deep Residual Learning
```

同样的写法可以直接接在 `curl` 后面：`curl -s <API 地址> | jq '.'`——管道把响应正文（JSON 文本）交给 jq，这就是第 7 章 §7.3.1 的做法。

## $\rm \S \, 8.3$ 正则表达式：命令行里的筛选与提取

第 3 章区分过通配符与正则：通配符只能匹配文件名（`*.txt`），正则匹配的是**文件内容里的模式**。第 6 章的[正则表达式：字符串的搜索语言](06-文本编码压缩包与数据格式.md)一节你已经学会了基本语法（`\d`、`[0-9]`、`^`、`$` 等）——但那时的例子只做“找出符合模式的行”。真实任务往往更进一步：**从匹配里提取信息**、**防止模式匹配过头**。本节把正则放回命令行工具箱，补上三块：`-E`、捕获组、贪婪陷阱。

### $\rm \S \, 8.3.1$ `-E`：让 `+`、`?`、`()` 生效

grep 和 sed 默认只用“基本”正则语法——`.`、`*`、`^`、`$`、`[abc]` 直接可用，但 `+`、`?`、`()` 这些元字符会被当作普通字符。加 `-E` 开启扩展语法后，全部元字符直接生效。第 6 章的例子 `grep -E '20(1[7-9])\b'` 已经用过它，现在说明原因：没有 `-E` 时 `(1[7-9])` 按字面处理，模式变成“先找字面的 `20(1`，再跟一个 7-9 的数字，再加 `)`”——样例数据里没有这种串，所以匹配结果为空；加了 `-E` 才是在找 2017~2019 这几个年份。

回到贯穿项目，`papers.txt` 每行一条论文记录（Bash / Git Bash，练习目录）：

```bash
# 筛选 2020-2024 年的论文：202 后跟 0-4 中任意一个数字
grep -E "202[0-4]" papers.txt
# 预期输出 1 行：GPT-3:  Language Models are Few-Shot Learners|2020|...

# 以大写字母开头、以数字结尾的行（^ 行首，$ 行尾）
grep -E "^[A-Z].*[0-9]$" papers.txt
# 预期输出：样例 3 行都满足，整份 papers.txt 原样输出

# 把连续多个空白压缩成一个空格（sed -E 替换）
sed -E 's/\s+/ /g' papers.txt
# \s = 空白，+ = 一次或多次；预期输出：第二行标题里的双空格变成一个空格，其余行不变
```

`\s` 是 GNU sed 的简写（Linux、WSL、Git Bash 可用）；macOS 自带的 BSD sed 不认它，要写成各平台通用的字符类 `[[:space:]]`：`sed -E 's/[[:space:]]+/ /g' papers.txt`。

### $\rm \S \, 8.3.2$ 捕获组：分组、反向引用与提取

括号 `( )` 圈住的部分叫**捕获组**（capturing group）：它参与匹配，同时给这一段单独编号，供后续引用——sed 用 `\1` 引用第一个组，`\2` 引用第二个，依此类推。

一个常见误解是“`grep -o` 配合括号就能只输出括号里的内容”。实际上 `grep -o` 只输出**整个匹配**，括号对输出没有任何影响（括号在 grep 里负责分组，供正则内部使用，例如 `(ab)+` 表示 `ab` 重复多次）。下面这条命令的每一行输出都仍带 `DOI: ` 前缀：

```bash
# 提取 DOI：10. 后跟数字和斜杠、再跟任意非空格字符
grep -oE "DOI: (10\.[0-9]+/[^ ]+)" papers.txt
# 预期输出 3 行，每行形如：DOI: 10.48550/arXiv.1706.03762
```

注意 DOI 里的句点必须转义成 `\.`——否则 `10.` 会匹配 `10x`。想去掉前缀，接一条 sed 把行首的 `DOI: ` 删掉即可（两步都可运行，Bash / Git Bash）：

```bash
grep -oE "DOI: (10\.[0-9]+/[^ ]+)" papers.txt | sed 's/^DOI: //'
# 预期输出 3 行，形如：10.48550/arXiv.1706.03762
# 's/^A/B/' 表示“把每行开头的 A 换成 B”，这里 B 为空，等于删掉行首的 `DOI: `
```

sed 的另一种做法是用括号圈住要留下的部分，再用 `\1` 把它放回去：

```bash
sed -E 's/.*(10\.[0-9]+\/[^ ]+).*/\1/' papers.txt
# 预期输出与上一条相同的 3 行 DOI 编号
```

这条命令有三点值得注意：它是**替换**而不是过滤，所以不含 DOI 的行会原样输出；两侧的 `.*` 都是贪婪的，一行里若出现两个 `10.x/...` 片段，只有最后一个会被留下；模式里的 `/` 需要写成 `\/`，否则会和 `s///` 的分隔符混淆。若数据里混有大量不含 DOI 的行，先用 grep 过滤更清楚：

```bash
grep "DOI:" papers.txt | sed -E 's/.*(10\.[0-9]+\/[^ ]+).*/\1/'
```

### $\rm \S \, 8.3.3$ 陷阱：`.*` 是贪婪的

`<.*>` 直觉上像“一对尖括号”，实际匹配的是从**第一个 `<` 到最后一个 `>`** 的整段——`.*` 默认尽可能多地吃字符，这叫**贪婪匹配**（greedy）。一行里有 `<a>x</a> <b>y</b>` 两对标签时，`<.*>` 一次吞掉整行。要“匹配到就停”，在量词后加 `?` 变成 `.*?`（非贪婪）：

```bash
# 贪婪：一次吞掉整行（Bash / Git Bash）
echo '<a>x</a> <b>y</b>' | rg -o "<.*>"
# 预期输出 1 行：<a>x</a> <b>y</b>

# 非贪婪：匹配到第一个 > 就停
echo '<a>x</a> <b>y</b>' | rg -o "<.*?>"
# 预期输出 4 行：<a>、</a>、<b>、</b> 各占一行
```

注意：GNU grep 的 `-E` 语法不支持非贪婪（`?` 会被忽略），所以这里用 ripgrep（`rg`），也可以换成 Python 或 VS Code 搜索框的“使用正则”模式，效果相同。

> **经验规则**：正则的表达力很强，但“匹配过头”是最高频的错误——写完模式先在最小输入上验证。regex101.com 提供交互式测试：左边写正则，右边实时高亮匹配并逐字符解释；不想联网时，VS Code 搜索框打开“使用正则”模式后逐次输入模式，也能立刻看到匹配范围。

## $\rm \S \, 8.4$ 现代 Shell 工具：更快、更美、更聪明的替代

`find`、`cat`、`cd`、`Ctrl+R` 这些经典工具可靠地工作了几十年。现代出现了一批替代品，核心用途不变，但更快、更好看、默认行为更聪明——参数和默认行为并不完全兼容，所以叫“替代”而不是“升级”：

- **fd**：`find` 的替代。更快、默认遵守 `.gitignore`（不会一头扎进 `node_modules`）、输出带颜色。用法与 `find` 不同：`fd connectTimeout` 直接在当前目录递归搜索（不用写 `.` 和 `-name`），`fd -e cpp` 按扩展名过滤，`fd --type f` 只找文件。
- **bat**：`cat` 的替代。带语法高亮、行号，还能在代码左侧显示 Git 的增删标记。`bat main.cpp` 代替 `cat main.cpp`，`bat --list-themes` 看可选主题。
- **fzf**：交互式模糊查找器——输入文件名的一部分，候选项实时收窄。单独运行 `fzf` 浏览当前目录的文件；它还能接管 `Ctrl+R`（比 §25.2 的原版历史搜索更好用）；`code $(fzf)` 在 VS Code 中打开选中的文件；`git diff --name-only | fzf | xargs git add` 从改动文件里挑出要暂存的部分（Git 第 19 章才正式学，这里先感受组合的威力）。
- **zoxide**：更聪明的 `cd`——记住你最常去的目录。`z proj` 跳到最匹配的常用目录，哪怕你只输入了 “proj” 这几个字符；`zi` 交互式选择目标。它的初始化是**新增** `z` 和 `zi` 两个命令，并不改变 `cd` 的行为；想让 `z` 接管 `cd` 要显式写 `--cmd cd`（初始化写进 Shell 配置文件的持久化方式见第 25 章 §25.4）。

> **经验规则**：你不需要把这些全部替换——从 `fd` 和 `fzf` 开始，用熟了再加下一个。它们与原版工具并存，随时可以退回。
>
> 安装通过各平台的系统包管理器完成（系统包管理器是什么、为什么各平台命令不同，下一章 §9.3 统一讲）。注意 `winget install` 一次只接受一个包标识，装多个要写成多条命令：

| 平台（包管理器） | 安装命令 |
|---|---|
| Windows（winget） | `winget install sharkdp.fd`、`winget install junegunn.fzf`、`winget install sharkdp.bat`、`winget install ajeetdsouza.zoxide`；本章正则示例用的 ripgrep 是 `winget install BurntSushi.ripgrep.MSVC` |
| macOS（Homebrew） | `brew install fd fzf bat zoxide ripgrep` |
| Debian/Ubuntu（apt） | `sudo apt install fd-find fzf bat zoxide ripgrep`；注意命令名是 `fdfind` 和 `batcat`（不是 `fd`、`bat`） |
| 仓库里没有该包时 | 较旧的 Debian/Ubuntu 发行版可能没有 `zoxide`：若已装 Rust 工具链可用 `cargo install zoxide`；Windows 上也可用 Scoop（下一章 §9.3.5）装这些工具 |

## $\rm \S \, 8.5$ 动手实践

### $\rm \S \, 8.5.1$ 实践一：写一个带检查的构建脚本

把 §8.1 的 `build.sh` 扩展成可复用的版本（在练习目录中，Bash / Git Bash）：

1. 脚本开头用 `set -euo pipefail`。
2. 源文件路径用参数提供，带默认值（`${1:-main.cpp}`），产物名也改成参数。
3. 文件不存在时输出错误到 stderr 并 `exit 1`。
4. 故意在 `main.cpp` 里引入一个编译错误（删掉一个分号）再运行脚本——观察它停在哪一步；紧接着运行 `echo $?` 查看退出码，应为非零。修复后重跑，确认编译、运行、完成三段输出依次出现，`echo $?` 为 0。

### $\rm \S \, 8.5.2$ 实践二：sed 与 awk 清洗论文数据

在 §8.1 开头的练习目录里（`papers.txt`、`app.log` 已就绪）：

1. 用 `awk -F'|' '{print $1, $2}' papers.txt` 打印标题与年份。预期输出 3 行「标题 年份」；若某行错位，先检查 `-F` 后面跟的是不是竖线。
2. 用 `awk -F'|' '{s += $4} END {print s}' papers.txt` 求引用数总和，预期输出 `430000`。
3. 用 `sed 's/2016/2015/' papers.txt` 试试改年份：**先不加 `-i` 运行**，确认只有一行发生变化，而且同一行 DOI 里的 `2016` 没被改动（sed 默认每行只换第一次匹配）；确认无误后 `cp papers.txt papers.txt.bak` 备份，再加 `-i` 原地修改。
4. 用 `grep ERROR app.log | awk '{print $4}' | sort | uniq -c | sort -rn` 统计日志中状态码的出现次数，预期输出 `2 500`。去掉中间的 `sort` 再跑一次，观察相同状态码还能不能合并计数。

### $\rm \S \, 8.5.3$ 实践三：正则提取与贪婪陷阱

1. 自造一个日志文件 `log.txt`（3~4 行即可），每行含一个 IP 地址（如 `192.168.1.5`）和日期（如 `2024-03-01`）。用 `grep -oE "[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+" log.txt` 提取所有 IP；预期输出每个 IP 一行，行内其他内容全部被丢掉。
2. 用 `sort | uniq -c | sort -rn` 统计每个 IP 的出现次数。注意 `uniq -c` 只合并**相邻**的重复行，所以前面的 `sort` 不能省（§8.2.3）。
3. 运行 `echo '<a>x</a> <b>y</b>' | rg -o "<.*>"` 和 `echo '<a>x</a> <b>y</b>' | rg -o "<.*?>"`，对比两次输出：前者 1 行吞掉整行，后者 4 行、逐个标签。没装 `rg` 就按 §8.4 的清单安装（Windows：`winget install BurntSushi.ripgrep.MSVC`）。

### $\rm \S \, 8.5.4$ 实践四：体验现代工具

1. 按 §8.4 的安装清单装上 `fd`（Windows：`winget install sharkdp.fd`；Debian/Ubuntu 装完后命令名是 `fdfind`）。
2. 在练习目录里分别用 `fd -e cpp` 和 `find . -name '*.cpp'` 找 `.cpp` 文件，对比输出格式与速度。
3. 运行 `fzf`，输入几个字符看候选收窄的效果；若装了 `bat`，用 `bat` 打开 `main.cpp`，对比 `cat` 的显示。
4. 若装了 `zoxide` 并完成了初始化，去几个常用目录后输入 `z` 加名字片段，看它能否记住你的去向；再用 `cd` 回原地，确认 `cd` 本身的行为没有被改变。

## $\rm \S \, 8.6$ 总结

- Shell 脚本把重复命令序列固化成文件：`set -euo pipefail` 让脚本“失败即停”，`${1:-默认值}` 处理参数，`>&2` 把错误与正常输出分开。
- grep 找到行，sed 修改行，awk 计算列——遇到文本处理任务先想“需要哪几个”，而不是直接打开 Python；处理 JSON 时用 jq，它理解嵌套结构。
- 正则表达式是文本筛选与提取的通用语言：`-E` 开启扩展语法，`( )` 捕获组给片段编号，配合 sed 的 `\1` 才能只留下想要的部分（`grep -o` 只给整个匹配），`.*` 默认贪婪、容易“吃多”，需要时改用 `.*?`。
- fd/bat/fzf/zoxide 与经典工具并存，按需替换——从 `fd` 和 `fzf` 开始，用熟一个再加下一个。

## $\rm \S \, 8.9$ 本章自测答案

> 先闭卷作答本章“关键概念回顾”与“应用与辨析”，再核对以下答案。

### $\rm \S \, 8.9.1$ 自测答案 · 关键概念回顾
1. `set -e` 任何命令失败立即停止（不会带着旧产物继续跑）；`set -u` 使用未定义变量时报错；`-o pipefail` 管道中任一命令失败则整体失败。
2. sed 按行做替换、删除、打印（流编辑器），适合“改文本”；awk 把每行按分隔符拆成列，适合“算数据”——过滤、求和、分组统计。
3. `+`、`?`、`()` 等元字符从字面字符变成语法；捕获组 `( )` 给括号内的片段编号，sed 可以用 `\1` 引用它。注意 `grep -o` 只输出整个匹配，不会只输出括号内的部分——想去掉前后缀要再接一条 sed 替换。
4. 它是贪婪匹配，默认尽可能多地吃字符（`<.*>` 会从第一个 `<` 吃到最后一个 `>`）；在量词后加 `?` 变成 `.*?` 即非贪婪。注意 GNU grep 的 `-E` 不支持非贪婪，用 ripgrep 或 Python。
5. fd→find，bat→cat，fzf→交互式文件/历史查找（可增强 Ctrl+R），zoxide→cd（用新增的 `z`/`zi` 跳转常用目录，`cd` 本身的行为不变）。

### $\rm \S \, 8.9.2$ 自测答案 · 应用与辨析
6. `-i` 直接改写原文件且不可撤销（没有版本控制时）；正确顺序是先用不带 `-i` 的命令看输出、必要时留 `.bak` 备份，确认无误再原地修改。
7. 需要复杂数据结构、跨平台一致行为或 Windows 原生环境时。经验规则：脚本要上服务器用 Bash；不确定时 Python 往往比 Shell 更少环境差异问题。
8. JSON 有嵌套结构和多行字符串，按行处理的 sed/awk 会误伤或漏掉；jq 理解 JSON 结构，能正确提取嵌套字段、筛选和变换。
