# $\rm Chapter \, 8$ 设备与精度：GPU 与混合精度

前七章的世界只有一个设备（CPU）和一种精度（float64）。真实训练把这两个假设同时打破：矩阵乘法搬到 GPU 上，数值从 float64 压到 float32 甚至 float16。本章给迷你框架加上设备概念，用实验量出精度的代价与收益，并解释混合精度为什么敢用 16 位浮点。

> 1. □ 本册 §1 的 Tensor 与 dtype 字段；
> 2. □ 本册 §6 的训练循环与对照方法；
> 3. □ 浮点数的符号-指数-尾数表示（回读：连续数学分册 §2）；
> 4. □ GPU 的 SIMT 执行模型（回读：计算机系统结构册 §8）。

## $\rm \S \, 8.1$ 设备抽象：数据与计算必须同地

迷你框架加设备只差一个字段：`Tensor` 增加 `device` 属性（本机 CPU 上用 `'cpu'` 与 `'cpu:0'` 模拟两台「设备」，只是标签，不真搬迁），再约定一条规则：参与同一运算的张量必须同设备，否则抛错。`.to(device)` 是唯一允许的搬迁入口：

```python
class Tensor:
    def __init__(self, data, device='cpu'):
        self.data = np.asarray(data, dtype=np.float64)
        self.device = device                 # 设备标签，本机不真搬迁
    def to(self, device):
        return Tensor(self.data, device)     # 搬运 = 换标签发新对象

t = Tensor(W, device='cpu:0')
t2 = t.to('cpu')                             # 搬运完成
t + w                                        # 设备不同 → RuntimeError
```

`__add__` 里加一行 `assert self.device == other.device` 就把规则变成代码。这条规则在 torch 内部叫设备分派（device dispatch）：每个算子收到张量后先查 `device` 字段，再决定调用 CPU 内核还是 CUDA 内核。迷你框架的「设备」只是标签，torch 的设备背后是两套完整的算子实现，`torch.add` 一个名字、两套代码，接口与实现就此分层。`.to('cuda')` 把张量搬到显存；一个 batch 的训练要「数据与模型同地」：`X.to('cuda')` 与 `model.cuda()` 都得做。跨设备运算直接报错不是 torch 小气，是设计：`RuntimeError: Tensor on device meta is not on the expected device cpu!`（真跑捕获，用 torch 的 meta 设备在 CPU 机器上演示同类报错）。报错比隐式搬运好，因为搬运是最贵的操作之一：数据过 PCIe 总线的带宽以 GB/s 计，隐式搬运会把性能问题藏进无声的慢。

## $\rm \S \, 8.2$ float32 vs float64：速度、内存与数值误差的账

同一 MLP（$8\to32\to2$）、同一数据（§6.2 的高斯数据）、同一种子、20 epoch，torch 只换 dtype。本机 CPU 实测：

| 指标 | float64 | float32 | 倍率 |
| --- | --- | --- | --- |
| 20 epoch 耗时 | 0.134 s | 0.088 s | 1.52 |
| 参数字节数 | 2832 B | 1416 B | 2.0 |
| 最终 loss | 0.132959 | 0.132959 | 相同 |
| 测试 acc | 0.90 | 0.90 | 相同 |
| 与 float64 参数最大差 | （基准） | ${7.6\times10^{-7}}$ | |

验证环境：WSL Ubuntu，PyTorch 2.14.1+cpu。三个读数：内存精确减半（尾数从 52 位缩到 23 位，字节数减半）；训练 20 epoch 后 float32 的参数与 float64 偏离 ${7.6\times10^{-7}}$ 量级，恰好是 float32 的机器精度（${\approx1.2\times10^{-7}}$）累积的样子，loss 与 acc 纹丝不动；CPU 上 32 位还快了 1.5 倍。GPU 上差距更大：A100 的规格口径是 fp32 矩阵算力约 19.5 TFLOPS、fp64 约 9.7 TFLOPS，张量核心（Tensor Core）对半精度还要再快一个量级，本机无 GPU，这些数字是规格书口径而非实测。

把 GPU 的账算完整还差一条带宽账，同样是规格口径：A100 显存带宽约 2039 GB/s，而主机到显卡的 PCIe 4.0 只有约 32 GB/s，差 60 倍。这就是 §8.1「数据与计算同地」的数字注脚：一个 batch 的数据搬进显存只要毫秒，但每个 step 都搬一遍就把 GPU 喂不饱，正确的做法是整个数据集（或分块）常驻显存、整份模型常驻显存，搬运只发生在训练开始与结束时。

深度学习敢用低精度，靠的是「训练的结果是参数，参数差 ${10^{-7}}$ 无所谓」：梯度本身来自带噪的 SGD（§7.3），噪声比舍入误差大得多。

这个论证有个边界要划清：float32 买得起的是「每一步差一点」，不是「误差无界累积」。上面的 ${7.6\times10^{-7}}$ 是 20 epoch 的账；epoch 拉长，偏离会缓慢增长，但 SGD 每步都被「当前 batch 的噪声」重新洗牌，舍入误差不系统叠加，最终稳在与梯度噪声同量级的位置。真正怕低精度的是另一处：§8.3 的小梯度被抹零，那是「差一点」与「差很多」的分界线。

## $\rm \S \, 8.3$ float16 的下溢：小梯度被抹零

float16 的格式是 1 位符号、5 位指数、10 位尾数，最小正规数 ${6.1\times10^{-5}}$，最小非正规数 ${2^{-24}\approx5.96\times10^{-8}}$。用 numpy 真跑一组表示实验：

| 值 | float16 表示 | 相对误差 |
| --- | --- | --- |
| ${10^{-4}}$ | ${1.000\times10^{-4}}$ | ${1.7\times10^{-4}}$ |
| ${10^{-5}}$ | ${1.001\times10^{-5}}$ | ${1.4\times10^{-3}}$ |
| ${10^{-6}}$ | ${1.013\times10^{-6}}$ | ${1.3\times10^{-2}}$ |
| ${10^{-7}}$ | ${1.192\times10^{-7}}$ | ${1.9\times10^{-1}}$ |
| ${10^{-8}}$ | 0 | 1.0 |

梯度更新 ${w\gets w-\mathrm{lr}\cdot g}$ 在 $\mathrm{lr}=10^{-3}$、$g=10^{-5}$ 时更新量只有 ${10^{-8}}$：float32 里是 ${1.000\times10^{-8}}$，float16 里直接是 0。真跑一万步（初值 ${w=10^{-3}}$）：float32 的 $w$ 走到 ${8.999\times10^{-4}}$，float16 的 $w$ 原地不动（${1.0004\times10^{-3}}$）。梯度明明非零，参数却学不到它，这就是下溢抹零。

loss scaling（损失缩放）是针对它的手术：把损失乘一个大数 ${S}$（如 ${2^{10}}$），反向传播的梯度全体跟着乘 ${S}$，${10^{-8}}$ 的更新量变成 ${10^{-5}}$，落回 float16 的可表示区；优化器更新前再除回 ${S}$（在 float32 里做）。同一组数字验证：直接算更新，float16 得 0；先乘 ${2^{10}}$ 再在高精度除回，得 ${1.001\times10^{-8}}$，与真值同量级。

下溢实验的完整版放进表里：初值 ${w=10^{-3}}$、$\mathrm{lr}=10^{-3}$、$g=10^{-5}$，连走一万步（验证环境 NumPy 2.5.4）：

| 实现 | 单步更新量 | 一万步后的 ${w}$ |
| --- | --- | --- |
| float32 | ${1.000\times10^{-8}}$ | ${8.999\times10^{-4}}$ |
| float16 | 0 | ${1.0004\times10^{-3}}$ |

float16 的参数在起点附近纹丝不动：不是学得慢，是压根没学。这类 bug 在真实训练里的长相是「某些层的参数一万步零变化」，数值下溢要排在怀疑名单前列。

## $\rm \S \, 8.4$ 混合精度：FP16 与 BF16 的分工

混合精度（mixed precision）的前向反向用 16 位跑、参数主拷贝与更新保持 float32（autocast 自动决定每个算子用哪种；GradScaler 就是 §8.3 的 loss scaling 的官方实现）。16 位有两种格式，取舍在指数与尾数之间：

| 格式 | 位分配 | 最大值 | 最小正规数 | 有效十进制位 |
| --- | --- | --- | --- | --- |
| FP16 | 5 指数 + 10 尾数 | 65504 | ${6.1\times10^{-5}}$ | 约 3.3 |
| BF16 | 8 指数 + 7 尾数 | ${\approx3.4\times10^{38}}$ | ${1.2\times10^{-38}}$ | 约 2.9 |

真跑对照（torch bfloat16）：${10^{-8}}$ 在 BF16 里表示为 ${1.001\times10^{-8}}$，活着；在 FP16 里是 0。反过来，65504 在 BF16 里被舍成 65536，尾数粗的代价。BF16 的动态范围与 float32 相同，梯度再小也不下溢，所以不需要 loss scaling；FP16 尾数长、算得准，但要配 GradScaler 护航。一句话：FP16 保精度、BF16 保范围，现代 GPU 两者都有硬件加速，训练框架默认 BF16 的越来越多，理由正是「少一个要解释的补丁」。

对照表里还有一行值得单看：FP16 的最大值只有 65504，前向激活一旦超过它就溢出成 inf，损失再一平均就是 nan；BF16 的上限 ${3.4\times10^{38}}$ 与 float32 一致，从根上没有这个问题。混合精度选型的口诀由此而来：激活值范围不可控的网络（大模型、深网络）用 BF16，激活范围有把握、追求尾数精度的场合用 FP16 加缩放。

最后一个衔接：autocast 与 GradScaler 的分工正好是本章两节的内容。autocast 管「哪些算子用 16 位跑」（§8.4 的选型），GradScaler 管「16 位算出的梯度怎么活着送到更新」（§8.3 的缩放），两个开关各管一段、缺一不可。

## $\rm \S \, 8.7$ 本章自测答案

### $\rm \S \, 8.7.1$ 关键概念回顾答案

1. Tensor 加 `device` 字段、`.to()` 是唯一搬迁入口、跨设备运算抛错；报错让最贵的操作（数据搬运）保持显式，不藏进无声的慢。（§8.1）
2. 省一半内存与近一半时间；付出 ${10^{-7}}$ 量级的参数偏离，量级由 float32 机器精度 ${1.2\times10^{-7}}$ 决定。（§8.2）
3. ${2^{-24}\approx5.96\times10^{-8}}$；${10^{-8}}$ 比它还小，表示为 0，更新被完全抹掉。（§8.3）
4. 前向算损失时乘 ${S}$、反向梯度全体放大 ${S}$ 倍、优化器更新前在高精度里除回；除回若还在 float16 里做，${10^{-8}}$ 的缩小又下溢了。（§8.3）
5. FP16 保尾数（精度）、BF16 保指数（范围）；BF16 动态范围与 float32 相同，小梯度不下溢，无需缩放。（§8.4）
6. 噪声以下的舍入可以接受（SGD 的 batch 噪声更大，把舍入误差盖住），下溢线以下的抹零必须救（那是「差一点」变「根本没动」）；判据是误差量级与梯度噪声量级之比。（§8.2–8.3）

### $\rm \S \, 8.7.2$ 应用与辨析答案

1. 报 `RuntimeError`（设备不匹配）；`X = X.to('cuda')` 与 `model.to('cuda')` 两行都要，数据与计算同地。（§8.1）
2. 不会无限涨：偏差稳定在 float32 舍入与 SGD 噪声的平衡点，${10^{-7}}$ 到 ${10^{-6}}$ 量级；要影响 loss 得超过梯度噪声本身，这台实验的噪声远大于此。（§8.2）
3. 更量 ${10^{-7}}$，float16 表成 ${1.19\times10^{-7}}$，相对误差约 19%（表中 ${10^{-7}}$ 一行）；仍是「没归零但已经不准」。（§8.3）
4. 救不了梯度消失本身：scaling 放大的是「梯度表示」的下溢，把 ${10^{-9}}$ 搬进可表示区，但反向穿过网络时逐层衰减的结构没变；救了存储、救不了传播。（§8.3）
5. 损失曲线的分辨率由 SGD 噪声决定（batch 间抖动，§7.3 的振荡），${10^{-2}}$ 量级的抖动完全盖住 ${10^{-2.9}}$ 与 ${10^{-3.3}}$ 尾数之差。（§8.4）
