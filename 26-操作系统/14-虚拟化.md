# $\rm Chapter \, 14$ 虚拟化：trap-and-emulate 与第二层账

上一章的容器隔离了「操作系统的视图」，隔离的底线仍是共享同一个内核。虚拟化（virtualization）再退一步：让每个虚拟机以为自己独占整台裸机，从 CPU、内存到网卡。支撑这一切的核心机制出乎意料地收敛：让客户机的指令尽量直接在物理 CPU 上跑，出了边界就陷入（trap）给 hypervisor 模拟。本章讲这一个招式，以及它牵出的两本页表账。

> **开始前自检**：本章假设你已经会：
>
> 1. □ 知道 CPU 的用户态与内核态、系统调用走 trap 进内核（本册 §1.3、§11.2）；
> 2. □ 理解页表与地址翻译，TLB 缓存翻译结果（本册 §4.1–§4.2）；
> 3. □ 知道容器与 VM 的分工（本册 §13.4）；
> 4. □ 见过 `/proc/cpuinfo` 的 flags 列表（本章 §14.4 会用到其中三个）。

## $\rm \S \, 14.1$ 要解决的问题：一台机器当多台用

虚拟机的承诺与虚拟内存同构：给上层每个租户一个「独占硬件」的假象，底层把真实硬件时分复用。难点在 CPU 不是普通的可复用资源，它有特权态：客户操作系统（guest OS）也自以为拥有内核态，会执行特权指令（装页表、关中断、访问 I/O 端口）。宿主怎么处理这些指令，就是虚拟化的全部难点。

早期的纯软件方案各有一本苦账：解释执行太慢；二进制翻译（VMware 的起家技术）快但工程浩大；「半虚拟化」（Xen 早期）改客户内核源码，把特权操作换成显式调用。判据来自 1974 年的 Popek–Goldberg 定理：一个 ISA 是天然可虚拟化的，当且仅当所有敏感指令都是特权指令（用户态执行即陷入）。白话：hypervisor 全靠「出格就按铃」介入，所以每条需要管的指令必须一碰就按铃；x86 偏偏有十几条敏感指令用户态能悄悄执行、铃不响，hypervisor 既不知道也无法拦截，经典虚拟化因此在 x86 上不成立——直到硬件补了这一铃。

## $\rm \S \, 14.2$ 硬件虚拟化：多加一层态

2005 年前后，Intel VT-x 与 AMD-V 给 CPU 加了一个新执行层：hypervisor（宿主）跑在最外层，每个虚拟机有一个「非根模式」，guest 内核跑在非根模式里的「内核态」，guest 用户程序跑在非根模式的用户态。

规则只有一条：guest 执行敏感指令时，CPU 自动从非根模式陷入根模式（VM exit），hypervisor 检查并模拟这条指令的效果，然后注入回去（VM entry）。这就是 trap-and-emulate，整个虚拟化引擎围绕它展开：

1. guest 写页表 → VM exit → hypervisor 检查合法性、更新真正的映射（§14.3 的页表账）；
2. guest 访问硬件寄存器 → VM exit → hypervisor 模拟设备的应答；
3. guest 的普通算术与访存指令 → 不陷入，直接在物理 CPU 上全速执行。

好性能的关键是让 VM exit 尽量少：绝大多数指令（热路径上的访存、运算）必须不陷。实测里能直接看到硬件对这条路径的支持程度。WSL2 本身就运行在 Hyper-V 的轻量虚拟机里，读 `/proc/cpuinfo` 的 flags，能看到 `hypervisor`（CPU 报告自己在 VM 里）与三个直通给 guest 的虚拟化加速标志：`ept`（扩展页表，§14.3 的硬件）、`vpid`（地址空间标识，避免切 VM 时全刷 TLB）、`vnmi`（虚拟化版的中断控制）。宿主 Intel Core Ultra 7 255H 的这些标志出现在 WSL 会话里，说明硬件虚拟化特性本身又被虚拟化了一层（嵌套虚拟化），这条路径如今日常到无感。

### $\rm \S \, 14.2.1$ 特权级矩阵：哪些指令为什么必须陷入

把 §14.1 的判据摊开成矩阵。特权指令（privileged instruction）用户态执行必然陷入，敏感指令（sensitive instruction）行为随特权态变化；hypervisor 的介入点只有陷入，逐类过一遍：

1. 普通指令（算术、访存、跳转）：与特权态无关，全速直跑，hypervisor 全程不知情；
2. 特权且敏感（写 `CR0`、`HLT`、`IN`/`OUT`）：用户态一碰就陷入，hypervisor 检查并模拟效果；
3. 敏感但不特权（如 `SGDT`/`SIDT`、`POPF`、`CPUID`）：用户态执行不陷入，却摸到了 hypervisor 才该管的机器状态，Popek–Goldberg 判据正是在这里破口。

铃不响时 hypervisor 只能靠二进制翻译逐条改写指令，这正是 VMware 起家的工程重负。VT-x 的解法一句话：不改任何指令的语义，加一个模式位，非根模式下这批「静默敏感」指令统一改判为「可陷入」，矩阵第三列整个消失。

白话：hypervisor 只认门铃，第三类指令偷偷干活不按铃；VT-x 换了套门铃系统：进了非根模式，原来不按铃的也按铃。

**小结**：特权与敏感是两个独立维度，可虚拟化要求二者重合；VT-x 用非根模式把「敏感不特权」整体改成可陷入，矩阵重新闭合。

**本节小结**：VT-x/AMD-V 用「多一层态」修复了 x86 的虚拟化缺陷：guest 跑在非根模式，敏感指令一执行就 VM exit 交给 hypervisor 模拟，普通指令全速直跑；整个引擎的账都围绕「exit 次数」记，exit 越少越快。

## $\rm \S \, 14.3$ 两本页表账：影子页表与 EPT

虚拟化最贵的账在内存。guest 有自己的页表：把 guest 虚拟地址翻译成 guest 物理地址。但 guest 物理地址是假的，还要再翻译一次才落到宿主物理地址。如果每次访存都两段翻译、每段查页表，代价无法接受。两种方案：

1. **影子页表（software shadow）**：hypervisor 自己维护一张「guest 虚拟地址直通宿主物理地址」的合成页表塞给 MMU。快（一次翻译），但每次 guest 改页表都要 VM exit 来同步影子，写密集负载陷入风暴。
2. **EPT（extended page tables，AMD 叫 NPT）**：硬件直接两级翻译。MMU 先查 guest 页表得到 guest 物理地址，再用 EPT（由 hypervisor 配置）把 guest 物理地址翻译成宿主物理地址，两段都由硬件完成、各自有 TLB 缓存。代价是 TLB miss 时要走的页表级数翻倍（4 级页表变 8 次查表）。

现代平台默认 EPT。实测 flags 里的 `ept` 就是它的开关。这笔账与容器对比更清楚：容器没有第二层翻译（本册 §13），访存路径与普通进程完全一样；VM 的每个 TLB miss 都比裸机多走一截。「容器快」的另一处机制出处在这里。

### $\rm \S \, 14.3.1$ EPT violation：第二本账什么时候响铃

EPT 不是填满的表，只在 guest 首次用到某个 guest 物理页时才补映射。于是第二本账也有自己的铃：guest 访存的物理地址在 EPT 里无映射或权限不符（比如写只读页），CPU 直接 VM exit，即 EPT violation。hypervisor 分两种处理：

1. guest 页表里该页合法：属于请求分页（demand paging），hypervisor 分配宿主页、补好 EPT 表项后返回，guest 无感知；
2. guest 页表里也不合法：说明 guest 自己先犯了缺页，hypervisor 把 guest page fault 注入回去，让 guest 内核走本册 §4 的缺页路径自己处理。

白话：第一本账的铃是 guest 自己按的，第二本账的铃是 hypervisor 替它按的，排障时分清铃源就知道谁欠债。

### $\rm \S \, 14.3.2$ 数值实验：miss 放大与同步风暴

两本账的代价并成一笔期望值：记 TLB 命中率 ${h}$，未命中时除数据访问外要付的页表走查次数为 $W$：

$$
\bar{C}(h) \;=\; 1 + (1-h)\,W,
\qquad
W = 4\,(\text{裸机}),\;\; 1\,(\text{影子页表}),\;\; 4 + 4 \times 4 = 20\,(\text{EPT}).
$$

20 = 4 次 guest 走查加每级重走的 4 级 EPT 查询（含最终数据访问的 ${\text{GPA} \to \text{HPA}}$），正文「4 级变 8 次」只算了 guest 一半。用带局部性的模拟轨迹实跑核对（脚本与完整输出在 `_uni5_work/expOS14/`；轨迹 1,000,000 次访存、工作集 8192 页、LRU TLB 1024 项、90% 热在 512 页）：

1. 实测 TLB 命中率 ${h = 0.912}$，共 miss 87,996 次；
2. 页表走查总次数：裸机 351,984 次，影子页表 87,996 次（0.25 倍），EPT 1,759,920 次（5.00 倍）；
3. 叠加页表写突发（首触 8,192 页、每页 PTE 再改写一次）：影子页表 VM exit 16,384 次，EPT 只有首触 8,192 次 violation，第二遍改写 PTE 零 exit。

数字把两本账的性格讲全：影子页表稳态走查只有裸机四分之一，但每笔页表写都要 exit，写越密亏得越多；EPT 每 miss 多付 16 次走查，换来页表写零 exit。真实平台选 EPT 不是因为每 miss 更快，而是 fork、demand paging、页扫描这类写页表风暴太常见，影子页表的同步账控制不住；《性能工程》§2.4 量到的「随机访存延迟比裸机翻倍还多」就是这笔账的收据。

**小结**：数值上影子页表赢在稳态 miss（走查 0.25 倍）、输在同步 exit；EPT 每 miss 付 20 次走查但页表写零 exit，真实负载的写密集性让后者胜出。

**本节小结**：guest 地址要翻两次（guest 虚拟 → guest 物理 → 宿主物理），两本账的差别只在「谁来做第二笔」：影子页表让软件合成一张直通表、快在翻译慢在同步；EPT 让硬件两级各翻各的、把代价匀到每次 TLB miss 上。现代平台选了后者。

## $\rm \S \, 14.4$ KVM：Linux 把 hypervisor 做成驱动

Linux 的做法是 KVM：一个内核模块，把内核变成 type-1 hypervisor。结构上是三明治：

1. QEMU 进程：用户态，扮演设备模拟器（虚拟网卡、磁盘、显卡都是它用普通代码模拟的）；
2. KVM 内核模块：管理 VM exit 分发与内存映射，把需要模拟的请求转给 QEMU；
3. 硬件：VT-x/EPT/VMX 负责模式切换与两级翻译。

一次磁盘读取的完整旅程：guest 发虚拟磁盘请求 → VM exit → KVM 转给 QEMU → QEMU 转成宿主的真实文件读写 → 结果按中断的形状注入 guest（guest 内核还会经历本册 §11.2 的中断处理路径，只不过中断是 QEMU 造的）。每一跳都有成本，这也是 virtio 存在的理由：让 guest 知道自己在虚拟机里，直接用共享内存环传请求，砍掉大部分模拟开销。

### $\rm \S \, 14.4.1$ I/O 虚拟化三档：全模拟、半虚拟化、直通

正文那次磁盘读取走的是第一档，三档按「guest 离真相多远」排开：

| 档位 | guest 看到什么 | 一次请求的路径 | 得与失 |
| --- | --- | --- | --- |
| 全模拟（QEMU 默认） | 一台假想的真实设备 | 每次敲设备寄存器（MMIO/PIO）都 VM exit，QEMU 用软件状态机应答 | 兼容性最好，guest 不用换驱动；慢在每笔 I/O 一次 exit 加整套「演技」 |
| 半虚拟化（virtio） | 一台明说的虚拟设备 | guest 把请求写进共享内存的描述符环（virtqueue），批量提交 | 砍掉绝大多数 exit；代价是 guest 要装 virtio 驱动，承认自己在 VM 里 |
| 直通（SR-IOV 加 IOMMU） | 真网卡切出的一块虚拟功能（Virtual Function，VF） | IOMMU 把 guest 物理地址直接重映射到宿主物理地址，数据路径零 exit | 性能逼近裸机；代价是设备资源独占，热迁移与灵活配置让位 |

全模拟慢不在 QEMU 代码，而在它替设备背了「寄存器语义一点不少」的包袱：guest 每写一个状态寄存器都是一次 VM exit 加一段模拟代码，真实设备上这只是普通寄存器写，virtio 省掉的正是这整笔演技。SR-IOV（Single Root I/O Virtualization）与 IOMMU（Input–Output Memory Management Unit）则让真设备入场，hypervisor 只在控制路径出场。《计算机系统结构》§9.3 实测的 WSL2 虚拟盘每笔约 0.4 ms 固定往返就是这档 I/O 税的收据，《性能工程》§2.4 对内存侧 EPT 税有对称测量。三档按负载挑：关键网卡开 SR-IOV、日常盘用 virtio、古董系统留全模拟。

白话：全模拟是请演员把设备演全套，手势不许错；virtio 是演员摊牌「我是假的，点单写黑板上我端菜」；SR-IOV 是把真服务员切份，一桌包一份。

**小结**：三档的差别在 exit 次数：全模拟每笔 I/O 都 exit，virtio 用共享内存环把 exit 压到必要时刻，SR-IOV 加 IOMMU 让数据路径零 exit 而灵活性让位。

**本节小结**：KVM 的三层各司其职——硬件管切换与翻译、内核模块管分发、QEMU 管设备模拟；一次 I/O 要跨三层走完整个链路，virtio 的思路是干脆承认虚拟化、让 guest 与宿主直接对话，省掉「演得像真硬件」的整笔开销。

## $\rm \S \, 14.7$ 本章自测答案

### $\rm \S \, 14.7.1$ 关键概念回顾答案

1. 一个 ISA 天然可虚拟化，当且仅当所有敏感指令都是特权指令（用户态执行必然陷入）。x86 有十几条敏感但用户态可静默执行的指令，guest 做特权操作时 hypervisor 收不到陷入，无法介入。（§14.1）
2. 让陷入尽量少。普通指令（算术、访存）必须不经 hypervisor 直接执行，只有边界事件（写控制寄存器、访问 I/O、页表修改）才 VM exit；exit 次数是虚拟化开销的主项。（§14.2）
3. 影子页表把代价挪到 guest 改页表时（每次修改触发同步陷入）；EPT 把代价挪到 TLB miss（硬件两级翻译，miss 时多走一层查表）。前者陷入风暴，后者均匀小额。（§14.3）
4. 用户态的 QEMU。KVM（内核）只管模式切换与内存映射的分发，设备应答由 QEMU 用普通代码模拟，硬件做的是切换与翻译。（§14.4）
5. 半虚拟化：guest 明知自己在 VM 里，用共享内存的环形队列直接与宿主交换请求，跳过「模拟真实硬件再翻译」的整条弯路。（§14.4）

### $\rm \S \, 14.7.2$ 应用与辨析答案

1. 两层态：guest 用户态 →（trap）→ guest 内核态（非根模式）→（VM exit）→ 根模式。系统调用一次 guest 内 trap，特权操作再 VM exit。（§14.2）
2. guest 在用户态静默执行敏感指令，读到了 hypervisor 才有权管理的信息（或做了本该陷入的操作），hypervisor 既不知道也无法拦截，隔离与正确性同时失守；后果是 guest 可以探测甚至破坏虚拟化层。（§14.1）
3. 4 级页表在纯 guest 下 TLB miss 要走 4 次内存查表；加 EPT 翻译后走 8 次。TLB 命中率高的负载受影响小，页表频繁切换的负载（进程密集）受影响明显，vpid 与 PCID 缓解切换时的全刷。（§14.3）
4. WSL2 用 Hyper-V 起一个定制内核的轻量 VM，砍掉固件与设备模拟的包袱（设备走 virtio 化的协议），用途是开发环境而非完整虚拟机。flags 里 hypervisor/ept/vpid 直通给这个 guest，与任何 KVM 客户机同款。（§14.2、§14.4）
