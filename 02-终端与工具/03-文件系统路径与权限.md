# $\rm Chapter \,  3$ 文件系统、路径与权限

> 在[终端、Shell与命令行](02-终端Shell与命令行.md)中你学会了在目录之间移动、查看文件和运行程序。但你一定遇到过这种情况：资源管理器里明明能看到的文件，终端却说"找不到"；或者双击就能打开的程序，在终端输入名字却提示"不是内部或外部命令"。本章回答：文件到底在哪里，程序怎样找到它，以及系统凭什么允许或拒绝一次访问。

## $\rm \S \, 3.1$ 文件系统是一棵树（有时是一片森林）

在[终端、Shell与命令行](02-终端Shell与命令行.md)中，你已经在用 `cd` 在目录间移动。现在把镜头拉远，看看这些目录是怎样组织起来的。

### $\rm \S \, 3.1.1$ 根目录：所有路径的起点

一个磁盘或分区的文件系统，本质上是一棵倒置的树：最上层是一个**根目录**（root directory），下面分支出子目录和文件，子目录再分支出更多内容。

在 Windows 上，每个盘符都有自己的根，形成一片"森林"：

```text
C:\                    ← C 盘的根
├── Users\
│   └── Alice\
│       └── projects\
D:\                    ← D 盘的根
├── data\
└── tools\
```

在 Linux/macOS 上，所有存储设备挂载到同一棵树下，只有一个根 `/`：

```text
/                      ← 整个文件系统的根
├── home\
│   └── alice\
│       └── projects\
├── mnt\
│   └── data\          ← 可能是另一块硬盘挂在这里
└── tmp\
```

这就是为什么 Windows 路径以 `C:\` 或 `D:\` 开头，而 Linux 路径以 `/` 开头——它们只是组织方式不同，树状结构的思想完全相同。

> **竞赛生迁移提示**：目录结构就是一棵多叉树——根目录是根节点，`..` 是父节点指针，`.` 是节点自身，从根出发沿着子节点走下来的路径就是你在终端看到的目录路径。这和你在 OJ 中遍历目录树写过的 DFS 完全对应。

### $\rm \S \, 3.1.2$ 文件名、目录名和路径分隔符

路径由一串名字用分隔符连接而成。Windows 传统用反斜杠 `\`，Linux/macOS 用正斜杠 `/`。

现在许多 Windows 开发工具（包括 PowerShell 的许多命令）也接受 `/`，但 **不要假设所有工具都一样**。使用文件资源管理器的地址栏或 Tab 补全时，得到的仍然是反斜杠路径。跨平台项目中，优先使用正斜杠，或在代码中让语言/库处理分隔符差异。

一个完整的路径包含：

```text
C:\Users\Alice\projects\main.cpp
 ↑       ↑        ↑       ↑
盘符   目录名   目录名   文件名（含扩展名）
```

文件名和目录名在各自父目录中必须是唯一的。**目录本质上也是一种文件**，只是它存储的是"里面有什么"的列表，而不是普通数据。

## $\rm \S \, 3.2$ 绝对路径与相对路径

这是文件系统最核心的概念，也是"找不到文件"的第一大来源。

### $\rm \S \, 3.2.1$ 定义

- **绝对路径**：从根目录出发，完整写出到达目标的每一级。无论当前在哪里，它都指向同一个位置。
- **相对路径**：从当前工作目录出发。同一段相对路径，在不同当前目录下指向不同位置。

Windows 绝对路径的例子：

```text
C:\Users\Alice\projects\data\papers.json
D:\backup\2024.tar.gz
```

Linux/macOS 绝对路径的例子：

```text
/home/alice/projects/data/papers.json
/tmp/log.txt
```

相对路径的例子（两个平台通用）：

```text
data/papers.json          ← 当前目录下的 data 子目录中的文件
../backup/old.tar.gz     ← 上一级目录中的 backup 子目录中的文件
./main.cpp               ← 明确指当前目录中的文件（. 可以省略）
```

在[终端、Shell与命令行](02-终端Shell与命令行.md)中你已经见过 `.`（当前目录）和 `..`（上一级目录）——它们是相对路径的构建块。多层 `..` 也是合法的：

```text
../../global_config.json  ← 上两级目录中的文件
```

### $\rm \S \, 3.2.2$ 什么时候用绝对路径，什么时候用相对路径

**绝对路径**适合：
- 配置文件中的固定位置（如日志目录、数据目录）；
- 脚本中引用的系统工具路径；
- 跨项目引用一个不会移动的资源。

**相对路径**适合：
- 项目内的文件引用——整个项目目录移动到另一台机器或另一个位置后，相对路径仍然有效；
- 构建脚本、`#include`、`import` 等，它们通常相对于当前文件或项目根解释。

一个常见的坑：你在 `C:\Users\Alice\projects` 中写了一个脚本，里面用了 `data/input.txt`。后来你把脚本复制到 `D:\tools` 去运行，`data/input.txt` 就会相对于 `D:\tools` 解释，而不是原来的位置。

> **经验规则**：如果你希望移动项目目录后一切照常工作，用相对路径。如果你引用的资源固定在系统中某处，用绝对路径。不确定时，先确认当前目录。

### $\rm \S \, 3.2.3$ `~` 是什么

在[终端、Shell与命令行](02-终端Shell与命令行.md)中你见过 `~` 这个符号。在 Linux/macOS 和 PowerShell 中，`~` 通常展开为当前用户的**主目录**（home directory）：

```bash
# Bash
cd ~/projects     # 等价于 cd /home/alice/projects
```

```powershell
# PowerShell
Set-Location ~/projects   # 等价于 Set-Location C:\Users\Alice\projects
```

`~` 不是文件系统的一部分——它是 Shell 在解析命令时帮你替换的简写。在程序代码中（如 C++ 的 `fopen`）`~` 通常不会被展开，你需要写完整路径。

### $\rm \S \, 3.2.4$ 在终端中验证

任何时候不确定当前目录，先查看：

```powershell
# PowerShell
Get-Location
```

```bash
# Bash
pwd
```

构造一个路径后，用 `Test-Path`（PowerShell）或 `ls`（Bash）立即验证：

```powershell
Test-Path "C:\Users\Alice\projects\data\papers.json"
# 返回 True 或 False
```

```bash
ls /home/alice/projects/data/papers.json
# 文件存在则显示文件名，不存在则报 No such file or directory
```

> **经验规则**：`Test-Path`/`ls` 适合验证已知路径。当你只记得文件名、不知道它在哪时，用系统级搜索：Windows 的 **Everything**（voidtools.com，直接读 NTFS 的 MFT 索引，比系统自带搜索快几个数量级）、macOS 的 **Spotlight**（`Cmd+Space`；第三方 **Alfred** 更强大、支持工作流）、Linux 的 `locate`（部分发行版需先安装并 `updatedb` 建索引）。共同点：全盘索引，一秒钟内找到文件。

## $\rm \S \, 3.3$ 隐藏文件：不显示不代表不存在

有些文件默认不在文件管理器和普通 `ls` 中显示——它们被标记为"隐藏"。

### $\rm \S \, 3.3.1$ Unix/Linux/macOS：点号前缀

文件名以 `.` 开头即视为隐藏：

```text
.gitignore
.config/
.bashrc
```

`ls` 默认不显示它们。使用 `-a` 选项（all）才会列出：

```bash
ls        # 不显示隐藏文件
ls -a     # 显示包括 . 和 .. 在内的全部文件
ls -A     # 显示隐藏文件，但不包括 . 和 ..
```

大量开发工具把配置和状态保存在隐藏文件中——`.git` 目录存储了 Git 仓库的全部历史；`.vscode` 保存了 VS Code 的工作区设置。它们有意不打扰日常浏览，但当你排查配置问题时，要知道它们是存在的。

### $\rm \S \, 3.3.2$ Windows：文件属性

Windows 使用文件系统中的"隐藏"属性标记文件，与文件名无关。在 PowerShell 中查看和设置：

```powershell
# 查看隐藏项目（包括隐藏文件和目录）
Get-ChildItem -Hidden

# 同时显示隐藏和非隐藏
Get-ChildItem -Force
```

Windows 还有一个"系统"属性用于操作系统关键文件，用 `-System` 查看。

### $\rm \S \, 3.3.3$ 什么时候你会遇到隐藏文件

- 跟着教程做项目时，教程说"编辑 `.env` 文件"，你却在文件管理器中找不到——它可能被隐藏了。
- 复制一个目录给别人的时候，隐藏文件（如 `.git`）可能被漏掉，导致对方拿到的项目不完整。
- 排查磁盘空间时，某个隐藏目录可能占了大量空间但你一直没看到。

## $\rm \S \, 3.4$ 文件扩展名：约定，不是魔法

### $\rm \S \, 3.4.1$ 扩展名帮助程序判断类型

`main.cpp` 的 `.cpp` 部分就是扩展名。它的作用是告诉程序和人类"这可能是什么类型的文件"。编辑器根据扩展名选择语法高亮，编译器根据扩展名选择语言标准，文件管理器根据扩展名选择图标和默认打开方式。

但在文件系统层面，**扩展名只是文件名的一部分**。把 `photo.jpg` 改名为 `photo.cpp` 不会把 JPEG 图像转换成 C++ 源码——它仍然是一段二进制数据，只是系统现在会对它尝试 C++ 的打开方式。

### $\rm \S \, 3.4.2$ Windows 常见陷阱：隐藏已知扩展名

Windows 资源管理器默认**隐藏已知文件类型的扩展名**。当你看到一个名为 `README` 的文件时，它的真实完整名称可能是 `README.md` 或 `README.txt`。当你"新建文本文档"并看到 `新建文本文档.txt` 时，如果你手动改名为 `data.json`，实际文件变成了 `data.json.txt`——后面的 `.txt` 被隐藏了，导致程序不识别。

**建议**：在文件资源管理器的"查看"选项卡中勾选"文件扩展名"，始终显示完整文件名。

### $\rm \S \, 3.4.3$ 没有扩展名和多个扩展名

Linux 上许多可执行文件和配置文件没有扩展名。`.tar.gz` 有两个扩展名，表示"先经过 tar 打包，再经过 gzip 压缩"。习惯上从右向左读：最右边是最外层格式，打包与压缩这两层操作会在[文本、编码、压缩包与常见数据格式](05-文本编码压缩包与数据格式.md)中详细展开。

## $\rm \S \, 3.5$ 通配符：用一个模式匹配多个文件

Shell 提供了一组字符，帮你用模式批量指定文件，这叫 **globbing**（或通配符展开）。

### $\rm \S \, 3.5.1$ 基本通配符

| 通配符 | 含义 | 示例 |
|---|---|---|
| `*` | 任意长度的任意字符 | `*.cpp` 匹配所有 C++ 源文件 |
| `?` | 恰好一个任意字符 | `data_?.csv` 匹配 `data_1.csv`、`data_a.csv`，不匹配 `data_10.csv` |
| `[abc]` | 方括号内任意一个字符 | `file_[0-9].txt` 匹配 `file_0.txt` 到 `file_9.txt` |
| `[!abc]` | 方括号内字符之外的任意一个字符 | `[!0-9]*` 匹配不以数字开头的文件 |

在 C++ 中你学过字符类和范围——`[0-9]` 这个语法你应该不陌生。

### $\rm \S \, 3.5.2$ 在命令中使用

PowerShell：

```powershell
# 列出当前目录下所有 .cpp 文件
Get-ChildItem *.cpp

# 列出当前目录及其子目录下所有 .cpp 文件
Get-ChildItem -Recurse *.cpp
```

Bash：

```bash
# 列出当前目录下所有 .cpp 文件
ls *.cpp

# 列出当前目录及子目录下所有 .cpp 文件
# Bash 需先 shopt -s globstar 启用递归通配符（zsh 默认支持）
ls **/*.cpp
# 如果不确定当前 Shell 的通配行为，用 find 更可靠：
find . -name "*.cpp"
```

### $\rm \S \, 3.5.3$ 通配符不是正则表达式

一个常见混淆：`*` 在通配符中表示"任意字符序列"，在正则表达式中表示"重复前一个模式零次或多次"。它们是两套不同的系统。Shell 的文件通配符是 glob 模式，`grep` 和 `sed` 搜索的是正则表达式。如果不确定，先在小范围实验。

### $\rm \S \, 3.5.4$ 危险边界

```bash
rm *.log        # 删除当前目录下所有 .log 文件
rm -r test_*    # 递归删除所有以 test_ 开头的目录及其内容
```

在执行删除、覆盖或移动带有通配符的命令前，先用 `ls` 或 `Get-ChildItem` 确认匹配了哪些文件：

```bash
ls *.log         # 先看匹配了什么
# 确认无误后再执行
rm *.log
```

## $\rm \S \, 3.6$ 符号链接与快捷方式：一个位置，多个入口

### $\rm \S \, 3.6.1$ 概念

有时你希望同一个文件或目录出现在两个不同的路径下——不是复制，而是同一个东西有多个名字。

- **符号链接**（symbolic link / symlink）：文件系统级别的"指针"。访问符号链接时，系统自动跳转到目标。删除符号链接不会删除目标；删除目标后，符号链接变成"悬空"状态，指向不存在的位置。
- **Windows 快捷方式**（`.lnk` 文件）：是普通文件，由 Windows Shell 而非文件系统解释。许多命令行程序不识别 `.lnk` 文件，会把它当成普通文件。
- **硬链接**（hard link）：同一个文件数据对应多个文件名，删除任意一个不影响数据和另一个名字。限于同一文件系统内，不适用于目录（POSIX 限制）。日常开发中符号链接更常见。

### $\rm \S \, 3.6.2$ 创建和识别

PowerShell：

```powershell
New-Item -ItemType SymbolicLink -Path link_name -Target target_path
```

Bash：

```bash
ln -s target_path link_name
```

查看链接指向哪里：

```powershell
Get-Item link_name | Select-Object Target
```

```bash
ls -l link_name
# 输出显示 link_name -> target_path
```

### $\rm \S \, 3.6.3$ 典型用途

- 把某个大目录（如数据集）从位置 A 链接到项目中的方便位置，而不移动或复制原始数据。
- Python 虚拟环境和 Node.js 的 `nvm` 使用符号链接管理当前激活的版本。
- 系统中多个路径需要指向同一动态库的不同版本。

### $\rm \S \, 3.6.4$ inode、硬链接与符号链接的精确区别

每个文件在磁盘上都有一个**inode**（索引节点）——它存储文件的元数据（大小、权限、时间戳、数据块位置），但**不包含文件名**。文件名只是指向 inode 的标签。

```bash
ls -li                    # -i 显示 inode 号
# 123456 -rw-r--r-- 1 alice staff 1024 Aug 10 paper.txt
# ↑ inode                          ↑ 硬链接计数 = 1
```

**硬链接**（hard link）：两个文件名指向**同一个 inode**。删除任何一个文件名，数据仍然存在（只要至少还有一个硬链接指向它）。硬链接不能跨文件系统，不能指向目录。

```bash
ln paper.txt paper_backup.txt    # 创建硬链接
ls -li                           # 两个文件有相同的 inode 号，硬链接计数 = 2
rm paper.txt                     # 删除原文件名——数据仍通过 paper_backup.txt 可访问
```

**符号链接**（symlink / soft link）：是一个**独立的文件**，内容就是"目标路径"这个字符串。删除目标文件后，符号链接仍然存在但指向无效路径（broken link）。

| | 硬链接 | 符号链接 |
|---|---|---|
| 本质 | 同一个 inode 的另一个名字 | 一个"指向路径"的小文件 |
| 跨文件系统 | ❌ | ✅ |
| 指向目录 | ❌ | ✅ |
| 目标删除后 | 数据仍在 | 断链（dangling link） |
| `ls -l` 显示 | 普通文件 | `link -> target` |

### $\rm \S \, 3.6.5$ 原子重命名：为什么 `mv` 是安全的

```bash
mv old_name new_name    # 在同一个文件系统内——这是原子操作
```

在同一个文件系统内，`mv` 只是修改目录项中的文件名指向同一个 inode——不复制数据，不修改 inode 内容，且**不会出现"写到一半崩溃导致新旧文件都不完整"**的情况。这就是为什么很多程序通过"写临时文件→mv 覆盖目标文件"来保证数据完整性。

### $\rm \S \, 3.6.6$ 磁盘满与 inode 满：两种不同的"满了"

```bash
df -h     # 磁盘空间使用——"还有多少 GB"
df -i     # inode 使用——"还能创建多少个文件"
```

一块磁盘的 inode 数量在格式化时固定。如果程序创建了海量小文件（如 `node_modules` 十万个文件），即使磁盘空间还有很多 GB，`df -i` 可能显示 inode 已耗光——此时 `touch newfile` 会报 `No space left on device`，即使 `df -h` 显示还有空间。

```bash
# 诊断：哪个目录 inode 消耗最多
for d in /data/*/; do echo "$(find "$d" | wc -l) $d"; done | sort -rn | head -5
```

## $\rm \S \, 3.7$ 权限：系统凭什么允许或拒绝

你已经能在终端中创建、读取和删除文件。但迟早会遇到：

```text
Permission denied
Access is denied
```

权限回答两个问题：**谁**可以对这个文件做**什么**。

### $\rm \S \, 3.7.1$ Unix/Linux 权限模型

每个文件有三组权限，分别对应三类身份：

```text
-rwxr-xr--  1 alice  staff  4096 Mar 10 14:30 script.sh
 ↑  ↑  ↑
 |  |  其他用户（others）→ r--
 |  所属组（group）    → r-x
 所有者（owner）       → rwx
```

第一个字符表示类型（`-` 普通文件，`d` 目录，`l` 符号链接），接下来每三个字符一组。

每组三个字符的含义：

| 字符 | 含义 |
|---|---|
| `r` | **读**（read）：查看文件内容，列出目录内容 |
| `w` | **写**（write）：修改文件内容，在目录中创建/删除文件 |
| `x` | **执行**（execute）：运行文件（对普通文件），进入目录（对目录） |

如果某个权限被 `-` 替代，表示该身份没有这项权限。

> **对目录来说，`x` 权限特别容易误解**。即使你对一个目录有 `r` 权限（可以列出内容），没有 `x` 权限你也无法 `cd` 进去，也无法访问其中的文件——即使你知道文件名且对该文件有全部权限。可以把目录的 `x` 理解为"允许穿过这道门"。

### $\rm \S \, 3.7.2$ 数字表示法

你经常在教程中看到类似 `chmod 755` 这样的写法。它是把每组三个权限编码为一个 0-7 的数字：

```text
r = 4
w = 2
x = 1

7 = rwx = 4+2+1
6 = rw- = 4+2
5 = r-x = 4+1
4 = r-- = 4
0 = --- = 0
```

`755` 展开就是：

```text
7   = rwx
5   = r-x
5  = r-x
```

常见组合：

| 数字 | 含义 | 典型用途 |
|---|---|---|
| `755` | 所有者全权限，其他人读+执行 | 可执行程序、目录 |
| `644` | 所有者读写，其他人只读 | 普通数据文件 |
| `700` | 仅所有者全权限 | SSH 私钥、个人脚本 |
| `600` | 仅所有者读写 | 敏感配置文件 |

### $\rm \S \, 3.7.3$ 修改权限

```bash
# 符号模式（推荐初学使用——意图更明确）
chmod u+x script.sh     # 给 owner 加执行权限
chmod g-w data.txt      # 去掉 group 的写权限
chmod o-rwx secret.key  # 去掉 others 的全部权限

# 数字模式
chmod 755 script.sh
chmod 600 ~/.ssh/id_rsa
```

修改所有者（通常需要管理员权限）：

```bash
chown alice:staff file.txt
```

### $\rm \S \, 3.7.4$ Windows 权限模型

Windows 使用更细粒度的 ACL（Access Control List）系统，但日常开发中最常见的情况类似：

- 程序试图写入 `C:\Program Files\` 或系统目录时被拒绝（需要管理员权限）。
- 文件被另一个程序锁定打开时，其他程序无法写入。

PowerShell 中查看文件权限用：

```powershell
Get-Acl file.txt | Format-List
```

**Windows 和 Linux 权限模型不可直接互相翻译**。不要试图用 Linux 的 `rwx` 思维去理解 Windows ACL。在跨平台开发中，关键是理解"操作被拒绝"的大类原因（权限不足 / 文件被占用 / 路径不存在），并在各自系统中用相应的工具收集证据。

### $\rm \S \, 3.7.5$ 排查"Permission denied"的标准流程

这是你从 OJ 进入开发后，第一个真正独立的排障模式。遇到拒绝访问时，不要立即尝试管理员权限，而是按顺序收集证据：

```mermaid
flowchart TD
    A["Permission denied"] --> B["ls -l target<br/>文件是否存在？"]
    B -->|不存在| C["路径拼写错误<br/>或当前目录不对"]
    B -->|存在| D["whoami<br/>我是谁？"]
    D --> E["ls -l 的第三列是我吗？"]
    E -->|是| F["检查 rwx：缺哪个？<br/>chmod 补上"]
    E -->|否| G["我是 group 成员吗？"]
    G -->|是| H["检查中间一组 rwx<br/>缺哪个补哪个"]
    G -->|否| I["看最后一组 other 权限<br/>没有 → 请所有者或管理员授权"]
    F --> J["目录是否有 x？<br/>没有 x → 无法 cd 进去"]
    H --> J
    I --> K["确认原因后再提权<br/>不要先 sudo"]
```

> **记一个实用命令**：`stat` 比 `ls -l` 输出更详细（inode、块数、最后访问时间），`namei -l /path/to/file` 逐级解析路径中每一层目录的权限。排查深层目录权限问题时这两个命令可以省你很多时间。

1. **确认文件/目录是否存在**：`ls -l target` 或 `Test-Path target`
2. **确认当前身份**：
   ```bash
   whoami       # Bash
   ```
   ```powershell
   whoami       # PowerShell 同样可用
   ```
3. **查看文件权限和所有者**：
   ```bash
   ls -l target       # Bash — 输出前三列是权限、硬链接数、所有者、组
   stat target        # 更详细：inode、块数、时间戳
   ```
   ```powershell
   Get-Acl target | Format-List   # PowerShell
   ```
4. **判断问题类别**：
   - 自己是所有者但有 `r--` 而没有 `w` → 去掉写保护或加写权限
   - 自己不是所有者、other 没有权限 → 需要所有者或管理员授权
   - 目录没有 `x` 权限 → 即使文件有权限也无法访问
   - 父目录没有相应权限 → 即使子文件有权限也会被拦住
   - 逐级排查深层路径：`namei -l /a/b/c/d/file` 一眼看到哪一层断了
5. **只有在确认了原因之后**，再决定是否需要提权、修改权限或更改路径。

## $\rm \S \, 3.8$ 管理员与 root：一把需要理由的钥匙

### $\rm \S \, 3.8.1$ 它们是什么

- **Windows 管理员**（Administrator）：完整控制系统的账户。即使用户是管理员，Windows 默认也不以管理员权限运行程序——这是 UAC（用户账户控制）机制。
- **Linux root**：用户 ID 为 0 的超级用户，可以绕过几乎所有权限检查。

### $\rm \S \, 3.8.2$ 什么时候确实需要提权

- 安装系统级软件（如编译器、驱动、系统服务）；
- 修改 `C:\Program Files\`、`/etc/`、`/usr/`、`/opt/` 等系统目录；
- 绑定小于 1024 的端口（Linux 传统限制）；
- 修改系统配置、启用服务。

### $\rm \S \, 3.8.3$ 什么时候绝对不要用提权来解决

- 文件在你自己目录下却提示权限不足 → 检查文件当前的权限和所有者，可能是复制时带过来的限制；
- Git 操作提示权限问题 → 通常是 SSH key 权限太松或仓库文件所有者不对；
- `npm install` / `pip install` 提示权限 → 用项目级安装而非全局安装，或使用虚拟环境；
- 程序提示"端口被占用" → 找到占用者，而不是用 root 强绑定。

> **经验规则**：如果你说不清为什么需要管理员权限，就不要用。先用普通用户排查。能用普通用户解决的问题，永远不要用管理员解决——管理员权限会掩盖权限配置错误，并让一个拼写错误可能具有删除系统文件的破坏力。

## $\rm \S \, 3.9$ 不同系统的换行符：一个看不见的差异

这是跨平台开发中最隐蔽的问题之一。[计算机程序与开发全景](../01-基础观念/01-计算机程序与开发全景.md)中提过"换行格式：Windows 常见 CRLF，Linux 常见 LF"，这里再具体一点。

### $\rm \S \, 3.9.1$ 行是怎么结束的

当你按下回车键，编辑器和操作系统会在文本中插入一个看不见的"换行记号"。不同系统的默认记号不同：

| 系统 | 记号 | 转义表示 | 可见名称 |
|---|---|---|---|
| Windows | CR + LF | `\r\n` | 回车 + 换行 |
| Linux/macOS (现代) | LF | `\n` | 换行 |
| macOS (极早版本) | CR | `\r` | 回车 |

在 C++ 中你用过 `'\n'`，它被标准库翻译为当前平台的换行约定（文本模式下）。但当你从网上下载一个文件、从 Git 克隆一个仓库、或者在不同系统间移动文件时，换行符可能被保留为原始形式。

### $\rm \S \, 3.9.2$ 出问题时的症状

- 在 Windows 记事本中打开 Linux 文件，所有内容挤在一行；
- 在 Linux 终端中 `cat` 一个 Windows 文件，每行末尾出现 `^M`（即 `\r` 的可视化表示）；
- Git diff 显示"整个文件都改了"，实际上只是换行符变了；
- Shell 脚本在 Windows 编辑后上传到 Linux 执行时报 `\r: command not found`。

### $\rm \S \, 3.9.3$ 如何发现和解决

[文本、编码、压缩包与常见数据格式](05-文本编码压缩包与数据格式.md)会展开讲文本编码的完整排查。这里先给一个最小检查方法——在 PowerShell 中查看文件是否包含 `\r\n`：

```powershell
# 查看文件前几个字节的十六进制表示
Get-Content file.txt -AsByteStream -TotalCount 20
# 如果有 0x0D 0x0A 连续出现，那就是 CRLF
```

Git 可以在提交时自动转换换行符（通过 `core.autocrlf` 配置），这个配置会在[Git与团队协作](../05-开发工作流/17-Git与团队协作.md)一章讲到。现在只需要知道：**不同系统的换行符不同，这是正常的，有工具可以处理，不需要手动逐行修改。**

## $\rm \S \, 3.10$ 常见错误及其证据

### $\rm \S \, 3.10.1$ "明明文件在，终端说找不到"

**最可能的原因（按频率排序）**：

1. **当前目录不是你想象的那个**。解决：先执行 `pwd` 或 `Get-Location`。
2. **相对路径写错了层级**。解决：用 `ls` 或 `Get-ChildItem` 逐级验证路径中的每个目录都存在。
3. **文件名拼写或大小写问题**。Linux 区分大小写，`Readme.md` ≠ `README.md`。解决：`ls` 确认精确文件名。
4. **扩展名被 Windows 资源管理器隐藏了**，实际文件名多了 `.txt`。解决：在资源管理器的"查看"选项卡中勾选"文件扩展名"显示完整文件名——这就是[3.4.2 节](#342-windows-常见陷阱隐藏已知扩展名)讲的陷阱。
5. **程序在 PATH 中找不到，而你没有写 `./`**。当前目录通常不在 PATH 中，运行当前目录下的程序要写 `./app`——[终端、Shell与命令行](02-终端Shell与命令行.md#261-为什么当前目录中的程序常写-app)的 2.6.1 节详细讲过。

### $\rm \S \, 3.10.2$ "Permission denied"

排查流程见[3.7.5 节](#375-排查permission-denied的标准流程)。补充一个常见变种：目录的 `x` 权限缺失。即使你对 `/home/alice/data/file.txt` 有读写权限，如果 `/home/alice/data` 目录没有 `x` 权限，你连目录都进不去。

### $\rm \S \, 3.10.3$ "文件被另一个程序占用"（Windows 特有）

症状：尝试写入或删除一个文件，提示"文件正在使用中"。

证据收集：

```powershell
# 查看哪些进程正在使用某个文件（需要管理员权限）
# 如果没有管理员权限，先判断是不是自己打开了它（编辑器、终端等）
```

有时候最常见的"占用者"是你自己——你在编辑器中打开着这个文件，或者在另一个终端窗口中运行着使用该文件的程序。

## $\rm \S \, 3.11$ 动手实践

在一个新建的安全目录中完成。所有操作不会影响系统和其他项目。

### 实践一：绝对路径 vs 相对路径

1. 在任意位置创建一个新目录 `path-lab` 并进入。
2. 在 `path-lab` 中创建子目录 `src` 和 `data`。
3. 在 `data` 中创建一个文件 `input.txt`，写入任意内容。
4. 从 `src` 目录出发，用相对路径 `../data/input.txt` 查看文件内容。
5. 切换到完全不同的目录（比如用户主目录），用 `path-lab` 的绝对路径再次查看 `input.txt`。
6. 记录：哪种情况下相对路径更短？哪种情况下绝对不会找错？

### 实践二：通配符

1. 创建 `test_1.txt`、`test_2.txt`、`test_10.txt`、`demo.txt`、`test_backup.bak`。
2. 用 `ls test_?.txt`（Bash）或 `Get-ChildItem test_?.txt`（PowerShell）观察 `?` 匹配了哪些、漏掉了哪个。
3. 用 `*.txt` 和 `*.bak` 分别观察 `*` 的行为。
4. 先在安全目录中反复练习，不要在其他目录运行带通配符的删除命令。

### 实践三：权限（参考 [3.7.1 节](#371-unixlinux-权限模型)至 [3.7.3 节](#373-修改权限)理解模型即可）

1. 创建一个文件 `secret.txt`，写入内容。
2. 运行 `ls -l secret.txt` 记录初始权限。
3. 用 `chmod 600 secret.txt` 改为仅所有者可读写。
4. 用 `chmod 000 secret.txt` 去掉所有权限，尝试 `cat secret.txt`，观察错误信息。
5. 用 `chmod 644 secret.txt` 恢复，确认可以正常读取。
6. 创建一个子目录并去掉其 `x` 权限，尝试 `cd` 进去——观察即使有 `r` 权限也无法进入。

### 实践四：制造并诊断"找不到文件"

1. 在 `path-lab` 中，先 `cd src`。
2. 尝试 `cat input.txt`（不写路径前缀）。观察错误。
3. 用相对路径 `../data/input.txt` 成功访问。
4. 回到上一级目录 `cd ..`，再次尝试刚才失败的命令——现在成功了。解释为什么。

## $\rm \S \, 3.12$ 总结

本章和[终端、Shell与命令行](02-终端Shell与命令行.md)加在一起，给了你完整的"文件系统操作能力"：

- **文件系统是目录树**（Windows 多棵树，Linux 一棵树），根目录是所有绝对路径的起点。
- **绝对路径从根出发，相对路径从当前目录出发**。`..` 和 `.` 是构建相对路径的积木。
- **隐藏文件的存在机制不同，但都用于"默认不打扰"**。排查配置问题时记得它们。
- **扩展名是约定**。Windows 隐藏扩展名是导致"文件明明在这里却不被识别"的常见原因。
- **通配符帮你批量指定文件**，但执行修改/删除命令前先用只读命令确认匹配了哪些文件。
- **符号链接是文件系统级指针**，不是副本。删除链接不等于删除目标。
- **权限控制"谁可以对什么做什么"**。目录的 `x` 权限决定能否进入——这是最常见的误判点。
- **管理员/root 是最后手段，不是第一反应**。先确认文件是否存在、所有者是谁、权限是什么、父目录权限是否正常。

## $\rm \S \, 3.13$ 关键概念回顾

1. Windows 和 Linux 的根目录表示有什么不同？为什么？
> Windows 每个盘符有自己的根（C:\、D:\，形成"森林"）；Linux/macOS 所有存储设备挂载到唯一根 `/` 之下，所以只有一棵树。

2. 绝对路径和相对路径分别从什么位置开始解释？
> 绝对路径从根目录（Windows 的盘符根、Unix 的 `/`）出发，任何位置下都指向同一目标；相对路径从当前工作目录出发。

3. 通配符 `*` 和 `?` 分别匹配什么？通配符和正则表达式是一回事吗？
> `*` 匹配任意长度的任意字符，`?` 匹配恰好一个任意字符；不是一回事——Shell 通配符是 glob 模式，`grep`/`sed` 用的是正则表达式（其中 `*` 表示"重复前一个模式"）。

4. Linux 文件权限 `-rwxr-xr--` 中，所有者、组和其他用户的权限分别是什么？数字 755 对应的权限是什么？
> 所有者 rwx（读写执行）、所属组 r-x（读+执行）、其他用户 r--（只读）；755 = 所有者 rwx、组 r-x、其他用户 r-x。

5. 为什么对目录没有 `x` 权限就无法 `cd` 进去，即使你有 `r` 权限且知道里面文件的名字？
> 目录的 `x` 权限决定能否"穿过这道门"——进入目录、访问其中任何文件都需要它；`r` 只允许列出内容。

## $\rm \S \, 3.14$ 应用与辨析

6. 当前目录是 `/home/alice/projects`，写出访问 `/home/alice/data/file.txt` 的相对路径。
> `../data/file.txt`：先 `..` 到上一级 `/home/alice`，再进入 `data` 目录。

7. 在 Linux 上怎样让 `ls` 显示隐藏文件？
> `ls -a`（连 `.` 和 `..` 一起显示）或 `ls -A`（显示隐藏文件但不含 `.` 和 `..`）。

8. Windows 资源管理器隐藏扩展名会造成什么具体问题？
> 你看到的文件名不是完整名称：手动把"新建文本文档"改名为 `data.json` 后实际是 `data.json.txt`，程序按错误的类型处理文件导致"不识别"。

9. 符号链接和复制文件有什么区别？
> 符号链接是文件系统级指针，删除链接不删除目标，目标移动或删除后链接悬空；复制会创建独立的第二份数据，之后两者互不影响。

10. 遇到 "Permission denied" 时，应该按什么顺序收集证据？
> 确认文件/目录存在（`ls -l`）→ 确认当前身份（`whoami`）→ 查看权限和所有者（`ls -l`/`stat`/`Get-Acl`）→ 判断缺哪个权限、逐级检查父目录的 `x` → 确认原因后再决定是否提权。
