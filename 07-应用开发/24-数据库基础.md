# $\rm Chapter \,  24$ 数据库日常使用：连接、迁移与运维

> [上一章](23-SQL从零开始.md)让你在 SQLite 中写出了能用的 SQL。你把 `papers.db` 文件发给队友，队友的程序却读不到你刚插入的数据——你们两个人同时往同一个 `.db` 文件写数据时，SQLite 只允许一个写者，后写的人直接报错。更糟的是，你没法给队友的账号设置"只允许读论文、不允许删论文"的权限——任何能打开这个文件的人都能随意 `DELETE FROM papers`。这些问题都不是 SQL 语法的错，而是**文件数据库**的物理限制。真实项目中用一个独立的数据库服务进程来解决——客户端通过网络连接到它，服务进程统一管理并发写入和用户权限。这一章从 SQLite 过渡到 PostgreSQL。

## $\rm \S \, 24.1$ SQLite vs PostgreSQL：文件数据库 vs 服务数据库

### $\rm \S \, 24.1.1$ SQLite：零配置但单机

SQLite 不需要安装服务器——它就是一个 C 库，程序编译时链接它。数据库是一个文件（如 `papers.db`），你的程序直接用文件路径打开。

**适合**：移动 App（iOS/Android 都内置 SQLite）、桌面软件（VS Code 用 SQLite 存设置）、单机数据分析、原型开发。

**不适合**：多个进程同时写同一个数据库（SQLite 只支持一个写者）、需要细粒度权限控制、需要通过网络访问。

### $\rm \S \, 24.1.2$ PostgreSQL：独立服务进程

PostgreSQL（通常叫 Postgres）是一个**客户端-服务器数据库管理系统**。它作为后台服务进程运行（和[日常系统管理：软件、用户、服务与日志](../03-计算机系统/11-系统服务日志与软件安装.md)中学过的 systemd 服务是同一个模型），监听某个端口（默认 5432），等待客户端连接。

```bash
# 安装并启动 Postgres
sudo apt install postgresql           # Ubuntu/Debian
sudo systemctl enable --now postgresql  # 开机自启 + 立即启动
systemctl status postgresql           # 确认正在运行
```

### $\rm \S \, 24.1.3$ 什么时候该从 SQLite 迁移到 Postgres

| 情况 | SQLite | Postgres |
|---|---|---|
| 单用户、单机 | ✅ | ✅（重了些） |
| 多人同时写 | ❌（一次一个写者） | ✅ |
| 需要用户权限隔离 | ❌ | ✅ |
| 数据量 > 几百 GB | 可能 | ✅ |
| 生产 Web 应用 | 不适合 | ✅ |
| 需要 JSON/全文搜索/地理空间等高级功能 | 有限 | ✅ |

## $\rm \S \, 24.2$ 连接数据库：客户端、驱动与连接字符串

### $\rm \S \, 24.2.1$ 三种连接方式

1. **命令行客户端**：`psql`（Postgres）、`sqlite3`（SQLite）——人在终端中手动执行 SQL。
2. **图形客户端**：**DBeaver**（dbeaver.io，免费开源）、**TablePlus**（tableplus.com，macOS/Windows）、**pgAdmin**（Postgres 官方 Web GUI）、**DataGrip**（JetBrains 出品，付费）。这些让你浏览表结构、可视化查询结果、导出数据。
3. **应用程序**：你的 Python/C++ 代码通过**数据库驱动**连接。

### $\rm \S \, 24.2.2$ 连接字符串

无论哪种方式，连接到数据库都需要一组参数——**连接字符串**把它们编码成一个 URI 格式：

```text
postgresql://alice:<密码>@db.example.com:5432/paperdb
             ↑      ↑              ↑               ↑    ↑
             用户名 密码（不写明文）  主机            端口  数据库名

sqlite:///home/alice/projects/papers.db
         ↑
         本地文件路径（SQLite 不需要用户名密码主机）
```

**密码不能出现在源码中**——用环境变量（回顾[日常系统管理：软件、用户、服务与日志](../03-计算机系统/11-系统服务日志与软件安装.md)中的配置管理）：

```python
import os
DATABASE_URL = os.environ["DATABASE_URL"]  # 从环境变量读取，不在代码中写密码
```

## $\rm \S \, 24.3$ 数据库迁移：让表结构随代码演进

### $\rm \S \, 24.3.1$ 问题

你的第一版 `papers` 表只有 `title`、`year`、`citations`。第二版你想加入 `abstract` 字段和 `doi` 字段。你怎么更新生产数据库中已有的表结构？

手动 `ALTER TABLE papers ADD COLUMN abstract TEXT` 的问题：你的队友不知道你加了这个字段（他们本地的表结构还是旧的）；你不知道这个字段在三个月前是第几次迁移加的；回滚时你不知道怎么撤销。

### $\rm \S \, 24.3.2$ 迁移工具

**迁移**（migration）是"一次对数据库结构的变更，记录在一个带编号的脚本中"：

```sql
-- 001_create_papers.sql
CREATE TABLE papers (id SERIAL PRIMARY KEY, title TEXT, year INT);

-- 002_add_abstract.sql
ALTER TABLE papers ADD COLUMN abstract TEXT;
ALTER TABLE papers ADD COLUMN doi TEXT UNIQUE;

-- 003_add_tags.sql
CREATE TABLE tags (...);
```

迁移脚本按顺序编号，**永远向前追加，不修改已有迁移**。每个开发者本地跑同样的迁移序列，生产环境也跑同样的序列——数据库结构在任何环境中完全一致。

Python 生态中 **Alembic**（配合 SQLAlchemy）是最常用迁移工具。Node.js 有 **Knex.js** migrations。Go 有 **golang-migrate**。

## $\rm \S \, 24.4$ 备份与恢复：不是"复制文件就行"

### $\rm \S \, 24.4.1$ SQLite 的简单备份

```bash
# SQLite：备份就是复制文件（但必须在没有写操作时复制）
sqlite3 papers.db ".backup papers_backup.db"

# 或导出为 SQL 文本
sqlite3 papers.db .dump > backup.sql
```

### $\rm \S \, 24.4.2$ PostgreSQL 的逻辑备份

```bash
# 导出整个数据库为 SQL 文本
pg_dump paperdb > backup.sql

# 导出为自定义格式（可压缩、可并行恢复）
pg_dump -Fc paperdb > backup.dump

# 恢复
psql paperdb < backup.sql
pg_restore -d paperdb backup.dump
```

### $\rm \S \, 24.4.3$ 备份不是"存了就安全"

- **备份需要定期测试恢复**。一个从未被恢复过的备份可能已经是损坏的——你只是不知道而已。
- **开发/测试/生产数据库必须分开**。不要用生产数据做开发测试（脱敏后可以）。
- **备份文件包含所有数据**——备份文件的权限应设为 `600`（只有所有者可读写），不要放在可通过 Web 访问的目录下。

## $\rm \S \, 24.5$ 常见故障排查

### $\rm \S \, 24.5.1$ "连接被拒绝"

```bash
psql -h db.example.com -U alice paperdb
# psql: error: connection to server at "db.example.com", port 5432 failed: Connection refused
```

排查步骤（回顾[域名、HTTPS、代理与排障](../04-网络/22-域名HTTPS代理与排障.md)中的分层排障框架）：
1. Postgres 服务是否在运行？`systemctl status postgresql`
2. 是否监听正确的端口？`ss -tlnp | grep 5432`
3. 是否监听外部连接？Postgres 默认只监听 `localhost`——需要修改 `pg_hba.conf`
4. 防火墙是否拦截？`sudo ufw status`

### $\rm \S \, 24.5.2$ "权限不足"

```bash
# psql: error: FATAL: role "alice" does not exist
```

Postgres 的用户系统和操作系统用户是分开的。创建 Postgres 用户：
```sql
CREATE USER alice WITH PASSWORD 'secure_password';
GRANT ALL PRIVILEGES ON DATABASE paperdb TO alice;
```

### $\rm \S \, 24.5.3$ "表不存在"

可能的原因：连接到了错误的数据库（`\c paperdb` 切换数据库）；表名拼写错误（Postgres 把未加引号的表名转为小写）；或者迁移脚本还没执行。

## $\rm \S \, 24.6$ 动手实践

### 实践一：从 SQLite 迁移到 Postgres

1. 安装 Postgres，创建 `paperdb` 数据库。
2. 用 `psql` 连接，创建和 SQLite 练习中相同的表结构。
3. 写一个 Python 脚本，从 SQLite 的 `.db` 文件中读取数据，写入 Postgres。
4. 验证数据完整性和行数一致。

### 实践二：模拟备份恢复

1. 向 `papers` 表插入 10 条数据，记录行数。
2. 用 `pg_dump` 备份。
3. 删除 3 条数据，假装是误删。
4. 用 `psql` 恢复备份，确认恢复到了 10 条。

### 实践三：排查连接问题

1. 故意用错误的端口号连接 Postgres，观察错误信息。
2. 故意用不存在的用户名连接，观察错误信息。
3. 用[域名、HTTPS、代理与排障](../04-网络/22-域名HTTPS代理与排障.md)中的分层排查框架，从 TCP 层→用户认证层分别测试。

## $\rm \S \, 24.7$ 总结

- SQLite 是嵌入式文件数据库——零配置、单机、不适合并发写入。Postgres 是客户端-服务器数据库——独立服务进程、多用户、细粒度权限。
- 连接数据库需要驱动（代码层面）和连接字符串（包含主机、端口、用户名、密码、数据库名）。
- 数据库迁移是"按编号顺序管理表结构变更"。永远向前追加，不修改已有迁移。
- 备份必须定期测试恢复。开发/测试/生产数据库必须分离。

## $\rm \S \, 24.8$ 关键概念回顾

1. SQLite 和 PostgreSQL 在架构上的核心区别是什么？
> SQLite 是嵌入式文件数据库——程序直接读写 `.db` 文件，无独立服务进程。PostgreSQL 是客户端-服务器数据库——作为 systemd 管理的独立服务进程运行，客户端通过网络连接。

2. 连接字符串中通常包含哪些字段？哪些不应该出现在源码中？
> 主机、端口、用户名、密码、数据库名。密码和用户名不应该硬编码在源码中——从环境变量读取。

3. 数据库迁移解决的核心问题是什么？
> 保证表结构变更有序、可溯源、可复现——所有环境（开发、测试、生产）的数据库结构从同一套迁移脚本中生成，不会出现"我本地有这个字段但生产没有"。

4. 备份和导出有什么区别？备份的恢复为什么需要实际演练？
> 导出通常是逻辑层面的数据副本（SQL 文本）；备份可能是物理层面的完整快照。备份文件可能损坏、权限错误或格式不兼容——只有实际恢复一次才能确认备份有效。

## $\rm \S \, 24.9$ 应用与辨析

5. Python 脚本连接 Postgres 时报 `FATAL: role "alice" does not exist`，可能的原因是什么？
> Postgres 的用户系统和操作系统用户独立——需要在 Postgres 内部用 `CREATE USER` 创建角色，并 `GRANT` 相应权限。

6. 团队中两个人各自在本地给 `papers` 表加了不同的字段，都试图部署到生产环境。迁移工具如何防止混乱？
> 迁移脚本按编号顺序执行。如果两人各自创建了 `003_xxx.sql`，合并时会冲突——需要手动协调编号，确保所有环境的迁移序列一致。

7. `pg_dump` 在备份时数据库可以正常接受写入吗？
> 可以——PostgreSQL 支持在线备份（不阻塞读写）。但备份反映的是备份开始时刻的快照，开始后的写入不会出现在这个备份中。
