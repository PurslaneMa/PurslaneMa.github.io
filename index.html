初心

这个站最早只有一门课：2026 年整理吴翼老师的《深度学习》时，我把讲义逐页改写成不跳步的教材——这就是现在的深度学习分册。改写的过程中我确认了一件事：对有竞赛背景的读者，缺的从来不是资料，而是把动机讲清、把前置补齐、不指望读者去猜的成体系教材。课程默认你会的东西、一笔带过的推导、只给结论不给来路的「重要结论」，才是自学断线的真正原因。

于是我把同一套写法扩展到系统、数学与其他方向，长成了现在的一整站书目。它写给两类读者：想补全计算机系统与数学地基的竞赛生，以及愿意从第一阶段按顺序读起的零基础读者。全部内容免费；在服务器版登录后，还可以跨设备保存进度、逐节问 AI，并把章末习题的作答交给 AI 苏格拉底式批改——先判定对错，再用引导问题让你自己补全，不直接发参考答案。

设计理念

  1. 动机先行：每个概念出场前先讲清它要解决什么问题；在这个阶段用不到的知识点不出现。
  2. 不跳步：假设的前置要么当场补齐，要么给出回读位置；推导给全，不写「显然可得」。
  3. 题答分离：章首自检框、章末「应用与辨析」、复习章的交错练习都把题目和答案分开，闭卷作答后再核对；线上版可以逐题提交作答、由 AI 批改。
  4. 比喻统一：全书共用一套比喻（PATH＝地址簿、进程＝演出、Git 提交＝快照、镜像＝只读模板），不在各章另起炉灶。
  5. 先跑后写：正文里的实验数字都先真实跑出来再落章，固定随机种子、可复现；教学用的数据形态先验证它真的能产生要讲的现象。
  6. 接住竞赛直觉：能映射到已有竞赛技能的概念都点明映射——GF(2⁸) 乘法＝技能换个名字、KMP＝DFA、树形 DP＝树宽为 1 的 Courcelle 定理。

维护方法

这一节写给未来的维护者（首先是我自己）：改一章、加一本书、发一次版的动作都有固定路径。

  1. 改章节：各学科目录（NN-学科/）下的 Markdown 就是正文本体。写作规范看仓库根的 CLAUDE.md，流程速查看 维护手册.md；改完跑校验链（标题编号、lint_math.py 公式检查、「AI 味」扫描）再交付。
  2. 加书目：curriculum.yml 是章节数据的唯一来源，侧栏、顶栏、进度都从它派生；新学科要在 curriculum.yml、reader.html 的 BOOKS/PHASES 登记表与徽章 CSS 三处登记，并同步「学习地图」与 README 状态区。
  3. 发版本：build-pages.py 生成静态站（含缓存指纹），deploy-server.sh 一键发布到服务器；GitHub Pages 由快照仓库的 Actions 自动发布。改了 reader.html 必须重跑 build-pages，否则浏览器缓存旧脚本。
  4. 账号与 AI 后端：reader-api/app.py 是纯标准库单文件（账号、进度、逐节问答、习题批改），问答与批改共用每日额度，用户可在设置里填自己的 API Key 不限次；更新后端＝上传 app.py 并重启服务。
  5. 本页文案：直接写在 reader.html 的首页区块里（本段也是），改完重新构建部署即生效。
