全册的心智模型是把句子变成机器可计算的语义。到这里可以对「可计算」提出最严格的要求了：语义解析（semantic parsing）要求句子的输出不是向量、不是真值，而是一段能直接执行的程序，最常见的是一条 SQL。用户说「列出 2020 年之后 GPU 领域的论文」，程序的回答不是「这句话大概在问数据库」，而是把一句结构正确的查询交给数据库执行，把查出来的行原样递回去。第 1 章已经搭过同一条流水线的雏形：小文法把句子确定性地翻译成一阶逻辑公式，再在世界模型上算真假（§1.6）。本章把目标表示从逻辑式换成 SQL，把验收从真假判定换成执行对账，然后正面回答一个第 1 章末尾留下的路线问题：组合式规则与神经 seq2seq（《深度学习》§13.1）到底各赢在哪里。两条路线都会真跑：组合式解析器从零写出，seq2seq 用规则模拟其思想成分并在正文里标明模拟口径，所有数字先跑后写。

## $\rm \S \, 7.1$ 任务：答案不在句子里，在数据库里

先把任务钉死。给定一句自然语言问句和一个数据库，语义解析器要输出一条可执行的形式表示；对查询类任务，这个表示通常是一条 SQL。它与第 1 章的差异只在目标表示一端：组合机制（§1.5 的规则加方案）原样沿用，输出从一阶逻辑公式换成 SQL 语句；第 1 章把公式交给世界模型算真假，本章把 SQL 交给数据库引擎执行，取回的行就是答案。任务的难点也因此换了个方向。第 1 章的难点是「半个句子也得是合法的值」，靠 lambda 演算解决（§1.3）；本章的难点是表层与语义的数量差：同一句意思有无穷多种说法、多种语序，而正确的 SQL 往往只有一条。把 864 种问法映射到 54 条查询，是多对一的翻译。

验收口径也因此要两个，它们在本章实测里会分道扬镳，所以现在就定义清楚。精确匹配（exact match）要求解析器输出的字符串与金标 SQL 逐字符相同。执行准确率（execution accuracy）只要求两条 SQL 在同一数据库上执行出相同的结果行，字符串本身可以不同。两个口径各抓一种错：精确匹配对「子句顺序不同但结果相同」这类无害差别会误报，执行准确率对「碰巧同结果的错误查询」会漏报；工程上通常以执行准确率为准，因为用户要的是答案，不是字符串。这和 §6.5 的探针方法论是同一个精神：输出必须每一步可核对，核对的口径要在看读数之前定好。

实验的靶子是论文资料管理器的数据库（贯穿示例在《信息检索》§8.1 里长成了检索库，这里取它的最小形态）：一张 16 行的 papers 表，字段为标题、年份、标签、被引。问句空间由四个特征组合而成：句型 3 种（列出、有几篇、被引最多的是哪篇），年份条件 6 种（2019、2020、2021 三档乘以之前、之后两个算子），标签 3 种（数据库、GPU、NLP），语序 2 种（年份条件在前，或标签条件在前）。四个特征相乘，语义组合空间是 ${3 \times 6 \times 3 \times 2 = 108}$ 句，对应 54 条不同的 SQL：语序不改变 SQL，所以句子数是 SQL 数的两倍。玩具语言与第 1 章同一口径：电报体、按空格分词，例如「列出 2020 年之后 GPU 论文」与倒装的「列出 GPU 、 2020 年之后 的 论文」。

## $\rm \S \, 7.2$ 组合式路线：把第 1 章的施工图接到数据库上

组合式路线的配方在第 1 章已经备齐，这里只做替换。§1.5 的七条组合方案管的是「逻辑式怎么拼」，本章的八条规则管的是「SQL 怎么拼」，思想相同：每条句法规则配一条固定的组装动作，语义沿推导树自底向上成形。先看词库与规则的全貌：

| 类别 | 词条 | 对 SQL 的贡献 |
| --- | --- | --- |
| 句型 | 列出、有几篇、被引最多的是哪篇 | SELECT 子句；第三种附 ORDER BY 尾缀 |
| 数值 | 2019、2020、2021 | 谓词里的比较常数 |
| 算子 | 年之前、年之后 | 比较符 < 与 > |
| 标签 | 数据库、GPU、NLP | 等值谓词 |
| 虚词 | 论文、的、、 | 不进 SQL，只参与切分 |

规则 8 条，写成推导的样子是：

1. S → 句型 条件组 NP：取句型的 SELECT 子句，条件组产出 WHERE 子句，NP 消掉。
2. 条件组 → 条件；条件组 → 条件 条件组；条件组 → 条件 、 条件组：条件短语一或两个，中间有无顿号都收。
3. 条件 → 数值 算子：产出「年份 < 2019」这样的比较谓词。
4. 条件 → 标签：产出「标签 = 'GPU'」。
5. NP → 论文；NP → 的 论文：句尾名词短语，无语义贡献。

关键的一条组装纪律是：WHERE 子句里的谓词按固定次序（年份在前、标签在后）拼接，与它们在句子里的表面顺序无关。这就是施工图的作用（§1.5 的比喻沿用）：推导树负责把零件从句子里拆出来，SQL 的形状由组装方案决定，不由零件的出现顺序决定。两种语序的句子于是汇入同一条输出：

```text
输入: 列出 GPU 、 2020 年之后 的 论文
句型: 列出            -> SELECT 标题 FROM papers
条件: 标签 = 'GPU' ；年份 > 2020   （表层顺序：标签在前）
输出: SELECT 标题 FROM papers WHERE 年份 > 2020 AND 标签 = 'GPU';
```

解析器的核心代码不长，值得看清楚「语义与语序无关」落在哪一行：

```python
def parse_A(toks, lex, rules):
    qt, year, tag, i = toks[0], None, None, 1
    while i < len(toks):                      # 自左向右扫，收集零件
        t = toks[i]
        if t in lex["val"] and toks[i+1] in lex["op"]:
            year = (t, toks[i+1]); i += 2     # 数值+算子 -> 年份谓词
        elif t in lex["tag"]:
            tag = t; i += 1                   # 标签 -> 等值谓词
        elif t in lex["glue"]:
            i += 1                            # 虚词丢弃
        else:
            return None                       # 词库外的 token：解析失败
    head, tail = QT_ALL[qt]                   # 句型决定 SELECT 与尾缀
    preds = ["年份 %s %s" % (OP_SQL[year[1][1:]], year[0]),
             "标签 = '%s'" % tag]             # 固定次序，与表层语序无关
    return head + " WHERE " + " AND ".join(preds) + \
           (" " + tail if tail else "") + ";"
```

词库外的词当场拒绝，这一点和 §1.4 的类型检查是同一哲学：先查形状再执行，错误在入口暴露，而不是在数据库里静默出错。代价也提前看清：这 14 个词条、8 条规则只认识一种写法的每个零件，用户换个说法（「以前」替换「之前」，「GPU 领域」替换「GPU」）就出门左转解析失败。这个代价多大、怎么量，下一节算账。

把一句倒装问句完整走一遍，看八条规则怎么接力。输入「有几篇 NLP 、 2021 年之后 的 论文」：

1. 规则 1 选句型：首 token「有几篇」命中句型词库，取出 SELECT 骨架「SELECT COUNT(\*) FROM papers」，无尾缀。
2. 规则 2 起收集条件组：扫到「NLP」，后面跟的是「、」不是数值，按规则 4 记等值谓词「标签 = 'NLP'」。
3. 「、」命中虚词，丢弃；继续按规则 2 收集。
4. 扫到「2021」且下一个 token 是算子「年之后」，按规则 3 记比较谓词「年份 > 2021」。
5. 「的」丢弃，「论文」按规则 5 消掉句尾；条件组齐两个，收口。
6. 组装：谓词按固定次序（年份在前）接上 WHERE，输出「SELECT COUNT(\*) FROM papers WHERE 年份 > 2021 AND 标签 = 'NLP';」。

六步里没有一步看句子的表面语序：步骤 2 先收标签、步骤 4 才收年份，输出次序却由组装方案定死。同一句换成规范语序「有几篇 2021 年之后 NLP 论文」，六步的次序变、产出不变。这就是「施工图吸收语序」在代码里的样子。

### $\rm \S \, 7.3.1$ 设置与运行

实验程序在 WSL（Linux）里跑，当前目录 `26Fall/_uni5_work/expNU07/`，前置条件只有 python3（标准库，sqlite3 用于执行对账）。运行命令把标准输出全量重定向进结果文件：

```bash
python3 expNU07.py > result.txt   # 成功标志：退出码 0，result.txt 非空
```

程序自己数出的空间规模是后面一切账目的底座，输出前三行原样抄录：

```text
== expNU07 语义解析对照实验 ==
种子: 20261110   论文库: 16 行   语义组合空间: 108 句 / 54 条不同 SQL
表层形态账: 3 个槽位各有规范/变体 2 种说法 -> 形态类 2^3 = 8 -> 全空间 864 句 (SQL 仍 54 条)
```

固定种子 20261110，总耗时 0.033 秒。测试集两个：T1 从 108 句语义空间抽 40 句（规范语序 17、倒装语序 23），每个口径都数；T2 在三个槽位上各引入一种同义说法（句型「哪些」「多少篇」「引用最多的是哪篇」，算子「年以前」「年以后」，标签后加「领域」），每个槽位独立地掷硬币选规范或变体，共抽 400 句。T2 的全空间是 ${2^3 = 8}$ 个形态类、864 种句子。逐符号读这笔账：3 个特征各有 ${s_i = 2}$ 种说法，表层形态类是 ${\prod s_i}$，句子全空间是 108 乘 8；SQL 始终 54 条，因为说法与语序都只动表层、不动语义：

$$
\text{覆盖句数} = \prod_{i=1}^{F} v_i \qquad \text{表层形态类} = \prod_{i=1}^{F} s_i
$$

${F}$ 是特征数，${v_i}$ 是第 ${i}$ 个特征的取值数，${s_i}$ 是它的说法数。语义空间与形态空间的比值，就是两条路线账本的入口。

### $\rm \S \, 7.3.2$ 资源-覆盖账

文法逐阶段生长时，程序数出的账如下，词条与规则数直接来自代码里的词库和规则清单：

| 阶段 | 词条 | 规则 | 覆盖句数 | 不同 SQL |
| --- | --- | --- | --- | --- |
| 句型 | 4 | 2 | 3 | 3 |
| +年份条件 | 10 | 4 | 18 | 18 |
| +标签条件 | 13 | 6 | 54 | 54 |
| +语序变体 | 14 | 8 | 108 | 54 |
| +说法变体 | 20 | 9 | 864 | 54 |

资源线性增长（4 到 20 词条、2 到 9 规则），覆盖按特征数相乘（3 到 864 句）。这是组合式路线在封闭域里的王牌：加一个特征只添几行词库，所有旧规则原样复用，新句子的覆盖是乘出来的。但表尾藏着它的账单：864 句是「已知的」变体说法的乘积，而真实用户的说法集合不封顶。规则系统不必为每句写规则，却必须有人把变体一个个收编进词库，还得为全部 864 句准备测试与回归。爆炸不在规则数，在必须覆盖的表层形态空间。

### $\rm \S \, 7.3.3$ 变体账：一次实测的脆断

T2 的 400 句里，规范形态的句子按硬币概率占八分之一，实测基础词库解析成功 50 句，正是 ${400 \times (1/2)^3 = 50}$：三个槽位只要有一个用了没见过的说法，整句就解析失败，脆断是按槽位连乘的。修法便宜得惊人：词库加 6 个词条、规则加 1 条（「标签 领域」也算标签条件），同一份 T2 解析成功 400/400、执行一致 400/400。一条词库行收编一整类说法，这是组合结构的红利；但每来一种新说法都要人工走一遍这个流程，开放世界里这条路没有终点。

## $\rm \S \, 7.4$ seq2seq 思想，与它的规则模拟

另一条路线不写文法，只喂配对语料：给几千对「句子、SQL」，让模型自己学映射。这就是 seq2seq 的思想（《深度学习》§13.1）：编码器把输入序列压成表示，解码器逐 token 生成输出，端到端训练。它的战绩有目共睹，《自然语言处理》第 14 章记过这一笔：机器翻译里数年建成的规则系统被数月训出的神经模型超过。问题是我们没法在本章的预算里真训一个神经模型，而「不跑就写」违反本章的纪律。解法是把 seq2seq 的思想成分拆出来，用规则模拟其中两档极端形态，每个模拟器的口径先钉死：

> **模拟口径**：模拟的对象是「端到端学映射、逐 token 生成、无组合保证」这一思想成分，不是 RNN 或 Transformer 本身。
>
> 1. B0 纯记忆：输出训练集中最近邻句子的 SQL，原句照抄。模拟「插值半径为零」的极端：没有任何组合机制，泛化等于查训练覆盖率。这是下界。
> 2. B1 逐词直译：训练信号是「句 tokens 到 SQL 片段序列」的对齐语料（相当于假设词对齐已知；真实 seq2seq 要自己学对齐，注意力机制干的就是这件事，《深度学习》§13.2），解码时逐词查表取片段、按输入顺序拼装。模拟「局部决策、无全局重排」的极端：每一步输出只看当前词，SQL 的子句顺序跟着句子的词序走。
>
> 真实神经模型的行为落在两档之间：分布式表示带来有限的平滑泛化，但没有组合保证。两个模拟器都不含训练含混、曝光偏差等真实缺陷（《自然语言处理》第 15 章对照过这些），所以它们的失败都归因于思想成分本身，不是实现瑕疵。

B0 十几行，B1 五十行，都是确定性规则程序。B1 的训练从配对语料数出四张表：句型 token 到 SELECT 骨架的映射、数值加算子到年份谓词的映射、标签到等值谓词的映射、虚词到空串的映射；解码就是查表加拼串，谓词之间用 AND 连接（这条连接规则也是从训练语料数的：全部训练 SQL 的谓词都是 AND 相连）。训练集和组合式系统用同一批 108 句规范空间生成，训练量 ${N}$ 从 8 扫到 68。

B1 的解码值得单独走一遍，因为它的全部失败都藏在这个流程里。输入倒装句「列出 GPU 、 2020 年之后 的 论文」，逐词处理：

1. 首词「列出」查句型表，得骨架「SELECT 标题 FROM papers」，无尾缀。
2. 「GPU」查标签表，得谓词「标签 = 'GPU'」，按遇到顺序放进谓词序列。
3. 「、」「的」查虚词表，得空串，丢弃。
4. 「2020」加「年之后」查年份表，得谓词「年份 > 2020」，追加在标签谓词之后。
5. 「论文」丢弃，收口：拼上 WHERE，谓词按输入顺序用 AND 相连，输出「SELECT 标题 FROM papers WHERE 标签 = 'GPU' AND 年份 > 2020;」。

第 2 步先于第 4 步，输出里标签谓词就排在年份谓词前面：解码的每一步都只看当前词，没有任何一步能回头看「后面还有一个年份条件」。五个 token 全部在训练语料里出现过，所以这句解析成功；但它和金标的字符顺序不同，精确匹配判错、执行对账判对。同样的流程遇到训练里没见过的词（比如变体「年以前」），第 2 步的查表落空，B1 没有 B 铺垫的平滑机制，整句直接失败。逐词局部决策的收益与代价都在这五步里。

## $\rm \S \, 7.5$ 实测二：两条路线的对照成绩单

### $\rm \S \, 7.5.1$ T1：数据胃口与两口径分道扬镳

先看组合式系统 A 的主场成绩：零训练样本，T1 的 40 句解析成功 40、精确匹配 40、执行一致 40，规范语序与倒装语序两半全对。再看两个模拟器的训练量曲线（每行都是同一测试集 T1）：

| ${N}$ | B0 精确 | B1 解析 | B1 精确 | B1 执行 |
| --- | --- | --- | --- | --- |
| 8 | 2/40 | 34/40 | 14/40 | 34/40 |
| 16 | 3/40 | 40/40 | 17/40 | 40/40 |
| 32 | 11/40 | 40/40 | 17/40 | 40/40 |
| 68 | 27/40 | 40/40 | 17/40 | 40/40 |

两个读数值得停下。其一，B0 的精确分随 ${N}$ 爬升但永远追不上：${N = 68}$ 时 27/40，与期望值 ${40 \times 68/108 \approx 25}$ 同量级，正落在训练覆盖率的抽样波动里。纯记忆的「泛化」就是覆盖率，曲线形状由组合数学决定，与学习无关。其二，B1 的精确与执行在 ${N \ge 16}$ 后分道扬镳：精确停在 17/40，执行满分。分水岭就是语序。B1 按输入顺序拼谓词，倒装句产出的是「WHERE 标签 = 'GPU' AND 年份 > 2020」，SQL 完全合法、结果行与金标完全相同，执行口径判它全对；精确口径逐字符比对，判它 23 句倒装全军覆没（规范语序 17 句精确全对，倒装 0/23）。这正是 §7.1 预告的两口径分歧的实测形态：同一个系统，换个验收口径，结论从「一半不行」变成「全行」。数据胃口上 B1 也便宜得多：16 句训练就喂熟了全部 token，8 句时解析 34/40，缺的是没见过的数值-算子搭配。

### $\rm \S \, 7.5.2$ T2：变体面前，钱花在哪

变体集 T2 上，三个系统的满训练（B0、B1 各喂 68 句）成绩单：

| 系统 | 训练语料 | T2 精确 | T2 执行 |
| --- | --- | --- | --- |
| A 基础词库 | 0 样本 | 50/400 | 50/400 |
| A 扩充词库 | +6 词条 +1 规则 | 400/400 | 400/400 |
| B0 规范语料 | 68 句 | 32/400 | 32/400 |
| B0 变体语料 | 68 句（抽自 864） | 36/400 | 36/400 |
| B1 规范语料 | 68 句 | 21/400 | 50/400 |
| B1 变体语料 | 68 句（抽自 864） | 187/400 | 400/400 |

这张表是全章的账本。规则系统的钱花在文法上：A 的两个成绩（50 到 400）之间隔着的只是 7 行词库与规则，一次付清、全部 864 句受益。模拟 seq2seq 的钱花在数据上：B0 喂 68 句规范语料，T2 只对得上碰巧整句见过的 32 句；换喂变体语料也只涨到 36/400，因为 68 句对 864 种形态，覆盖率就是 ${68/864}$ 附近，缺的部分只能靠更多数据补。B1 靠逐词查表把变体的执行做满了（400/400，变体 token 见过就照常直译，一行代码没改），执行口径下它对说法变化的稳健性确实优于任何固定词库；但精确分 187/400 的构成同样干净：全部来自年份条件在前的句子，倒装的那一半被自己的语序死板收走。两条路线的胜负条件至此清楚：封闭域、要可审计的规范输出、变体可枚举，组合式赢；说法开放、愿意付数据与算力、只看答案对不对，学出来的映射赢。

### $\rm \S \, 7.5.3$ 常见错误与证据式排查：对账口径的两处真 bug

写实验程序时踩到的两个坑都留在账本里，值得原样展示，因为它们是评测类实验最典型的两类错误。第一处：评测函数最初只区分「解析成功」与「执行一致」两个口径，精确匹配被偷懒合并进了前者。第一版成绩单上 B1 倒装语序精确 23/23 满分，与 §7.4 走查推出的「倒装必错精确」直接矛盾。排查不需要改代码，只需要对账：手工取一句倒装句的输出与金标逐字符比对，字符串确实不同，于是把评测函数拆成解析、精确、执行三个独立计数器，重跑后倒装精确归零。教训与 §6.5 的控制任务同源：读数与推理矛盾时，先怀疑测量仪器，而修复的方式是让每个口径有独立的计数来源。

第二处更隐蔽：训练量曲线和满训练成绩单原本是两段独立代码，各自抽样训练集。同一张表里 ${N = 68}$ 那行报 B0 精确 27/40，几行之后的满训练小节报 26/40，两个本应相同的数字对不上。回查发现两段代码各自调用了随机数发生器，抽出的训练集不同，覆盖率自然不同。修法是让满训练小节直接复用曲线末行的那一轮模型，一个种子派生出全表，任何两个数字都能指回同一次抽样。这两处修完，result.txt 里才出现 §7.5 引用的全部数字。评测代码的账要像数据库一样能对账：任何一行都能回答「你从哪来」，否则多口径评测本身就会先撒谎。

## $\rm \S \, 7.6$ 适用条件与边界

把本章结论的适用范围划清楚，免得把玩具的账错用到真实系统上。对组合式路线：其一，本章的问句语言是槽位独立的电报体，没有结构递归；第 1 章列过的边界（交式形容词假设、大多数类量词、句法歧义、指代与时态，§1.7）在这里原样适用，真实 text-to-SQL 系统还要处理多表连接与嵌套子查询，规则文法的规模会再上一个数量级。其二，「组合泛化免费」这句话依赖特征独立性；本章的 B1 恰好也做了逐词组合，所以两档模拟都体现不出结构敏感的失败，那类失败（嵌套运算的重组泛化）在真实 seq2seq 上有实测记录，玩具语言太扁平，展示不了，这是模拟口径的又一层边界。其三，现代实践早已越过二选一：大模型用提示词直接生成 SQL，说法开放的问题被模型的预训练兜住，工程上真正继承本章遗产的是验收那一半，生成结果交给数据库执行对账（执行准确率），错了的查询进不了生产（§6.5 的「输出必须可核对」变成了任务定义）；query 改写与检索库的接口在《信息检索》§8.3 有实测版。对模拟本身：B0、B1 是思想成分的隔离实验，它们的数字回答「无组合保证的映射 worst case 在哪」，不能当作任何真实神经模型的成绩单预测。

## $\rm \S \, 7.9$ 本章自测答案

### $\rm \S \, 7.9.1$ 关键概念回顾答案

1. 共用的是句法驱动组合：每条规则一条组装方案、语义沿推导树自底向上、先查形状再执行（§7.2、§1.5）；分家在目标表示与验收：输出从一阶逻辑公式换成 SQL，验收从世界模型的真假判定换成数据库的执行对账（§7.1）。精确匹配会误报「子句顺序不同但结果相同」的无害差别；执行准确率会漏报「碰巧同结果的错误查询」（§7.1、§7.5.1）。
2. 加一个特征的写成本是几行词库加一条规则，收益是覆盖句数乘上该特征的取值数，旧规则全部复用（§7.3.2）。形态类按说法数相乘：3 个槽位各有 2 种说法，独立组合出 ${2^3 = 8}$ 类；语义不变，所以 SQL 仍是 54 条（§7.3.1）。
3. 分歧来自 B1 按输入顺序拼装 WHERE 谓词：倒装句产出「标签在前」的 SQL，合法且结果与金标相同，执行判对；精确匹配逐字符比对，判 23 句倒装全错（§7.5.1）。缓存与回归测试依赖输出形式稳定，该用精确匹配验收，或先规定输出的规范形式（§7.5.2）。
4. A 靠词库：加 6 词条 1 规则，一次性收编全部 864 句；B0 靠数据：换喂变体语料只把覆盖率从 ${68/108}$ 挪到 ${68/864}$ 附近，缺的靠更多样本补（§7.5.2）。前者的成本随特征数线性、随说法数线性，后者的成本随表层形态空间的乘积增长（§7.3.2）。

### $\rm \S \, 7.9.2$ 应用与辨析答案

1. 词条加 2（数值 50、100）加 1（算子短语「被引超过」）加规则 1 条（条件 → 算子 数值），词条 20 到 23、规则 9 到 10；覆盖句数乘 2 得 1728，形态类仍 8（新特征未引入说法）或按设计乘 3。会变的是全部成绩单：T1、T2 的抽样空间与金标 SQL 集都换，A 的精确满分不变，B0 的覆盖率分母变大、曲线更平，B1 的语序分歧不变（§7.3.2、§7.5）。
2. 失败在分词查词库环节：「领域」不在基础词库的任何类别里，解析器按词库外 token 拒绝（§7.2）。修法一：词库加「领域」一条并加规则「标签条件 → 标签 领域」，覆盖从 50/400 直接到 400/400（§7.3.3）。修法二：不改文法，把该句及其全部变体形态加进训练语料换 B1；但 68 句只覆盖 864 形态中的零头，T2 精确 36/400，要追平 A 需要约 864 句量级的标注（§7.5.2）。封闭域下修法一便宜两个数量级。
3. 甲错在把执行口径当成没有语序问题：B1 的输出确实全部执行正确，但精确口径下倒装 0/23，语序死板是实测到的事实，只是这个玩具语言里语序不影响语义才没伤到答案（§7.5.1）。乙错在曲线外推：B0 的精确分受覆盖率封顶，${N \to 108}$ 才逼近满分，而 ${N = 68}$ 时 27/40；更重要的是真实问句空间不封顶，纯记忆在新说法前的成绩由覆盖率决定，永远差一截（§7.5.2、§7.6）。
