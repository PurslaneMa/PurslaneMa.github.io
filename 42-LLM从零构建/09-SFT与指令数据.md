## $\rm \S \, 9.1$ 基座为什么不会对话：预训练学的是接话，不是回答

先看病因。预训练在每个位置上最大化的是

$$
\sum_{t} \log p_\theta\big(x_t \mid x_{<t}\big)
$$

这行在说：模型的全部本事，是「给定前文，接一个网页上会出现的 token」。它没有「回答」这个概念——你输入一句问题，对它来说只是一个「到目前为止的前文」，它要做的仍然是接一个统计上最顺的下文。

白话：这是接龙高手和助手的区别。接龙高手看到「法国的首都是哪里？」，最顺的接法不是「巴黎」，而是「中国的首都是哪里？」——在论坛和题库里，问题后面跟着的往往是另一个问题。base 模型不是不听话，是它眼里的世界只有文档，没有对话。

用概率语言把话说全：网页语料训出的 $\theta$ 拟合的是文档的分布；而「助手行为」——读一句指令、给一段针对它的回答、然后停下——在文档分布里占的概率质量低到几乎量不出来。所以助手行为不是「基座有但没显影」的能力，而是分布外：应答的格式、停机的时机、对指令的针对性，这三样本基就没在预训练里学到过。

SFT 做的事因此非常明确。拿一批（指令 $x$，回答 $y$）配对数据，最大化

$$
\max_{\theta}\ \mathbb{E}_{(x,y)\sim\mathcal{D}}\big[\log p_\theta(y \mid x)\big]
$$

读法：在「给定指令」这个条件下，把概率质量往「像回答的续写」上搬。$\mathcal{D}$ 是指令数据集，$\mathbb{E}$ 是按数据集求平均。参数还是那套参数、损失还是那个交叉熵，变的只有两处：数据换成了指令-回答配对，而且（§9.3 会讲）损失只算在回答上。打个比方：token 序列的全空间是一片大海，海面上所有「像一问一答」的序列构成一条窄窄的航道——SFT 不是给船换引擎，是把船从随机游走拽到航道上。

顺手算一笔 §1.3 的账：预训练的 $D$ 是万亿 token 量级，SFT 的 $D$ 只有亿量级，按 ${6ND}$ 折算，SFT 的算力账比预训练小四五个数量级——精加工的瓶颈从来不是卡，是数据。

本节小结：基座只会接话不会回答，因为预训练目标是文档续写；SFT 用同一套损失、换一批配对数据，把条件分布拉到指令-回答的航道上。

## $\rm \S \, 9.2$ 指令数据从哪来：人工、自举、蒸馏与精选

白话：预训练的原料是整个互联网，SFT 的原料却没处白拿——网上自然存在的「指令-回答」配对稀少且脏，这批数据基本要自己造。造法五条路线，各有一笔账：

| 来源 | 代表 | 一句话口径 |
| --- | --- | --- |
| 人工写 | InstructGPT 示范集 | 标注员手写约 1.3 万条指令与示范回答（Ouyang et al. 2022） |
| 模型自举 | Self-Instruct | 175 条种子任务让模型自己扩写成约 5.2 万条（Wang et al. 2022） |
| 蒸馏 | Alpaca | text-davinci-003 生成 5.2 万条，微调 Llama 7B，数据成本约 500 美元（Taori et al. 2023） |
| 任务混合 | FLAN 系列 | 60 多个 NLP 任务统一改写成指令格式（Wei et al. 2022）；FLAN Collection 扩到 1800 多个任务（Longpre et al. 2023） |
| 人工精选 | LIMA | 1000 条逐条筛选与修订的高质量样本（Zhou et al. 2023） |

1. **人工写**：质量上限最高，成本也是真金白银——专业标注员写一条好的多轮示范按分钟计费，而 SFT 要覆盖几十种任务类型，这条路线只适合起步的小规模核心集。
2. **Self-Instruct 自举**：核心是「以模型养模型」。给模型看 175 条人工种子任务，让它生成新指令并自己作答，再用规则过滤（指令是否可执行、是否与已有样本太像、回答是否答非所问）。良率一般，但边际成本近乎零——从此指令数据不再稀缺。
3. **蒸馏**：Alpaca 把 Self-Instruct 的路线搬到更强的 teacher（text-davinci-003）上，生成的 5.2 万条喂给 Llama 7B，小模型就有了神似的指令跟随形态。它同时暴露了天花板：蒸馏学得到腔调和格式，学不到 teacher 的知识底子——答得好不好，最终看基座。
4. **任务混合**：FLAN 的贡献是把「多任务」变成指令微调的配方，任务簇的多样性直接兑换成泛化能力（证据在 §9.6）。
5. **人工精选**：LIMA（Zhou et al. 2023）只用了 1000 条——从 Stack Exchange 最佳答案、维基教程等高质量来源逐条筛出并修订——微调 LLaMA 65B，人工评测能与用几十万级数据的对齐产品打得有来有回。它背后的论点叫「对齐是表层的」（superficial alignment hypothesis）：模型的知识与能力几乎全部来自预训练，SFT 教的只是「用哪种格式把本事露出来」。

开源世界里这五条路线都有现成货：FLAN Collection 全量开源，是任务混合路线的标准参考；OpenAssistant 是人工多轮对话的代表；UltraChat 走模型互问互答的自举路线；ShareGPT 口径的数据（用户上传的对话记录）量大，但许可与合规存疑。拿现成集子之前先问一句：它落在哪条路线上、过不过得了 §9.9 的四查。

质量与数量的账由此有了锚点：LIMA 证明数据的质量密度可以兑换数量。但别过度解读——它的隐含前提是基座本身足够强（65B 且预训练充分）；基座弱时，数量与多样性仍是硬需求，FLAN 系的证据在弱基座上反而更明显。

本节小结：指令数据五条来源——人工写贵、自举便宜、蒸馏快、FLAN 求广、LIMA 求精；「1000 条精选」把质量与数量的争论钉在「对齐学格式、预训练给能力」这个论点上。

## $\rm \S \, 9.3$ SFT 训练细节：损失、模板与学习率

### $\rm \S \, 9.3.1$ 损失只算回答部分的 token

预训练对序列里每个 token 都算损失，SFT 不是。把一条样本写成「指令 $x$ ＋回答 $y$」，损失只在 $y$ 的位置上算：

$$
\mathcal{L}_{\mathrm{SFT}}(\theta) = -\,\frac{1}{|\mathcal{M}|}\sum_{t \in \mathcal{M}} \log p_\theta\big(y_t \mid y_{<t},\,x\big)
$$

读法：$\mathcal{M}$ 是回答部分 token 的位置集合，$|\mathcal{M}|$ 是它的元素个数；指令部分的位置不在 $\mathcal{M}$ 里，不产生损失项。条件里的 $y_{<t}$ 是「回答已生成的部分」，$x$ 是一直作为条件在场的指令。

为什么这么设计？一句话：不教模型背诵问题。指令在推理时由用户给出，模型永远不需要学会「生成问题」；若对指令也算损失，等于把宝贵的更新量花在「给定前缀预测问题本身」上——这是预训练已经会的事，再教一遍只是浪费，更糟的是它会强化「接着往下编问题」的行为，正好是 §9.1 那个病灶的复活。这笔账 §9.5 会用实测数字量出来。

### $\rm \S \, 9.3.2$ chat template 与 loss mask 的实现

损失要落地，得先回答「回答部分从哪个 token 开始」——这是 chat template 的职责。模板用特殊 token 把对话编成模型可学的格式，比如

`<|user|> 问题 <|end|> <|assistant|> 回答 <|end|>`

三个设计点：角色头标记「谁在说话」；结束符 `<|end|>` 是训练出来的停机键——它必须在损失集合 $\mathcal{M}$ 里，否则模型学不会闭嘴，上线症状就是无限续写的话痨；多轮对话把每一轮都编进同一条序列。模板还有一条铁律：**训练与推理必须逐字节一致**——训练时「问题前后各一个空格」、推理时少一个空格，模型看到的就不是它学过的任务格式，答非所问不算 bug，算改了卷子。工程上把模板做成一份代码两侧共用，上线前跑一次「样本过模板再还原」的 round-trip 断言（§9.9 四查之一）。

实现上用一个小技巧：把输入序列复制一份当标签，指令位置全部改成 -100，交叉熵自动跳过（PyTorch 的 CrossEntropyLoss 默认忽略标签 -100；合法类标签非负，-100 是安全哨兵）。这个数组叫 loss mask，§9.4 会把一条真实样本的 mask 数组逐位构造出来给你看。

一个易踩的边界坑：特殊 token 必须整 token 切分、不许被 BPE 拆成普通字符，否则 mask 的边界就糊了；好在模板里的特殊 token 恰好在指令与回答之间给出一条干净的缝。

多轮对话的口径随之而来：每一轮的 assistant 段都进 $\mathcal{M}$，user 段与 system 段全程 mask——同一个会话里，模型在多个位置上各自学「接话与停机」。§9.4 的实测会给出一版两轮对话的 mask。

### $\rm \S \, 9.3.3$ 打包、截断与学习率

GPU 训练要求每个 batch 是定长序列（比如 4096），而一条对话往往只有几百 token。把多条样本首尾相接填满一个窗口，叫打包（packing）。两个坑：

1. **跨样本泄漏**：不设防的打包会让样本 B 的开头看见样本 A 的内容并产生注意力。常用对策是分块对角注意力，或在样本边界处重置位置编码——泄漏到底有多大，§9.4 量给你看（一个权重和 0.8166 的实测）。
2. **截断**：超长样本一刀切掉尾巴。切掉的若是回答的 `<|end|>`，这条样本就在教模型「话说到一半被掐断也是常态」，直接污染停机行为。长回答要么单独成批，要么只截指令不截回答。

学习率取小一两个数量级：预训练峰值在 ${10^{-4}}$ 量级，SFT 常在 ${10^{-5}}$ 量级起步。两个理由。其一，SFT 数据比预训练语料小五个数量级，同样的学习率在这么小的数据上反复走几轮，很容易把预训练磨好的表征整层冲垮——这是灾难性遗忘（§9.8）的加速器。其二，预训练的终点已经是损失面上的一个好盆地，SFT 只是在盆地内部挪到「对话」这一小格，不需要大步子。日程用短 warmup 加 cosine 退火，两三个 epoch 就收。

本节小结：损失只算回答 token（不教背题），模板加 -100 哨兵实现 mask 且训练推理逐字节一致，打包要防泄漏、截断别切停机键，学习率小一两个数量级、几个 epoch 收工。

## $\rm \S \, 9.4$ 实测：loss mask 逐位构造与 packing 隔离断言

白话：上一节的 mask 与打包都是「说起来容易」的操作，这一节把它们逐位摆在桌面上。所有输出在 WSL CPU 上真跑并存档（固定种子 2026，`_lfs_work/exp09/result.txt` 第 1、2、4 节）。

先构造单轮样本的 mask。词级玩具分词（每个词一个 token，id 按首次出现顺序），样本取 §9.1 的问路对话：

```python
words = "<|user|> 法国 的 首都 是 哪里 ？ <|end|> <|assistant|> 巴 黎 。".split()
vocab = {}
for w in words:
    if w not in vocab:
        vocab[w] = len(vocab)

template = "<|user|> {q} <|end|> <|assistant|> {a} <|end|>"
sample   = template.format(q="法国 的 首都 是 哪里 ？", a="巴 黎 。")
toks     = sample.split()
ids      = [vocab[w] for w in toks]

k     = toks.index("<|assistant|>") + 1   # 回答从角色头之后开始
mask   = [0] * k + [1] * (len(ids) - k)
labels = [t if m else -100 for t, m in zip(ids, mask)]
```

实测输出（`exp09/result.txt` 第 1 节）：

```text
tokens : ['<|user|>', '法国', '的', '首都', '是', '哪里', '？', '<|end|>', '<|assistant|>', '巴', '黎', '。', '<|end|>']
labels : [-100, -100, -100, -100, -100, -100, -100, -100, -100, 9, 10, 11, 7]
参与损失的 token 数 : 4 / 13
参与损失的 token : ['巴', '黎', '。', '<|end|>']
```

三条读法。其一，mask 是 9 个 0 接 4 个 1：指令、闭合符、连 `<|assistant|>` 角色头一起被抹掉——模型不必学会喊自己的名字，只需学会接话。其二，结尾的 `<|end|>` 是 1：停机键在损失集合 $\mathcal{M}$ 里，模型正是从这里学会「答完就停」（§9.3.2）。其三，13 个 token 只有 4 个产生损失项——SFT 的监督信号比预训练稀薄得多，每条样本的梯度都珍贵，这也回过头解释了 §9.2 为什么值得为质量较真。

多轮版本只多一条规则：随每个 `<|assistant|>` 开闸、随每个 `<|user|>` 关闸，两轮的 assistant 段（含各自的 `<|end|>`）全部进损失。实测（`exp09/result.txt` 第 2 节）：19 个 token 的四轮序列，mask 为前 5 个 0、两个 assistant 段各一段连续的 1（合计 9 个），夹在中间的整轮 user 提问全是 0——这就是「多位置学接话与停机」落地后的样子。

再量打包的泄漏。把样本 A（占位置 0 到 4）与样本 B（占位置 5 到 8）拼进一条长度 9 的序列，块对角掩码＝因果掩码再加一条「B 段不许看 A 段」。用一组固定随机打分算两种掩码下的注意力权重（`exp09/result.txt` 第 4 节）：

```python
plain = scores.masked_fill(causal, float("-inf")).softmax(-1)            # 只因果，不隔离
iso   = scores.masked_fill(causal | block, float("-inf")).softmax(-1)    # 块对角隔离
leak  = plain[b_start, :b_start].sum()   # B 段首个位置分给样本 A 的权重和
```

实测：无隔离时这个和是 0.8166——B 段开头把八成注意力送给了上一条样本；加上块对角掩码后，同一位置分给 A 段的权重和精确为 0.000000、分给自己 1.000000，B 段末位对 A 段的合计权重同为 0.000000，四条断言全部通过。这 0.8166 就是「训练好好的、多轮对话串味」在训练时的来源。

本节小结：mask 的形状是「prompt 全 0、回答与停机键全 1」，多轮随角色标记开关；打包必须配块对角隔离，实测泄漏能到 0.8166。

## $\rm \S \, 9.5$ 实测：整窗、只算回答、只算 prompt 三口径的损失

白话：「损失只算回答」是句口径，口径一换数字就换。这一节拿第 5 章训好的 nano 检查点（`nano_ckpt_final.pt`，配置与种子见 §5.10）与它的 token 流，把三个口径并排量出来。先说清边界：nano 只见过代码语料，没有真指令数据，这里的「prompt 与回答」只是窗口的前后两段——实验验证的是记账机制本身（-100 哨兵、均值口径、恒等式），不是指令效果。

实验设置：batch 8、窗口长 128，从第 5 章训练段随机取 8 个窗口，在第 64 个 token 处切成两段（WSL CPU，固定种子 2026，`exp09/result.txt` 第 3 节）：

| 口径 | 每 token 平均损失 | 参与记账的位置 |
| --- | --- | --- |
| 整窗都算 | 2.4585 | 1,024 |
| 只算回答（后 64 位） | 2.3300 | 512 |
| 只算 prompt（前 64 位） | 2.5870 | 512 |

两笔读法。其一，记账恒等式断言通过：${0.5\times 2.5870 + 0.5\times 2.3300 = 2.458493}$，与整窗口径的 2.458493 相差 ${2.38\times 10^{-7}}$——「-100 哨兵」只改记账位置，不改损失的数学，这正是它能放心当哨兵的原因。其二，前段比后段每 token 贵 0.2569：窗口开头的位置上下文短、天然更难猜，这是位置效应而非内容效应；但无论哪段贵，「整窗都算」都意味着一半梯度预算花在「复述 prompt」上——真指令数据里就是教模型背题。回答口径与整窗口径还差 0.1285，说明两口径给出的梯度方向确实不同：口径不是小事。

本节小结：三个口径三个数（2.4585、2.3300、2.5870），恒等式把三者钉死；「只算回答」省下一半梯度预算，花在该花的位置上。

## $\rm \S \, 9.6$ 效果的证据链：小模型打赢大模型

三块证据，一块比一块硬。

1. **InstructGPT 的跨尺寸反超**（Ouyang et al. 2022）：经 SFT 加后续偏好训练得到的 1.3B 模型，输出在人工偏好评测中被标注者优先于 175B 的 GPT-3——参数差约 130 倍。本章只取这个结论：后训练能改写「哪个模型更好用」的排名，这是预训练扩展律管不到的维度。论文里 SFT、奖励模型、强化学习三步的贡献没有完全拆开，机制整体留给第 10 章；但 base 到 SFT 一步的改变不需要任何评测也能亲眼看到——从胡言续写变成一个像样的对话者。
2. **指令泛化**（Wei et al. 2022，FLAN）：把 60 多个任务分成约 10 个任务簇，训练时整个簇留出（比如所有常识推理任务一律不见）；指令微调后的模型在未见过的任务簇上，零样本成绩反超同款未微调模型，且任务簇越多提升越大。「学会指令格式」本身是一种可迁移的技能——这是 §9.2 里任务混合路线的理论根据。
3. **能力与对齐的分界**：把前两条放在一起看，SFT 的角色画像清楚了——它重新分配模型已有的能力（把「会但露不出来」的本事拉到指令航道上），不凭空注入新知识。LIMA 是这个判断的极端表述，FLAN 的泛化提升是它的修正项：格式少量数据就够，泛化要靠任务多样性，知识归预训练管。

读这三块证据要带对照组意识：InstructGPT 的偏好评测是人评而非基准分，比较对象是同题同条件下的大型基座；FLAN 的对照是「同款模型、只差指令微调」这一个变量。变量隔离干净的证据才允许推出因果——「SFT 有效」这类结论，靠的从来不是单点高分，而是这样的成对比较。

本节小结：1.3B 反超 175B 说明后训练开辟了新维度，FLAN 留簇实验说明指令格式可泛化，两块拼出分界——SFT 管展现，预训练管本事。

## $\rm \S \, 9.7$ 全参还是 LoRA：可训练参数的账

白话：全参微调是把整台机床拆开重调，LoRA（Low-Rank Adaptation，低秩适配，Hu et al. 2021）是底座不动、在关键部件旁边挂一对小桨。账算下来你会发现，SFT 这个工种的活，小桨大多数时候够用。

做法：想改一个权重矩阵 ${W}$（形状 ${d_{out}\times d_{in}}$）时，不动它，在旁边挂两个小矩阵——${A}$（${r\times d_{in}}$）与 ${B}$（${d_{out}\times r}$）——前向改成

$$
h = Wx + \frac{\alpha}{r}\,B\,A\,x
$$

读法：${r}$ 是秩（rank，常用 8 到 64），${\alpha}$ 是缩放系数（常取 ${r}$ 的 1 到 2 倍）；${B}$ 初始化为零，所以训练第 0 步模型与 base 完全等价，从基座出发不跳变；可训练的只有 ${A}$、${B}$ 这对小桨，梯度与优化器状态也只为它们存在。

把账算到 Llama-3-8B 上（配置同 §4.7.1，${r=16}$，q、k、v、o 四个注意力投影全挂）。低秩增量的参数量是 ${r(d_{in}+d_{out})}$，逐投影手算并拿脚本实数核对（WSL CPU，`exp09/result.txt` 第 5 节）：

| 投影 | 形状（${d_{out}\times d_{in}}$） | LoRA 参数/层 |
| --- | --- | --- |
| q | ${4096\times 4096}$ | 131,072 |
| k、v（各） | ${1024\times 4096}$ | 81,920 |
| o | ${4096\times 4096}$ | 131,072 |

每层合计 425,984，32 层共 13,631,488——占全模型 8,030,261,248 的 **0.1698%**（公式与 torch 张量逐个建出来数的实数完全一致）。显存账随之改写：底座冻结后不再需要梯度与优化器状态，bf16 存一份 16.06 GB；可训练的 13.63M 个参数按 fp32 权重、梯度、一阶矩、二阶矩全套 16 字节算 0.218 GB——合计约 16.28 GB，对比全参微调的参数态 128.48 GB，省约 7.9 倍。这就是「单卡也能微调 8B」的全部魔法：省的不是参数，是参数身边的四件套。

训完还有一步收尾：合并（merge）。把 ${( \alpha/r )BA}$ 直接加进 ${W}$，得到 ${W' = W + ( \alpha/r )BA}$——多出来的一层消失了，推理路径与原模型逐算子相同，零额外延迟。不合并也有一种用法：底座共享、按租户挂不同的小桨（多 adapter 服务），代价是推理多一次小矩阵乘。两种形态怎么选，§9.10 第 3 条有现场口径。最后一句实话：低秩约束在指令跟随这类「换格式」任务上通常够用；要往模型里灌新领域知识、大改行为时，全参仍有优势——选型先问「这次微调在学什么」。

本节小结：LoRA＝冻结底座加一对低秩小桨，8B 上 ${r=16}$ 挂满注意力投影只训 0.17% 的参数、显存从 128.48 GB 降到 16.28 GB；上线前合并回权重，推理零开销。

## $\rm \S \, 9.8$ 多任务混合与灾难性遗忘

白话：学生猛刷一个月竞赛数学，再默写古诗文就开始串行。模型在窄数据上猛训，会把基座的其他本事冲掉，这个现象叫灾难性遗忘（catastrophic forgetting）——SFT 数据量小、还要在 base 上反复走几轮，正是高发区。

过拟合的症状清单，看板上一条条对着看：

1. **模板腔**：不管问什么，回答都以同一句话开头、同一个结构收尾——模型把「格式」学成了死记；
2. **输出退化**：回答变短、变泛、开始复读，多样性塌缩；
3. **基座能力滑坡**：MMLU、代码、多语言这类基准较 base 明显下滑——指令分涨了，本事丢了；
4. **语言混杂**：中文回答里蹦英文腔、翻译腔——预训练攒下的语言直觉被冲松了。

混合比怎么定？没有普适公式，但有三条定则。其一，起点按用途加权：通用对话、代码、数学、安全拒答各占一块，各家工业配方保密，量级是「几成对几成」的粗粒度配比。其二，重放预训练数据：往 SFT 混合里掺约 5%–10% 的原始预训练语料（也有配方压到 1%–2%，量级就是「几个百分点」），在损失面上等于给基座能力系了根锚——这是对抗遗忘最便宜的老办法（工业惯例）。其三，用两张卷子调：一张测指令能力（新学的），一张测基座能力（怕丢的），每改一次配比两张都看，谁塌了往谁那边加数据。

重放之外还有正则路线：给参数变化量加 L2 惩罚，或按参数对旧任务的重要度加权束缚（EWC 一类），把参数拴在 base 附近——道理与第 10 章对齐目标里的 KL 缰绳同源。工程上掺数据比调正则更省心，所以重放是首选，正则是补充。

本节小结：窄数据猛训会冲垮基座，症状是模板腔、退化、滑坡、串语言；对策是粗粒度任务配比加百分之几的预训练重放，再用「指令卷＋基座卷」双卷盯梢。

## $\rm \S \, 9.9$ 实操清单：清洗四查与评测先行

数据侧四查，一条不过关就别进训练集：

1. **去重**：精确去重加 MinHash/LSH 模糊去重（同第 2 章的口径）。指令数据的重复比网页更致命——同一条样本出现二十次，模型学到的不是知识而是模板腔（§9.8 症状一）。
2. **去污染**：训练指令不得与评测基准重合，改写、翻译过的也算。第 11 章讲污染怎么检测，但根治在数据侧——已知基准全量剔除是开工前的动作，不是训完后的补救。
3. **质量过滤**：启发式规则（长度、语言、乱码）打底，再用一个强模型给每条样本的指令清晰度与回答质量打分，低分丢弃或回炉重写。
4. **格式校验**：模板 round-trip——样本过 tokenize 再 decode 回来必须逐字还原；loss mask 抽检——随机抽样人工核对 mask 数组（§9.4 的构造就是标准抽检动作）。

评测先行：训练开跑之前，base 模型在留出指令集、MMLU 子集、困惑度上的分数先测好记下来（指标定义全在第 11 章）。没有 base 一列，训完只剩「感觉变强了」；有了它，§9.8 的每条症状才有数字判据。训练中每半个 epoch 在验证指令集上测一次损失，按验证曲线挑 checkpoint——SFT 常在第一个 epoch 末就接近最优，最后一个 checkpoint 往往过拟合最重，别默认交最后一份。这一步的成本不到一次训练的百分之一，省它是最亏的省钱。

本节小结：数据四查——去重、去污染、质量、格式；评测先行——base 基线先落表，训练之后才有得比。

## $\rm \S \, 9.10$ 工程实录

白话：这一节是老师傅的本子接着记。每条三段：现场怎么做、为什么、谁背书。

1. **模板一份代码，两侧共用**。现场做法：chat template 写成一个函数，训练数据处理与线上推理服务都调它，仓库里放一条「样本过模板再还原」的断言常跑。为什么：模板差一个空格或换行，模型等于拿到一份没学过的卷子，症状是线上胡答而离线复现不出来——「训推不一致」类 bug 的大头在这。出处：工业惯例（各推理框架把 chat template 单独成模块，就是为这一条）。
2. **packing 必配隔离，新数据先跑断言**。现场做法：凡打包，块对角 mask 与打包逻辑写在同一处、永不分离；换数据集或改窗口长度，先跑一遍 §9.4 那套泄漏断言再开训。为什么：不隔离的打包训练 loss 往往更好看（样本间互相「剧透」），坏的却是多轮与长上下文行为，事后极难归因。出处：HF 生态踩过的公开坑（打包泄漏多次成 issue），断言写法见 §9.4。
3. **LoRA 的秩与合并**。现场做法：秩从 8 到 64 起步（16 是常见默认），挂注意力投影优先于挂 FFN；单体服务上线前一律合并回权重，只有「一个底座伺候多套性格」才保留分离形态。为什么：合并后推理路径与原模型相同、零额外延迟；分离形态省的是多份底座，付的是每次请求多一次小矩阵乘与一套 adapter 管理。出处：LoRA 论文实践口径（Hu et al. 2021）加工业惯例。
4. **重放百分之几，双卷盯梢**。现场做法：混合里掺 5%–10% 预训练语料；配比每次改动，「指令卷＋基座卷」两张评测都跑。为什么：重放是防遗忘最便宜的保险，但加多了拖慢指令能力的收敛，唯有双卷能告诉你锚的另一头沉没沉。出处：工业惯例（各家配方保密，量级口径见 §9.8）。
5. **NeFTune 这类小便宜**。现场做法：训练时给嵌入输出加均匀噪声（幅度按序列长度与维度归一，${\alpha/\sqrt{Ld}}$ 量级，${\alpha}$ 取 5 上下），推理原样关掉。为什么：在指令跟随与对话评测上常有白捡的提升，实现只有几行；它改变的是训练时的输入分布，推理必须关。出处：NeFTune（Jain et al. 2023）。属于「顺手试、有效就留」的那一类。
6. **两三个 epoch 就是红灯区**。现场做法：SFT 训练计划默认 2–3 个 epoch，每个 epoch 末存检查点并跑验证，按验证曲线选交付件。为什么：SFT 数据小、学习率虽低但反复走，第二个 epoch 后过拟合抬头是常态，最后一个检查点常常是最差的那个（§9.9 的「评测先行」就是为这一刻准备的）。出处：工业惯例。
7. **先跑通再放量**。现场做法：拿几百到一两千条样本，把「模板、mask、打包、训练、验证」全链路先跑通，再扩到几万条。为什么：SFT 的坑九成在管道不在规模——mask 错位、模板不一致、泄漏，小数据上半天真相比大数据上三天便宜得多；LIMA 用 1000 条走到头，也顺带证明了链路本身不需要大数据来验证。出处：工业惯例，口径与 §9.2 的 LIMA 相互印证。

## $\rm \S \, 9.11$ 常见错误与证据

1. **打包不隔离**。实测（WSL CPU，固定种子 2026，`exp09/result.txt` 第 4 节）：九个 token 拼两条样本，不加块对角掩码时，样本 B 的首个位置把 0.8166 的注意力权重送给了样本 A。症状：训练 loss 反而更低（多了「剧透」）、单条样本评测无恙、多轮对话与长上下文里串味。修法：块对角掩码与打包写在一处，换数据先跑断言。
2. **对 prompt 也算损失**。三口径实测（`exp09/result.txt` 第 3 节）：整窗 2.4585、只算回答 2.3300、只算 prompt 2.5870——整窗口径把一半梯度预算花在「复述问题」上，方向还与回答口径差出 0.1285。症状：模型爱接着往下编问题、回答被「问句续写」的格式带偏。修法：labels 前缀全部 -100，抽样打印 mask 人工过目（§9.4 的逐位构造就是标准动作）。
3. **合并时漏乘 ${\alpha/r}$**。把 LoRA 合进权重时写成 ${W+BA}$ 而不是 ${W+( \alpha/r )BA}$，等于悄悄给微调量换了缩放。数值演示（8 乘 8 缩比，${r=4}$、${\alpha=16}$，`exp09/result.txt` 第 5 节）：正确合并与漏乘版本在同一输入下输出最大差 18.95，两者与底座的差分别为 25.26 与 6.32——漏乘版只有正确微调量的四分之一强度。症状：本地训得好好的，合并部署后「变笨」或「没变化」。修法：合并走单独函数并配单元测试，缩放系数只出现一处。

## $\rm \S \, 9.13$ 应用与辨析

## $\rm \S \, 9.14$ 本章自测答案

> 先闭卷作答 §9.12 与 §9.13，再核对。

### $\rm \S \, 9.14.1$ 关键概念回顾答案

1. 预训练拟合文档分布的逐 token 条件族 $\sum_t \log p_\theta(x_t\mid x_{<t})$；SFT 最大化 $\mathbb{E}_{(x,y)}\log p_\theta(y\mid x)$，把条件质量搬到指令-回答航道上。读指令、应答、停机这套行为在网页语料里概率质量近零，所以是分布外。（§9.1）
2. Alpaca 用的是 Self-Instruct 的自举路线、换更强的 teacher（text-davinci-003）生成 5.2 万条。上限卡在基座：蒸馏传得了格式与腔调，传不了知识底子。（§9.2）
3. 论证「对齐是表层的」：1000 条精选样本就能把 65B 基座调出与几十万级数据产品相当的表现，说明 SFT 主要教格式与展现。隐含前提：基座够强、预训练充分；基座弱时数量与多样性仍是刚需。证据链的展开见效果一节。（§9.2）
4. 指令由用户给出、模型永远不需要学会生成问题，对指令算损失是浪费且会复活「续编问题」的病灶。公式见 $\mathcal{L}_{\mathrm{SFT}}$ 的定义，$\mathcal{M}$ 是回答 token 的位置集合。`<|end|>` 在 $\mathcal{M}$ 里模型才学得会停机，否则上线即话痨。（§9.3.1）
5. 泄漏用分块对角注意力或边界重置位置编码来防（实测泄漏 0.8166，见 §9.4）；截断别切回答的 `<|end|>`，长回答单独成批或只截指令。学习率小一两个数量级，因为数据小五个数量级、大步子会冲垮预训练表征（遗忘加速器），且预训练终点已是好盆地、只需小步挪进对话格。（§9.3.3）
6. 两侧必须逐字节一致：训练与推理用同一份模板函数，上线前跑 round-trip 断言。不一致时模型拿到的是没学过的任务格式，症状是线上答非所问、离线复现不出来。（§9.3.2）
7. $\Delta W=BA$，${A}$ 为 ${r\times d_{in}}$、${B}$ 为 ${d_{out}\times r}$；${B}$ 零初始化使第 0 步增量恰好为零、训练从 base 平滑出发。省下的主要是梯度与 AdamW 的一阶、二阶矩——底座冻结后，128 GB 级的「四件套」缩成 0.218 GB 的小桨全套。（§9.7）
8. 合并得 ${W'=W+( \alpha/r )BA}$ 后推理路径与原模型逐算子相同、零额外延迟。漏乘 ${\alpha/r}$ 等于把微调强度悄悄除以 ${\alpha/r}$（数值演示下输出差 18.95、强度只剩四分之一），症状是部署后「变笨」或「没变化」，参见常见错误与证据一节。（§9.11）
9. 模板腔、输出退化、基座基准滑坡、语言混杂。四查：去重、去污染、质量过滤、格式校验。（§9.8）

### $\rm \S \, 9.14.2$ 应用与辨析答案

1. 全参微调参数态 128.48 GB（每参数 16 字节），80 GB 的卡装不下；LoRA 只需冻结底座 16.06 GB 加小桨全套 0.218 GB，约 16.28 GB，80 GB 的卡绰绰有余。「80 GB 也不够」的情形：要全参微调更大的底座，或激活显存（长上下文、大 batch）挤爆余量——参数态之外还有一本激活账。（§9.7）
2. 最可疑：打包没做样本隔离。实测证据是不隔离时跨样本注意力权重和可达 0.8166；验证办法是拿那套断言脚本对该数据管道跑一遍，再看多轮样本在隔离与不隔离下的注意力分布差异。（§9.4）
3. 这是症状三「基座能力滑坡」：指令分涨、基座分掉，窄数据过拟合冲垮了预训练本事。处置：往混合里掺 5%–10% 预训练语料重训；按验证曲线回滚到基座分未塌的检查点，配「指令卷＋基座卷」双卷重调配比。（§9.8）
4. 可能原因：其一，`<|end|>` 没进损失集合 $\mathcal{M}$（模型没学过停机键）；其二，`<|end|>` 在分词时被 BPE 拆成普通字符（特殊 token 没有整 token 注册，mask 边界糊掉）；其三，推理侧模板与训练侧不一致、停机符对不上。能直接在训练数据上查的是后两条：抽检分词后的序列里 `<|end|>` 是否作为整 token 存在、id 是否落在 mask 为 1 的位置。（§9.3.2）
