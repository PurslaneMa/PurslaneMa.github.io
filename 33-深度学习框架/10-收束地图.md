## $\rm \S \, 10.1$ 能力总表与报错翻译表

把九章压成九行。读法是问「没有它会怎样」：PyTorch 的每一层能力都在替你承担一件你不会想手做的事。

| 你能让 PyTorch 做的事 | 对应写法（章） | 没有它会怎样 |
| --- | --- | --- |
| 把数据装进带形状与类型的对象，做矩阵运算与广播 | `torch.tensor`、`@`、`.reshape`、`.sum(dim=1, keepdim=True)`（§1） | 数据只是嵌套列表，形状错了没有东西会拦 |
| 让框架替你算导数 | `requires_grad=True`、`loss.backward()`、`.grad`（§2） | 每换一次网络结构，链式法则都要手推一遍 |
| 把「谁由谁算出」记成图，反向一遍扫完 | `grad_fn` 链、`torch.autograd`（§2–3） | 上百万参数的求导是人写不出来的展开式 |
| 用层拼网络，参数自动收集 | `nn.Linear`、`nn.Sequential`、`nn.Module`、`model.parameters()`（§4） | 手写 ${x@W+b}$，还要自己给每个参数记账、按名字取出来 |
| 打分与更新各一行到位 | `nn.CrossEntropyLoss`、`torch.optim.Adam`、`opt.step()`（§5） | 损失自己写（还要处理溢出），三种更新式各自手推 |
| 五句话把训练串起来 | `zero_grad → forward → loss → backward → step`（§6） | 前向反向的调用次序、评估与训练的切换全要自己安排 |
| 数据怎么进来与循环解耦 | `Dataset`、`DataLoader(shuffle=True)`（§7） | 采样、组批、拼接焊死在循环里，换数据源就重写循环 |
| 同一份代码换硬件、换精度 | `.to(device)`、`autocast`、`GradScaler`（§8） | 代码与「数据在哪台机器、用什么精度」绑死在一起 |
| 训练现场可中断、可搬运、可多卡 | `state_dict`、`torch.save`、`DistributedDataParallel`（§9） | 跑崩一次从头再来，一张卡不够用就只能等 |

表的第二种用法是把报错翻译回组件。训练里遇到报错先别搜文档，先问它属于哪一层的职责范围：

| 报错或症状 | 属于哪一层 | 回读 |
| --- | --- | --- |
| `mat1 and mat2 shapes cannot be multiplied` | 张量的形状与广播 | §1.6 |
| `element 0 of tensors does not require grad` | 计算图没挂上 | §2.6 |
| `grad can be implicitly created only for scalar outputs` | 非标量输出没传 `gradient` | §2.2 |
| `.grad` 一直是 `None` | 张量不是叶子，或前向在 `no_grad` 里 | §2.3、§2.6 |
| `Trying to backward through the graph a second time` | 图已被释放 | §2.2 |
| loss 出现 `nan` | 数值稳定性或精度 | §5.4、§8.6 |
| 评估时显存一直涨 | 评估段忘了 `torch.no_grad()` | §6.2 |
| 每个 batch 的内容永远是同一类 | 忘了 `shuffle=True` | §7.1、§7.5 |
| `expected device cuda:0 but got cpu` | 数据与模型不同地 | §8.1 |
| 某些参数一万步零变化 | float16 下溢抹零 | §8.5 |
| loss 不降反升 | 优化器三句顺序，或学习率 | §5.2、§6.5 |
| 读盘时 `KeyError`、`size mismatch` | state_dict 的键名或形状对不上 | §9.1、§9.7 |

这张翻译表练熟之后，读别人的训练代码也用它：先把陌生的工程代码归到总表的某一行，读不懂的地方往往是它在自己造某一行的轮子。

## $\rm \S \, 10.2$ 给我一个任务，我该写哪几行

下面是六种常见需求的最短代码骨架，都可以套进 §6.1 的训练脚本里。共同的部分（`import torch`、`nn`、数据）不重复写。

### $\rm \S \, 10.2.1$ 多分类任务

```python
model = nn.Sequential(nn.Linear(8, 32), nn.ReLU(), nn.Linear(32, 3))
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
loss_fn = nn.CrossEntropyLoss()
for xb, yb in loader:                 # xb: (B, 8)，yb: (B,) 类别下标
    opt.zero_grad()
    loss = loss_fn(model(xb), yb)     # 模型输出 logits，不要再套 Softmax
    loss.backward()
    opt.step()
```

最后一层的输出宽度等于类别数，标签是整数下标，交叉熵自己完成 softmax（§4.3）。

### $\rm \S \, 10.2.2$ 回归任务：换两行

```python
model = nn.Sequential(nn.Linear(8, 32), nn.ReLU(), nn.Linear(32, 1))
loss_fn = nn.MSELoss()                # 标签要浮点、形状 (B, 1)
```

其余与 §10.2.1 一字不差。分类与回归在框架里的区别只有最后一层的宽度和损失函数，这是「把问题变成一个可以求导的标量」这一层的全部内容。

### $\rm \S \, 10.2.3$ 自定义模块：需要残差或多路输入时

```python
class Block(nn.Module):
    def __init__(self, d):
        super().__init__()            # 先调，子层才会被注册进 parameters()
        self.fc = nn.Linear(d, d)
    def forward(self, x):
        return x + torch.relu(self.fc(x))
```

`nn.Sequential` 只能表达一路直连；出现分支、相加、多输入时就要自己写 `forward`（§4.2）。

### $\rm \S \, 10.2.4$ 自己造数据集：数据在磁盘或要现场增强

```python
class MyData(Dataset):
    def __init__(self, paths):
        self.paths = paths
    def __len__(self):
        return len(self.paths)
    def __getitem__(self, i):
        return load_and_augment(self.paths[i])   # 返回张量，别返回 numpy
loader = DataLoader(MyData(paths), batch_size=32, shuffle=True, num_workers=4)
```

读盘与增强藏在 `__getitem__` 背后，训练循环一个字不用改（§7.2）。

### $\rm \S \, 10.2.5$ 搬到 GPU 并开混合精度：加五行

```python
device = 'cuda' if torch.cuda.is_available() else 'cpu'
model.to(device)
scaler = torch.amp.GradScaler(enabled=(device == 'cuda'))
for xb, yb in loader:
    xb, yb = xb.to(device), yb.to(device)
    opt.zero_grad()
    with torch.autocast(device_type=device, dtype=torch.bfloat16, enabled=(device == 'cuda')):
        loss = loss_fn(model(xb), yb)
    scaler.scale(loss).backward()
    scaler.step(opt)
    scaler.update()
```

模型与数据都必须搬到同一台设备上；`autocast` 管用哪种精度算，`GradScaler` 管算出来的小梯度别被抹零（§8.2）。

### $\rm \S \, 10.2.6$ 从 checkpoint 接着训

```python
ckpt = torch.load('ckpt.pt', map_location=device)
model.load_state_dict(ckpt['model'])
opt.load_state_dict(ckpt['opt'])       # 丢了这个，动量与 Adam 状态清零
start_epoch = ckpt['epoch'] + 1
```

`map_location` 让存档能在另一台机器上读回来（比如从 GPU 存、在 CPU 上读），优化器状态则决定续训与直跑的轨迹是否完全一致（§9.6）。

## $\rm \S \, 10.3$ 三条主线的收束

1. **自动微分 = 计算图 + 拓扑序**。§2 讲怎么用，§3 把规则写成 40 行代码：前向建图时记下每条边的局部导数，反向按逆拓扑序扫一遍。这套算法的不变量是「一个节点的梯度要等全部下游回传完才齐」，同一规则在册内换了三次装：标量闭包（§3.2）、层矩阵公式（§4.4）、关掉记账的 `no_grad`（§2.3）。
2. **训练循环 = 五句话胶水**。§6 的骨架九章不变：清、前向、损失、反向、更新。§7 换数据来源、§8 换设备与精度、§9 加梯度平均与存档，五个动作一个没动过。判断一条工程改动是否「只动工程不动算法」，就看它是否插在五个动作之间的缝隙里：§9 的梯度平均插在反向与更新之间，§8 的 loss scaling 插在损失与反向之间。
3. **工程层 = 让同一份循环在更大的资源上跑**。设备抽象管「在哪算」，dtype 管「用什么算」，DataLoader 管「喂多快」，数据并行管「几双手一起算」，checkpoint 管「算崩了怎么办」。五样工程的共同敌人是同一份循环在不同资源上的错位：数据错位、设备错位、精度错位、卡间错位、断点错位，各自的接口都是为消掉一种错位而设计的。

三条主线在 §10.1 的总表上各有落点：主线一占前三行，主线二占第六行，主线三占后三行。表、主线、九章，三套索引指向同一批知识，闭卷时能互相推出，就算收束完成。

## $\rm \S \, 10.4$ 源码阅读路线

| 项目 | 规模 | 看什么 | 读完的收获 |
| --- | --- | --- | --- |
| micrograd | 约 300 行 | `Value._backward` 闭包、`backward()` 里的拓扑排序 | 「引擎没有更多东西了」 |
| tinygrad | 数千行 | 一个算子（如 `add`）的 CPU 与 GPU 两份实现 | 设备分派在真实代码里的长相 |
| PyTorch `autograd` | 数万行 | `variable.py` 的 `Function` 节点、`engine.cpp` 的多线程反向调度 | 单线程拓扑序如何扩成并行引擎 |

1. **micrograd**：本册 §3 的同源实现。重点盯两处：`Value._backward` 闭包怎么把「本节点的回传规则」记在图上（§3.1 的空 lambda 被运算符重载覆盖），以及 `backward()` 里 `topo` 列表怎么用一次 DFS 排好。
2. **tinygrad**：把 micrograd 的思路做成能跑 GPU 的张量库。看同一个 `add` 如何有 CPU 与 GPU 两份实现、按 `device` 字段查表调用（§8.4 的「标签」升级成「分派」），以及 lazy execution 与本册记账方式的异同。
3. **PyTorch 的 autograd 目录**：`variable.py` 与 `engine.cpp`。看 `Function` 与反向图的节点表示，以及多线程执行反向任务队列的调度：§3 的单线程拓扑序如何扩成并行的引擎。

三段路线的纵深递增：第一段读完懂算法，第二段读完懂分层，第三段读完懂工程。读不动第三段是正常的，它依赖 C++ 与多线程。判断自己读没读懂的办法有三条：

1. 合上源码，能在 §10.1 的表里指出每个看到的类对应哪一行；
2. 能对别人讲清「micrograd 的 `_backward` 为什么是闭包而不是方法」；
3. 能说出 PyTorch 引擎与 §3.3 的实现差在「并行调度」而不在「微分的数学」。

## $\rm \S \, 10.8$ 本章自测答案

### $\rm \S \, 10.8.1$ 关键概念回顾答案

1. 见 §10.1 表；最不能缺的是张量与自动微分这两层，没有载体与导数规则，其余能力都没有挂靠点。（§10.1）
2. 自动微分的不变量是逆拓扑序回传，循环的不变量是五个动作的顺序，工程层的不变量是「算法不动」；五样工程一个动作都没动。（§10.3）
3. 最后一层的输出宽度与损失函数；因为训练循环只认「一个可以求导的标量损失」，怎么把预测打到分数上在框架层就只剩这两处可换。（§10.2.1、§10.2.2）
4. micrograd 懂算法（闭包回传与拓扑排序）、tinygrad 懂分层（算子的多设备实现）、PyTorch autograd 懂工程（并行反向引擎）；「看什么」见 §10.4 的表。（§10.4）
5. 看改动是否插在五个动作之间的缝隙里；§9 的梯度平均插在反向与更新之间，§8 的 loss scaling 插在损失与反向之间。（§10.3）
6. 与主线第 43、44 章是「用法在外、机制在本册」：那两章教你跑起来与管理多卡任务，本册负责解释报错、不降、多卡不一致的内部原因；与深度学习分册是「原理在外、用法在本册」，本册每一章都能回到那边找理论后方。（§10.5）

### $\rm \S \, 10.8.2$ 应用与辨析答案

1. 属于优化器那一层（§5）；它是循环五个动作里的第一个「清」。（§10.1、§6.1）
2. 训练循环主线：§7 把手写切片换成 `DataLoader`、§9 在反向与更新之间插梯度平均；证据是 §9.5 的梯度同步实验（${2.2\times10^{-16}}$）与 §7.5 的逐数一致对照（${\max|\mathrm{diff}|=0}$）。（§10.3）
3. 挂在自动微分主线：把前向存中间量的地方改成存检查点、反向时重算；动 §3 的引擎与 §4.4 的层，循环五个动作不变，重算藏在 `backward` 内部。（§10.3）
