# $\rm Chapter \, 4$ 线段相交与扫描线

第 1 章解决了「一对线段相交吗」，本章解决「n 条线段有多少交点」——暴力 O(n²) 在 n = 10⁵ 时熄火，扫描线把「每对都查」改成「只查邻居」。这是计算几何从「会判定」到「会做规模」的分水岭，也是后续所有大规模几何算法的模板。

> **开始前自检**：本章假设你已经会：
>
> 1. □ 第 1 章的相交判定与精度纪律（§1.2—1.3）；
> 2. □ 平衡树（有序集合）的插入/删除/前驱后继 O(log n)；
> 3. □ 事件驱动的思想（按时间排序处理，OI 扫描线常规）。
>

## $\rm \S \, 4.1$ 问题的三种规模

n 条线段，问：

1. **有没有交点**（判定版）；
2. **有多少交点**（计数版，重复点算多重）；
3. **把所有交点列出来**（报告版）。

暴力全对判定是 O(n²)——n = 10⁵ 的平方是 10¹⁰ 次判交，爆炸。关键观察：**绝大多数线段对根本「没机会」相交**——它们在 x 方向上隔得很远。扫描线把「x 方向的远近」变成「处理顺序」，让算法只看「在扫线位置上有交集的线段对」。

**白话**：把平面竖着切一刀，从最左扫到最右；只有「当前刀口上互相重叠」的线段才有可能相交，其余的对永远不必检查。

**三种规模的实账**（同一份 20 段数据：seed = 7、端点在 $[0, 10]^2$ 上均匀取，§4.4 程序段可复跑）：

```text
判定版: 查到第 21 对即停, 有交点: (1, 3)
计数版: 交点对数 k = 45
报告版: 前 3 条 (i, j, 交点):
  (1, 3)  (2.3869, 4.5384)
  (1, 6)  (2.2429, 4.5811)
  (1, 10) (5.1485, 3.7193)
报告版共列出 45 个交点 (每对一个)
```

读法：判定版付了 21 次判交就收工——全对 190 次里剩下 169 次永远不必付；计数版必须把 190 对全部过完才知道是 45；报告版在这之上还要解坐标（每解一个交点是一次两直线求交，浮点从这一步进账）。三档工作量的分水岭在「要不要全部、要不要坐标」，扫描线把后两档统一压到 $O((n+k)\log n)$——下一节看它怎么压。

## $\rm \S \, 4.2$ 扫描线机制（本章主证）

**事件**：每条线段的左端点（进入）、右端点（离开）、以及**交点**（顺序变化）。事件按 x 排序处理（x 相同按 y 排，保证确定性）。

**活动集** $\mathcal{A}$：当前刀口穿过的线段，按「刀口处的 y 值」排序维护在平衡树里。

**核心引理（正确性心脏）**：若两条线段 ${s, t}$ 相交于 $p$，则在事件点 $p$ 之前，$s$ 与 $t$ 在活动集里必**相邻**过——证明：从「两者都进入活动集」到交点之前，若中间有第三条线段 $u$ 恒夹在两者之间，则 $u$ 在刀口位置始终位于 $s$ 与 $t$ 之间，由连续性 $u$ 也必须穿过 $p$；于是 $p$ 被更早地计入（处理到 $u$ 时）。归纳即得「${s, t}$ 在某个时刻相邻」。$\blacksquare$

**算法骨架**（事件驱动）：

1. 左端点事件：插入活动集，**只检查与左右邻居的交**（新线段只可能与邻居相交，由引理反证）；
2. 右端点事件：删除，**检查它的左右邻居彼此**（邻居原本隔着它，现在成了新邻居）；
3. 交点事件：交换两线段的顺序，**检查新形成的邻居对**。

**复杂度**：每处理一个事件 O(log n)（树操作）；事件总数 = 2n 端点 + k 交点 ⟹ **O((n + k) log n)**。k 小时近线性——这就是 Bentley–Ottmann（1979）的全部魔法（完整版含退化处理，出处 de Berg《Computational Geometry》第 2 章与 Preparata–Shamos 第 7 章）。

**完整 trace（5 条手选线段，坐标全是半整数，每步可手核；程序实跑照抄）**：

1. s0 = (0,0)–(0.5,7)：最左的陡线，谁也不交；
2. s1 = (1,1)–(6,6)：斜率 1，即 y = x；
3. s2 = (2,6)–(6,2)：斜率 −1，即 y = 8−x，与 s1 交于 (4,4)（y = x 与 y = 8−x 联立即得）；
4. s3 = (5,3.5)–(5,5)：竖直，上端点 (5,5) 恰落在 s1 上——一次端点触碰；
5. s4 = (7,0)–(7,4)：最右的竖线，谁也不交。

事件按 (x, y) 字典序进堆，活动集按刀口处的 y 值排序（记 s@y）：

| 事件 (x, y) | 类型 | 活动集（处理后） | 报交 |
| --- | --- | --- | --- |
| (0.0, 0.0) | s0 进 | [s0@0.00] | 无 |
| (0.5, 7.0) | s0 出 | [] | 无 |
| (1.0, 1.0) | s1 进 | [s1@1.00] | 无 |
| (2.0, 6.0) | s2 进 | [s1@2.00, s2@6.00] | s1×s2 @ (4,4)，交点入堆 |
| (4.0, 4.0) | s1↔s2 交换 | [s2@4.00, s1@4.00] | 无 |
| (5.0, 3.5) | s3 进 | [s2@3.00, s3@3.50, s1@5.00] | s3×s1 @ (5,5)，端点触碰 |
| (5.0, 5.0) | s3 出 | [s2@3.00, s1@5.00] | 无 |
| (6.0, 2.0) | s2 出 | [s1@6.00] | 无 |
| (6.0, 6.0) | s1 出 | [] | 无 |
| (7.0, 0.0) | s4 进 | [s4@0.00] | 无 |
| (7.0, 4.0) | s4 出 | [] | 无 |

四个值得停一步的地方：

1. 交点 (4,4) 在 s2 **进场**时就被发现——进场只查左右邻居，s2 的左邻居恰是 s1；
2. 交换事件修正活动集的次序：交点左侧 s1 在下、右侧 s1 在上；交换后重测新邻居对，已报过的 (s1, s2) 靠「报交对集合」去重；
3. 端点触碰不必等 s3 出场：刀口 x=5 处活动集排成 s2(3) < s3(3.5) < s1(5)，s3 与两个邻居各测一次，s3×s1 命中 (5,5)——判交原语对「端点落在对方身上」返回相交，正是第 1 章 §1.3 的 on_seg 分支；
4. 11 个事件、2 次报交、活动集长度全程 ≤ 3——「只查邻居」省下的判交次数就摊在这张表里。

## $\rm \S \, 4.3$ 退化：实现者的沼泽

优雅的引理在退化面前全是坑，实现前必须点名：

1. **共线族**：多条线段共线重叠——活动集里「y 值相同」的排序不稳定，需要给共线组定序规则（按进入顺序）；
2. **多线段共点**：一个事件点上有 m 条线段——事件用一个点批量处理（撤销-重排-重测），O(m log m)；
3. **端点恰在另一条线段上**：判交的 on_seg 分支（第 1 章 §1.3）在此反复出现。
4. **浮点**：交点坐标是计算值——报告版算法一切排序键都可能被舍入污染；精度纪律（第 1 章 §1.2）在这里从「判定安全」升级成「顺序安全」。

**读法**：这就是为什么 Bentley–Ottmann 在教科书里是三百行、在 CGAL 里是万行——理论复杂度与实现健壮性之间的鸿沟，全在退化。

**共点退化的程序演示**（3 条线段交于 (5,5)：s0=(1,1)–(9,9)，s1=(1,9)–(9,1)，s2=(5,0)–(5,10)）：

```text
两两计数口径: 3 个交点 -> ['s0×s1 @ (5.0, 5.0)', 's0×s2 @ (5.0, 5.0)', 's1×s2 @ (5.0, 5.0)']
合并同点口径: 1 个 -> [(5.0, 5.0)]
```

读法：两两口径下 $\binom{3}{2} = 3$ 对线段各报一次，几何上却是同一个点；合并口径要做「同点归并」——精确算术里判坐标相等即可，浮点报告版里得换成 eps 邻域判同，第 1 章 §1.2 的判等纪律在这里从「比较安全」升级成「归并安全」。口径要在写题前钉死：计数题通常要两两口径（差一个组合数因子），画图与去重要合并口径。

## $\rm \S \, 4.4$ 数值实验

固定种子（seed = 7）在 $[0, 10]^2$ 上取 20 条随机线段：

1. 暴力 O(n²) 数交点：**k = 45**（严格穿越判定，共点按多重计会略多）；
2. 简化扫描线（事件排序＋活动集 set＋邻居对重测）：同样给出 **45**——两路逐位一致；
3. 第 1 章四案例判定回归全过（十字/端点/共线/平行）；
4. 退化专项：构造 3 条共点线段（交于 (5,5)），暴力与扫描线都报 3 个交点（两两计），说明多重计数口径要提前钉死。

程序段给完整可跑版（简化扫描线约 60 行；退化案例单列）。

简化扫描线全文（40 行：事件堆＋活动集＋邻居重测；活动集用「按刀口 y 现查的有序表」顶替平衡树——n = 20 不吃亏，真实现换平衡树才拿 $O(\log n)$）：

```python
import random, heapq
def cross(o, a, b): return (a[0]-o[0])*(b[1]-o[1]) - (a[1]-o[1])*(b[0]-o[0])
def seg_inter(a, b, c, d):                     # 穿越判交, 返回交点列表
    d1, d2 = cross(c, d, a), cross(c, d, b); d3, d4 = cross(a, b, c), cross(a, b, d)
    if not (((d1>0) != (d2>0)) and ((d3>0) != (d4>0)) and d1 and d2 and d3 and d4): return []
    r, s = (b[0]-a[0], b[1]-a[1]), (d[0]-c[0], d[1]-c[1])
    t = ((c[0]-a[0])*s[1] - (c[1]-a[1])*s[0]) / (r[0]*s[1] - r[1]*s[0])
    return [(a[0]+t*r[0], a[1]+t*r[1])]
def y_at(s, x):                                # 线段在刀口 x 处的 y 值
    return s[0][1] if s[1][0] == s[0][0] else s[0][1] + (x-s[0][0])/(s[1][0]-s[0][0])*(s[1][1]-s[0][1])
def sweep(segs):                               # 事件堆 + 活动集 + 邻居重测
    ev = [e for i, s in enumerate(segs) for e in ((min(s)[0], min(s)[1], 0, i), (max(s)[0], max(s)[1], 1, i))]
    heap = ev[:]; heapq.heapify(heap); active, rep = [], set()
    def check(i, j, x):                        # 邻居对测试, 交点严格在右侧才入堆
        i, j = min(i, j), max(i, j); pts = seg_inter(*segs[i], *segs[j])
        if pts and (i, j) not in rep:
            rep.add((i, j))
            if pts[0][0] > x + 1e-12: heapq.heappush(heap, (pts[0][0], pts[0][1], 2, i, j))
    while heap:
        x, y, tp, *pl = heapq.heappop(heap)
        if tp == 0:                            # 左端点: 插入 + 查左右邻居
            i = pl[0]; key = y_at(segs[i], x); pos = 0
            while pos < len(active) and y_at(segs[active[pos]], x) < key: pos += 1
            active.insert(pos, i)
            if pos > 0: check(active[pos-1], i, x)
            if pos < len(active)-1: check(i, active[pos+1], x)
        elif tp == 1:                          # 右端点: 删除 + 前后邻居互查
            i = pl[0]; pos = active.index(i); active.pop(pos)
            if 0 < pos < len(active): check(active[pos-1], active[pos], x)
        else:                                  # 交点: 交换次序 + 查新邻居
            i, j = pl
            if i in active and j in active and abs(active.index(i) - active.index(j)) == 1:
                pi, pj = active.index(i), active.index(j)
                active[pi], active[pj] = active[pj], active[pi]; lo, hi = min(pi, pj), max(pi, pj)
                if lo > 0: check(active[lo-1], active[lo], x)
                if hi < len(active)-1: check(active[hi], active[hi+1], x)
    return rep
random.seed(7); S = [((random.uniform(0, 10), random.uniform(0, 10)), (random.uniform(0, 10), random.uniform(0, 10))) for _ in range(20)]
rep, brute = sweep(S), {(i, j) for i in range(20) for j in range(i+1, 20) if seg_inter(*S[i], *S[j])}
print(len(rep), len(brute), rep == brute)
```

在我机器上的输出（seed = 7 的 20 段，任务锚 k = 45 双路对账）：

```text
45 45 True
```

读法：三个数是三重账——扫描线报 45 对、暴力报 45 对、且两路报的是**同一批线段对**（`rep == brute` 逐对比对，不只是数目相等）。交点入堆前那句 `pts[0][0] > x + 1e-12` 防的是死循环：端点重合的线段对会在同一事件点上互相报交，若允许交点的 x 等于当前事件的 x，处理完又入堆、堆永不空。

## $\rm \S \, 4.7$ 本章自测答案

1. 活动集引理：相交对在交点前必曾相邻，非邻居对可安全跳过。（§4.2）
2. 左端点（插入＋查邻）、右端点（删除＋邻邻互查）、交点（交换＋查新邻）。（§4.2）
3. 实际交点数；k 小时近线性。（§4.2）
4. 共线族需组内定序；共点用批量撤销-重排。（§4.3）
5. 坐标是计算值，浮点污染排序键——顺序不稳定。（§4.3）
6. 进场处理会把新线段插进活动集并立即与左右邻居各测一次交。s3 在 x=5 进场时邻居恰是 s1，而 s1 恰好穿过 s3 的上端点 (5,5)——判交原语对「端点落在对方身上」返回相交（第 1 章 §1.3 的 on_seg 分支），于是进场即报。出场时的「前后邻居互查」是为「两段到活动集中段才相交、进场时还不是邻居」的情形准备的；进场就能看见的交不必等出场。（§4.2）
7. 推导（反证）：若不检查，端点重合的线段对会在同一事件点上互相报交并入堆，交点的 x 等于当前事件的 x——处理完又入堆，堆永不空，算法不终止。要求交点严格在右侧（x 大于当前事件 x，再加 $10^{-12}$ 余量）后，每个交点至多入堆一次；那个余量是浮点下给「本该相等」留的（第 1 章 §1.2）。（§4.4）
8. 两两口径报 $\binom{3}{2} = 3$ 个（每对线段各一次），合并口径报 1 个；报告版要做同点归并——精确算术判坐标相等，浮点下判 eps 邻域。选错口径，计数差一个组合数因子、同一坐标重复输出三份。（§4.3）

**带走清单**：扫描线三类事件与活动集引理；复杂度 O((n+k) log n)；退化四清单；45 交点双验证锚（§4.4 程序段 `45 45 True`）；「判定正确 ≠ 规模可行」的分水岭认识。
