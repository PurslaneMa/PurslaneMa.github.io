## $\rm \S \, 6.1$ 训练脚本：从造数据到评估

要解决的问题：数据、模型、损失、优化器都现成，缺的是把它们按固定时序接起来的那几行。整份脚本分四段。第一段造数据：自造 2 类高斯数据，8 维特征，两类中心在 ${\pm 0.5\cdot\mathbf{1}}$，各 250 个样本，400 训练、100 测试。

```python
import numpy as np, torch, torch.nn as nn, torch.nn.functional as F
torch.manual_seed(0)
rng = np.random.default_rng(42)                          # 造数据用固定种子
n, d = 500, 8
y = np.repeat([0, 1], 250)                               # 两类各 250 个
X = rng.normal(size=(n, d)) + (2 * y[:, None] - 1) * 0.5  # 两类中心在 ±0.5·1
p = rng.permutation(n)
X, y = X[p], y[p]
Xtr = torch.tensor(X[:400]); ytr = torch.tensor(y[:400]).long()  # 训练 400
Xte = torch.tensor(X[400:]); yte = torch.tensor(y[400:]).long()  # 测试 100
```

第二段是模型（§4 的 `nn.Module` 写法）、损失与优化器（用法见 §5）：

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.l1 = nn.Linear(8, 32)
        self.l2 = nn.Linear(32, 2)
    def forward(self, x):
        return self.l2(F.relu(self.l1(x)))     # 网络结构 8 → 32 → 2
model = MLP().double()                         # float64，与后文对照口径一致
criterion = nn.CrossEntropyLoss()              # 吃 logits，内部自带 Softmax
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
```

第三段是循环，第四段是评估：

```python
EPOCHS, BS = 20, 32
hist = []                                      # 每个 epoch 记下 (loss, acc)
for epoch in range(EPOCHS):
    model.train()                              # 训练模式（§6.2）
    perm = torch.randperm(len(Xtr))            # 每 epoch 重打乱训练集
    for s in range(0, len(Xtr), BS):
        j = perm[s:s + BS]
        optimizer.zero_grad()                  # ① 清旧账
        logits = model(Xtr[j])                 # ② 前向
        loss = criterion(logits, ytr[j])       # ③ 算损失
        loss.backward()                        # ④ 反向
        optimizer.step()                       # ⑤ 更新
    model.eval()                               # 评估模式（§6.2）
    with torch.no_grad():                      # 评估不建图
        logits = model(Xte)
        te_loss = criterion(logits, yte).item()
        te_acc = (logits.argmax(1) == yte).double().mean().item()
    hist.append((te_loss, te_acc))
    print(f"epoch {epoch+1:2d}  test_loss {te_loss:.4f}  test_acc {te_acc:.2f}")
```

| 写法 | 说明 |
| --- | --- |
| `optimizer.zero_grad()` | 清上一轮残留的梯度 |
| `logits = model(xb)` | 前向，`model(xb)` 等价于 `model.forward(xb)` |
| `criterion(logits, yb)` | 这个 batch 的损失（交叉熵吃原始 logits） |
| `loss.backward()` | 反向，梯度写进各参数 |
| `optimizer.step()` | 按梯度原地更新参数 |

五句话有硬约束：`zero_grad` 在 `backward` 之前（`+=` 会混入旧账），`step` 在 `backward` 之后（优化器只读梯度、写参数，§5）。

## $\rm \S \, 6.2$ 三份数据、训练历史与 train/eval

要解决的问题：训练完怎么知道在学、又该用哪份数据检验？数据通常切三份：训练集每个 epoch 更新参数；验证集每个 epoch 末调超参、选模型，不参与更新；测试集只在最后用一次，对外报告的数字出自它。本章的小实验只用训练集与测试集两份（400 / 100）。上面每个 epoch 的 loss 与 acc 追加进 `hist`，结束时回看整条曲线。真跑 20 个 epoch 的历史如下（脚本每 epoch 打一行，此处摘首末两行；验证环境：WSL Ubuntu，PyTorch 2.14.1+cpu，float64）：

```text
epoch  1  test_loss 0.3783  test_acc 0.84
epoch 20  test_loss 0.2213  test_acc 0.92
```

loss 从 0.3783 降到 0.2213、acc 从 0.84 升到 0.92，说明网络确实在学。评估段还必须 `with torch.no_grad():`（不更新参数、不需要梯度，关掉记账省内存也更快，§2.3），并且评估前要 `model.eval()`：Dropout 训练时随机丢单元、评估时全部保留，BatchNorm 训练时用当前 batch 的统计量、评估时用滑动平均。本章的 `MLP` 没有这两层，但一旦用上就必须切，第 9 章存 checkpoint 时它是坑。

| 写法 | 说明 |
| --- | --- |
| `model.train()` / `model.eval()` | 训练/评估两套语义：Dropout、BatchNorm 的行为切换 |
| `with torch.no_grad():` | 块内不建计算图，评估专用 |

## $\rm \S \, 6.3$ 打开盖子：十行骨架与逐 epoch 对齐

不打开盖子，你会缺一块判断力：五句话的循环会写，却说不清它内部动了什么，也说不出 PyTorch 与手写实现在哪一位上分道。前五章的手写零件正好拼出同一循环的迷你版。十行骨架（`net` / `softmax_ce` 来自 §4、§5）：

```python
for epoch in range(EPOCHS):              # 第一层：全量数据过一遍
    idx = epoch_perm(epoch)              # 本 epoch 的样本置换（§6.3 讲对齐）
    for s in range(0, len(idx), BS):     # 第二层：切 batch
        j = idx[s:s + BS]
        net.zero_grad()                  # ③ 清旧账（gradW 是 +=，§3.2）
        z = net(Xtr[j])                  # ① 前向
        loss, gz = softmax_ce(z, ytr[j]) # ② 损失层：返回 loss 与 dL/dz
        net.l1.backward(net.a1.backward(net.l2.backward(gz)))    # ④ 反向
        for L in (net.l1, net.l2):       # ⑤ 更新：SGD 就两行
            L.W -= lr * L.gradW
            L.b -= lr * L.gradb
```

骨架注释里的「§6.3」指下文的对齐三决定。这十行的顺序是硬约束：`zero_grad` 在 `backward` 之前（`+=` 累积旧账），更新在 `backward` 之后（优化器只读梯度、写参数，§5.2）；反向一行从最内层往外读，先算 $\partial L/\partial z$ 进 `l2`，再穿 ReLU，最后进 `l1`。PyTorch 的对应物就是 `optimizer.zero_grad()`、`loss.backward()`、`optimizer.step()` 三句，顺序一字不差。

网络与数据：`MLP` 与 §6.1 同结构（$8\to32\to2$，ReLU 激活）、同一份数据；迷你侧用 §4、§5 的手写层与 `softmax_ce`，torch 侧用 `nn.Linear` 与 `F.cross_entropy`。一处口径差别要说明：这套对照实验的超参是 batch 32、$\mathrm{lr}=0.5$，与 §6.1 脚本的 $\mathrm{lr}=0.1$ 不同，两组的数字各自成立、不互相印证（前者的目标是逐数对齐，后者是尽快把 loss 压下去）。

对照的前提是「同结构、同初始化、同超参」，难点在两边是两套独立的世界。三个对齐决定：

1. **初始化对齐**：`torch.manual_seed` 与 `np.random.seed` 是两个互不相干的状态机，对不齐。可靠做法是在 numpy 里用 `default_rng(42)` 生成一次 He 初始化（$\mathcal{N}(0,\sqrt{2/f_{\mathrm{in}}})$），把同一组数组拷贝进两边。`torch.manual_seed(0)` 照常声明，但实验不依赖它。
2. **batch 顺序对齐**：每个 epoch 的样本置换用独立种子 `default_rng(123+e)` 预生成，两边共用。共享同一个生成器对象是错的：迷你侧先跑会消耗随机状态，torch 侧拿到的就是另一组置换。
3. **数值对齐**：torch 侧全部用 float64（`model.double()`），损失用 `F.cross_entropy`（内部是 log-softmax，与 §5.4 的稳定 softmax 数学等价）。

超参：batch 32、$\mathrm{lr}=0.5$、20 个 epoch。逐 epoch 对照（loss 为该 epoch 各 batch 损失的均值，acc 为测试集准确率）：

| epoch | loss 迷你 | loss torch | ${|\Delta L|}$ | acc 迷你 | acc torch |
| --- | --- | --- | --- | --- | --- |
| 1 | 0.3411 | 0.3411 | ${1.1\times10^{-16}}$ | 0.89 | 0.89 |
| 2 | 0.2174 | 0.2174 | 0 | 0.92 | 0.92 |

## $\rm \S \, 6.4$ 打开盖子：zero_grad 清账与训练器

不打开盖子，你会缺一块判断力：知道每步要清梯度，却看不出「忘了清」会把轨迹带偏多远。下面真跑一个对照：同一个 epoch 的前三个 batch，正常版与「忘清梯度」版逐步的损失：

| 步 | 每步清梯度 | 不清梯度 |
| --- | --- | --- |
| 1 | 0.9976 | 0.9976 |
| 2 | 0.5602 | 0.5602 |
| 3 | 0.6610 | 0.2552 |

前两步看不出差别（`gradW` 出生时是零，第一轮累积无旧账），第三步起分叉：不清梯度时 $\mathrm{l1}$ 的 $|\mathrm{gradW}|$ 累积到 9.69，正常版只有 3.78。旧账混进新梯度，等效于把前几步梯度全加起来当一步用，方向已不是这个 batch 的方向，损失可能短期更低（上表如此），但那是巧合不是正确。梯度裁剪一句话：反向之后、`step` 之前加一句 `if g_norm > clip: g *= clip / g_norm`，把过大的梯度缩回半径 ${\mathrm{clip}}$ 内，防 RNN 类网络的反向爆炸（深度学习分册 §7）。

把十行骨架封装成函数时多出三个决定：其一，返回训练历史（每 epoch 的 loss 与 acc 列表），§6.3 的表就是它的产物；其二，评估放每 epoch 末并包在 `torch.no_grad()` 里，不建图、省内存；其三，随机性归训练器内部的生成器，测试集永远顺序遍历，评估才可复现。

```python
def train(net, Xtr, ytr, Xte, yte, epochs, lr, bs):
    hist = []
    for e in range(epochs):
        run_one_epoch(net, Xtr, ytr, e, lr, bs)      # §6.1 的中层与内层
        hist.append((loss_all(net, Xte, yte),        # 评估不更新参数
                     acc(net, Xte, yte)))
    return hist
```

## $\rm \S \, 6.5$ 常见错误与报错翻译

loss 不降时按下面这张表逐行排查；主线的第 43 章 [§43.9](../06-编程语言/43-PyTorch与模型训练全过程.md) 有更系统的调试流程。

| 可能的原因 | 症状 | 怎么改 |
| --- | --- | --- |
| 忘了 `zero_grad()` | 梯度越滚越大，loss 震荡或变 `nan` | 每步开头补 `optimizer.zero_grad()`（§6.4 的分叉实验） |
| 学习率太大 | loss 乱跳、不降或直接 `nan` | 从 ${10^{-3}}$ 起每次乘或除 10 试，先把 lr 调小 |
| 忘了 `model.train()` | 带 Dropout / BatchNorm 时训练行为不对，loss 不降 | 训练开头 `model.train()`、评估前 `model.eval()`（§6.2） |
| 数据与标签错位 | loss 卡在随机水平（分类约 ${\ln C}$）不动 | 取一个 batch 手动对齐输入与标签（§6.2） |
| 最后一层少激活 | 输出被夹成常数、梯度消失 | 回归接 `nn.Sigmoid`、分类把 logits 直接交给 `CrossEntropyLoss` |

## $\rm \S \, 6.8$ 本章自测答案

### $\rm \S \, 6.8.1$ 关键概念回顾答案

1. 「清、前向、损失、反向、更新」；`zero_grad` 在反向前（梯度 `+=` 累积，不清则混入旧账），`step` 在反向后（优化器只读梯度、写参数）。（§6.1、§6.4）
2. Dropout（训练随机丢弃、评估关闭）与 BatchNorm（训练用当前 batch 统计量、评估用滑动平均）；`no_grad()` 让评估段不建图、不记反向的账。（§6.2）
3. 训练集更新参数、验证集调超参选模型、测试集只用于最后报告数字；只用一次是为了不让调参间接「看过」它，报告的数字才可信。（§6.2）
4. 初始化对齐（同一组 He 数组拷进两边）、batch 顺序对齐（按 epoch 独立种子预生成置换）、数值对齐（两边都用 float64）。（§6.3）
5. `gradW` 出生时是零数组，头两步没有旧账可混；第三步起 `+=` 把历史梯度全混进来，$|\mathrm{gradW}|$ 从 3.78 涨到 9.69。（§6.4）

### $\rm \S \, 6.8.2$ 应用与辨析答案

1. 清梯度发生在反向之后，等于白清；反向在清之前执行，累积的是上上步的旧账，第一步损失不变（还没有旧账），从第二步起轨迹走偏。（§6.4）
2. 落到 float32 的舍入量级，约 ${10^{-7}}$ 上下；机器精度 ${2.2\times10^{-16}}$ 是 float64 独有的整齐。（§6.3；第 8 章实测 ${7.6\times10^{-7}}$）
3. 每 epoch 从 13 步（${\lceil 400/32\rceil}$）变成 1 步；此时「batch 梯度」就是全量梯度，这条轨迹就是（全批）梯度下降，SGD 退化成 GD。（§6.1）
4. 计算图：评估段也建图，中间量全部留着等 backward，显存随评估次数涨；`no_grad()` 是「本次前向不记账」的开关。（§6.2）
