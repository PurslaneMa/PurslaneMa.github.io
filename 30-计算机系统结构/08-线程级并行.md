# $\rm Chapter \, 8$ 线程级并行：多核、SMT 与 GPU

数据级并行把工具加宽，本章把工具复制：更多线程、更多核，直至一台几万个执行单元的 GPU。§1.2 的功耗墙说过，2005 年后频率涨不动，厂商把每年的晶体管预算改花在核数上；本章结这笔账：多核复制什么、共享什么；SMT 在一个核里塞两个线程图什么；GPU 凭什么把吞吐推高三个数量级，又凭什么不万能。真跑一个三档实验：单线程 1.0 倍，双线程挤同一逻辑核 0.98 倍，分到两个核 2.09 倍。

## $\rm \S \, 8.1$ 多核复制什么

一块多核芯片上，每个核背一整套私有机件，核与核之间共享三样。复制与共享的清单：

1. 每核私有：取指、译码、重命名、乱序调度、执行端口、L1 与 L2（本书 §3、§4 的全部家当）；
2. 全片共享：最后一级缓存 L3、内存控制器、片上互联；
3. 互联：核间的环形或网状线路，跨越的跳数就是访问邻居缓存与 L3 的额外路费。

这个清单直接决定两件事。其一，多核加速比的上限回到了 §1.3 的 Amdahl 定律：$f = 0.95$ 的程序在无穷核上也只值 20 倍，买 32 核机器跑串行代码是把 96% 的硅片晾着。其二，各核的 L1/L2 各写各的，立刻撞上上一章的问题：同一地址在多个核的缓存里各有拷贝，MESI 就是多核时代书桌间的记账员。

「复制什么、共享什么」还是一道设计题。复制得越多，单核性能越差（预算摊薄、核间距离拉长），共享得越多，一致性流量越贵。服务器芯片堆 64 核共享 L3 与内存通道，缓存命中率被邻居的分赃行为左右；这是操作系统册 §3.7「I/O 密集与 CPU 密集」的硬件版：负载的形状决定哪种复制划算。

**本节小结**：多核芯片每核留一整套私有执行机件，L3 与内存通道全片共享；私有引出上一章的 MESI 记账，共享引出 Amdahl 的串行封顶与邻居互踢。复制与共享的配比是一道随负载形状而变的设计题。

## $\rm \S \, 8.2$ SMT：一个核跑两个线程

核内常有富余：乱序窗口里的指令卡在缓存缺失上，执行端口一半在打瞌睡（§5.1 的延迟账：内存 100 ns 够 ALU 跑几百拍）。**同时多线程（SMT，simultaneous multithreading），x86 商品名超线程**，把架构状态复制一份（两套寄存器、两个程序计数器），前端轮流给两个线程发指令，执行端口、缓存谁有空谁用：一个线程等内存时，另一个占着 ALU 干活。复制的是记账簿（几 KB 的寄存器堆），共享的是真正贵的部件（执行端口、缓存、TLB），所以性价比极高，代价是两线程互相争抢时各自变慢。

实验量化这三档（C + pthread，每线程跑四条互不依赖的整数反馈链作纯计算负载，总迭代数固定；`sched_setaffinity` 绑核；WSL2、gcc 13.3.0 `-O2`，各档取 3 次最快）：

```c
for (i = 0; i < n; i++) {
    a += K1; a ^= a >> 30; a *= K2;   /* 这样的链共四条，互不依赖 */
}
```

| 摆法 | 总耗时 | 吞吐 |
| --- | --- | --- |
| 1 线程，绑 cpu0 | 3.478 s | 1.00 倍 |
| 2 线程，都绑 cpu0 | 3.554 s | 0.98 倍 |
| 2 线程，cpu0 + cpu2 | 1.666 s | 2.09 倍 |

三行三个故事。同一逻辑核上的「双线程」只是分时复用，计算量不变时间就不变（0.98 倍，多出的 2% 是切换开销）；分到两个核，吞吐 2.09 倍，略超 2 的部分来自本机 vCPU 频率不对称与取最快的抖动，如实报告。一个诚实的括号：本机 WSL2 把拓扑报告为 16 核 16 线程（每核 1 线程），虚拟机里看不到 SMT 的兄弟线程，「同核」档量的是分时而非真 SMT；文献口径里真 SMT 的收益通常在 1.2 至 1.4 倍（两线程共享一套执行端口，翻不了倍），这个数字是公开基准的量级，不是本机实测。实验把「并行」这个词拆出了三档精度：分时不是并行，真并行才翻倍，SMT 是两者之间的中间态。SMT 也不是只赚不赔：两个线程抢同一套缓存时互相踢数据，实时性敏感的场景（以及部分数据库、游戏主机的实测）里关掉 SMT 反而更快，买不买这份 1.3 倍，要看你的负载是「等内存」还是「抢缓存」。

**本节小结**：SMT 只复制几 KB 的记账簿（寄存器堆、程序计数器），共享真正贵的执行端口与缓存，用一线程的访存等待填另一线程的算力空隙，收益 1.2 至 1.4 倍量级；实测三档把分时、SMT、真并行拆成三个不同的词。下一节把「复制执行单元」推到极致看 GPU。

## $\rm \S \, 8.3$ GPU 的组织：几千个小核与延迟隐藏

GPU 把「复制执行单元」推到极致，复制方式与 CPU 相反：CPU 的核大而少（复杂乱序、大缓存、强分支预测），GPU 的核小而多（成千上万个简单流水线，弱分支、小缓存）。它的组织从上到下四层：

1. GPU 整片：几十到上百个**流多处理器（SM，streaming multiprocessor）**；
2. 每个 SM：上百个简单执行单元加一大片寄存器堆，管着几千个在册线程；
3. **线程束（warp）**：32 个线程捆成一束，走完全相同的指令序列（§7.3 掩码执行的万人版，分支不齐的线程束按「都做再挑」收费）；
4. 显存：GDDR 或 HBM，带宽以 TB/s 计，是 CPU 内存的十倍以上，但单次延迟同样上百拍。

GPU 的生存法则是**延迟隐藏（latency hiding）**：调度器在一个 warp 卡在访存时零成本切换到另一个就绪的 warp，用几百个在飞线程把访存延迟填满。CPU 与 GPU 是同一道题的两种解法：

1. CPU：乱序窗口在几百条指令里找不依赖的活（§4.4），窗口有限，故要大缓存与强预测；
2. GPU：放弃深窗口，用线程数量填，warp 切换不花流水线冲刷的钱。

两套机器的分工画成一张表：

| 维度 | CPU 大核 | GPU |
| --- | --- | --- |
| 单线程延迟 | 乱序 + 大缓存，压到底 | 不隐藏单线程延迟，靠别的 warp 填 |
| 分支 | 预测器伺候，错了罚十几拍 | warp 内不齐就全按掩码收费 |
| 强项 | 分支密集、串行依赖链 | 规则的批量乘加、高吞吐 |
| 典型带宽 | 内存几十 GB/s | 显存以 TB/s 计 |

深度学习分册第 2 章的 AlexNet 故事（2012 年 CNN + GPU 组合拳）与本站 AI 工程册第 33 章的推理成本账，落点都在这张表的右列：神经网络的训练是规则乘加的海啸，没有分支纠缠，天生住在 GPU 那一行。一个边界声明：本机没有独立 GPU 可做实测，本节与 §8.4 的 GPU 数字是公开规格与教科书口径的量级，不是本机实验；CPU 侧三档（§8.2）才是本机实测。

**本节小结**：GPU 用「极简核 × 海量线程」换吞吐，warp 是 32 线程同指令的执行单位（§7.3 掩码逻辑的万人版），延迟隐藏靠零成本 warp 切换填访存空隙——CPU 用深窗口和大缓存压单线程延迟，GPU 干脆不压、用人数填。下一节算 GPU 自己的缓存行账：访存合并。

## $\rm \S \, 8.4$ 访存合并：GPU 版的缓存行账

几千个执行单元挤一条显存总线，地址怎么发是生死问题。**访存合并（coalescing）**：一个 warp 的 32 个线程若访问连续地址，硬件把它们合成尽量少的缓存行事务。手算这笔账：

| warp 的 32 个线程 | 总字节 | 缓存行事务 | 相对运费 |
| --- | --- | --- | --- |
| 连续 float（步长 1） | 128 | 2 | 1 倍 |
| 步长 32 个 float | 128 | 32 | 16 倍 |
| 读转置（跨行取列） | 128 | 32 | 16 倍 |

步长版每次访问各占一条自己的行，32 次事务只喂 32 个数，运费涨 16 倍。跟 §5.3 的跨步实验一模一样的病，只是病人换成了 warp。所以 GPU 代码的第一纪律是把数据布局对齐到「相邻线程访问相邻地址」，转置、padding、SoA 布局，全为这一条服务。

收拢本章：并行有三个台阶，SMT 榨一个核的空隙（1.2 至 1.4 倍量级），多核复制整核（理想线性，被 Amdahl 封顶），GPU 复制到极简核 + 极多线程（吞吐三数量级，代价是编程模型与访存纪律）。三个台阶共用一张体检表：

1. 负载里有多少可并行的规则计算，决定吞吐上限（Amdahl 的 $f$）；
2. 有多少分支与依赖，决定 CPU/GPU 分界；
3. 数据供给跟不跟得上，决定实际落点（账法同 §7.4）。

## $\rm \S \, 8.7$ 本章自测答案

> 先闭卷作答 §8.5 与 §8.6，再核对。

### $\rm \S \, 8.7.1$ 关键概念回顾答案

1. 私有：取指、译码、重命名、乱序调度、执行端口、L1/L2；共享：L3、内存控制器、片上互联。私有意味着各核要自己的一致性记账（MESI），共享意味着总供给有限，多核抢带宽回到串行占比的封顶，即 Amdahl。（§8.1）
2. 复制架构状态（寄存器堆、程序计数器），共享执行端口、缓存、TLB。簿记便宜所以性价比高；贵的部件没复制，两线程挤同一个端口池，收益只能来自填缝隙，故 1.2 至 1.4 倍量级。（§8.2）
3. 同核档量分时复用（0.98 倍），分核档量真并行（2.09 倍），单线程档是基准。「都绑 cpu0」的同一时刻只有一个线程在跑，计算总量不变时间不变，只是轮流上。（§8.2）
4. 32 个线程一束、同指令序列。访存卡住的 warp 被挂起，调度器立刻切到就绪 warp，用海量在飞线程填满延迟；CPU 靠乱序窗口在几百条指令里找不依赖的活，窗口小得多。（§8.3）
5. 连续：128 字节 = 2 条缓存行，2 次事务；跳开：32 条各自独立的行，32 次事务，运费 16 倍。（§8.4）
6. 可并行的规则计算占比（上限）、分支与依赖密度（CPU/GPU 分界）、数据供给带宽（实际落点）。（§8.4）
7. L3 是容量上的省钱术（一份大缓存服务所有核），也是风险上的公地：邻居把行踢进 L3，你的缺失率跟着涨，账记在你的延迟上；任务编排（操作系统册 §3）要考虑这个邻居效应。（§8.1）

### $\rm \S \, 8.7.2$ 应用与辨析答案

1. I/O 密集线程经常让出端口等访存，恰把空隙让给 CPU 密集线程，SMT 的填缝隙逻辑在负载混搭时收益最大；单一负载自己跟自己抢端口，收益小。（§8.2）
2. 病因一：batch 太小，warp 太少填不满延迟，修法：加大 batch；病因二：访存不合并（§8.4 的 16 倍运费），修法：改数据布局对齐相邻线程；病因三：分支纠缠严重或算子太碎，修法：合并小算子、减少 warp 内分歧。（§8.3、§8.4）
3. 连续访问：每 warp 128 字节一档、2 行事务；按列：每线程跳 $10^4 \times 8$ 字节，每线程独占一条行，32 行事务，差 16 倍，乘上矩阵乘的访存总量就是运行时间差。（§8.4）
4. GPU 赌「分支少、来了就按掩码全算」，省掉预测器与深流水线换更多执行单元；CPU 赌「预测多半对」，赌错付十几拍冲刷。负载形状决定谁赌赢。（§8.3）
5. 更大的核意味着更深的乱序窗口、更大的缓存与更长的关键路径，单线程收益早就边际递减（§4.4 的 IPC 停在个位数）；同样的晶体管复制成更多核，至少在可并行负载上按核数兑现，这是功耗墙后的行业选择。（§8.1、§1.2）
