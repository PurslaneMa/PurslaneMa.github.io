# $\rm Chapter \, 1$ 浮点：IEEE 754 与舍入误差

本站连续数学册 §1.7 留过一句警告：「浮点不是实数」。本册把这句话展开成一门账学：计算机里的数是有限格网上的点，每步运算都把精确结果贴回格网，误差从哪里来、长多大、怎么压，每一条都要能算出数来。本章先算「表示」这一笔账：一个数装进 64 位时丢了什么；下一章再算「公式」那一笔：公式本身近似时又丢什么。两笔账在第 2 章 §2.2 的差分步长选择上正面相遇。

> **开始前自检**：本章假设你已经会：
>
> 1. □ 二进制与十六进制记数、科学记数法（高中），§1.1 把浮点读成二进制的科学记数法；
> 2. □ 实数的稠密性与「格网点之间有空隙」的图景（连续数学册 §1.2、§1.7），§1.2 的 $\varepsilon_{\rm mach}$ 就是给空隙定量；
> 3. □ 无穷小记号 $o(\cdot)$ 与相对误差的量级语言（连续数学册 §3.1），§1.3 分析抵消时用它分账；

## $\rm \S \, 1.1$ 一串二进制的科学记数法

IEEE 754 双精度（double precision）把 64 位分成三段：1 位符号 $s$、11 位指数 $e$、52 位尾数 $f$，代表的数是

$$
(-1)^s \times 1.f \times 2^{\,e-1023}
$$

读法与十进制科学记数法 $3.14\times10^2$ 同构：尾数管「有几位有效数字」，指数管「数有多大」。尾数首位那个 1 不占存储（正规数隐含），所以有效位数实为 53 位二进制，约 $53\log_{10}2\approx 15.9$ 位十进制。相邻两个浮点数的间距不是均匀的：在二进制段 $[2^k,\,2^{k+1})$ 内间距恒为 $2^{k-52}$，段每翻一倍、间距跟着翻倍。大数稀、小数密，这是浮点与实数的第一条结构差异。

0.1 为什么存不准：把它写成 $2^{-4}$ 的科学记数法，尾数是 $1.10011001100\ldots_2$，二进制下无限循环，52 位装不下。实际存的是最近的浮点数，用十六进制看一清二楚：

```python
>>> (0.1).hex(), (0.2).hex(), (0.3).hex()
('0x1.999999999999ap-4', '0x1.999999999999ap-3', '0x1.3333333333333p-2')
>>> (0.1 + 0.2).hex()
'0x1.3333333333334p-2'
```

0.1 与 0.2 各自带着一点向上舍入的偏差，相加后落在 $0.3$ 的编码旁边：末位是 `...4` 而真值 $0.3$ 的最近编码是 `...3`，十进制打印出来就是 `0.30000000000000004`。数学上 $0.1+0.2=0.3$ 严格成立；浮点里成立的是「三者的最近可表示点不同」。本站连续数学册把实数造成完备空间（§1.4 的 Cauchy 准则），浮点格网连 Cauchy 列都装不下：一列浮点数可以步步相减变小却极限落空。

## $\rm \S \, 1.2$ 机器 epsilon 与舍入

把空隙定量的尺是机器 epsilon（machine epsilon）：1 与下一个浮点数的距离，双精度是 $2^{-52}=2.22\times10^{-16}$。用 `np.nextafter` 现场量：

```python
>>> np.nextafter(1.0, 2.0) - 1.0     # 2.220446049250313e-16
>>> np.spacing(2.0**52), np.spacing(2.0**53)
(1.0, 2.0)
>>> 2.0**53 + 1.0 == 2.0**53
True
```

三条读数：其一，间距在 $2^{52}$ 处恰好是 1.0，翻到 $2^{53}$ 处变成 2.0；其二，$2^{53}+1$ 落在格点之间，被舍回 $2^{53}$，于是「双精度能精确表示所有不超过 $2^{53}\approx9\times10^{15}$ 的整数」是精确边界而非口号；其三，单精度 $\varepsilon_{\rm mach}=2^{-23}\approx1.19\times10^{-7}$，约 7 位十进制有效数字，这就是深度学习用 float32 训练时 loss 只在第七位附近抖动的账本来源。

舍入（round to nearest）规则：每次运算先把结果按实数算准，再贴到最近的格点，相对误差不超过 $\varepsilon_{\rm mach}/2$。单步误差小到可以忽略，麻烦全部在累积：一百万步之后还剩多少，§1.4 实测。这里先把纪律立起来：**两个公式在实数算术下等价，在浮点算术下未必**，因为浮点加法不满足结合律（§1.4 的实验直接展示），任何「数学上等价」的改写都要重新过一遍误差账。

## $\rm \S \, 1.3$ 灾难性抵消

**灾难性抵消（catastrophic cancellation）**：两个相近的数相减，前导数字互相抵消，差变小，而两数自带的绝对误差原样留下，除以变小的差之后相对误差暴涨。账目：$a$、$b$ 各带相对误差 $\varepsilon_{\rm mach}/2$，则 $a-b$ 的绝对误差约 $\varepsilon_{\rm mach}\lvert a\rvert/2$；真差 $\lvert a-b\rvert$ 比 $\lvert a\rvert$ 小多少倍，相对误差就放大多少倍。

第一个实例来自求根公式。解 $x^2-10^8x+1=0$：两根之积为 $c/a=1$，大根约 $10^8$，小根应为 $10^{-8}$。直接套公式（float64）：

```python
>>> a, b, c = 1.0, -1e8, 1.0
>>> d = (b*b - 4*a*c) ** 0.5
>>> x1, x2 = (-b + d) / (2*a), (-b - d) / (2*a)
>>> x2, x1 * x2
(7.450580596923828e-09, 0.7450580596923828)
```

小根算出 $7.45\times10^{-9}$，错了四分之一；验算 $x_1x_2=0.745\ne1$ 抓住了它。坏在哪一步：$\sqrt{b^2-4ac}\approx10^{16}$ 与 $\lvert b\rvert=10^8$ 相加时，真实差 $10^{-8}$ 藏在第 24 位有效数字里，早已被舍掉。稳定写法先用公式算大根 $x_1$（无抵消），再用 Vieta 恒等式 $x_2 = c/(a\,x_1)$ 重构小根，得 $10^{-8}$ 精确，$x_1x_2=1.0$。恒等式在这里不是装饰，是验算器与稳定化器的双重身份。

第二个实例是方差公式的两种写法：$\mathrm{Var}=\mathrm{E}[X^2]-\mathrm{E}[X]^2$ 对 $\frac1n\sum_i (x_i-\bar x)^2$。数据取 $10^4$ 附近的噪声（真方差约 1）：

| 写法 | float64 结果 | float32 结果 |
| --- | --- | --- |
| $\mathrm{E}[X^2]-\mathrm{E}[X]^2$ | $0.9946864545$ | $16.0$ |
| 先减均值再平方平均 | $0.9946864529$ | $0.9946866$ |

float64 下第一种写法只坏到第九位（$\mathrm{E}[X^2]\approx10^8$，前八位在相减时抵消）；float32 下它给出 16.0，答案错了 15 倍，完全报废。numpy 的 `np.var` 用的是先减均值的写法，这不是风格选择，是误差账算出来的。

## $\rm \S \, 1.4$ 求和的顺序：一百万个 float32

浮点加法不满足结合律，顺序本身就是变量。实验：$n=10^6$ 个 $[0,1)$ 均匀随机数（`np.random.seed(0)`），存成 float32，四种方法求和，真值用 float64 的 `math.fsum` 逐个累加得 $500396.952189$：

| 方法 | 结果 | 相对误差 |
| --- | --- | --- |
| 顺序累加（float32） | $500381.06$ | $3.2\times10^{-5}$ |
| `np.sum`（成对求和） | $500396.94$ | $2.9\times10^{-8}$ |
| `math.fsum`（精确累加器） | $500396.952189$ | $0$ |
| Kahan 补偿求和（float32） | $500396.94$ | $2.9\times10^{-8}$ |

顺序累加错了约 16：每次相加的舍入误差像随机游走一样累积，$10^6$ 步走出 $10^{-7}\times\sqrt{10^6}$ 量级。`np.sum` 默认成对求和（pairwise summation）：把数组劈两半各自求和再相加，树状结构把误差增长压到 $O(\varepsilon\log n)$。Kahan 求和是另一条路，核心五行：

```python
s = np.float32(0); c = np.float32(0)
for v in xs:
    y = v - c                      # 把上一步丢掉的量找回来
    t = s + y
    c = (t - s) - y                # 记下这一步被舍掉的部分
    s = t
```

每步把上次丢失的量 $c$ 加回本次加数，再把新丢失的量记进 $c$。最小演示（float32）：$10^8$ 后面跟 1000 个 1，顺序累加得 $10^8$，1000 个 1 全被间距吞掉；Kahan 得 $100001000$，分毫不差。两种方法在上一张大表里都达到 float32 能表达的最好答案（真值贴到格网正是 500396.94），而 Kahan 的代价是每步 4 次运算换 1 次加法。要既快又准，float64 加成对求和通常已经够用；对精度偏执的场合（账务、长程模拟）用 `math.fsum`，它维护一个精确累加器，误差为零。

求和顺序在实践里的影子：并行归约的顺序随线程数改变，同一个训练脚本换一张卡，loss 末几位就不同（本站深度学习分册的训练实验里出现过）。连续数学册 §4.2 讲实数级数的重排可以改变和，那需要无穷项；浮点的重排不需要无穷项，一百万项就够。

## $\rm \S \, 1.6$ 应用与辨析

1. 判断并说明理由：「双精度能精确表示所有不超过 $2^{53}$ 的整数，所以任何 double 运算的误差都不超过第 16 位有效数字。」
2. 给 float32 构造一组最少数据的序列，使顺序求和与 `math.fsum` 的结果相差超过 1%，并解释构造原理。
3. 同一个训练脚本在两张显卡上跑，loss 的前几位一致、末几位不同。用本章哪条原理解释？这算不算 bug？
4. 本章用 $x_1x_2=c/a$ 当验算器。再找一个可以用恒等式当数值验算器的场景，写出验算式与失败时的读数。
5. `np.arange(0, 1, 0.1)` 与 `np.linspace(0, 1, 11)` 都想生成 0.1 步长的格点，两者的元素可能相差一个 $\varepsilon_{\rm mach}$ 量级。用本章的表示账解释差别来自哪里。

## $\rm \S \, 1.7$ 本章自测答案

> 先闭卷作答上面两节，再核对。

### $\rm \S \, 1.7.1$ 关键概念回顾答案

1. 1 位符号、11 位指数、52 位尾数，代表 $(-1)^s\times1.f\times2^{e-1023}$；与科学记数法同构（尾数管精度、指数管量级），且尾数首位 1 隐含，有效位 53 位二进制。间距在 $[2^k,2^{k+1})$ 内为 $2^{k-52}$，段翻倍间距翻倍，大数稀、小数密。（§1.1）
2. 0.1 的二进制尾数 $1.1001100\ldots_2$ 无限循环，52 位装不下，存的是最近舍入值 $0\mathrm{x}1.999999999999\mathrm{ap}{-4}$；$0.1+0.2$ 的编码末位是 `...4`，而 0.3 的最近编码末位是 `...3`，相差一个 $\varepsilon_{\rm mach}$ 量级。（§1.1）
3. 定义是 1 与下一个浮点数的距离，双精度 $2^{-52}=2.22\times10^{-16}$；$53\log_{10}2\approx15.9$。`np.spacing(2.0**52)=1.0`、`np.spacing(2.0**53)=2.0`，说明间距跨段翻倍，$2^{53}+1$ 被舍回 $2^{53}$，是整数精确表示的硬边界。（§1.2）
4. 相近数相减时绝对误差不变（约 $\varepsilon_{\rm mach}\lvert a\rvert/2$）、真差变小，相对误差放大 $\lvert a\rvert/\lvert a-b\rvert$ 倍。小根 $\lvert-b-\sqrt{b^2-4ac}\rvert$ 是两个大数之差，前导位全部抵消；Vieta 重构 $x_2=c/(ax_1)$ 用除法代替减法，绕开抵消，实测把 $7.45\times10^{-9}$ 修成精确的 $10^{-8}$。（§1.3）
5. 坏在 $\mathrm{E}[X^2]-\mathrm{E}[X]^2$ 的减法：$\mathrm{E}[X^2]\approx10^8$ 与 $\mathrm{E}[X]^2\approx10^8$ 相减，float32 的 7 位有效数字在相减后一位不剩，剩下的全是误差；先减均值把减法挪到 $O(1)$ 量级再做，抵消消失。（§1.3）
6. $c$ 记上一次加法被舍掉的部分 $c=(t-s)-y$，下次先做 $y=v-c$ 找回；大项之后跟一串小项时，顺序累加的小项全被间距吞掉，Kahan 把它们攒进 $c$ 逐次找回，实测 1000 个 1 一个不丢。（§1.4）

### $\rm \S \, 1.7.2$ 应用与辨析答案

1. 前半句对，后半句错。整数边界只管「存」，不管「算」：每次运算都要舍入（相对误差至多 $\varepsilon_{\rm mach}/2$），灾难性抵消能把相对误差放大任意多倍（§1.3 的求根公式错 25%，方差公式在 float32 下错 15 倍）。（§1.2、§1.3）
2. 例如 $[10^8,\,1]$（float32）：精确和 $100000001$，顺序和为 $10^8$（间距是 8，1 被吞），相对误差 $10^{-8}$ 不够 1%；把 1 换成更大的丢失量或把 $10^8$ 换成更小的底数即可放大。原理：加数与部分和的量级差超过 $\varepsilon_{\rm mach}$ 的倒数时，小加数整体被舍掉。（§1.4）
3. 并行归约与算子融合改变了求和（及归约）的顺序，浮点加法不满足结合律，顺序即结果；末位差异是浮点算术的固有性质，不是 bug，判断正确性的口径应放到容忍带而不是末位相等。（§1.4）
4. 例如解线性方程组后代入原方程算残差 $\lVert A\hat x-b\rVert$（第 4 章 §4.3 会正式用它）：残差小只说明解满足方程，若残差大则求解过程必有错。恒等式验算的通则：选一个真值已知的量（积、和、残差），算它的数值偏差。（§1.3）
5. `arange` 从 0 开始逐步加 0.1，每步在舍入后的值上再加，误差逐步累积；`linspace` 直接算 $i/10$，一次舍入到位。两者在第 3 个点就出现 $0.30000000000000004$ 对 $0.3$ 的差别，逐点比较时要用容差而不是相等。（§1.1、§1.2）
