**Step 3：实现核心逻辑**

`paper.cpp`：

```cpp
#include "paper.hpp"
#include <fstream>
#include <sstream>
#include <algorithm>
#include <cctype>

std::vector<Paper> read_papers(const std::string& filepath) {
    std::vector<Paper> papers;
    std::ifstream file(filepath);
    if (!file.is_open()) {
        return papers;  // 调用方检查空 vector
    }
    std::string line;
    while (std::getline(file, line)) {
        if (line.empty() || line[0] == '#') continue;  // 跳过空行和注释
        std::stringstream ss(line);
        std::string title, year_str, venue, citations_str;
        std::getline(ss, title, '|');
        std::getline(ss, year_str, '|');
        std::getline(ss, venue, '|');
        std::getline(ss, citations_str, '|');
        if (title.empty()) continue;
        papers.push_back({
            title,
            std::stoi(year_str),
            venue,
            std::stoi(citations_str)
        });
    }
    return papers;
}

std::vector<Paper> filter_by_year(const std::vector<Paper>& papers,
                                   int min_year, int max_year) {
    std::vector<Paper> result;
    std::copy_if(papers.begin(), papers.end(), std::back_inserter(result),
        [&](const Paper& p) { return p.year >= min_year && p.year <= max_year; });
    return result;
}

std::vector<Paper> filter_by_keyword(const std::vector<Paper>& papers,
                                      const std::string& keyword) {
    std::vector<Paper> result;
    std::string kw_lower = keyword;
    std::transform(kw_lower.begin(), kw_lower.end(), kw_lower.begin(),
                   [](unsigned char c) { return std::tolower(c); });
    std::copy_if(papers.begin(), papers.end(), std::back_inserter(result),
        [&](const Paper& p) {
            std::string title_lower = p.title;
            std::transform(title_lower.begin(), title_lower.end(),
                           title_lower.begin(),
                           [](unsigned char c) { return std::tolower(c); });
            return title_lower.find(kw_lower) != std::string::npos;
        });
    return result;
}
```

**Step 4：编写入口**

`main.cpp`：

```cpp
#include <iostream>
#include "paper.hpp"

void print_usage() {
    std::cerr << "Usage: paper-cli <datafile> [options]\n"
              << "  --year MIN-MAX     Filter by year range\n"
              << "  --keyword WORD     Filter by title keyword\n"
              << "  --top N            Show top N by citations\n"
              << "  --help             Show this message\n";
}

int main(int argc, char* argv[]) {
    if (argc < 2) {
        print_usage();
        return 1;
    }

    std::string filepath = argv[1];
    auto papers = read_papers(filepath);
    if (papers.empty()) {
        std::cerr << "Error: no papers loaded from " << filepath << '\n';
        return 2;
    }

    // 解析可选参数
    for (int i = 2; i < argc; ++i) {
        std::string arg = argv[i];
        if (arg == "--help") {
            print_usage();
            return 0;
        } else if (arg == "--year" && i + 1 < argc) {
            std::string range = argv[++i];
            auto dash = range.find('-');
            int min_y = std::stoi(range.substr(0, dash));
            int max_y = std::stoi(range.substr(dash + 1));
            papers = filter_by_year(papers, min_y, max_y);
        } else if (arg == "--keyword" && i + 1 < argc) {
            papers = filter_by_keyword(papers, argv[++i]);
        } else if (arg == "--top" && i + 1 < argc) {
            int n = std::stoi(argv[++i]);
            std::sort(papers.begin(), papers.end(),
                [](const Paper& a, const Paper& b) {
                    return a.citations > b.citations;
                });
            if (static_cast<int>(papers.size()) > n)
                papers.resize(n);
        }
    }

    // 输出结果
    for (const auto& p : papers) {
        std::cout << p.title << " (" << p.year << ") "
                  << p.venue << " - " << p.citations << " citations\n";
    }
    std::cerr << papers.size() << " papers found.\n";
    return 0;
}
```

### 代码解释

- `read_papers`：逐行读取、按 `|` 分割、构造 `Paper` 结构体。空行和以 `#` 开头的注释行被跳过。
- `filter_by_year` / `filter_by_keyword`：使用 `std::copy_if` + lambda 实现声明式筛选——你说"要什么条件"，而非"怎样循环"。
- `main`：`argv[1]` 是数据文件路径；后续参数按 `--flag value` 成对解析。筛选是流水线式的：先读全部，再逐步缩小范围。
- 退出码：`0` 成功，`1` 参数不足，`2` 数据加载失败。这些退出码可以被 Shell 或脚本检查。

### 验收标准

- [ ] 编译零错误零警告（`-Wall -Wextra`）
- [ ] `./paper-cli papers.txt` 输出全部 4 篇论文
- [ ] `./paper-cli papers.txt --year 2017-2020` 只输出 2017—2020 年的论文
- [ ] `./paper-cli papers.txt --keyword "Attention"` 只输出标题含 "Attention" 的论文
- [ ] `./paper-cli papers.txt --top 2` 输出引用数最高的 2 篇
- [ ] 组合筛选工作正常（如 `--year 2017-2020 --keyword "Language"`）
- [ ] 不传参数时输出用法提示，退出码为 `1`
- [ ] 指定不存在的文件时输出错误信息，退出码为 `2`

### 常见错误

| 现象 | 原因 | 排查方法 |
|------|------|---------|
| `'g++' is not recognized` | 编译器不在 PATH | 运行 `g++ --version`；安装或检查 PATH |
| `undefined reference to read_papers` | 忘记链接 `paper.cpp` | 确认命令包含 `main.cpp paper.cpp` |
| `std::stoi exception` | 数据文件格式错误（年份位置不是数字） | 检查 `papers.txt` 每行恰好 4 个 `\|` |
| 中文乱码 | 终端编码与文件编码不一致 | Windows 终端运行前执行 `chcp 65001`；文件保存为 UTF-8 |
| 输出 0 条结果 | 筛选条件过严或文件读取失败 | 先用不带参数的命令确认数据加载成功 |

### 复盘问题

1. 为什么选择 `|` 而不是逗号作为分隔符？（逗号在论文标题中可能出现，`|` 少见得多。）
2. 如果数据文件有 $10^6$ 行，当前的筛选方式有什么问题？（全部加载到内存；对大文件应逐行读取并即时筛选，不把全部数据放入 `vector`。）
3. 退出码 `0`/`1`/`2` 的约定在后续阶段会怎样被使用？（Shell 脚本和 CI 可以根据退出码决定是否继续执行后续步骤。）

**Step 3：编写清洗脚本**

`clean.py`：

```python
#!/usr/bin/env python3
"""论文数据清洗器：读取 JSON/CSV → 清洗 → 输出规范 JSON。"""
import json
import csv
import sys
from pathlib import Path


def clean_title(title):
    """去掉首尾空格；空标题或无效标题返回 None。"""
    if title is None:
        return None
    title = str(title).strip()
    return title if title else None


def clean_year(year):
    """年份必须是 1900—2099 的整数；否则返回 None。"""
    try:
        y = int(year)
        return y if 1900 <= y <= 2099 else None
    except (ValueError, TypeError):
        return None


def clean_citations(citations):
    """引用数必须是非负整数；空字符串视为 0。"""
    if citations is None or str(citations).strip() == '':
        return 0
    try:
        c = int(citations)
        return c if c >= 0 else None
    except (ValueError, TypeError):
        return None


def clean_paper(raw):
    """清洗单条论文记录，返回 dict 或 None（无效记录）。"""
    title = clean_title(raw.get('title'))
    year = clean_year(raw.get('year'))
    citations = clean_citations(raw.get('citations'))

    if title is None or year is None or citations is None:
        return None

    return {
        'title': title,
        'year': year,
        'venue': str(raw.get('venue', '')).strip() or 'Unknown',
        'citations': citations
    }


def load_json(path):
    with open(path, encoding='utf-8') as f:
        return json.load(f)


def load_csv(path):
    rows = []
    with open(path, encoding='utf-8') as f:
        reader = csv.DictReader(f)
        for row in reader:
            rows.append(row)
    return rows


def main():
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <input-dir> [output-file]", file=sys.stderr)
        sys.exit(1)

    input_dir = Path(sys.argv[1])
    output_file = sys.argv[2] if len(sys.argv) > 2 else 'papers_clean.json'

    if not input_dir.is_dir():
        print(f"Error: {input_dir} is not a directory", file=sys.stderr)
        sys.exit(2)

    all_raw = []
    for f in input_dir.iterdir():
        if f.suffix == '.json':
            all_raw.extend(load_json(f))
        elif f.suffix == '.csv':
            all_raw.extend(load_csv(f))

    total = len(all_raw)
    cleaned = []
    for raw in all_raw:
        paper = clean_paper(raw)
        if paper:
            cleaned.append(paper)

    # 按引用数降序排列
    cleaned.sort(key=lambda p: p['citations'], reverse=True)

    with open(output_file, 'w', encoding='utf-8') as f:
        json.dump(cleaned, f, ensure_ascii=False, indent=2)

    skipped = total - len(cleaned)
    print(f"Done: {len(cleaned)} papers written to {output_file}", file=sys.stderr)
    if skipped > 0:
        print(f"  Skipped {skipped} invalid records", file=sys.stderr)


if __name__ == '__main__':
    main()
```

**Step 4：运行**

```bash
python clean.py raw/ output/papers_clean.json
```

### 代码解释

- 四个 `clean_*` 函数各自负责一种字段的验证和标准化：`clean_title` 去空格和空值，`clean_year` 校验范围，"twenty twenty three" 这种字符串会变成 `None` 从而丢弃，`clean_citations` 把空值默认为 `0`。
- `main` 遍历输入目录中的 `.json` 和 `.csv` 文件，统一加载为字典列表，再逐条清洗。清洗失败的记录被跳过，最后报告跳过了多少条。
- 输出按引用数降序排列——给后续阶段的数据库导入减少一次排序。

### 验收标准

- [ ] 虚拟环境创建成功，`python --version` 显示正确版本
- [ ] 脚本运行后 `output/papers_clean.json` 存在
- [ ] 空标题的记录被丢弃
- [ ] `"twenty twenty three"` 这种非数字年份记录被丢弃
- [ ] 空 citations 被填充为 `0`
- [ ] 输出按 `citations` 降序排列
- [ ] `stderr` 报告了跳过的记录数

### 常见错误

| 现象 | 原因 | 排查方法 |
|------|------|---------|
| `ModuleNotFoundError: No module named 'csv'` | 几乎不可能——`csv` 是标准库 | 检查是否在正确的 venv 中 (`which python`) |
| `json.decoder.JSONDecodeError` | JSON 格式错误（多余逗号、注释等） | 用 `python -m json.tool raw/file.json` 验证 |
| `UnicodeDecodeError` | 文件不是 UTF-8 | 在 `open()` 中指定正确编码如 `encoding='gbk'` |
| 输出为空数组 `[]` | 输入目录路径错误或所有记录都无效 | 先打印 `len(all_raw)` 确认读取到了数据 |

### 复盘问题

1. 为什么用 Python 而不是 C++ 做数据清洗？（Python 的标准库 `json`/`csv` 和动态类型让字段级清洗写起来更快；不需要管理内存和重编译。）
2. 如果某篇论文没有 `venue` 字段会怎样？（`raw.get('venue', '')` 返回空字符串，`strip()` 后为空，最终赋值 `'Unknown'`——不会崩溃。）
3. 清洗脚本的退出码是如何被确定的？（`sys.exit(0)` 成功，`sys.exit(1)` 参数错误，`sys.exit(2)` 输入路径错误——和阶段一的 C++ 程序遵循相同约定。）

**Step 1：编写建表 SQL**

`schema.sql`：

```sql
-- 论文主表
CREATE TABLE IF NOT EXISTS papers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    year INTEGER NOT NULL,
    venue TEXT NOT NULL DEFAULT 'Unknown',
    citations INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 标签表
CREATE TABLE IF NOT EXISTS tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE
);

-- 论文-标签 多对多关系
CREATE TABLE IF NOT EXISTS paper_tags (
    paper_id INTEGER NOT NULL,
    tag_id INTEGER NOT NULL,
    PRIMARY KEY (paper_id, tag_id),
    FOREIGN KEY (paper_id) REFERENCES papers(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE
);

-- 笔记表（每篇论文可有多条笔记）
CREATE TABLE IF NOT EXISTS notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    paper_id INTEGER NOT NULL,
    content TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    FOREIGN KEY (paper_id) REFERENCES papers(id) ON DELETE CASCADE
);

-- 常用查询加速
CREATE INDEX IF NOT EXISTS idx_papers_year ON papers(year);
CREATE INDEX IF NOT EXISTS idx_papers_citations ON papers(citations);
CREATE INDEX IF NOT EXISTS idx_paper_tags_paper ON paper_tags(paper_id);
CREATE INDEX IF NOT EXISTS idx_paper_tags_tag ON paper_tags(tag_id);
```

**Step 2：编写数据导入脚本**

`seed.py`：

```python
#!/usr/bin/env python3
"""将清洗后的 JSON 数据导入 SQLite，并添加示例标签和笔记。"""
import json
import sqlite3
import sys
from pathlib import Path


def init_schema(conn, schema_path):
    with open(schema_path, encoding='utf-8') as f:
        conn.executescript(f.read())


def insert_papers(conn, papers):
    for p in papers:
        conn.execute(
            "INSERT INTO papers (title, year, venue, citations) VALUES (?, ?, ?, ?)",
            (p['title'], p['year'], p['venue'], p['citations'])
        )


def add_sample_tags(conn):
    """为每篇论文自动添加基于 venue 和年份的示例标签。"""
    tags = {}
    for (tag_name,) in conn.execute("SELECT DISTINCT venue FROM papers"):
        if tag_name and tag_name != 'Unknown':
            tags[tag_name] = tag_name
    # 添加几个手工标签
    for name in ['deep-learning', 'nlp', 'computer-vision', 'foundation-model']:
        tags[name] = name

    for name in tags.values():
        conn.execute("INSERT OR IGNORE INTO tags (name) VALUES (?)", (name,))

    # 为每篇论文按 venue 自动打标
    for (paper_id, venue) in conn.execute("SELECT id, venue FROM papers"):
        if venue in tags:
            tag_id = conn.execute(
                "SELECT id FROM tags WHERE name = ?", (venue,)
            ).fetchone()[0]
            conn.execute(
                "INSERT OR IGNORE INTO paper_tags (paper_id, tag_id) VALUES (?, ?)",
                (paper_id, tag_id)
            )


def main():
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <papers_clean.json>", file=sys.stderr)
        sys.exit(1)

    json_path = Path(sys.argv[1])
    if not json_path.is_file():
        print(f"Error: {json_path} not found", file=sys.stderr)
        sys.exit(2)

    with open(json_path, encoding='utf-8') as f:
        papers = json.load(f)

    conn = sqlite3.connect('papers.db')
    conn.execute("PRAGMA foreign_keys = ON")

    init_schema(conn, 'schema.sql')
    insert_papers(conn, papers)
    add_sample_tags(conn)

    conn.commit()

    # 验证
    paper_count = conn.execute("SELECT COUNT(*) FROM papers").fetchone()[0]
    tag_count = conn.execute("SELECT COUNT(*) FROM tags").fetchone()[0]
    print(f"Imported: {paper_count} papers, {tag_count} tags", file=sys.stderr)

    conn.close()


if __name__ == '__main__':
    main()
```

### 代码解释

- `PRAGMA foreign_keys = ON`：SQLite 默认不强制外键约束，需要手动开启。否则删除论文时不会级联删除关联的 `paper_tags` 和 `notes`。
- `INSERT OR IGNORE`：标签名有 UNIQUE 约束，重复插入时静默跳过而非报错。
- 索引 `idx_papers_year` 和 `idx_papers_citations` 加速后续阶段的按年份和引用数排序查询。
- `add_sample_tags` 是一个简化的自动打标：把 venue 当作标签，再加几个手工标签。真实场景中你会从关键词、摘要或外部 API 获取标签。

### 验收标准

- [ ] `papers.db` 文件生成成功
- [ ] `SELECT COUNT(*) FROM papers` 返回正确数量
- [ ] `tags` 和 `paper_tags` 表有关联数据
- [ ] 外键约束生效：删除一篇论文后，关联的 `paper_tags` 和 `notes` 也被删除
- [ ] `.schema papers` 显示所有字段和约束正确

### 常见错误

| 现象 | 原因 | 排查方法 |
|------|------|---------|
| `no such table: papers` | 未执行 `schema.sql` | 确认 `init_schema` 调用在 `insert_papers` 之前 |
| `FOREIGN KEY constraint failed` | 引用了不存在的 paper_id 或 tag_id | 先确认主表中有对应记录 |
| `UNIQUE constraint failed: tags.name` | 重复插入相同标签名，且未使用 `OR IGNORE` | 改用 `INSERT OR IGNORE` |
| 数据重复导入 | 多次运行 `seed.py` | 导入前加 `DELETE FROM papers` 或在建表时用 `DROP TABLE IF EXISTS` |

### 复盘问题

1. 为什么选择 SQLite 而不是 MySQL/PostgreSQL？（SQLite 不需要安装服务器、不需要配置用户和权限、数据就是一个文件——对学习和本地项目最友好。第 24 章讲了何时需要切换到客户端-服务器数据库。）
2. `paper_tags` 表的 `PRIMARY KEY (paper_id, tag_id)` 有什么作用？（保证同一篇论文不会被打上同一个标签两次；同时为查询"某论文的所有标签"和"某标签的所有论文"提供了高效的索引。）
3. 如果论文数据有 $10^5$ 条，`INSERT` 逐条执行有什么问题？怎样改进？（每条 INSERT 都是一次独立事务，极慢；可以用 `executemany()` 批量插入，并在循环外包裹 `BEGIN`/`COMMIT`。）

```python
"""论文资料管理器 HTTP API"""
import sqlite3
from flask import Flask, request, jsonify, g

app = Flask(__name__)
DATABASE = 'papers.db'


def get_db():
    if 'db' not in g:
        g.db = sqlite3.connect(DATABASE)
        g.db.row_factory = sqlite3.Row  # 让查询结果可以用字段名访问
        g.db.execute("PRAGMA foreign_keys = ON")
    return g.db


@app.teardown_appcontext
def close_db(exception):
    db = g.pop('db', None)
    if db is not None:
        db.close()


def query_papers(year_min=None, year_max=None, keyword=None,
                  venue=None, sort_by='citations', order='desc',
                  limit=50, offset=0):
    """构建参数化查询，防止 SQL 注入。"""
    # 注意：sort_by 和 order 不能参数化，需要白名单校验
    ALLOWED_SORT = {'citations', 'year', 'title'}
    ALLOWED_ORDER = {'asc', 'desc'}
    if sort_by not in ALLOWED_SORT:
        sort_by = 'citations'
    if order not in ALLOWED_ORDER:
        order = 'desc'

    sql = "SELECT * FROM papers WHERE 1=1"
    params = []

    if year_min is not None:
        sql += " AND year >= ?"
        params.append(year_min)
    if year_max is not None:
        sql += " AND year <= ?"
        params.append(year_max)
    if keyword:
        sql += " AND title LIKE ?"
        params.append(f'%{keyword}%')
    if venue:
        sql += " AND venue = ?"
        params.append(venue)

    # count
    count_sql = sql.replace("SELECT *", "SELECT COUNT(*) AS cnt")
    total = get_db().execute(count_sql, params).fetchone()['cnt']

    sql += f" ORDER BY {sort_by} {order} LIMIT ? OFFSET ?"
    params.extend([limit, offset])

    rows = get_db().execute(sql, params).fetchall()
    papers = [dict(r) for r in rows]

    return {'total': total, 'limit': limit, 'offset': offset, 'papers': papers}


@app.route('/api/papers', methods=['GET'])
def list_papers():
    year_min = request.args.get('year_min', type=int)
    year_max = request.args.get('year_max', type=int)
    keyword = request.args.get('keyword')
    venue = request.args.get('venue')
    sort_by = request.args.get('sort_by', 'citations')
    order = request.args.get('order', 'desc')
    limit = request.args.get('limit', 50, type=int)
    offset = request.args.get('offset', 0, type=int)

    result = query_papers(year_min, year_max, keyword, venue,
                          sort_by, order, limit, offset)
    return jsonify(result)


@app.route('/api/papers/<int:paper_id>', methods=['GET'])
def get_paper(paper_id):
    row = get_db().execute("SELECT * FROM papers WHERE id = ?", (paper_id,)).fetchone()
    if row is None:
        return jsonify({'error': 'Paper not found'}), 404

    # 同时获取标签和笔记
    tags = get_db().execute(
        "SELECT t.name FROM tags t "
        "JOIN paper_tags pt ON t.id = pt.tag_id "
        "WHERE pt.paper_id = ?", (paper_id,)
    ).fetchall()

    notes = get_db().execute(
        "SELECT id, content, created_at FROM notes WHERE paper_id = ?",
        (paper_id,)
    ).fetchall()

    return jsonify({
        'paper': dict(row),
        'tags': [t['name'] for t in tags],
        'notes': [dict(n) for n in notes]
    })


@app.route('/api/papers', methods=['POST'])
def add_paper():
    data = request.get_json()
    if not data or 'title' not in data or 'year' not in data:
        return jsonify({'error': 'title and year are required'}), 400

    try:
        cursor = get_db().execute(
            "INSERT INTO papers (title, year, venue, citations) VALUES (?, ?, ?, ?)",
            (data['title'], int(data['year']),
             data.get('venue', 'Unknown'), int(data.get('citations', 0)))
        )
        get_db().commit()
        new_id = cursor.lastrowid
        return jsonify({'id': new_id, 'message': 'created'}), 201
    except (ValueError, sqlite3.Error) as e:
        return jsonify({'error': str(e)}), 400


@app.route('/api/venues', methods=['GET'])
def list_venues():
    rows = get_db().execute(
        "SELECT DISTINCT venue FROM papers WHERE venue != 'Unknown' ORDER BY venue"
    ).fetchall()
    return jsonify([r['venue'] for r in rows])


if __name__ == '__main__':
    # 初始化数据库（如果是首次运行）
    import os
    if not os.path.exists(DATABASE):
        conn = sqlite3.connect(DATABASE)
        with open('schema.sql', encoding='utf-8') as f:
            conn.executescript(f.read())
        conn.close()

    app.run(debug=True, port=5000)
```

### 代码解释

- `g` 是 Flask 的请求上下文对象，`get_db()` 保证每个请求只创建一次数据库连接，请求结束后自动关闭。
- `query_papers` 动态构建 SQL 但使用参数化查询（`?` 占位符）防止 SQL 注入。`sort_by` 和 `order` 不能参数化，因此使用白名单校验——任何不在白名单的值都被重置为默认值。
- 分页通过 `LIMIT` 和 `OFFSET` 实现，返回 `total` 让前端可以计算总页数。
- `GET /api/papers/<id>` 不仅返回论文本身，还附带标签列表和笔记列表——这是一次 JOIN 查询完成的工作，但为了代码清晰拆成了三步查询。生产环境中你会用更复杂的 JOIN 一次返回。
- `app.run(debug=True)` 启用热重载（修改代码后自动重启）和详细错误页面——仅在开发时使用。

- [ ] `POST /api/papers` 正确数据返回 201 和新 ID

### 常见错误

| 现象 | 原因 | 排查方法 |
|------|------|---------|
| `Address already in use` | 端口 5000 已被占用 | 换端口 `app.run(port=5001)` 或 `lsof -i :5000` 查占用进程 |
| `ImportError: No module named 'flask'` | Flask 未安装或 venv 未激活 | `pip list \| grep flask`；确认 `which python` 指向 venv |
| 返回空数组 | 数据库无数据或路径错误 | 确认 `papers.db` 在当前目录且有数据 |
| CORS 错误（前端调用时） | 默认不允许跨域 | 安装 `flask-cors` 并 `CORS(app)` |

### 复盘问题

1. 为什么 `sort_by` 不能用 `?` 参数化？（SQL 参数化只能替换值，不能替换标识符——表名、列名、ORDER BY 方向都不能参数化。因此必须用白名单校验。）
2. `row_factory = sqlite3.Row` 有什么好处？（让查询结果可以用 `row['title']` 而非 `row[0]` 访问，代码更可读，也不依赖列顺序。）
3. 如果同时有 100 个用户访问这个 API，单线程 Flask 有什么问题？（Flask 开发服务器一次只处理一个请求；生产环境需要用 gunicorn/uWSGI 启动多个 worker 进程，参见第 28 章。）

const API_BASE = 'http://127.0.0.1:5000/api';

// 页面加载时获取 venue 列表填充下拉菜单
async function loadVenues() {
    try {
        const res = await fetch(`${API_BASE}/venues`);
        const venues = await res.json();
        const select = document.getElementById('venue-filter');
        venues.forEach(v => {
            const opt = document.createElement('option');
            opt.value = v;
            opt.textContent = v;
            select.appendChild(opt);
        });
    } catch (err) {
        console.error('加载 venue 列表失败:', err);
    }
}

// 渲染论文卡片
function renderPapers(papers) {
    const container = document.getElementById('papers-container');
    if (papers.length === 0) {
        container.innerHTML = '<p class="empty">没有找到匹配的论文。</p>';
        return;
    }
    container.innerHTML = papers.map(p => `
        <article class="paper-card">
            <h3>${escapeHtml(p.title)}</h3>
            <div class="meta">
                <span class="year">📅 ${p.year}</span>
                <span class="venue">📖 ${escapeHtml(p.venue)}</span>
                <span class="citations">📊 ${p.citations} 引用</span>
            </div>
        </article>
    `).join('');
}

// 防止 XSS
function escapeHtml(text) {
    const div = document.createElement('div');
    div.textContent = text;
    return div.innerHTML;
}

// 搜索
async function search(page = 1) {
    const keyword = document.getElementById('keyword').value.trim();
    const venue = document.getElementById('venue-filter').value;
    const yearMin = document.getElementById('year-min').value;
    const yearMax = document.getElementById('year-max').value;
    const sortBy = document.getElementById('sort-by').value;
    const limit = 10;
    const offset = (page - 1) * limit;

    const params = new URLSearchParams({ limit, offset, sort_by: sortBy });
    if (keyword) params.set('keyword', keyword);
    if (venue) params.set('venue', venue);
    if (yearMin) params.set('year_min', yearMin);
    if (yearMax) params.set('year_max', yearMax);

    try {
        const res = await fetch(`${API_BASE}/papers?${params}`);
        const data = await res.json();
        renderPapers(data.papers);
        document.getElementById('stats').textContent =
            `共 ${data.total} 篇论文，显示第 ${offset + 1}–${Math.min(offset + limit, data.total)} 篇`;
        renderPagination(data.total, limit, page);
    } catch (err) {
        document.getElementById('papers-container').innerHTML =
            '<p class="error">加载失败，请确认 API 服务已启动。</p>';
        console.error('搜索失败:', err);
    }
}

function renderPagination(total, limit, current) {
    const totalPages = Math.ceil(total / limit);
    const pag = document.getElementById('pagination');
    if (totalPages <= 1) { pag.innerHTML = ''; return; }
    let html = '';
    for (let i = 1; i <= totalPages; i++) {
        html += `<button class="${i === current ? 'active' : ''}" onclick="search(${i})">${i}</button>`;
    }
    pag.innerHTML = html;
}

// 事件绑定
document.getElementById('search-btn').addEventListener('click', () => search(1));
document.getElementById('keyword').addEventListener('keydown', e => {
    if (e.key === 'Enter') search(1);
});

// 页面初始化
loadVenues();
search(1);

    border-color: var(--primary);
}

.empty, .error { text-align: center; color: var(--text-secondary); padding: 2rem; }
.error { color: #dc2626; }

### 代码解释

- `escapeHtml`：在插入用户可控数据到 DOM 前进行转义，防止 XSS 攻击。即使数据来自你自己的 API，这也是一道防御层。
- `URLSearchParams`：自动处理查询参数的编码——空格变 `%20`，中文变百分号编码。
- `fetch` 返回 Promise，`await` 等待 HTTP 响应。如果 API 未启动，`fetch` 会抛异常并被 `catch` 捕获，页面上显示友好提示而非白屏。
- 分页计算：`offset = (page - 1) * limit`。后端返回 `total` 使前端能计算总页数，而不需要猜测。
- CSS 变量（`--primary` 等）让后续调整配色时只需改一个地方。

### 操作步骤

**Step 1：准备远程服务器**

假设你有一台运行 Ubuntu 的云服务器，IP 为 `203.0.113.10`，用户为 `deploy`：

```bash
# 本地：复制项目到服务器
scp -r stage4-api deploy@203.0.113.10:/home/deploy/paper-manager/

# SSH 登录

python3 -m venv venv
source venv/bin/activate
pip install flask
```

**Step 2：编写 systemd unit 文件**

在服务器上创建 `/etc/systemd/system/paper-api.service`：

```ini
[Unit]
Description=Paper Manager API
After=network.target

[Service]
Type=simple
User=deploy
WorkingDirectory=/home/deploy/paper-manager/stage4-api
ExecStart=/home/deploy/paper-manager/stage4-api/venv/bin/python app.py
Restart=on-failure
RestartSec=5
StandardOutput=append:/home/deploy/paper-manager/logs/api.log
StandardError=append:/home/deploy/paper-manager/logs/api.log

[Install]
WantedBy=multi-user.target
```

**Step 3：启动并验证**

```bash

sudo systemctl enable paper-api       # 开机启动

# 验证
sudo systemctl status paper-api       # 应显示 active (running)
curl http://127.0.0.1:5000/api/papers # 应返回 JSON

# 查看日志
sudo journalctl -u paper-api -f       # 实时跟踪
tail -f /home/deploy/paper-manager/logs/api.log
```

**Step 4：测试崩溃重启**

```bash
# 故意杀掉进程
sudo systemctl kill -s SIGKILL paper-api

# 等 5 秒后检查状态
sleep 6
sudo systemctl status paper-api       # 应显示 active (running) —— 自动重启了
```

### 代码解释

- `Type=simple`：systemd 认为 ExecStart 启动的进程就是主服务进程。Flask 的 `app.run()` 在前台运行，适合 simple 类型。
- `Restart=on-failure`：进程异常退出时（退出码非 0 或信号终止）自动重启。`RestartSec=5` 在重启前等 5 秒，防止频繁崩溃造成"风暴"。
- `StandardOutput=append` / `StandardError=append`：把应用日志追加到文件。systemd 的 journal 也会捕获这些输出，所以两种方式都能看到日志。
- `WantedBy=multi-user.target`：系统进入多用户模式（正常的服务器状态）时启动此服务。

### 验收标准

- [ ] `systemctl status paper-api` 显示 `active (running)`
- [ ] 重启服务器后 `curl http://127.0.0.1:5000/api/papers` 仍然正常
- [ ] 杀掉进程后 5 秒内自动重启
- [ ] 日志出现在 `logs/api.log` 和 `journalctl` 中

### 常见错误

| 现象 | 原因 | 排查方法 |
|------|------|---------|
| `Failed to start paper-api.service` | unit 文件路径或 ExecStart 路径错误 | `sudo journalctl -xe` 查看详细错误；用绝对路径 |
| 服务启动了但 `curl` 无响应 | Flask 默认只监听 `127.0.0.1`，外部无法访问 | 改为 `app.run(host='0.0.0.0')`——但这应配合反向代理，不直接暴露 |
| 手动运行正常但 systemd 启动失败 | 环境变量、PATH 或工作目录不同 | 在 unit 文件中设置 `Environment=` 或 `EnvironmentFile=` |
| `Permission denied` | systemd 试图以 root 运行但不需要 | 设置 `User=deploy` 确保日志目录可写 |

### 复盘问题

1. 为什么用 systemd 而不是 `nohup python app.py &`？（systemd 提供统一的管理接口：启动、停止、重启、开机启动、崩溃恢复、日志收集——不需要记住 PID 或写 wrapper 脚本。）
2. `Restart=always` 和 `Restart=on-failure` 的区别？（`always` 即使正常退出也重启；`on-failure` 只在异常退出时重启。API 服务应该用 `on-failure`，因为你手动 `systemctl stop` 不应该触发重启。）
3. Flask 开发服务器适合生产环境吗？（不适合。`app.run()` 是单线程、单进程的开发服务器。下一阶段会用 Docker + gunicorn 替换。）

Caddy 会自动向 Let's Encrypt 申请 TLS 证书并配置 HTTPS 重定向。不需要手动操作证书文件。

### 验收标准

- [ ] `https://papers.example.com` 可以通过浏览器访问
- [ ] 地址栏显示锁图标（有效 HTTPS）
- [ ] API 可以通过 HTTPS 访问：`curl https://papers.example.com/api/papers`
- [ ] HTTP 自动重定向到 HTTPS
- [ ] 证书在 90 天内自动续期（Caddy 默认行为）

### 常见错误

| 现象 | 原因 | 排查方法 |
|------|------|---------|
| 域名访问不到 | DNS 记录未生效或防火墙未开放 80/443 | `nslookup papers.example.com`；检查安全组规则 |
| HTTPS 证书申请失败 | Let's Encrypt 无法通过 HTTP 验证域名所有权 | 确认域名已正确解析、80 端口可从公网访问、没有其他服务占用 80 |
| `too many redirects` | 反向代理和后端都在做重定向 | 只在边缘（Caddy/Nginx）做 HTTPS 重定向，内部服务用 HTTP |
| 502 Bad Gateway | 反向代理无法连接后端容器 | `docker compose ps` 确认容器运行中；检查容器名是否匹配 Caddyfile 中的 hostname |

### 复盘问题

1. 为什么在反向代理层配置 HTTPS，而不是每个容器自己配？（证书管理集中在边缘，内部容器之间用 HTTP 通信——简单且安全，因为容器网络是隔离的。）
2. Caddy 和 Nginx 的主要区别？（Caddy 自动申请和续期 HTTPS 证书，配置更短；Nginx 性能更高、插件生态更丰富、更适合高流量场景。对于本项目，Caddy 的简洁性更有优势。）
3. 把 API 直接暴露在 `5000` 端口有什么风险？（没有 TLS 加密、没有访问控制、没有限流。反向代理提供了统一的入口来做这些事情。）

## $\rm \S \, 43.12$ 阶段十一（选读）：集成小型 PyTorch 模型

### 目标

为论文管理器添加一个简单的"论文推荐"功能：基于论文标题的文本相似度，用一个小型 Sentence Transformer 模型生成嵌入向量（Embedding），存储到 SQLite，支持"查找相似论文"API。这一步验证：PyTorch 环境、模型加载、推理和结果集成。

### 前置条件

- GPU（推荐）或 CPU
- PyTorch 已安装（参见第 40 章）
- 至少 $2 \, \text{GB}$ 显存或 $4 \, \text{GB}$ 内存

### 操作步骤

**Step 1：安装依赖**

```bash
pip install torch sentence-transformers
```

**Step 2：扩展数据库**

为 `papers` 表添加 `embedding` 列：

```sql

```

**Step 3：编写嵌入生成脚本**

`scripts/generate_embeddings.py`：

```python
"""为论文标题生成嵌入向量并存入数据库。"""
import json
import sqlite3
from sentence_transformers import SentenceTransformer

DB_PATH = 'data/papers.db'
MODEL_NAME = 'all-MiniLM-L6-v2'  # 小模型，约 80 MB，CPU 也可运行

def main():
    # 加载模型（首次运行会自动下载）
    model = SentenceTransformer(MODEL_NAME)

    conn = sqlite3.connect(DB_PATH)
    rows = conn.execute("SELECT id, title FROM papers WHERE embedding IS NULL").fetchall()

    print(f"Generating embeddings for {len(rows)} papers...")
    for paper_id, title in rows:
        embedding = model.encode(title)
        # 存为 JSON 数组字符串
        emb_json = json.dumps(embedding.tolist())
        conn.execute("UPDATE papers SET embedding = ? WHERE id = ?", (emb_json, paper_id))

    conn.commit()
    conn.close()
    print("Done.")
```

**Step 4：添加"相似论文"API**

在 `app.py` 中添加：

```python
import json
import numpy as np
from sentence_transformers import SentenceTransformer

# 全局加载模型（服务启动时加载一次）
model = None

def get_model():
    global model
    if model is None:
        model = SentenceTransformer('all-MiniLM-L6-v2')
    return model


@app.route('/api/papers/<int:paper_id>/similar', methods=['GET'])
def similar_papers(paper_id):
    limit = request.args.get('limit', 5, type=int)

    # 获取目标论文的嵌入向量
    row = get_db().execute(
        "SELECT id, title, embedding FROM papers WHERE id = ?", (paper_id,)
    ).fetchone()
    if row is None:
        return jsonify({'error': 'Paper not found'}), 404
    if row['embedding'] is None:
        return jsonify({'error': 'No embedding available for this paper'}), 400

    target_emb = np.array(json.loads(row['embedding']))

    # 遍历所有有嵌入的论文，计算余弦相似度
    all_rows = get_db().execute(
        "SELECT id, title, year, venue, citations, embedding FROM papers WHERE embedding IS NOT NULL AND id != ?",
        (paper_id,)
    ).fetchall()

    results = []
    for r in all_rows:
        emb = np.array(json.loads(r['embedding']))
        # 余弦相似度
        sim = np.dot(target_emb, emb) / (np.linalg.norm(target_emb) * np.linalg.norm(emb))
        results.append({
            'id': r['id'],
            'title': r['title'],
            'year': r['year'],
            'venue': r['venue'],
            'citations': r['citations'],
            'similarity': round(float(sim), 4)
        })

    results.sort(key=lambda x: x['similarity'], reverse=True)
    return jsonify({'paper_id': paper_id, 'similar': results[:limit]})
```

### 验收标准

- [ ] `python scripts/generate_embeddings.py` 成功生成嵌入向量
- [ ] 数据库中至少有一篇论文的 `embedding` 字段非空
- [ ] `GET /api/papers/1/similar` 返回相似论文列表，每篇含 `similarity` 分数
- [ ] 相似度分数在 $0$ 到 $1$ 之间

### 常见错误

| 现象 | 原因 | 排查方法 |
|------|------|---------|
| `CUDA out of memory` | 模型太大或同时加载了多个模型 | 使用更小的模型（如 `all-MiniLM-L6-v2`），或 `model.to('cpu')` |
| 所有相似度为 0 | 嵌入全为零（模型未正确加载） | 检查 `model.encode("test")` 的输出是否非零 |
| `KeyError: 'embedding'` | 忘记执行 `ALTER TABLE` | 运行 `python scripts/generate_embeddings.py` 前先执行 SQL |
| 相似度计算极慢 | 逐条 Python 循环计算 $10^5$ 条 | 小数据集（$< 10^4$）OK；更大数据集应用 FAISS 或向量数据库 |

### 复盘问题

1. 为什么存嵌入向量而不是每次实时计算？（一次推理 vs 每次请求推理——$10^4$ 篇论文 × 每次请求重新计算是不可接受的。存嵌入是一次性计算成本，查询只是向量点积。）
2. 为什么用 Sentence Transformer 而不是 TF-IDF？（TF-IDF 只能匹配相同词汇；"deep learning" 和 "neural network" 的 TF-IDF 相似度为 0。嵌入向量能捕捉语义相似性。）
3. 这个方案的规模化瓶颈在哪？（全表扫描计算相似度是 $\mathcal{O}(n)$；$n > 10^5$ 时应使用近似最近邻索引如 FAISS。）

## $\rm \S \, 43.13$ 关键概念回顾

**Q1：为什么贯穿项目选择从 C++ CLI 开始，而不是直接从 Web 应用开始？**

> 从最熟悉的 C++ 和最简概念（文件读取、参数、标准流）出发，确保读者只承担一个新概念（项目结构）的负担。每阶段只增加一层。

**Q2：各阶段之间的数据是怎样流动的？**

> 阶段一（C++ → 标准输出）→ 阶段二（Python 读取原始文件 → 清洗 JSON）→ 阶段三（Python → SQLite）→ 阶段四（Flask → HTTP JSON）→ 阶段五（浏览器 fetch → DOM）。每个阶段的输出恰好是下一个阶段的输入。

**Q3：为什么 API 的 `sort_by` 用白名单校验而不是参数化查询？**

> SQL 参数化只能替换值，不能替换表名、列名或排序方向。白名单是防止 SQL 注入的同时允许动态排序的标准做法。

**Q4：Docker Compose 中 `depends_on` 为什么不保证服务就绪？**

> `depends_on` 只控制容器启动顺序，不等待应用层就绪（如数据库接受连接、API 开始监听端口）。健康检查 + `depends_on` 的 `condition: service_healthy` 可以弥补。

**Q5：HTTPS 证书为什么配置在反向代理层而不是每个容器中？**

> 证书管理集中在边缘，内部容器网络是隔离的。修改证书配置不需要重新构建应用容器。

## $\rm \S \, 43.14$ 应用与辨析

**Q1：如果论文数据有 $10^6$ 条，哪些阶段的设计需要修改？**

> 阶段一 C++ 不能全量加载到 `vector`；阶段三 SQLite 可能不够，考虑 PostgreSQL；阶段四 API 需要游标分页而非 OFFSET；阶段五前端需要虚拟滚动；阶段十一需要 FAISS 近似搜索替代全量余弦相似度计算。

**Q2：有人说"SQLite 不适合生产环境"，在本项目中它究竟适不适合？**

> 对于单服务器、单用户或少量并发用户的场景，SQLite 完全适合。它的限制是并发写入（单写者锁），而非数据量。如果未来需要多服务器读写同一数据库，才需要切换到客户端-服务器数据库。技术选择要匹配实际约束，不是看标签。

**Q3：这个项目还缺少哪些"真实生产环境"会有的东西？**

> 认证与授权（谁可以 POST 论文）、输入验证的严格 schema（不只是 `if not data`）、API 限流、监控告警（Prometheus + Grafana）、CI/CD 自动部署（GitHub Actions）、数据库迁移工具（Alembic）、自动化测试覆盖。这些可以作为继续深入的方向。
