# $\rm Chapter \, 2$ 自动求导：不用手推导数

上一章造出的运算对象算完就忘：`c = a * b` 执行完，`c` 不知道自己来自乘法，`a` 也不知道自己被用过。训练神经网络时，最后一步是算出损失对每一个参数的导数，好知道该把每个参数往哪个方向调；参数动辄上百万个，手推不现实。这一层能力叫自动微分（automatic differentiation，autograd），在 PyTorch 里被压成三行代码。本章前半讲这三行怎么用（`requires_grad`、`loss.backward()`、`.grad`，以及不要求导时怎么办），后半打开盖子，看清它为什么一遍反向就够，并用手推与逐数对照证明梯度确实是这么流回来的。

## $\rm \S \, 2.1$ 训练要的是梯度：三行拿到全部参数的导数

梯度（gradient）就是损失对某个参数的导数：符号说该往哪个方向调，绝对值说该调多少，优化器（optimizer）拿它决定每一步怎么改参数。PyTorch 用三行把「全部参数的梯度」一次算出来（下面代码的注释就是真跑输出；验证环境：WSL Ubuntu，PyTorch 2.14.1+cpu，float64，下同）：

```python
import torch

x = torch.tensor([1.0, 2.0], requires_grad=True)   # 声明：这个张量要梯度
w = torch.tensor([3.0, 4.0], requires_grad=True)
loss = (w * x).sum()        # 一个标量损失
loss.backward()             # 反向传播：把梯度写进各叶子
print(x.grad, w.grad)       # tensor([3., 4.]) tensor([1., 2.])
```

三个动作各司其职：`requires_grad=True` 告诉 PyTorch 从此为这个张量记账；`loss.backward()` 从损失出发反向扫一遍，把每个参数的梯度算出来；`.grad` 把结果读回来，形状与参数本身相同。这正是上一章留下的 `requires_grad` 与 `grad` 两个字段：前者是开关，后者是结果。

| 写法 | 说明 |
| --- | --- |
| `torch.tensor(data, requires_grad=True)` | 声明需要梯度，PyTorch 开始记录与它有关的运算 |
| `loss.backward()` | 从标量损失反向传播一遍，梯度写进各叶子张量 |
| `x.grad` | 读回 `x` 的梯度，与 `x` 同形状；没求过导时是 `None` |

能得到 `.grad` 的张量有个名字：叶子张量（leaf tensor），指用户直接创建、不是由别的运算算出来的张量。上面的 `x`、`w` 是叶子，`loss` 不是：`loss` 由 `w * x` 再求和得到。只有叶子的 `.grad` 会被长期保存；中间张量的梯度用一次就丢（要留得显式调 `.retain_grad()`）。这正是训练里容易踩空的地方：你只能读回自己亲手建的那些参数。

## $\rm \S \, 2.2$ 别让梯度越滚越大：zero_grad、非标量输出与 retain_graph

`backward()` 往 `.grad` 里写的方式是累加，不是覆盖。同一个叶子被两张计算图用到，两次反向的梯度就加在一起：

```python
a = torch.tensor([1.0, 2.0], requires_grad=True)
(a * 2).sum().backward()
print(a.grad)               # tensor([2., 2.])
(a * 3).sum().backward()    # 第二张图，梯度继续累加
print(a.grad)               # tensor([5., 5.])
```

5 是 2 与 3 之和，不是 3。映射到训练循环：每一步 `backward()` 都把梯度加进上一步残留的 `.grad`，不清零就一路滚大，所以训练循环每步开头要 `zero_grad()`（第 5 章把它与优化器放在一起讲）。另外还有两条规矩要记，其一，`backward()` 只对标量用，输出若是向量，得告诉它各分量按什么权重求和，最省事是每个分量权重都为 1：

```python
b = torch.tensor([1.0, 2.0], requires_grad=True)
y = b * b                              # 非标量
y.backward(torch.ones_like(y))         # 等价于对 y.sum() 求导
print(b.grad)                          # tensor([2., 4.])
```

其二，默认 `backward()` 跑完就拆图、释放中间量，想在同一张图上反向两次必须第一次就传 `retain_graph=True`：实测 `z = c * c` 带上它连跑两次，`c.grad` 从 `tensor(4.)` 累加到 `tensor(8.)`（导数是 ${2c = 4}$，两遍相加）；事后再补没有用，图已经拆了。日常训练用不到它，每个 batch 重新前向就得到新图，图用完即弃正合意。

| 写法 | 说明 |
| --- | --- |
| `zero_grad()` | 把上一轮残留的 `.grad` 清零，训练循环每步开头调用 |
| `y.backward(torch.ones_like(y))` | 输出非标量时，指定各分量的求和权重 |
| `y.backward(retain_graph=True)` | 第一次反向时保留计算图，供第二次使用 |

## $\rm \S \, 2.3$ 什么时候不该求导：no_grad 与 detach

记账不是白记的：建图要存中间量，占内存也占时间。评估模型、或者某段运算本就不要梯度时，用 `torch.no_grad()` 关掉记账；`.detach()` 则是张量级手术，从某一个张量往回切断梯度：

```python
d = torch.tensor([1.0, 2.0], requires_grad=True)
with torch.no_grad():                   # 块内所有运算都不建图
    e = d * 2
print(e.requires_grad)                  # False：块内没记账
f = d * 2
fd = f.detach()
print(fd.requires_grad, fd.grad_fn)     # False None
```

`no_grad` 是块级开关，管一整段代码；`.detach()` 只作用于一个张量，得到与原张量共享数据、但不带图的新张量。什么时候用哪样：

1. 评估与推理：整段前向套 `with torch.no_grad():`，省内存、更快（第 6 章的评估段这么做）；
2. 手动更新参数：`optimizer.step()` 内部就在 `no_grad` 下改参数，按 `.grad` 直接写数值，不再建图；
3. 把张量当常量喂进下一段计算：标签或已算好的特征先 `detach()`，防止梯度顺着它倒灌回去。

| 写法 | 说明 |
| --- | --- |
| `with torch.no_grad():` | 块内运算不建图，评估与手动更新参数时用 |
| `t.detach()` | 返回共享数据、不带图的新张量，切断回传 |

## $\rm \S \, 2.4$ 打开盖子：为什么反向模式省下 5 万倍

不打开盖子，你会缺一块判断力：知道 `backward()` 能出梯度，却不知道它为什么一遍就够、什么时候它反而不划算。取一个 2-3-3-1 的网络（输入 2 维，两层隐层各 3 个单元，输出 1 个），对全部 25 个参数（${6+3+9+3+3+1}$）用链式法则：如果把每个参数的求导式**完整展开**（不共享任何中间结果），展开式的项数等于该参数到损失之间的路径数。逐个数：第一层 6 个权重各有 3 条路径（经任一第二隐层单元到输出），第二层 9 个权重各 1 条，偏置 3 条、3 条、3 条、1 条，合计 39 项，每项 3 个局部导数因子，共 117 次乘法；换个网络结构，全部重推。反向传播的算法：对图上 25 条边各算一次局部导数，中间结果全部复用。

| | 链式法则全展开 | 反向传播（记忆化） |
| --- | --- | --- |
| 2-3-3-1 网络的求导代价 | 39 项，每项 3 因子 | 25 个局部导数各算一次 |
| 换网络结构 | 全部重推 | 零改动：图变了，规则不变 |
| 本质 | 重复子问题暴力重算 | 记忆化：每个子问题算一次 |

展开式的长相抽一项出来看。第一层权重 ${w^{(1)}_{ij}}$ 经第 ${k}$ 个第二隐层单元的那条路径，展开后就是一个三因子乘积：

$$
\frac{\partial o}{\partial h^{(2)}_k}\cdot\frac{\partial h^{(2)}_k}{\partial h^{(1)}_j}\cdot\frac{\partial h^{(1)}_j}{\partial w^{(1)}_{ij}},
$$

39 项里每一项都长这样，项与项之间大量共享同一些因子，展开式却没有共享机制；反向传播的共享机制就是记忆化本身。

自动微分有两大模式。前向模式（forward mode）给每个数配一个对偶分量 ${(v,\,v')}$，运算规则同步传播值与导数（${{(uv)}'=u'v+uv'}$）：一遍前向得到输出对**一个**输入方向的导数，术语叫 JVP（Jacobian-vector product）。反向模式先跑前向记账，再从输出端反向扫一遍，得到损失对**所有**中间量的梯度（VVP）。代价规则由此而定：前向按方向数（输入维数）计价，反向按输出数计价。训练的场景是 1 个 loss 对上百万参数：反向一遍完事，前向要跑上百万遍。

| | 前向模式 | 反向模式 |
| --- | --- | --- |
| 每个数携带 | 一个方向导数分量 | 一个输出端梯度 |
| 一遍得到的 | 输出对**一个**方向的导数（JVP） | 损失对**全部**中间量的梯度（VVP） |
| 代价按什么计 | 方向数（输入维数） | 输出数 |
| 典型用武之地 | 雅可比矩阵、灵敏度分析 | 训练：1 个 loss 对全部参数 |

实测这笔账（${d=256}$ 的三层 tanh MLP，${P=196608}$ 个参数；反向用 torch autograd，前向模式用复步法实现单方向 JVP，复步法即算 ${f(x+\mathrm{i}h)}$ 取虚部，精度到机器级）：

| 量 | 实测（单次） |
| --- | --- |
| 反向传播一次，得全部 ${P}$ 个梯度 | 35.1 ms |
| 前向模式一个方向（复步 JVP） | 9.2 ms |
| 前向模式拿全部梯度的推算代价 | ${P\times 9.2\,\mathrm{ms}\approx 30}$ 分钟 |
| 两者之比 | 约 5 万倍 |

复步 JVP 的正确性有对照：同一方向上它与 torch autograd 算出的投影梯度相差 ${4.4\times10^{-15}}$（float64 机器级）。竞赛生视角：这就是「暴力枚举 vs 记忆化搜索」的差距，自动微分把记忆化搜索从「手推一次的网络」变成「对任意计算图自动执行」。前向模式不是没用，输出维数小于输入维数时它更快；只是训练恰好是最不利于它的场景。

## $\rm \S \, 2.5$ 打开盖子：计算图与逐数梯度

不打开盖子，`.grad` 里的数只是冒出来的结果；这一节把一次 `backward()` 拆成看得见的四步，再用逐数对照证明 PyTorch 走的就是这四步。

计算图是一张流水记账：节点是运算，边是中间值的流向。以 ${z=x\cdot y+w}$ 为例，取 ${x=2}$、${y=3}$、${w=1}$，图的文字版：`x, y → [乘法节点] → p = 6`，`p, w → [加法节点] → z = 7`。反向传播从输出端出发，规则只有一条：**局部导数乘下游梯度**。

1. 输出端：${\partial z/\partial z=1}$；
2. 加法节点：局部导数对两个输入都是 1，把下游梯度原样分发，得 ${\partial z/\partial p=1}$、${\partial z/\partial w=1}$；
3. 乘法节点：局部导数 ${\partial p/\partial x=y=3}$、${\partial p/\partial y=x=2}$，各乘上从下游收到的 ${\partial z/\partial p=1}$；
4. 收账：${\partial z/\partial x=1\cdot 3=3}$，${\partial z/\partial y=1\cdot 2=2}$，${\partial z/\partial w=1}$。

每一步只用两类东西：前向存下的值（乘法节点要用 ${x}$ 和 ${y}$ 的值）与下游传来的梯度；顺序必须从输出端往输入端走，一个节点要乘的「下游梯度」必须先收齐，所以得先算完所有下游节点。这个顺序就是图的拓扑序的逆序，第 3 章的引擎会显式地做这个排序。同一张图让 PyTorch 建一遍，每个运算的返回张量都带一个 `grad_fn`，指向记账本里的自己这一页；链不用手翻，五行代码走完（对照实验真跑所用）：

```python
xt = torch.tensor(2.0, requires_grad=True)
yt = torch.tensor(3.0, requires_grad=True)
wt = torch.tensor(1.0, requires_grad=True)
z = xt * yt + wt        # z = 7.0
z.backward()
node, chain = z.grad_fn, []
while node is not None:
    chain.append(type(node).__name__)
    nxt = node.next_functions
    node = nxt[0][0] if nxt else None
# 输出：AddBackward0 -> MulBackward0 -> AccumulateGrad
```

`AddBackward0` 是加法节点，`MulBackward0` 是乘法节点，`AccumulateGrad` 是叶子（`x`、`y`、`w` 这类原始张量）的梯度收集器：链的末端就是图的三片叶子。`backward()` 执行的正是上面那四步，梯度写进每个叶子的 `.grad`。逐数对照：

| 变量 | 手推 | torch autograd | 差 |
| --- | --- | --- | --- |
| ${\partial z/\partial x}$ | 3.0 | 3.0 | 0 |
| ${\partial z/\partial y}$ | 2.0 | 2.0 | 0 |
| ${\partial z/\partial w}$ | 1.0 | 1.0 | 0 |

手推与引擎完全一致并不奇怪：引擎只是把这四步写成了对所有图都成立的循环，下一章就把这个循环写出来。

## $\rm \S \, 2.6$ 常见错误与报错翻译

1. `.grad` 是 `None`，三种原因：
    1. 忘了 `requires_grad=True`：张量没被标记，图根本没建，`backward()` 直接报 `element 0 of tensors does not require grad and does not have a grad_fn`；
    2. 访问的不是叶子：中间张量的 `.grad` 默认是 `None`（真跑访问时 PyTorch 还会打一段 `UserWarning`，建议改用叶子或先 `.retain_grad()`）；
    3. 运算被 `torch.no_grad()` 包住：块内不记账，产出的张量 `requires_grad` 是 `False`，对它 `backward()` 报上面同一句。
2. 第二次 `backward()` 报 `Trying to backward through the graph a second time`：默认第一次 `backward()` 就把图拆了、释放了中间量，要在同一张图上反向两次，第一次就传 `retain_graph=True`（§2.2 的实测：带上后连跑两次，梯度累加到 `tensor(8.)`）。
3. 对非标量调 `backward()` 报 `grad can be implicitly created only for scalar outputs`：损失本来就该是标量，手里若是向量，传 `backward(torch.ones_like(y))`，或先 `y.sum().backward()`（§2.2）。
4. 忘了 `zero_grad()`，梯度越滚越大：`backward()` 是累加写入不是覆盖，训练循环里忘了清零，第 ${k}$ 步的 `.grad` 是前 ${k}$ 步之和，表现为 loss 剧烈震荡或直接 `nan`（第 5 章、第 6 章各有一个分叉实验）。

## $\rm \S \, 2.9$ 本章自测答案

### $\rm \S \, 2.9.1$ 关键概念回顾答案

1. `requires_grad=True` 是记账开关，`backward()` 反向算梯度，`.grad` 存结果；只有用户手建的叶子会被长期保存 `.grad`，中间量用完即丢（要留得 `.retain_grad()`）。（§2.1）
2. 累加。不清零的话每步都把梯度加上去，第 ${k}$ 步的 `.grad` 是前 ${k}$ 步之和，越滚越大。（§2.2）
3. 手推要对每个参数展开链式法则且换个结构全部重推；自动微分把「展开」变成「对任意图自动执行的记忆化」，代价从 39 项降到 25 个局部导数。（§2.4）
4. 前向按方向数（输入维数）、反向按输出数；训练是 1 个 loss 对百万参数，反向一遍、前向百万遍，实测差距约 5 万倍。（§2.4）

### $\rm \S \, 2.9.2$ 应用与辨析答案

1. 图：`x, y → [乘] → p`，`p → [tanh] → q`，`q, w → [加] → z`；局部导数依次为 ${y}$ 与 ${x}$（乘）、${1-\tanh^2(p)}$（tanh）、两个 1（加）。（§2.5）
2. 只有 `wt.grad` 有值（等于 1）；图照样记（`z.grad_fn` 链完整），只是 `xt`、`yt` 不是叶子收集器，它们的梯度停在中间量上不落地。（§2.5）
3. 多花建图的内存与时间（每步都存中间量），结果不会错；评估不需要梯度，整段前向该套 `no_grad`。只想把张量当常量喂进去，用 `.detach()` 即可。（§2.3）
