## $\rm \S \, 4.1$ 循环序：ijk 对 ikj，六倍起步

任务是最日常的矩阵乘 ${C = A \times B}$，float32、${N = 1024}$，三个数组共 12 MiB。ijk 版把 $k$ 放最内层：

```c
for (i ...) for (j ...) {
    float s = 0.0f;
    for (k ...) s += A[i*n+k] * B[k*n+j];   /* B 按 k 步进：跳 n*4 字节 */
    C[i*n+j] = s;
}
```

ikj 版只把两个下标换了个位置：

```c
void mm_ikj(float * restrict C, const float * restrict A,
            const float * restrict B, long n) {
    for (long i = 0; i < n; i++)
        for (long k = 0; k < n; k++) {
            float a = A[i * n + k];               /* 内层只读一次 A，驻在寄存器 */
            for (long j = 0; j < n; j++)
                C[i * n + j] += a * B[k * n + j]; /* B 行与 C 行都顺着缓存行走 */
        }
}
```

`restrict` 是 §3.4 那类「签收前提」的关键词：向编译器承诺三个指针互不重叠，编译器才敢放心排访存。两版在数学上算的是同一个 $C$，先把缺失账推出来，再跑。缓存行 64 B 装 16 个 float；本机 L1d 为 64 组 × 64 B，组周期 4096 B（§2.4 步长仪已证）。ijk 的内层 $k$ 循环里，$A[i][k]$ 与 $C$ 都没问题（行内连续），可 $B[k][j]$ 随 $k$ 每步跳 ${n \times 4 = 4096}$ B——恰好是组周期，1024 条不同的行全部落进**同一个 L1 组**，组相联只有十几路，装不下，于是每次访问都缺失。$k$ 循环跑 ${N^3}$ 次，B 的 L1 缺失就约是 ${N^3 = 1.07 \times 10^9}$ 次；A 行与 C 行各贡献 ${N^2/16}$，零头。ikj 版把 $j$ 放最内层，$B[k][j]$ 与 $C[i][j]$ 都顺着行走，$B$ 一整行 64 条缓存行流式用完即弃，$C$ 一整行 16 KB 常驻 L1，全程 L1 缺失约 ${N^3/16 = 6.7 \times 10^7}$ 次，是 ijk 的 1/16。实测（同一进程轮转交错，5 轮取最速，绑 0 号核，全部内核经 objdump 证实无一条 ymm 向量指令、比的是访存不是向量宽度）：

| 版本 | 时间 (s) | GFLOPs | 相对 ikj |
| --- | --- | --- | --- |
| ijk | 2.162 | 0.993 | 0.15× |
| ikj | 0.322 | 6.670 | 1.00× |

6.7 倍差距，方向与缺失账一致：缺失比 16 倍，时间比 6.7 倍，因为 ijk 的每次缺失虽然次数多，单次却更便宜。这笔账可以精确对上。ijk 用 2.162 s 付掉约 ${1.07 \times 10^9}$ 次缺失，平均每次 2.0 ns——远低于 §2.4 实测的 L3 延迟 25.6 ns。差的那一截是在途并发：乱序执行引擎不等上一单回来就发下一单，若同时保持 $m$ 条缺失在途，单条缺失的摊销价就是 ${L/m}$：

$$
m \;\approx\; \frac{L}{T_{\text{每缺失}}} = \frac{25.6\,\text{ns}}{2.0\,\text{ns}} \approx 13
$$

读法：$L$ 是单条缺失的延迟，$T_{\text{每缺失}}$ 是实测的平均摊销价，商是在途缺失数的下限估计。约 13 条在途，正好在处理器填充缓冲区的量级上，这就是 §2.5 那句「带宽要靠并发去买」的现场版。ikj 的账同样能对：${6.7 \times 10^7}$ 次缺失摊 0.322 s，每次 4.8 ns，落在 L2 与 L3 的混合档（16.9 与 25.6 ns 之间，$B$ 共 4 MiB 大部分驻 L3）。同一章的实验隔两小时重跑过一次，ijk 漂到 0.666 GFLOPs、ikj 漂到 8.451，比值从 6.7× 漂到 12.7×：跨运行的绝对值与比值都不可信，可信的是「ijk 灾难性地慢」这个量级判断和缺失模型，所以结论全部挂在同一次运行内部的比较上。

白话：ijk 读 B 像在一栋每层 1024 间房的大楼里每次都跳到下一层同一号房，电梯（缓存组）每趟只为一件行李来回；ikj 是把整层走廊的房间推着车走一遍，一趟运十六件。

> 本节小结：最内层循环决定缺失形状，步长撞上组周期就是全缺失；ijk 约 ${N^3}$ 次缺失摊出 2.0 ns/次的在途价，ikj 约 ${N^3/16}$ 次落在 L2/L3 档，6.7 倍差价全部来自访问顺序。

## $\rm \S \, 4.2$ 分块：把工作集训进 L1

循环序修对了还不够。ikj 每换一个 $i$ 就把整个 $B$（4 MiB）重新流一遍，$N$ 一大 $B$ 连 L3 都装不下。分块（blocking，把矩阵切成 ${b \times b}$ 的小块、让三块小板在缓存里配齐再算）是标准的下一层解法：

```c
void mm_block(float * restrict C, const float * restrict A,
              const float * restrict B, long n, long b) {
    for (long ii = 0; ii < n; ii += b)
        for (long kk = 0; kk < n; kk += b)
            for (long jj = 0; jj < n; jj += b)
                for (long i = ii; i < ii + b; i++)
                    for (long k = kk; k < kk + b; k++) {
                        float a = A[i * n + k];
                        for (long j = jj; j < jj + b; j++)
                            C[i * n + j] += a * B[k * n + j];
                    }
}
```

内三层就是 §4.1 的 ikj，只是被限制在一条 ${b \times b}$ 的小块里跑；外三层决定下一块搬哪三块小板。先推缺失账：A、B、C 三块小板只要 ${3b^2 \times 4}$ 字节能住进 L1，每块小板每次被大循环访问时就只付一遍流式缺失，总计：

$$
M_{\text{L1}} \approx \frac{3N^3}{16\,b}
$$

读法：分母的 16 是每行缓存的 float 数，$b$ 是块边长；$b$ 越大，小板被反复搬进搬出的次数越少，缺失数按 $1/b$ 掉。${b = 32}$ 时 ${M_{\text{L1}} \approx 6.3 \times 10^6}$，比 ijk 的 ${10^9}$ 少两个数量级还多。模型还预言了一个约束：三块小板共 ${3b^2 \times 4}$ 字节，${b = 64}$ 时是 49 KB，恰好顶穿 48 KB 的 L1d。实测先把 $b$ 从 8 扫到 256（${N = 1024}$，与 §4.1 同一次运行）：

| 块边长 $b$ | 三块小板合计 | 时间 (s) | GFLOPs | 相对 ikj |
| --- | --- | --- | --- | --- |
| 8 | 0.8 KB | 0.482 | 4.454 | 0.67× |
| 16 | 3 KB | 0.347 | 6.182 | 0.93× |
| 32 | 12 KB | 0.336 | 6.386 | 0.96× |
| 64 | 49 KB | 0.416 | 5.161 | 0.77× |
| 128 | 196 KB | 0.344 | 6.246 | 0.94× |
| 256 | 786 KB | 0.307 | 6.994 | 1.05× |

两件事值得停一下。第一，${N = 1024}$ 时分块没有赢：峰值 0.96× 到 1.05×，与 ikj 打平。原因不是分块没用，是 ikj 已经把瓶颈换掉了。用 §1.8 的强度账看：ijk 的搬运量约 ${N^3 \times 64}$ 字节，强度 ${I \approx 2N^3 / 64N^3 = 1/32 \approx 0.03}$ FLOP/B，深度访存受限；分块 ${b=32}$ 的搬运量降到 ${3N^3/16b \times 64}$ 字节，强度 ${I = b/6 \approx 5.3}$ FLOP/B。本机平衡点用同一次运行的数估：标量 6.7 GFLOPs 除以这类混合流实测的 23.5 GB/s，约 0.29 FLOP/B。0.03 在平衡点左侧九倍，5.3 在右侧十八倍：分块把杆子从带宽屋檐底下挪进了片内。片内的真天花板不在乘加算力，在 L1 访存端口：汇编证实内层每元素是「load C、FMA 读 B 并乘加、store C」共两次 load 加一次 store，每拍至多消化一个元素，按 §2.4 的 2.6 GHz 口径折算约 5.2 GFLOPs——实测 6.67 说明真实运行频率在 boost 档（第 3 章的频率漂移现象又见面了），折算口径不影响「瓶颈已不在 DRAM」的判断。想再快只剩 §3.3 的 SIMD 一条路，《42-LLM 从零构建》§6.3 在同一块芯片上把这个循环向量化后跑到 80.2 GFLOPS，那就是这间机房的天花板。第二，${b = 64}$ 那行的坑与模型预言吻合：49 KB 顶穿 48 KB 的 L1，三块小板开始互踢，跌到 0.77×；${b \ge 128}$ 后小板干脆住 L2，流式价虽然贵些但缺失次数更少，曲线回爬。

分块的兑现时刻在 ${N = 4096}$：$B$ 长到 64 MB，标称 24 MiB 的 L3 装不下，ikj 每换一个 $i$ 都要从 DRAM 把整个 $B$ 重流一遍（本机 DRAM 随机档 220～290 ns，§2.4）。补测（轮次降为 3，其余纪律同）：

| 版本 | 时间 (s) | GFLOPs | 相对 ikj |
| --- | --- | --- | --- |
| ikj | 36.86 | 3.729 | 1.00× |
| block b=32 | 19.50 | 7.050 | 1.89× |
| block b=64 | 23.66 | 5.808 | 0.98× |
| block b=128 | 19.23 | 7.147 | 1.92× |

缺失模型接着对：ikj 在 ${N = 4096}$ 的 L1 缺失约 ${N^3/16 = 4.3 \times 10^9}$ 次，摊 36.86 s，每次 8.6 ns，正落在 L3 与 DRAM 的混合档；分块 ${b=32}$ 缺失少 170 倍，速度翻回 1.9 倍，GFLOPs 几乎与 ${N = 1024}$ 时持平（7.05 对 6.39）——工作集训进 L1 之后，问题规模翻四倍速度不掉，这就是「缓存友好」三个字的含金量。

白话：ikj 是每来一位客人就把整仓库重新跑一遍的搬运工；分块是把客人要的货按托盘配齐，托盘尺寸还必须塞进货梯（L1）——塞到 49 KB 那一刻货梯门关不上，反而更慢。

> 本节小结：缺失数 ${3N^3/16b}$ 按块边长倒数下降，但收益只在「块住得进 L1 且 B 装不进 L3」时兑现；${N=1024}$ 分块与 ikj 打平（瓶颈已换到片内访存端口），${N=4096}$ 时 1.9 倍，${b=64}$ 顶穿 L1 的坑模型提前预言。

## $\rm \S \, 4.3$ 软件预取：一个被证伪的假设

§4.1 的在途账留下一个诱人的假设：ijk 的瓶颈是在途缺失数，硬件自己只能攒约 13 条，那用指令显式预取（software prefetch，让程序自己提前报出下一批地址）把在途数再抬上去，是否更快？ijk 里下一单地址可提前 $D$ 步精确算出：${B[(k+D) \cdot n + j]}$。在 $k$ 循环里加一行 `__builtin_prefetch(&B[(k+D)*n+j], 0, 1)`，扫三个距离（objdump 证实预取指令真的在循环里，各一条 `prefetcht`）：

| 版本 | 时间 (s) | GFLOPs | 相对 ijk |
| --- | --- | --- | --- |
| ijk（无预取） | 2.162 | 0.993 | 1.00× |
| ijk+pf D=8 | 2.511 | 0.855 | 0.86× |
| ijk+pf D=32 | 2.839 | 0.756 | 0.76× |
| ijk+pf D=128 | 3.117 | 0.689 | 0.69× |

假设被证伪，而且证得干脆：三个距离全部变慢，距离越大越慢。加的那一行长这样：

```c
for (long k = 0; k < n; k++) {
    if (k + D < n)
        __builtin_prefetch(&B[(k + D) * n + j], 0, 1); /* 提前 D 步报下一单地址 */
    s += A[i * n + k] * B[k * n + j];
}
```

`__builtin_prefetch(p, 0, 1)` 两个附加参数分别是读写意图（0 表示只读）与局部性（1 表示用完就想丢，正合 B 行流式的命）。事后账也说得通：乱序执行在 ijk 里早已把在途数顶到填充缓冲上限（§4.1 估的 13 条），显式预取抢的是同一批缓冲名额，额外付一条指令加一次地址计算，净效果只能为负；距离越大，抢得越早、占用越久。机制层我们只有间接证据（没开性能计数器），但方向判断与 §2.5 的在途账自洽。这条弯路的价值在于它划清了预取的适用条件：**硬件没能自己攒够在途数时预取才有饭吃**——例如访存地址在循环外才能算出、或预取器学不出节奏的场景。本实验里硬件已经吃饱了，加菜只会撑着。

白话：硬件预取器像个已经很勤快的传菜员，你非要再雇一个帮厨替他提前喊单，厨房端子（填充缓冲）就那么几个，帮厨喊得越多，传菜员越是转不开身。

> 本节小结：显式预取三档全负收益（-14% 到 -31%），因为乱序执行已把在途缺失顶到上限；预取救的是硬件学不出地址的场景，不是雪中送炭的万能贴。

## $\rm \S \, 4.4$ AoS 与 SoA：布局的过路费

同一份数据，按什么形状摆进内存，决定每条缓存行里有多少字节是你要的。两种典型摆法：数组结构（Array of Structures，AoS）把每个对象的所有字段打包连续存放；结构数组（Structure of Arrays，SoA）把每个字段各排一条独立数组。用 ${N = 2^{21}}$ 个粒子做最小对照，核是同一句话 ${x \mathrel{+}= v_x \cdot dt}$ 的三个分量。两种布局在源代码里只差一个声明：

```c
typedef struct { float x, y, z, vx, vy, vz, m, pad; } Part; /* 32 B，两条粒子一条行 */
static Part *P;                          /* AoS：一个粒子的全部字段打包连续 */
static float *X, *Y, *Z, *VX, *VY, *VZ;  /* SoA：每个字段各排一条独立数组 */
```

两版核函数 `step_aos` 与 `step_soa` 都被 `noinline` 钉住防止内联扰动计时，初值逐位相同，`dt` 经 volatile 读入防常量折叠，同一进程内两个版本每轮交错计时 7 轮取最速：

| 编译档 | AoS ns/粒子 | SoA ns/粒子 | 加速比 | AoS 等效带宽 | SoA 等效带宽 |
| --- | --- | --- | --- | --- | --- |
| -O2（标量，objdump 证实零向量指令） | 2.739 | 2.027 | 1.35× | 23.4 GB/s | 23.7 GB/s |
| -O3（自动向量化） | 2.051 | 0.938 | 2.19× | 31.2 GB/s | 51.2 GB/s |

标量档的差距能精确入账。每粒子的真实流量：SoA 读 24 B 写回 24 B 共 48 B；AoS 虽然只脏了 ${x,y,z}$ 的 24 B，但写回按整条 64 B 缓存行计价，且没碰过的 m 与填充搭同一辆车，每粒子实付 32 B 读加 32 B 写回共 64 B：

$$
\frac{T_{\text{AoS}}}{T_{\text{SoA}}} \approx \frac{64\,\text{B}}{48\,\text{B}} = \frac{4}{3} \approx 1.33
$$

读法：两种布局的等效带宽几乎相同（23.4 对 23.7 GB/s，都是这类读改写混合流在这台机器上买得到的 DRAM 带宽），时间差全部来自流量差，比值 ${4/3}$ 与实测 1.35 严丝合缝。也就是说标量档的 AoS 税是纯过路费：m 与填充两个字段没被任何指令碰过，却让每粒子多付 16 字节写回。向量化档把税放大了：SoA 是干净的 32 字节连续 load 加 add，-O3 汇编只有 10 条向量指令；AoS 每条向量寄存器里混着 8 个粒子的 8 个字段，编译器必须用逐字段重排指令把 ${x}$ 与 ${v_x}$ 拆出来——objdump 里 `vpermd` 洗牌连成串，向量指令多达 112 条。结果 SoA 跑到 51.2 GB/s，AoS 只到 31.2，差距从 1.35× 拉开到 2.19×。布局选错，向量化是替错误放大音量，不是救命。

白话：AoS 像把一家四口的行李塞进同一个箱子，去海滩只用得着泳衣，却得为整箱付托运费；SoA 是每人一个背包，要用什么抽什么，一条流水线直通到底。

> 本节小结：布局税按「每条缓存行里没用的字节」计价，标量档实测 1.35× 对上流量账 4/3；向量化后编译器要用重排指令拆字段，税涨到 2.19×。字段能不能独立成列，设计表结构时就要想。

## $\rm \S \, 4.5$ 伪共享：一行 64 字节的跨核运费

前几节的账都发生在单核。上了多核，缓存行还是记账单位，收费规则由 MESI 执行（《计算机系统结构》§6.2 已给过账，多核机制本身第 5 章展开）：任何核要写一行，必须先把这行的独占权拿到手，独占权靠广播无效化换。《计算机系统》§10.3.4 给过定义：两个线程各写各的变量、语义上毫无共享，但变量恰在同一条 64 字节行上，每条写都要付一次跨核行搬运，这就是伪共享（false sharing）。本节把它钉到本机的账上，并记一次真实的翻车。

实验设计：两个线程各把一个计数器自增一亿次，唯一变量是两个计数器摆哪。摆法与两种计数方式的核心代码：

```c
static long adj[2];                              /* 紧挨着：同一条 64 B 缓存行 */
typedef struct { long v; char pad[56]; } Slot;   /* 8 + 56 = 64 B，各占一条 */
static Slot slot[2];

if (atomic_mode)                                 /* atomic 档：每笔真拿所有权 */
    for (long i = 0; i < ITERS; i++)
        __atomic_fetch_add(t, 1, __ATOMIC_RELAXED);
else                                             /* bare 档：普通 load-add-store */
    for (long i = 0; i < ITERS; i++)
        (*t) += 1;                    /* volatile：每次都真的过一遍 load+store */
```

adjacent 版的两个线程分别写 `adj[0]` 与 `adj[1]`，padded 版分别写 `slot[0].v` 与 `slot[1].v`。线程用 `pthread_setaffinity_np` 显式钉到两个 vCPU 并打印落点，5 轮取最速，计时区间从起跑线屏障之后起算：

| 计数方式 | 单线程基线 | adjacent（同行） | padded（分行） | 同行/分行 |
| --- | --- | --- | --- | --- |
| atomic | 4.88 ns/op | 28.89 ns/op（约 75 拍） | 4.79 ns/op | 6.03× |
| bare | 0.23 ns/op | 2.06 ns/op | 0.24 ns/op | 8.62× |

atomic 那行是教科书现场：分行时 4.79 ns/op，与单线程 4.88 几乎相同，两条核各跑各的、总吞吐恰好翻倍；挪到同一行立刻 28.9 ns/op（约 75 拍），每笔自增都真的在跨核搬运行所有权。《计算机系统结构》§6.3 在同一台机器上测过同款现象（同行 20.4 ns 对分行 4.4 ns，4.7 倍），两边口径一致，量级互相背书。bare 那行要小心读：比值 8.62× 看着更大，绝对价却只有 2.06 ns 对 28.9 ns，差 14 倍。bare 的写可以在 store buffer 里排队攒批，下一条读直接从缓冲转发，行所有权的跨核账被流水线藏掉大半，只在缓冲排空时露头；`lock` 前缀的 RMW 每一笔都必须真正拿到行所有权，一分钱账都藏不住。这与 §6.3 的结论互相印证：**伪共享的账单爱在同步原语上冒头，裸写有时能被 store buffer 打折，原子指令从不打折。**

翻车记录值得完整留下。第一版实验把 padded 配置写成 `bench_pair((long*)slot)`，`(long*)slot + 1` 落在 slot[0] 的填充字节（偏移 8）上，而真正的 slot[1].v 在偏移 64——「不同行」配置实测是同一行，测出 0.84× 的无效数据，方向都不对。抓住它靠的是证据而不是直觉：输出里打印了计数器终值，`slot[1].v = 0` 说明第二线程的一亿次自增根本没写到目的地。第二版改为显式传两个指针、每次运行校验计数器终值，才得到上表。另有一处反常照实存档：bare 单线程 0.23 ns/op 折合不到一拍，低于教科书给的同地址读写链延迟；我们怀疑过 WSL 时钟失准，用 Windows 侧秒表对 K=1 与 K=10 两档负载独立计时（墙钟差 1.15 s ÷ 9 ≈ 0.32 ns/op），与 WSL 时钟一致——时钟没说谎，这台 CPU 在这条微模式上就是快。绝对值存疑不影响本章任何比值结论，但「报数字必须报环境」的规矩在这里又添了一条例子。最后补一句绑核：换一对 vCPU（0,1 与 0,2 两档都跑过）惩罚倍率只在 5.4× 到 6.0× 之间动，结论对核间距离不敏感。

白话：MESI 是按行车记账的高速公路，两个核轮流往同一条行上写字，就像两家店轮流霸占同一辆车送货，车在两店之间没日没夜地跑，运的全是本来各买各的货；填充 56 字节就是给每家店买一辆自己的车，一次付清。

> 本节小结：伪共享按行收跨核运费，atomic 同行 28.9 ns 对分行 4.8 ns（6.0 倍，与《计算机系统结构》§6.3 的 4.7 倍互证）；裸写被 store buffer 打折到 2.1 ns，原子 RMW 不打折；取址 bug 靠计数器终值抓出，绑核对结论不敏感。

## $\rm \S \, 4.8$ 本章自测答案

概念回顾答案：

1. ijk 的 B 缺失约 ${N^3}$，ikj 约 ${N^3/16}$，比值 16。组周期 4096 B 使 ijk 内层步长（${n \times 4}$ B）恰好把所有访问压进同一个 L1 组，十几路的组相联装不下 ${N}$ 条行，于是每次都缺失；ikj 顺行走行，每行 16 个 float 摊一次缺失（§4.1）。
2. ${m \approx 25.6 / 2.0 \approx 13}$ 条在途。落在乱序执行引擎的内存填充缓冲区上：它决定同时能挂多少条缺失请求，是 §2.5「带宽靠并发买」的物理上限（§4.1）。
3. $N$ 是矩阵边长、$b$ 是块边长、16 是每条 64 B 缓存行的 float 数，$M$ 是三块小板合计的 L1 缺失估计。${b = 64}$ 时三块小板 ${3 \times 64^2 \times 4 = 49}$ KB 顶穿 48 KB 的 L1d，小板之间开始互踢，实测跌到 0.77×（§4.2）。
4. ${N = 1024}$ 时 $B$（4 MiB）装得进 L3，ikj 的缺失已经便宜到瓶颈换成片内访存端口（每元素两读一写，每拍约一个元素，6.7 GFLOPs 已贴住），分块省下的缺失不再是瓶颈；${N = 4096}$ 时 $B$（64 MB）连 L3 都装不下，ikj 每换一行 $i$ 都从 DRAM 重流整个 $B$（摊到 8.6 ns/缺失），分块把缺失砍掉约 170 倍，速度差才重新显现（§4.2）。
5. m 与填充两个字段共 8 B，从未被指令读写。但缓存行的写回粒度是 64 B：同一条行上任何字节脏了，整行都要按 64 B 付写回，AoS 布局让这 8 B 搭上了每粒子两条行的车（§4.4）。

应用与辨析答案：

1. 先看证据再看机制：其一，若真是伪共享，两个计数器地址差小于 64 B（打印两指针差即知），且线程被钉在不同核上时时间显著变长、钉到同一核时惩罚消失——把程序分别在「两核」与「一核」绑定下各测一次，惩罚随绑定消失即坐实；其二，给其中一个计数器加 64 B 填充复测，若时间回落到单线程档，同样是坐实。若指针差本就大于 64 B，查锁争用与调度迁移，别在伪共享上浪费时间（§4.5）。
2. 成立的条件：硬件没能攒够在途缺失（地址在乱序窗口外才能算出、预取器学不出节奏），此时预取用一条指令的代价换一条提前在途的缺失，净赚。破产的条件正是 §4.3 的现场：乱序执行已把在途数顶到填充缓冲上限时，预取抢同一批名额还多付指令，实测三档 -14% 到 -31%，距离越大亏越多。判据是把 §4.1 式的在途估算先算出来，再决定要不要出手（§4.3）。
3. 只更新 ${x}$ 时，SoA 流量降为读 8 B 写回 8 B 共 16 B/粒子；AoS 仍是整行写回计价，每粒子实付 64 B，账面比涨到 4×。标量档差距会更大；向量化档的差距反而先消失——单字段连续数组与 AoS 里 8 个 ${x}$ 的间距都是 32 B，编译器对 AoS 的单字段循环可以用跨步 load（或直接判定不划算退回标量），洗牌税没了，剩下的只是纯流量差。预测先行，复测脚本把两个赋值删掉即可（§4.4）。

**你现在能做什么**：拿到任何一段「莫名其妙慢」的循环，你能先算缺失账与算术强度，判断它在带宽屋檐还是算力屋檐下，然后按顺序检查最内层循环方向、工作集与块大小、数据布局的字节利用率，每一项改动都设计对照实验并用同进程交错计时取证。
