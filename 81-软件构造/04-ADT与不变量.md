# $\rm Chapter \, 4$ ADT 与不变量

> **本章假设你已经会**
>
> 1. spec 的三段条款：前置、后置、副作用，且没写的就是允许的，B3 的漏检根因在 modifies 条款出现后闭环，见第 3 章 §3.5。
> 2. 替换原则：改合同的唯一安全通道是削弱前置＋加强后置，不可比的合同两头不讨好，见第 3 章 §3.4。
> 3. 预言机的来历：测试判定对错的依据要从合同里抄，抄漏了条款测试再密也白搭，见第 2 章 §2.1 与 §2.3。
> 4. 静默错误的形状：异常零个、值全错，等下游对账才现形；崩溃自带现场反而是便宜的死法，见第 1 章 §1.3。

第 3 章把合同立到了函数级：`top_pages` 的进与出、强与弱、改与不伤人，都有判据。但函数级合同有一块管不到的地盘：`top_pages` 要挑出 pages 最大的记录，得先有人保证 records 里每条的 pages 是个正数；`total_pages` 要把页数加起来，得先有人保证列表里没有 None。这些「数据本身必须长什么样」的承诺不属于任何一次调用，它是围着同一份数据转的所有函数共同的依赖。给每个函数都写一遍？条款会重复出几十份，改一处漏七处。本章把合同从函数层升级到类型层：把数据与其操作打包成抽象数据类型（§4.1），为它立一份私有合同——表示不变量（§4.2）；然后用锚点实验一证明这份私有合同有多不禁碰，外部一行 append 就能改坏它，防御性拷贝是防火墙的补法（§4.3）；再用锚点实验二证明「不变量靠论证保持」的论证本身也会错，checkRep 断言把违反抓在肇事操作当场（§4.4）；最后算拷贝的成本账与设防的分寸（§4.5）。本章实验全部在 WSL2（python 3.12.3）上真跑过，脚本与完整输出见本册实验记录 `expSW04/result.txt`，两个脚本合计 0.18 秒。

## $\rm \S \, 4.1$ 从函数合同到类型合同：抽象数据类型

先立任务。论文资料管理器里，论文记录（标题，页数）这份数据要被十几个函数围着转：挑最重要的 k 篇、统计总页数、按页数查某篇的排名。函数级合同管的是单次调用，可这份数据自己的规矩——「页数是正数」「不能混进 None」——写在谁的合同里？答案是：这份数据需要成为一个类型，规矩立在这个类型上。

**抽象数据类型**（abstract data type，ADT）指由操作集合定义的类型：外界只能通过这组操作访问其中的数据，内部怎么存是实现的事。名字里的「抽象」就在这：使用方面对的是操作，不是存储。给论文架写一个最小 ADT，命名 `PaperShelf`：

```python
class PaperShelf:
    def __init__(self, papers): ...   # 从论文列表造一个书架
    def top(self, k): ...             # 返回页数最大的 k 篇
    def total_pages(self): ...        # 返回全部论文的页数总和
    def get_all(self): ...            # 返回全部论文
```

类内部的存储叫**表示**（representation，简称 rep）。`PaperShelf` 选的 rep 是一个列表 `[(title, pages), ...]`，按 pages 从大到小排序。先把一个实现完整写出来（无防御版，§4.3 会拿它做事故现场）：

```python
class PaperShelfBare:
    def __init__(self, papers):
        self._papers = sorted(papers, key=lambda p: -p[1])   # 按 pages 降序

    def get_all(self):
        return self._papers

    def top(self, k):
        return self._papers[:k]

    def total_pages(self):
        return sum(p[1] for p in self._papers)
```

rep 是实现的私事：明天把列表换成按页数建索引的字典，只要四个操作的行为不变，使用方一行代码都不用改。这句保证凭什么成立？凭 rep 与抽象值之间那层翻译保持不变。

rep 是列表，有序、可重复；而「书架上有哪些论文」这件事本身没有顺序可言。把 rep 映射到它所表示的抽象值的函数叫**抽象函数**（abstraction function，AF）：

$$
AF:\;R \to A,\qquad AF\bigl(\left[\,(t_1,p_1),\,\dots,\,(t_n,p_n)\right]\bigr)=\left\{\,(t_1,p_1),\,\dots,\,(t_n,p_n)\right\}
$$

读法：$R$ 是全部可能的 rep 值构成的空间，$A$ 是抽象值空间；${AF}$ 把列表映射成集合，顺序与重复在映射里被抹掉，它们是 rep 的私事，不是「书架上的论文」这个抽象概念的一部分。拿三个具体 rep 把映射走一遍：

```text
rep1 = [('SVD详解',30), ('TCP入门',25), ('哈希表笔记',18)]
rep2 = [('哈希表笔记',18), ('SVD详解',30), ('TCP入门',25)]
rep3 = [('SVD详解',30), ('TCP入门',25), ('哈希表笔记',18), ('SVD详解',30)]

AF(rep1) = {('SVD详解',30), ('TCP入门',25), ('哈希表笔记',18)}
AF(rep2) = 同一集合   —— 顺序不是抽象事实
AF(rep3) = 同一集合   —— 重复不是抽象事实
```

三个不同的 rep 映射到同一个抽象值，这正说明 AF 是多对一的：rep 的差异里有一部分（顺序、重复）抽象层不关心。AF 有什么用？两个场合。读懂自己的实现：把 rep 从列表换成字典时，沿 AF 核对新 rep 映射到的集合不变，类型级行为就不会变，那句「使用方一行不改」的保证由此兑现；排查 bug：debugger 里看到的是 rep，人脑要恢复的是抽象值，AF 是中间那副眼镜。AF 写在类的注释里，给维护实现的人看，使用方永远不需要知道它。

白话：ADT 是一台自动售货机，按钮（操作）是它对外的全部，货道怎么摆（rep）是内部的事；AF 是货道布局到「卖哪些货」的翻译表，画给补货员看，顾客不用看。

> 本节小结：ADT 由操作集合定义类型，rep 是实现私有的存储；AF 把 rep 空间映射到抽象值空间，顺序与重复这类表示细节在映射中被抹掉；使用方只面对操作，rep 与 AF 都是写给维护者的私有文件。

## $\rm \S \, 4.2$ 表示不变量 RI：实现的私有合同

有了 rep，实现的胃口也来了：rep 是按 pages 降序排好的列表，`top(k)` 就可以是干净的切片 `rep[:k]`，按页数查排名可以数到第一个小于阈值的就停。这些实现全部押注在同一件事上：列表**任何时候**都是按 pages 降序排好的。这个押注必须变成一条明文的承诺，就是表示不变量。

**表示不变量**（representation invariant，RI）指一个对象的 rep 在任何可观察时刻都必须满足的性质，是一个 rep 上的谓词：

$$
RI:\;R \to \{\text{true},\,\text{false}\},\qquad \mathrm{OK}(S)=\{\,r \in R \mid RI(r)=\text{true}\,\}
$$

读法：${\mathrm{OK}(S)}$ 是类 $S$ 的全部合法 rep 构成的集合，${RI}$ 就是合法性的判据。`PaperShelf` 的 RI 押的就是三条：列表中没有 None；每条记录的 pages > 0；按 pages 非增排序。注意 RI 与 AF 的分工：AF 只需要对合法 rep 定义（非法 rep 根本不该出现，谈何表示什么），RI 负责把非法 rep 挡在门外；抽象值里没有「顺序」这个概念，所以「必须有序」不是抽象事实，是 rep 的私规，这正是 RI 称为「实现的私有合同」的原因，使用方的世界里不存在这条合同。

私有合同的效力靠一条论证维持，不是靠运气：构造器必须从合法 rep 出发（建立 RI），此后每个操作都必须把合法 rep 变成合法 rep（保持 RI）。构造器建立、每个操作保持，归纳起来，任何可观察时刻 rep 都合法，`top` 与 `count_ge` 的押注因此成立。归纳论证要求逐操作核对，对着 §4.1 的实现核对一遍：

1. 构造器：入参里的论文页数若混着负数或 None，`sorted` 只管排序不管合法性，RI 的头两条根本建立不起来。建立 RI 不是排个序就完事，必要时要在构造器里校验入参、拒绝非法数据。这一步先把起点钉在 ${\mathrm{OK}(S)}$ 里。
2. `top`、`total_pages`、`get_all`：它们只读不写 rep（observer），保持 RI 是白拿的。但注意这个「白拿」有隐藏条款：返回值若把 rep 的引用递了出去，读操作就拐弯变成了写通道，§4.3 的实验专门炸这一条。
3. 新增的 `add(title, pages)`：从头扫描找到第一个 pages 小于新值的下标、插入。插入点选对了，降序保持，RI 守住；插入点差一个下标，RI 从这条操作开始漏。论证断不断，就悬在每个 mutator 的一两行代码上。

这条论证在两点上比函数级合同苛刻：其一，合同只管调用进出，RI 管的是对象一生中的每个瞬间；其二，函数违约伤害一次调用，RI 违约毒化的是此后所有依赖这份 rep 的操作。

白话：RI 是宿舍楼内部的纪律条例，住户合同（spec）里不会写「必须穿睡衣走走廊」，但楼里每个操作（宿管、保洁）都按这条纪律配合；纪律一旦有人破坏，全楼的配合同时失灵。

> 本节小结：RI 是 rep 上必须恒真的谓词，合法 rep 全体构成 ${\mathrm{OK}(S)}$；AF 只对合法 rep 定义，RI 与 AF 一挡一译；效力靠「构造器建立 RI、每个操作保持 RI」的归纳论证维持，逐操作核对、漏一即断；RI 是实现的私有合同，使用方不可见也不可依赖。

## $\rm \S \, 4.3$ 锚点实验一：rep exposure 与防御性拷贝

归纳论证有一个没人明说的前提：rep 只被类自己的操作碰。如果 rep 的引用跑到了类外面，外面的代码可没签过 RI 这份私有合同，它连合同的存在都看不到。rep（或其一部分的引用）跨出类型边界的情形叫**表示暴露**（rep exposure）。按第 3 章 §3.5 的留白原则这几乎是必然出事的：`get_all` 的合同没写「返回的是内部引用，请勿改动」，那外部对一个拿到手的列表 append、sort、insert，什么都没违约。

实验对象是两个只差一行的实现：`PaperShelfBare` 的 `get_all` 直接 `return self._papers`（交出内部引用），`PaperShelfSafe` 的 `get_all` 返回 `list(self._papers)`。外部拿到 `get_all` 的返回值后做三件事：`append(("草稿", -7))` 塞进非法数据，`sort(key=title)` 按标题重排（外部以为这是自己的列表），`append(None)` 塞进一个 None。实测输出（照抄 `result.txt`）：

```text
初始 RI 检查: 通过
事后 RI 检查: ['[5] pages=-7 <= 0', '[6] None 元素',
               '[2,3] 乱序: pages 12 < 18', '[3,4] 乱序: pages 18 < 21']
top(3) 实际: [('SVD详解', 30), ('TCP入门', 25), ('git指南', 12)]
top(3) 期望: [('SVD详解', 30), ('TCP入门', 25), ('缓存策略', 21)]
total_pages() 实际: 崩溃 -> TypeError: 'NoneType' object is not subscriptable
```

三行外部代码，三种后果各占一样本：RI 被破出四条违反（非法页数、None、两处乱序）；依赖 RI 的 `top(3)` 交出错数据，第三名被「git指南」的 12 页顶替，应是「缓存策略」的 21 页，异常零个、值全错，§1.3 的静默形态；不依赖顺序的 `total_pages` 则被 None 直接炸成 TypeError。同一个类，有的操作错得无声、有的操作当场崩溃，取决于它押了 RI 多少。防御版的同一套攻击打过去，实测 RI 检查通过、`top(3)` 正确、`total_pages()` 得 106，外部那三行代码全部打在拷贝上，rep 毫发无损。

还有第二条泄漏通道，比出参更隐蔽：入参。`PaperShelfBare` 的构造器写 `sorted(papers, ...)`，恰好新建了一个列表，入参安全纯属侥幸；把这一行换成 `self._papers = papers` 加原地 `sort()`（实验里的 `PaperShelfLeakyCtor` 正是这个写法），调用方改自己手里的入参列表就等于改架子内部。实测：调用方把 `src[0]` 换成 `("草稿", -7)` 后，RI 检查报出 `['[0] pages=-7 <= 0', '[0,1] 乱序: pages -7 < 25']`。入参出参是同一条防火墙的两面。

把偶然升级成统计：随机生成书架、随机组合一到三外部动作（塞负页数、塞 None、乱位插入、shuffle、按标题排序、随机删除），对两个实现各攻击 1000 轮。实测无防御版 860 轮 RI 被破，防御版 0 轮。无防御版剩下那 140 轮不是安全，是那一轮抽到的动作恰好无害（比如只 pop 了一个中间元素）；防御版的 0 则是结构保证，攻击在物理上就打不到 rep。实验复现方式（WSL Bash，当前目录为本册实验记录 `expSW04`，脚本只读、输出重定向到 `result.txt`，单脚本约 0.08 秒；成功验证是末两行为「无防御版 RI 被破: 860 / 1000 轮」与「防御版 RI 被破: 0 / 1000 轮」）：

```bash
python3 exp1_rep_exposure.py > result.txt
```

修法有名字：在类型边界上复制，叫**防御性拷贝**（defensive copy）。规则是拷贝发生在边界、rep 内部照常传引用：构造器把入参拷进来，每个可能把 rep 一部分递出去的出参拷出去。`PaperShelfSafe` 与事故版的全部差别就三处：

```python
class PaperShelfSafe:
    def __init__(self, papers):
        self._papers = sorted(list(papers), key=lambda p: -p[1])  # 入参拷贝

    def get_all(self):
        return list(self._papers)                                  # 出参拷贝
```

要紧的是说清它的失效边界：`list(self._papers)` 是浅拷贝，只复制外壳；本例够用是因为元素是（标题， 页数）的元组、不可变，若 rep 里存的是 dict，改元组改不坏、改 dict 照样穿透，那就要深拷贝。拷贝也不是唯一设防方案，成本账与替代方案在 §4.5 展开。

白话：rep exposure 是防火墙上没关的门，你家装修（RI）再讲究，邻居（外部代码）能推门进来砸；防御性拷贝是门口放一份复印件，客人随便涂改，原件永远在里屋。

> 本节小结：rep exposure 指 rep 的引用跨出类型边界，外部代码没签 RI 合同、按留白原则怎么改都不违约；实测三行外部代码造出四条 RI 违反、一处静默错值、一处当场崩溃，1000 轮模糊攻击破防 860 轮，防御性拷贝版 0 轮；拷贝要同时设防入参与出参，浅拷贝只在元素不可变时够用。

## $\rm \S \, 4.4$ 锚点实验二：checkRep 在关键操作后断言

§4.2 说 RI 靠归纳论证维持，但论证是人写的，人写的就会错。一个操作的实现差之毫厘（循环起点差一个下标），RI 就在谁也没察觉的地方断了，此后每个依赖它的操作都在替这个 bug 背锅。要抓住这类违反，靠代码审查逐行盯不如让机器盯：把 RI 谓词写成一个方法，在构造器和每个改动 rep 的操作末尾断言它为真。这个方法惯例上叫 `checkRep`。

实验给 `PaperShelf` 加一个有序插入的 `add(title, pages)`：从头扫描找到第一个 pages 小于新值的下标、插进去。注入的 bug 只有一个下标：扫描从 1 开始而不是 0，漏掉与队首的比较。后果高度局部化：只有当新插入的是全架最大页数时，它被插到下标 1 而不是 0，其余插入完全正确。checkRep 本身就是 §4.2 那个 RI 谓词的直译：

```python
def _check_rep(self):
    rep = self._papers
    for i, p in enumerate(rep):
        assert p is not None and p[1] > 0, f"RI 违反: 位置 {i} 存在 {p!r}"
    for i in range(1, len(rep)):
        assert rep[i - 1][1] >= rep[i][1], (
            f"RI 违反: 位置 {i-1} pages={rep[i-1][1]} < "
            f"位置 {i} pages={rep[i][1]}, rep={rep}")
```

调用点挂在两处：构造器末尾，以及每个改动 rep 的方法（这里是 `add`）末尾。同一份 300 步操作脚本（add、top、total_pages、count_ge 混合，seed 固定）跑两遍，checkRep 关的那遍同时拿一个永远重排的参考实现逐步对账。实验复现方式（WSL Bash，当前目录 `expSW04`，单脚本约 0.10 秒；成功验证是「AssertionError 在第 4 步当场触发」一行出现）：

```bash
python3 exp2_checkrep.py >> result.txt
```

实测：

```text
[checkRep 关] 第一次 RI 违反: 第 4 步 (op=add, 参数=('p4', 28))
[checkRep 关] 第一次可观察输出与参考不符: 第 9 步 (op=count_ge)
[checkRep 关]   该步 buggy 输出: 0        参考输出: 3
[checkRep 关] 静默腐蚀的操作数: 5 步 (从 RI 被破到症状现形)
[checkRep 关] 全程可观察输出错误: 134 / 300 步
```

数字要一条条读。第 4 步的 `add('p4', 28)` 把 28 插到了队首 1 后面（队首当时是 pages=1），RI 从这一步起被破。此后 5 步里一切看起来正常：total_pages 照样算对，因为它不依赖顺序，乱序对它不可见；RI 被破的腐蚀是选择性的，症状会漂移。第 9 步 `count_ge` 首次交出错值（报 0，实际 3），从此全程 300 步里 134 步的输出是错的。第 4 步犯案，第 9 步才有人看见，中间的现场早被后续操作覆盖，这正是 §1.3 说的崩溃便宜、静默昂贵的机制根源。

checkRep 开的那遍，同一份脚本：

```text
[checkRep 开] AssertionError 在第 4 步当场触发 (op=add, 参数=('p4', 28))
[checkRep 开] 断言信息: RI 违反: 位置 0 pages=1 < 位置 1 pages=28,
              rep=[('p2', 1), ('p4', 28)]
[checkRep 开] 检测延迟: 0 步（抓它的正是肇事操作本身）
```

检测延迟从 5 步压到 0 步，而且崩在肇事操作自己身上：traceback 指向的代码行就是写错的那行，断言信息里连乱序对和整个 rep 都印出来了，排查时间从「读完整段调用链」缩到「读一行报错」。fail fast 的全部价值就在这：错误暴露得离作案现场越近，定位越便宜。

成本也要记账，实验用无 bug 版跑满 300 步、重复 5 次取最快：checkRep 关 0.64 ms，开 0.86 ms，约 1.3 倍的相对开销、毫秒级的绝对开销。这个账在真实代码库里要重算：checkRep 对 rep 是线性扫描，rep 越大越贵，放在高频调用的内层会肉疼。行业惯例是把开关做成环境相关的选择：开发与测试期全开（此时抓一个 bug 的收益远超开销），性能敏感的发布构建再关。Python 的机制顺带一提（版本相关行为，非永恒事实）：`python3 -O` 运行时 assert 语句整体被剔除，关开销不用改代码，代价是所有断言一起消失。

白话：checkRep 是仓库管理员下班前点名，货没少时点名费几分钟，货丢了当场就知道是哪班次弄丢的；不开点名，丢货要等顾客投诉（count_ge 报错数），中间过了五班次，监控早被冲掉了。

> 本节小结：RI 的归纳论证会错，checkRep 把 RI 写成断言、挂在构造器与每个改 rep 的操作末尾；实测一个单下标 bug，无断言时 RI 被破 5 步后才现形、全程 134/300 步错值，有断言时延迟 0 步、当场炸出乱序对与完整 rep；开销实测约 1.3 倍相对值，工程分寸是开发期开、发布构建关。

## $\rm \S \, 4.5$ 分寸与边界：拷贝的成本账

防御性拷贝不是免费首选项，先把账算全再决定在哪设防。

1. 拷贝的真实成本：出参拷贝对 rep 是一次线性扫描，`get_all` 这类全量出参每次调用都付 O(n)；高频调用下这是实打实的开销，不是理论担忧。
2. 设防的两头，付账的也两头：§3.5 留下的账在这里结清。实现方做防御性拷贝，成本归实现方；或者合同写明条款，`modifies: 无` 换成对出参的承诺「返回的列表与内部状态无关，可任意修改」，承诺本身也压着实现（逼它拷贝或者换 rep），成本还是绕回实现，但写进合同至少让调用方不必瞎猜。两头全不设防的代码库，就是 §4.3 那个 860/1000 的现场。
3. RI 的强度也要分寸：RI 越强，实现敢押的注越多（效率越高），但每个操作维护不变量的成本越高。立一条没人用的 RI 是白付维护费：本例三条 RI 各有主顾，None 与正页数保护 total_pages 与 count_ge，有序保护 top 与 count_ge 的早停，删掉任何一条都有操作失去依据。
4. 结构性替代方案存在但先立个路标：若 rep 用不可变类型（元组的元组），外部根本改不动，拷贝可以从根上免掉，这条路连同它在并发下的红利是第 6 章的主题，此处只指路。

最后钉一遍本章实验的边界：860/1000 是这个攻击分布下的实测值，换个分布数字会变，不变的是定性结论——暴露 rep 的类把 RI 的存亡交给了外部代码的手气，防御性拷贝把它收回结构保证；checkRep 的 1.3 倍开销同样是这 300 步脚本下的实测，rep 变大、断言变复杂，账都要重算。

## $\rm \S \, 4.8$ 本章自测答案

概念回顾答案：

1. 「抽象」指使用方只能通过操作集合访问类型，接触不到存储；rep 随便换而不惊动使用方，靠的是每个操作的行为（即类型级合同）不变，AF 保证新旧 rep 映射到同一抽象值（来源：§4.1）。
2. RI 管合法 rep 的门槛，AF 管合法 rep 到抽象值的翻译。列表有序是实现为让 top 切片、count_ge 早停而自立的规矩，抽象值「书架上的论文集合」没有顺序概念，顺序在 AF 中被抹掉，所以它是 rep 的私规不是抽象事实（来源：§4.2）。
3. 覆盖对象一生中所有可观察时刻：构造器给出合法起点，每个操作保持合法性，归纳即任意时刻合法。任何操作漏了保持论证（或 rep 被外部引用改坏，见第 4 问）论证即断（来源：§4.2、§4.3）。
4. 不算违约，因为外部代码签署的只有操作级 spec，RI 是实现私有合同、对外不可见；按第 3 章 §3.5 的未完全确定规格原则，get_all 的合同没写「返回内部引用、勿改」，外部对拿到的列表怎么改都在自由裁量权内（来源：§4.3）。
5. 说明 RI 被破的腐蚀是选择性的：只有押注 RI 的操作（top 的切片假设、count_ge 的早停假设）交错值，不依赖顺序的 total_pages 照常正确。于是症状漂移、现场被覆盖，bug 从作案到现形隔了数步操作，定位成本陡增（来源：§4.4）。
6. 位置是类型边界：构造器入参、每个把 rep 一部分递出去的出参，rep 内部传引用无妨。浅拷贝在元素不可变时够用（改不动元素本体）；元素含可变对象（如 dict）时浅拷贝挡不住穿透，必须深拷贝，或让 rep 只存不可变元素（来源：§4.3、§4.5）。

应用与辨析答案：

1. 没有。列表推导新建了一个列表，出参天然是拷贝，rep 的引用没有跨出边界。量级差别在成本而不在安全：`get_all` 返回引用省一次 O(n) 拷贝却破了防火墙；`titles` 每次调用都付一次 O(n) 构造，买到的是结构性安全，这个钱是应该花的（来源：§4.3、§4.5）。
2. 两处修改：其一，构造器改为 `self._items = list(items)` 加排序（或 `sorted(items)`），堵住入参暴露，理由是调用方可能继续用自己手里的列表；其二，审查每个出参，凡返回 `self._items` 或其切片的改为返回拷贝。`top(k)` 不敢用二分：二分的正确性完全押在「有序」这条 RI 上，而当前实现的 RI 连是否成立都无法保证（入参暴露随时可能改坏顺序），押注前先补防线，或先用 checkRep 确认 RI 在运行中始终成立（来源：§4.3、§4.4）。
3. 分寸：改动 rep 的每个方法（构造器、add、remove 这类 mutator）末尾必挂，违反十有八九发生在改 rep 的现场；纯读且实现不依赖 RI 细节的方法（如 total_pages 对顺序无依赖）可以不挂。判断依据：挂断言的收益是「抓 RI 违反的现场」，出现违反的概率与 rep 大小、操作复杂度正相关，开销与 rep 大小线性相关；所以高频小 rep 的 mutator 值得挂，低频大 rep 的纯读操作可豁免，发布构建统一关（来源：§4.4、§4.5）。

**你现在能做什么**：挑出你最近写的任何一个类，两分钟内写出它的 RI（至少两条），然后逐个检查出参与构造器，凡是把 rep 的引用递出边界的，当场改成防御性拷贝。

类型层的合同到本章立住了：数据有了操作定义的边界，边界内有一份私有纪律，纪律有防火墙与断言两道防线。但 `PaperShelf` 至今只有一个实现，使用方面对的也还是这个具体的类；怎么把「操作集合」与「实现」正式拆开、让多个实现可以互换而不惊动调用方，是下一章接口与设计原则的起点。
