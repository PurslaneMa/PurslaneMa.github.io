# $\rm Chapter \, 10$ 收束地图：分层思维与排障工具箱

九章铺完了一条完整的路：以太网把帧送到隔壁、IP 把包送过千山、TCP 把字节可靠地排好、HTTP 在其上对话、TLS 给全程上锁。本章收束成两样带走的东西：一张「每层承诺什么、不承诺什么」的总图，和一条从下往上的固定排障路线：出了网络问题，按层逐级敲门，每层一个工具一行命令，敲到哪层不响应，问题就在哪层。

> **开始前自检**：本章假设你已经会：
>
> 1. □ 说出五层各自的封装头与职责（§1.2–§1.3）；
> 2. □ 区分 IP 的尽力而为与 TCP 的可靠（§3.1、§5.1）；
> 3. □ 把一次 HTTPS 请求拆成 DNS/握手/TLS/处理四段并实测过（§7.2、§9.3）；
> 4. □ 用 dig/openssl 的两行输出读出证书链（§9.6）。

## $\rm \S \, 10.1$ 总图：每层的承诺与不承诺

| 层 | 承诺 | 明确不承诺 | 出问题的样子 |
| --- | --- | --- | --- |
| 链路（§2） | 帧送达隔壁设备、差错检测丢弃 | 不修复、不管跨网 | 网线/Wi-Fi/交换机：接口灯、arp 无响应 |
| IP（§3） | 按最长前缀尽力投递 | 不保证到、不保证序、不保证只到一次 | 丢包、断路：ping 不通、traceroute 断在某一跳 |
| TCP（§4–7） | 字节流可靠有序、不丢不重、不堵死对方 | 不保证时延、不管内容含义 | 重传堆积、TIME_WAIT 耗尽、连接重置 |
| TLS（§9） | 机密、完整、两端身份 | 不防服务器自己作恶、0-RTT 不防重放 | 证书报错、握手失败、版本不匹配 |
| 应用（§8） | 请求-响应语义、内容格式 | 不保证业务正确 | 状态码、慢查询、DNS 过期 |

读表的正确姿势是**竖着读**：上层的一切承诺都以下层的不承诺为原料：TCP 的「不丢」是在 IP 会丢的前提下造出来的，TLS 的「可信」是在任何人都能读的线路上造出来的。**每层的价值 = 它从下一层的混乱里秩序化了什么**。

## $\rm \S \, 10.2$ 五级排障演练：从下往上敲门

「网站上不去」时，别急着重启，按层敲门，每级一行命令，停在哪级，问题就限定在哪层。一次真实演练（WSL2 采集，目标是清华主页）：

```text
[1] ping 网关          → 2 packets, 0% loss, rtt avg 2.7ms     ← 本地链路通
[2] ping 223.5.5.5     → 0% loss, avg 3.7ms                   ← 出网关到公网通
[3] getent hosts 域名  → 2402:f000:…:15:66                    ← DNS 能翻
[4] TCP 探测 443       → real 0m0.010s                        ← 端口开、三次握手成
[5] curl 计时          → HTTP 200 | dns 5ms tcp 9ms tls 36ms 总 55ms
```

五级的判定表（停在哪行，查什么）：

1. **[1] 断**：本机到网关都不通（Wi-Fi 掉线、网线、本机防火墙）。查 `ip addr`（有没有地址）、`ip link`（接口状态）；
2. **[2] 断 [1] 通**：局域网好、出不去，运营商/路由器问题。`traceroute` 看断在第几跳（第 1 跳断=自家路由，第 2 跳起断=运营商）；
3. **[3] 断 [2] 通**：网络通、名字翻不出（DNS 故障）。换 `223.5.5.5` 再试（`dig @223.5.5.5`），通了就是默认解析器的问题；
4. **[4] 断 [3] 通**：IP 在、端口关，服务没起或防火墙拦。服务端 `ss -lntp` 看监听、云厂商安全组；
5. **[5] 里分段慢**：都通但慢，按 curl 的四个数判：`dns` 大走 §8.2、`tcp` 大是 RTT/握手（§7.2）、`tls` 大看 §9.3、`总 − 前三段` 大是服务器处理。

这条阶梯的纪律与操作系统分册 §10.2 的四步定位同构：**从便宜到贵、从粗到细，每步用观测证据收窄方向**，不凭感觉换零件。

四种典型故障在阶梯上的指纹（同样的「打不开」，敲门结果各不相同）：

| 故障 | [1] 网关 | [2] 公网 IP | [3] DNS | [4] 端口 | [5] 计时 | 定位 |
| --- | --- | --- | --- | --- | --- | --- |
| Wi-Fi 掉了 | 断 | 断 | 断 | 断 | — | 第 1 级即命中 |
| 运营商出口故障 | 通 | 断 | 断 | 断 | — | traceroute 看断在第几跳 |
| 默认 DNS 被劫持 | 通 | 通 | 慢/错 | — | dns 段大 | 换 `@223.5.5.5` 对照（§8.2） |
| 服务进程挂了 | 通 | 通 | 通 | 断（拒连/超时） | — | 服务端 `ss -lntp` 查监听 |

读表的方法与 OS 册的慢法表一致：**敲门是取指纹，判型靠组合**：四级读数一次拿齐，故障空间已经被切成互斥的格子。

**本节小结**：排障的纪律是「按层从下往上敲门」：每级一行命令、停在判定分支上，断在哪级问题就限定在哪层，慢则交给 curl 的四段分解继续拆。

## $\rm \S \, 10.3$ 分层思维的两个推论

1. **每层可替换**：接口不变、实现可换。家里 Wi-Fi 换成有线，以太网帧换载体，IP 以上全部无感；HTTP/1.1 换 2 换 3，应用语义不变；TLS 套件升级，HTTP 不知情。反过来用：**排查时可以整层替换做对照**（换网络、换 DNS、换浏览器、换 HTTPS/HTTP），哪层替换后现象消失，问题就在那层；
2. **跨层信息会丢**：每层只把自己的头交给上层，TCP 看不见 IP 走了哪条路（traceroute 借 TTL 另辟蹊径）、HTTP 看不见 TCP 的重传（应用层超时只能瞎等）、TLS 不知道对端 RTT（QUIC 把传输与加密合并，动机之一正是拿回跨层信息）。**「在哪一层，就只能看到哪一层的风景」**。排障卡住时，问自己是不是站在错误的层上看。

第三个推论关于设计：**给别人造层时，接口合同决定别人能做什么**。TCP 只往上传「字节流」，于是 HTTP 只能自己发明消息边界（§8.4 的三种收尾）；IP 不给「路径可见」，于是 traceroute 只能借 TTL 逼它开口。设计 API 也一样：你交出去的字段集合，就是使用者的全部世界，少给一个字段，使用者就要用一个丑陋的 workaround 来赎。读协议史时带着这条看：HTTP/2 的新头字段、QUIC 的连接标识，都是「向下多要一点信息」的接口修订。

**本节小结**：分层送出两个推论——整层可替换（排查时就是对照实验法）、跨层信息会丢（卡住时先问自己站没站错层）；再加一条设计观：接口合同就是使用者的全部世界。

## $\rm \S \, 10.4$ 工具箱：每层一件趁手的

| 层 | 工具 | 一句话用法 |
| --- | --- | --- |
| 链路 | `ip addr` / `ip link` | 有没有地址、接口 up/down |
| IP | `ping` / `traceroute`（Windows `tracert`） | 通不通、断在第几跳 |
| DNS | `dig`（Windows `nslookup`） | `dig @223.5.5.5 域名` 换解析器对照 |
| TCP | `ss -lntp` / `nc -vz host port` | 谁在监听 / 端口敲得开吗 |
| TLS | `openssl s_client -connect host:443` | 证书链、协议版本、套件 |
| 应用 | `curl -w` 模板 / 浏览器 Network 面板 | 四段计时 / 请求瀑布 |
| 全线 | Wireshark | 以上都定位不了时，从帧开始肉眼逐层拆 |

工具箱的最后一行 Wireshark 常被神化，记住它的正确位置：它验证「线路上发生了什么」，而前五级工具验证「我的世界里缺了什么」，问题多半在后者。

工具之外还差一样：**记录基线**。网络问题的「慢」与「断」都要有正常时的参照才可判，趁今天一切正常，把常用站点的五级读数各存一份（RTT 几毫秒、DNS 几毫秒、tls 几十毫秒）。故障时对照基线，偏离量级立刻显形；没有基线，你就只能对着一个孤零零的读数猜。
基线本身也是健康检查：每季度重跑一遍，就能发现「DNS 从 5 ms 涨到 40 ms」这类渐进劣化，它们单看都「还能用」，趋势上看全是事故前兆（计算机速通 §32 的可观测性思想在网络的落点）。

一行过滤的 tcpdump 抓包（WSL2，Linux 万能起点）：

```bash
tcpdump -i any -nn -c 40 'host www.example.com and port 443'
```

`-i any` 所有接口、`-nn` 不做名字反查（避免 DNS 反而拖慢）、`-c 40` 只抓 40 包就停。抓下来的文件（`-w out.pcap`）再交给 Wireshark 逐层拆：命令行做过滤、图形界面做解剖，两头各干擅长的事。

选型纪律：**先用行内工具拿读数，Wireshark 是最后的显微镜**：逐帧人工看对时间极贵，而分段计时已经把问题锁到层了。

## $\rm \S \, 10.8$ 本章自测答案

### $\rm \S \, 10.8.1$ 关键概念回顾答案

1. 价值 = 从下一层的混乱里秩序化了什么。TCP 在「IP 会丢会乱」之上造出「字节流不丢不乱」；TLS 在「任何人都能读能改」之上造出「机密＋完整＋身份」。（§10.1）
2. 第 [1][2] 级只用 IP 地址。用法：先纯 IP 验证「路通不通」，再单独验 DNS，两条互不掺和，把「名字翻不出」与「路走不通」彻底分开，不致把 DNS 故障误诊成断网。（§10.2）
3. 换解析器重试（`dig @223.5.5.5 域名`）：通＝默认解析器问题（缓存投毒/故障/被劫持），不通＝该域名本身解析异常，再看权威。（§10.2）
4. 因为层的接口固定、实现可换，替换前后现象的差就是该层的贡献。例子：网络从 Wi-Fi 切手机热点，现象消失即 Wi-Fi/局域网层问题。（§10.3）
5. TLS 被设计在 TCP 之上，只拿到「字节流」抽象，看不到下层的 RTT、重传、拥塞窗口，传输层信息在接口处被丢掉；QUIC 把传输与加密合并在同一层实现，握手里直接带 RTT 估计与丢包信号，合并层次正是为了拿回跨层信息。（§10.3、§8.6）

### $\rm \S \, 10.8.2$ 应用与辨析答案

1. ① `ping -c 2 网关`（断→查本机/接入）；② `ping -c 2 223.5.5.5`（断→traceroute 定位跳数）；③ `getent hosts 站点域名` 或 `dig`（断→换 `@223.5.5.5` 对照）；④ `nc -vz 站点 443`（断→DNS 通则查服务端/防火墙）；⑤ `curl -w '…dns/tcp/tls/总…'`（通而慢→四段分解）。每条都停在判定分支上，不做多余动作。（§10.2）
2. 三段握手共约 44 ms，剩约 4.15 s 在「请求发出 → 首字节返回」之间，即服务器处理或对端生成响应慢。候选一：服务端应用瓶颈（验证：直接打服务器内网地址/绕过 LB 对比，或看服务端日志的时间戳）；候选二：请求触发的外部依赖慢（数据库/第三方 API；验证：对同一服务发一个无依赖的轻请求对照）。（§7.4、§10.2）
3. 分层的透明性：防火墙做深度检测看的是**载荷内容**（TLS 密文），端口只是路由注脚，挪端口不改变「密文里没东西可看」这一事实；而且 SNI（§8.2 的 DNS 之外另一处明文域名）照样在 ClientHello 里明着走。有意义的做法是管理侧申请白名单或按公司政策处理，技术上的「躲」解决不了政策问题。（§9.4、§9.6）
