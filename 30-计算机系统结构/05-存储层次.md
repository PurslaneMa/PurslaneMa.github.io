# $\rm Chapter \, 5$ 存储层次：缓存与局部性

前四章把处理器练成了短跑健将：一拍发射四五条指令。可再快的腿也得有饭吃：一次内存访问的耗时够 ALU 跑上百拍，递不上操作数，乱序窗口再大也是空转。计算机速通 §10.3 见过这个现象的表皮，本章拆机制：一座金字塔式的存储层次怎么靠局部性养活，缓存的三段地址切分怎么手算，以及两个真跑实验：跨步遍历把每访问成本拉大 25 倍、矩阵乘换个循环次序快 3.4 倍。

## $\rm \S \, 5.1$ 一座金字塔：量级与动机

处理器与内存的速度差约两个数量级：L1 缓存 4 拍上下，内存 100 ns（3 GHz 下约合 300 拍）。硬靠山是**存储层次（memory hierarchy）**：越靠上越快、越小、越贵，越靠下反之。缓存的统一比喻延续全书：缓存是书桌，内存是自家书架，SSD 是仓库；书桌上只放正在用的几本书，桌子大小由硅片预算决定。本机（Intel Core Ultra 7 255H，WSL2 实测 `lscpu`）各层的容量与典型延迟：

| 层 | 容量（本机实测） | 典型访问延迟 |
| --- | --- | --- |
| 寄存器 | 32 个 × 64 位（§2.2 的架构账） | 0 拍，就是操作数本身 |
| L1 数据缓存 | 48 KiB/核 | 约 4 拍 |
| L2 缓存 | 3 MiB/核 | 约 14 拍 |
| L3 缓存 | 24 MiB，全核共享 | 约 50 拍 |
| 内存 | 数十 GiB | 约 100 ns |
| SSD | TiB 级 | 约 100 µs |

延迟一栏为典型值（按拍折算随频率浮动），容量一栏是本机数字。读表三个抓手：

1. 每降一层，容量涨 10 到 100 倍，延迟涨几倍到几十倍：快与贵同源（SRAM 贵而快，DRAM 便宜而慢）；
2. L1 分成数据与指令两块，正是 §3.4 结构冒险的解法留下的格局，本章只谈数据那块；
3. 表中延迟是「命中」的价；未命中要往下一层讨，实际价格是两层延迟之差乘缺失率。

金字塔能成立的全部前提写成一个词：**局部性（locality）**。时间局部性说刚用过的数据马上还会用（循环变量）；空间局部性说用过地址 $a$，$a$ 旁边的很快也会被用（数组顺序遍历）。缓存把数据按块搬上书桌，赌的就是这两条。

## $\rm \S \, 5.2$ 缓存的组织：切分、相联与写策略

内存与缓存之间的搬运单位是**缓存行（cache line）**，典型 64 字节：哪怕只要 1 个字节，也整行搬上来，赌的是空间局部性。缓存里每行存三样：数据、内存地址的指纹（标记）、有效位。地址如何定位到某一行？把地址切成三段：

$$
\text{地址} = \text{标记} \;|\; \text{索引} \;|\; \text{偏移}
$$

手算一个 8 KB、4 路组相联的缓存（32 位地址）：

1. 偏移：行内 64 字节，占低 6 位；
2. 索引：总容量 8192 字节 ÷ 每组 $4 \times 64 = 256$ 字节，共 32 组，占 5 位；
3. 标记：$32 - 6 - 5 = 21$ 位。

查找流程：索引进组，组内 4 行的标记并排比较，命中则按偏移取字节。**组相联（set associative）**是容量与速度的折中：直接映射（每组 1 行）硬件最简但冲突频繁，全相联（整个缓存一组）最灵活但比较器爆炸，中间取个 4 到 16 路。相联度每翻一倍，比较器与功耗跟着翻倍，换来冲突缺失的下降；L1 常取 4 到 8 路、L3 常取 8 到 16 路，是这条曲线上的常用点。缺页里的地址翻译（操作系统册 §4.4）用的是同一套「切位段查表」的手艺。

查不到就是**缺失（miss）**，按原因分三类，各配各的药方：

1. 强制缺失（compulsory）：这块数据第一次被访问，谁来都得缺；药方是预取；
2. 容量缺失（capacity）：工作集比缓存大，装不下；药方是分块（blocking）压缩工作集；
3. 冲突缺失（conflict）：容量装得下，但几块数据映射到同一组互相踢；药方是改数据布局或加相联度。

组满要踢人，踢谁？理想策略 LRU（最久未使用）在硬件上要为每组记账，代价高，实际用近似 LRU（如伪 LRU 树）。这道「挑谁换出」的题你在操作系统册 §5 刚做过：页面置换是同一道题的页面版，粒度 4 KB、时间尺度秒级、用软件记账；缓存行版粒度 64 字节、纳秒级，连精确记账都嫌贵。写命中也有两派：write-through（同时写穿到下层，简单、费带宽）与 write-back（只改缓存，记一个脏位，被淘汰时才写回；操作系统册 §5 的脏页是同一思想的页面版）。

## $\rm \S \, 5.3$ 实验一：跨步遍历里的缓存行

1 GiB 的 `int64` 数组（$2^{27}$ 个元素），四种步长各扫一遍求和，只动步长不动语义。环境：WSL2（内核 6.6.87）、gcc 13.3.0 `-O2`、Intel Core Ultra 7 255H；每组取 3～5 次重复的最快值，确定性无随机。核心代码：

```c
for (size_t i = 0; i < N; i += st) sum += a[i];   // st ∈ {1, 8, 64, 512}
```

| 步长（元素） | 访问次数 | 总耗时 | 每次访问 |
| --- | --- | --- | --- |
| 1 | 134,217,728 | 115.0 ms | 0.86 ns |
| 8 | 16,777,216 | 65.7 ms | 3.92 ns |
| 64 | 2,097,152 | 24.0 ms | 11.46 ns |
| 512 | 262,144 | 5.7 ms | 21.74 ns |

读这张表先看单位：每访问耗时从 0.86 ns 涨到 21.74 ns，25 倍。机制三层。第一，每 8 个 `int64` 恰好占一条 64 字节缓存行：步长 1 时一次访问摊到 $\frac{1}{8}$ 行的搬运成本，步长 8 起每次访问独占一行，整行搬上来只用 8 字节，其余全浪费；第二，步长 64 与 512 时连空间局部性的赌注都收不回，纯付整行成本；第三，步长 512 意味着 4096 字节一跳，一页 4 KB 一跳，TLB（操作系统册 §4.5）的翻译缓存也开始挨打。步长越小越快，不是玄学，是把缓存行的每一分钱都花在刀刃上。

表里还藏着一个反直觉数：步长 8 的总耗时（65.7 ms）比步长 1（115.0 ms）短。总耗时是「每访问」乘「次数」，步长 8 每访问贵 4.6 倍，但访问次数只有八分之一；两种步长反正都要把同一条缓存行搬上来，总字节流量相近，总耗时相近合理。真正的悬崖画在「每访问」口径上。

## $\rm \S \, 5.4$ 实验二：矩阵乘的循环次序

$n=512$ 的 double 矩阵乘，浮点运算量完全相同，只交换内外层循环。环境同 §5.3：

```c
// ijk：内层 B[k*n+j]，j 固定 k 增长，步长 n*8 = 4096 字节
for (i...) for (j...) { s = 0; for (k...) s += A[i*n+k] * B[k*n+j]; C[i*n+j] = s; }
// ikj：内层 j 连续，B[k*n+j] 与 C[i*n+j] 顺流而下
for (i...) for (k...) { aik = A[i*n+k]; for (j...) C[i*n+j] += aik * B[k*n+j]; }
```

实测：ijk 178.3 ms，ikj 52.6 ms，比值 3.39 倍；两种次序算出的 `C[7][9]` 都是 4039.250，语义分毫未动。ijk 的内层每次乘加都跳 4096 字节取一个 double：正好一页一跳，缓存行用 8 字节、TLB 每次都换页，§5.3 表里步长 512 那行的病它全占了；ikj 的内层是教科书式的顺序遍历，一条 64 字节缓存行喂 8 次乘加。

两条使用说明。1. 为什么用裸 C 而不是 numpy：numpy 的矩阵乘内部自带分块与 SIMD，测出来的是库的优化而非循环次序本身，用它对比 ijk/ikj 不公平；裸 C 关掉所有帮助，才能把变量逼到只剩次序。2. 这就是「缓存不友好」四个字的实价：计算机速通 §10.3 预告过同类程序差 5 倍，更极端的规模与分布下 10 倍、百倍都真实存在。OJ 卡常卡的是算法常数，游戏卡帧卡的是资源遍历路径：贴图与模型按空间顺序流式读入命中率高，资源散布各处随机跳读，书桌与书架之间来回跑，帧率就掉。共同答案是顺着存储层次的方向走路，让下一次访问落在刚搬上书桌的那一行里。

1. §5.3 表中步长 8 的总耗时（65.7 ms）比步长 1（115.0 ms）短，为什么步长 512 的总耗时反而只有 5.7 ms？「每访问最慢」与「总耗时最短」矛盾吗？

## $\rm \S \, 5.7$ 本章自测答案

> 先闭卷作答 §5.5 与 §5.6，再核对。

### $\rm \S \, 5.7.1$ 关键概念回顾答案

1. 速度差两个数量级，靠单一存储既快又大不可能；金字塔用小而快的层装热点数据。支撑规律：时间局部性与空间局部性。（§5.1）
2. 偏移 6 位、索引 5 位、标记 21 位。索引回答「进哪一组」，标记回答「组内这行是不是我要的那块」，偏移回答「行内第几字节」。（§5.2）
3. 强制缺失（首见，预取）、容量缺失（工作集超缓存，分块）、冲突缺失（同组互踢，改布局或加相联度）。（§5.2）
4. 「满员时挑谁换出」。页面置换粒度 4 KB、软件记账、秒级；缓存行 64 字节、硬件近似记账、纳秒级。（§5.2）
5. write-through 赌写不频繁、图省心；write-back 赌局部性、攒批量写回，代价是要记脏位。脏位对应页面置换判「页是否要写回磁盘」的同名机制。（§5.2）
6. 32 组。同索引不同标记的数据挤进同一组，4 路下放第 5 块就把最旧的一块踢出去，是冲突缺失的标准剧本；加相联度或改数据布局可解。（§5.2）

### $\rm \S \, 5.7.2$ 应用与辨析答案

1. 不矛盾。总耗时 = 每访问 × 次数，步长 512 只访问 262,144 次（是大步长 512 倍、访问数小 512 倍）；它的每访问最贵（21.74 ns），总量却最小。两个口径对应第 1 章延迟与吞吐的分家。（§5.3、本书 §1.1）
2. 行主序下按列走，相邻两次访问差 $N \times$ 元素大小字节：$N=512$ 时恰是 4096 字节一跳，缓存行与 TLB 双输；按行走是顺序遍历。与 §5.4 的 ijk 内层同病。（§5.3、§5.4）
3. 冲突缺失：容量明明够，但若干热点块映射到同组互踢。验证法：给数组垫上不同的偏移（padding）或加相联度，缺失大减即可归因；若垫偏移无效再查容量。（§5.2）
4. 把其中一个数组垫开几个元素（或改打包成结构体数组之外的布局），让两块数据落进不同组；代价是多用一点内存，换掉冲突互踢。（§5.2）
5. 行长不变，偏移位数不动；组数翻倍，索引多 1 位；地址总长固定，多出的位从标记里扣（21 位减到 20 位）。同容量下不同相联度的切分差异全由此而来。（§5.2）
