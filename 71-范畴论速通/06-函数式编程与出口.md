## $\rm \S \, 6.1$ 类型类对账单：Functor、Applicative、Monad

Haskell 用**类型类（type class）**给「满足某组公理的类型构造子」立接口。三个类型类正好是本册前几章的编程拼写（先看代码再看对应）：

```haskell
class Functor f where
  fmap :: (a -> b) -> f a -> f b        -- 自函子 T 在态射上的作用

class Functor f => Applicative f where
  pure  :: a -> f a                     -- eta：散件装包
  (<*>) :: f (a -> b) -> f a -> f b     -- 装包的函数应用到装包的值

class Applicative f => Monad f where
  (>>=) :: f a -> (a -> f b) -> f b     -- bind = mu . fmap
  return = pure                         -- 别被名字骗了，它就是 eta
```

**对账单**（逐行回指本册）：

1. `Functor f`：$f$ 是 $\mathrm{Hask}$ 上的自函子，`fmap` 是它对态射的作用；两条定律 `fmap id = id`、`fmap (f . g) = fmap f . fmap g` 就是第 1 章函子的两条公理原文。
2. `Applicative f`：`pure` 是第 5 章的 $\eta$；`(<*>)` 让「装包的函数」也能应用——范畴论身份是**松幺半函子（lax monoidal functor）**：它带着 $\mathrm{Id} \Rightarrow f$ 与 $f \otimes f \Rightarrow f$（配合 $\mathrm{Hask}$ 的积结构）且保结构不逆。四条 applicative 律（恒等、同态、交换、复合）保证这两件套协同合法；等价性陈述在此，证明不进速通射程。
3. `Monad f`：`(>>=)` 即第 5 章 $\mathrm{bind}(m, f) = \mu(T f(m))$，三律逐字对应——`return x >>= f = f x`（左单位）、`m >>= return = m`（右单位）、`(m >>= f) >>= g = m >>= (\x -> f x >>= g)`（结合）。

层级关系 Functor ${\Rightarrow}$ Applicative ${\Rightarrow}$ Monad 严格递增：会 `fmap` 不一定会 `pure`/`(<*>)`，会 applicative 不一定会 bind。分水岭一句话——**Applicative 的结构不依赖值，Monad 的结构依赖值**。§6.7 程序段用一个列表把分水岭跑给你看：applicative 的 `<*>` 对 $[1, 2]$ 与两个函数给出固定的 $2 \times 2 = 4$ 个结果（笛卡尔式、形状事先定死），bind 却允许「偶数直接出局」（每个元素自己决定产出多少）——前者是松幺半函子的张量积世界，后者才动用了 $\mu: T^{2} \Rightarrow T$ 的拍平权。范畴论把这层区别说成：Applicative 处处是「保结构的搬运」，Monad 多了「塌缩的能力」。

**本节小结**：三个类型类逐格回指本册——Functor 对自函子公理（第 1 章）、Applicative 对松幺半函子（$\eta$ + 张量）、Monad 对单子三律（第 5 章）；层级递增的分水岭是「结构是否依赖值」。下一节看纯函数性这条编程纪律。

## $\rm \S \, 6.2$ 纯函数性与引用透明

**纯函数（pure function）**：输出只由输入决定、不读写外部世界的函数——同样的参数永远同样的结果，没有副作用的暗门。**引用透明（referential transparency）**：任何表达式可以替换成它的求值结果，而程序行为不变。白话：**引用透明是「表达式可当货币使用」**——一张 $10$ 元的钞票和「这 $10$ 元」在任何场合等值互换，不用查它经了谁的手；副作用就是钞票上藏着的暗记，换个场合兑换就出事。

两条纪律互相咬合：全由纯函数写成的程序自动引用透明。红利列清单：

1. **等式推理**：`f(g(x)) = g(f(x))`（当 $f$、$g$ 各自纯且 $T$ 是函子时这是 fmap 公理的应用）可以在纸面上算程序——第 1 章验证过的「两次 map 合一次」优化，就是把代码当等式改写的实例；
2. **编译器自由**：公共子表达式消除、惰性求值、并行调度——凡是「换个顺序求值」的优化，都靠引用透明担保不变味；
3. **测试即定义**：纯函数的测试覆盖就是输入输出的对照表，没有 mock 数据库、没有环境劫持。

副作用的去向是本章的题眼：**没有消失，是被关进类型签名**。状态被写成 $S \to (A, S)$（第 5 章 State 单子：明买明卖的状态管道）、失败被写成 $A \sqcup \{\ast\}$（Maybe）、多结果被写成 $\mathrm{List}(A)$——每个效应都从「暗门」升级为「签名」，函数类型不再说谎。IO 的处理最干脆：Haskell 把它做成一个抽象单子，外界交互的细节对类型系统不透明，类型系统只担保「IO 动作不会被纯代码偷跑」——这份诚实（承认有一步是黑箱）比「函数式消灭副作用」的口号更接近真相。

**本节小结**：纯函数 $\Rightarrow$ 引用透明 $\Rightarrow$ 等式推理、编译器自由、测试即定义；副作用没有被消灭而是被类型化收容——State、Maybe、List 各自签名在册，IO 是诚实的黑箱。下一节处理效应叠加的工程现实。

## $\rm \S \, 6.3$ 单子变形器一瞥

现实程序要同时要几种效应：读状态又可能失败（解析器）、记日志又多结果（爬虫）。两个单子能不能复合？范畴论给的是冷静的答案：$T_1 \circ T_2$ **一般不是单子**——bind 需要 $\mu: (T_1 T_2)^{2} \Rightarrow T_1 T_2$，而 $T_1 T_2 T_1 T_2$ 里两层结构交错，没有天然的拍平顺序；补齐它需要一条**分配律**（Beck distributive law：$T_2 T_1 \Rightarrow T_1 T_2$ 的自然变换，配四条相容公理）。分配律存在与否逐对验，没有免费午餐——这是第 5 章「拍平不是白给的」在工程侧的回声。

工程界的通行解法是**单子变形器（monad transformer）**：不复合两个现成的单子，而是给每个效应做一个「参数化单子」，把别的单子叠进自己的签名里。代表：$\mathrm{StateT}\;s\;M\;a = s \to M\,(a, s)$——状态动作的每步结果先交给 $M$ 处理；取 $M = \mathrm{Maybe}$ 得 $\mathrm{StateT}\;s\;\mathrm{Maybe}\;a = s \to \mathrm{Maybe}\,(a, s)$：**带失败出口的状态机**。配套操作 `lift` 把内层单子的动作抬进叠加层。

§6.7 程序段把这个叠加整台跑起来（用 python 仿写，`None` 代 $\mathrm{Nothing}$）：动作 $\mathrm{sub1}$ 递减状态、$0$ 处失败；动作 $\mathrm{read}$ 读状态。两问两答：

$$
s = 2 \;\Rightarrow\; ((\mathrm{None}, 1), 1) \qquad
s = 0 \;\Rightarrow\; \mathrm{None}
$$

（读法：$s = 2$ 时 $\mathrm{sub1}$ 成功、状态落 $1$、$\mathrm{read}$ 读回 $1$、整条链输出 $((\mathrm{None}, 1), 1)$；$s = 0$ 时 $\mathrm{sub1}$ 当场失败，bind 短路，输出 $\mathrm{None}$——失败穿透了整条状态管道。）变形器让效应自由叠加，代价 §6.4 清算时付。

**本节小结**：单子复合一般不合法（$\mu$ 缺、需 Beck 分配律），工程解法是变形器——StateT 把 Maybe 叠进状态签名，失败穿透状态管道的实跑两问两答。下一节付账。

## $\rm \S \, 6.4$ 思维价值与局限：一份诚实的清算

先记功劳，再记欠账。

**真灵的三件事。**

1. **接口即泛性质**。类型类的定义不说「怎么实现」，只说「满足什么」——`fmap` 的合法性由两条公理封顶，这正是第 3 章泛性质的句式：竞赛的冠军由「与所有竞争者的交换关系」定义，不看内部构造。最深的例子是 fold：`foldr f z` 的合法性等价于它是 $\mathrm{List}$-代数之间的保求值映射（第 5 章 §5.2：List-代数恰是幺半群，fold 对幺半群求值）——初始代数的唯一同态，泛性质的又一次上岗。连带 `List` 类型本身就是第 4 章自由幺半群的编程拼写：**类型的语义是自由对象，接口的语义是泛性质**。
2. **公理即优化与重构的安全网**。fmap 公理 `fmap f . fmap g = fmap (f . g)` 直接兑现「两次遍历合一次」（第 1 章程序验过的性能事实）；单子三律让 do-notation 的糖衣合法——语法糖展开后任一重排都语义不变，重构可以放心动手。
3. **词汇经济**。「容器」「效应」「拍平」被命名后，库设计的对话成本骤降：traverse、free monad、效果系统——每个新名字都站在本册的公理骨架上，第 5 章「效应即伴随的影子」正是这层词汇的红利。

**别指望的两件事。**

1. **泛性质不写业务逻辑**。范畴论给「接口长什么样」的判据，不给「这行代码对不对」的答案；单子律几乎从不直接抓 bug——它们约束的是容器演算本身，而 bug 十有八九住在业务分支里。把 monad 教程当捷径、以为「懂了单子就懂了并发」的人，撞的都是这堵墙（所谓 monad tutorial fallacy：比喻不能替代对具体效应的理解）。
2. **抽象塔有维护税**。变形器搭到三四层（$\mathrm{StateT}$ 套 $\mathrm{ExceptT}$ 套 $\mathrm{ReaderT}$），类型错误的报错长过出错的那行代码；Haskell 的惰性求值在抽象层叠厚后加剧空间泄漏，工业界的采用率也诚实反映了这份税。效应系统（algebraic effects）等新方案正在替代变形器塔——范畴论的词汇还在场，机制在换代。

一句话定调：**范畴论是编程的透镜，不是流水线**——它把重复的模式命名成公理与伴随，让你在正确的抽象层谈设计；它不替你设计，更不替你调试。

**本节小结**：三件真灵——接口即泛性质（fmap、fold、List＝自由幺半群）、公理即安全网（fmap 融合、do-notation 合法性）、词汇经济（效应即伴随）；两件别指望——不写业务逻辑、单子律不抓 bug、抽象塔收维护税。透镜的定位立此存照。

## $\rm \S \, 6.7$ 程序段：分水岭与变形器的机器验收

第一段验 Applicative/Monad 分水岭（同型数据、两条管线、形状对比）：

```python
# Applicative 与 Monad 的分水岭：结构是否依赖值
def fmap(f, m):  return [f(x) for x in m]
def ap(fs, m):   return [f(x) for f in fs for x in m]   # Applicative 的 <*>（笛卡尔式）
def bind(m, f):  return [y for xs in m for y in f(xs)]  # Monad 的 >>=

fs = [lambda x: x + 1, lambda x: x * 10]
m  = [1, 2]
print("applicative ap  :", [f(x) for f in fs for x in m])      # 2x2，结构事先定死
print("monad bind      :", bind(m, lambda x: [x] if x % 2 else []))
#                偶数直接丢弃——每个元素决定自己产出多少，结构依赖值

# Applicative 律的形状抽查（恒等律与同态律）
id_ = [lambda x: x]
print("identity law ap(pure(id), m) == m :", ap(id_, m) == m)
h = lambda x: x * 3
print("homomorphism pure(f) <*> pure(x) == pure(f x) :",
      [h(7)] == [f(7) for f in [h]])
```

实跑输出（本章数值锚，照抄）：

```text
applicative ap  : [2, 3, 10, 20]
monad bind      : [1]
identity law ap(pure(id), m) == m : True
homomorphism pure(f) <*> pure(x) == pure(f x) : True
```

（读法：`ap` 给出 $[2, 3, 10, 20]$——两个函数乘两个值，四个结果、无一逃逸，结构在运行前定死；`bind` 给出 $[1]$——$2$ 是偶数、它的续算产出空列表，结构随值坍缩。同一份 $[1, 2]$，两种宇宙。）第二段验单子变形器（python 仿写 $\mathrm{StateT}\;s\;\mathrm{Maybe}$）：

```python
# 单子变形器一瞥：MaybeT(State) —— 在「状态机」里叠一层「可能失败」
# T a = s -> Maybe(a, s)，用 None 表示 Nothing
Just  = lambda a, s: (a, s)
Nothing = None

def eta(a):  return lambda s: Just(a, s)
def bind(st, f):
    def run(s0):
        r = st(s0)                      # st 是一个状态动作：s -> Maybe(a, s)
        if r is Nothing: return Nothing
        a, s1 = r
        return f(a)(s1)
    return run

sub1 = lambda _: lambda s: Just(None, s - 1) if s > 0 else Nothing  # 递减，0 处失败
read = lambda s: Just(s, s)                                          # 读状态动作

prog = bind(bind(eta(3), sub1), lambda n: bind(read, lambda cur: eta((n, cur))))
for s in (2, 0):
    print("run prog at s =", s, "->", prog(s))
```

实跑输出：

```text
run prog at s = 2 -> ((None, 1), 1)
run prog at s = 0 -> None
```

读程序的几句话：`bind` 的前三行就是变形器的全部机制——状态动作先跑、结果交内层单子（这里是 Maybe）验收、失败短路、成功续跑；$s = 2$ 走完整条管道、$s = 0$ 一步出局，失败穿透状态管道的两种命都在场。想加深：把 `sub1` 换成任意带守卫的动作、把 Maybe 换成 List（每步多结果、管道分叉），同一副骨架照跑——变形器「参数化内层单子」的设计当场兑现。

## $\rm \S \, 6.8$ 六问参考答案

1. `fmap id = id` 与 `fmap (f . g) = fmap f . fmap g` 对应函子公理的保恒等与保复合（第 1 章）；`return` 是 $\eta$、`(>>=)` 是 $\mu \circ T f$（第 5 章）。糙点：Hask 里类型并不真是集合——`undefined`（底元）潜伏在每个类型中、严格性让 `seq` 能区分「逻辑等价」的程序，函子定律只在「忽略底元」的意义上成立；严格的范畴模型要另请 $\omega$-CPO 或范畴。（§6.1）
2. 分水岭：Applicative 的计算结构不依赖值（形状先定），Monad 的结构依赖值（$\mu$ 允许按值塌缩）。$[2, 3, 10, 20]$ 在 applicative 侧——$2 \times 2$ 笛卡尔、无一个元素能出局；$[1]$ 在 monad 侧——偶数续算产出空列表、被拍平抹掉。（§6.1、§6.7）
3. 定义：任何表达式可替换为它的求值结果而行为不变。编译器红利：公共子表达式消除、惰性求值与求值顺序重排的安全担保；重构红利：等式推理——代码改动可以按公理在纸面上验证。副作用去处：类型签名（State 的 $S \to (A, S)$、Maybe 的 $A \sqcup \{\ast\}$、List 的多结果、IO 的抽象黑箱）。（§6.2）
4. 复合的 bind 需要 $\mu: (T_1 T_2)^{2} \to T_1 T_2$，但 $T_1 T_2 T_1 T_2$ 里两层效应交错，拍平顺序没有天然选择；补齐需要 Beck 分配律 $T_2 T_1 \Rightarrow T_1 T_2$ 加四条相容公理。$\mathrm{StateT}\;s\;\mathrm{Maybe}\;a = s \to \mathrm{Maybe}\,(a, s)$；$\eta(a)(s) = \mathrm{Just}(a, s)$；bind 跑状态动作、结果交 Maybe 验收、失败短路、成功续跑（§6.7 程序段）。（§6.3）
5. 例一：`fmap` 的合法性由两条公理封顶，任何满足公理的实现自动合法——定义在「满足什么」上。例二：`foldr f z` 合法当且仅当它是 List-代数的保求值映射（第 5 章 List-代数＝幺半群、fold＝在幺半群里求值）——fold 的语义是初始代数的唯一同态，泛性质的冠军句式。（§6.4）
6. 真有用：接口即泛性质（类型类与 fold 的语义）、公理即优化与重构的安全网（fmap 融合、do-notation）、效应词汇经济（「效应即伴随的影子」贯穿库设计）。别指望：泛性质不写业务逻辑、单子律几乎不抓 bug（bug 住在业务分支）；抽象塔有维护税（深层变形器的类型错误与性能税，工业采用率是诚实的投票）。（§6.4）
