# $\rm Chapter \, 9$ 数据通路总装：拼出一颗单周期处理器

前八章造的积木在这一章拼整机：触发器当 PC 与流水线寄存器（§6），加法器与 ALU 算地址与结果（§4），寄存器堆放数据（§6.4），存储器装指令与变量（§8），时钟按 §7 的约束式定节拍。拼出来的东西叫**数据通路（datapath）**：一条指令在一拍之内流过取指、译码、执行、访存、写回五站。本章以 RISC-V 的 add、lw、beq 三条指令为主线走通它，再真跑一个最小模拟器收尾。

> 2. □ 会用 2 读 1 写的寄存器堆真值行为（本册 §6.4）；
> 3. □ 会算单周期路径约束与 slack（本册 §7.2）；

## $\rm \S \, 9.1$ 五站流水线化的骨架：单周期通路

单周期处理器的通路按数据流排成五站，用文字走一遍图：

1. **取指**：PC 是一个 32 位寄存器（一排 D 触发器，§6.4），它的值当地址送进指令存储器（§8 的 SRAM），取出当拍指令；
2. **译码**：指令的位字段切开，opcode 决定这条指令是什么，rs1、rs2 两个字段送寄存器堆的读地址端口；
3. **执行**：寄存器堆两个读端口吐出的值进 ALU（§4）；ALU 做什么由 ALU 控制信号选定，R 型算加减，访存指令算地址；
4. **访存**：lw 与 sw 把 ALU 算出的地址送数据存储器（§8 的 DRAM 视角，这里一律按理想 SRAM 计延迟）；
5. **写回**：结果多路选择器挑一路（ALU 结果、存储器读出数据），送回寄存器堆的写端口，在时钟边沿写入。

PC 的更新在边沿发生：非分支指令加 4，分支命中时改成分支目标。整条路在一个周期内走完，下一拍取下一条指令。

指令里的偏移与立即数不是寄存器，是编码在指令位段里的常数；译码站把它符号扩展成 32 位，交给 ALUSrc 信号选进 ALU 当第二操作数。lw 与 sw 的地址是「基址寄存器加立即数偏移」，beq 的分支目标是「PC 加符号扩展的偏移」，常数从指令字段直接流进 ALU，不经过寄存器堆。

**本节小结**：五站每站都是前几章造好的器件，PC 在边沿更新、整条路一拍走完；立即数是唯一不走寄存器堆的「外来的」操作数，从指令位段直接流进 ALU。

## $\rm \S \, 9.2$ 三条指令走通路与控制信号

三条代表指令各走一遍。**add**（R 型）：取指、译码、寄存器堆读出 rs1 与 rs2、ALU 做加法、不访存、把和写回 rd。**lw**（访存）：寄存器堆读出 rs1 作基址，符号扩展的立即数当偏移，ALU 算出有效地址，数据存储器读出一个字，写回 rd；它比 add 多一整站，这条差距 §9.3 要算账。**beq**（分支）：ALU 做减法判零，零标志与指令的 offset 字段一起决定 PC 下一拍取顺序指令还是分支目标。

三条指令的**控制信号（control signals）**取值表：

| 控制信号 | add | lw | beq |
| --- | --- | --- | --- |
| RegWrite（写回使能） | 1 | 1 | 0 |
| ALUSrc（第二操作数选立即数） | 0 | 1 | 0 |
| ALUOp | 加 | 加（算地址） | 减 |
| MemRead | 0 | 1 | 0 |
| MemWrite | 0 | 0 | 0 |
| MemToReg（写回选存储器数据） | 0 | 1 | 0 |
| PCSrc（PC 选分支目标） | 0 | 0 | 判零结果 |

读法：译码器按 opcode 查出这一列，各信号分别去开对应的 MUX 与门；写回与 PC 更新都发生在边沿，与 §6 的采样规则一致。addi 不访存不读第二寄存器，控制列与 add 几乎相同，只有 ALUSrc 翻成 1：第二操作数从寄存器换成符号扩展的立即数。控制信号通路与数据通路是两个并行的网络，前者告诉后者每一拍怎么接。

> **控制视角**：加一条新指令，数据通路多半不用动，动的是译码器真值表里多出的一列。可扩展性来自这张表的规整，这就是控制与数据通路分工的意义。

**本节小结**：三条指令共用同一条物理通路，差别全在控制信号表的一列——每个信号去开一个 MUX 或一扇门，写回与 PC 更新照旧在边沿发生。

## $\rm \S \, 9.3$ 单周期的代价：最慢指令卡死全片

单周期的定义是「一条指令一个时钟周期」，而周期由 §7.2 的约束式卡死，路径取所有指令里最长的那条。用 §4 与 §7 的延迟数字拼账（单位 ns）：${T_{clk \to q}} = 0.30$，指令存储器 0.40，寄存器堆读 0.25，ALU 0.50，数据存储器 0.60，${T_{setup}} = 0.20$。

| 指令 | 路径合计 (ns) |
| --- | --- |
| add | $0.30+0.40+0.25+0.50+0.20 = 1.65$ |
| beq | $0.30+0.40+0.25+0.50+0.20 = 1.65$ |
| lw | $0.30+0.40+0.25+0.50+0.60+0.20 = 2.25$ |

周期被 lw 卡死在 2.25 ns，频率上限由约束式直接给出：

$$
f_{\max} = \frac{1}{T_{clk}} = \frac{1}{2.25\,\text{ns}} \approx 444\,\text{MHz}
$$

add 与 beq 明明 1.65 ns 就能走完，却陪着 lw 等满一拍。所有指令共用一拍的浪费，就是流水线（计算机系统结构册 §3）要治的病：把单周期通路在五站之间插上一排排 D 触发器切成五段，每段按各自最慢的站定时钟，吞吐率起来的同时每段周期大幅缩短。那册的 CPI 与主频指标，电路根基全在本章这张延迟账上。

**本节小结**：单周期的周期不由平均值决定，由最慢指令（lw）的最长路径卡死；§7.2 的约束式在这张延迟账上给出 444 MHz 的上限，快指令全在陪跑——这笔浪费是下一册流水线的出发点。

## $\rm \S \, 9.4$ 最小模拟器：真跑一段程序

行为级模拟器把每条指令的通路走法写成代码（寄存器堆 8 项 x0 至 x7，x0 恒 0；内存 64 字；支持 add、addi、sub、lw、sw、beq、bne 七条指令），跑一段 7 条静态指令的小程序，累加 1 加到 5 并存回内存：

```python
if op == "lw":   regs[rt] = mem[base + off]      # 访存站
elif op == "bne": pc = target if regs[a] != regs[b] else pc + 1   # 分支改 PC
```

x0 恒 0 不是省一个触发器，是给「清零、与零比较、传值」提供常数源；往 x0 写的动作在写端口被硬线丢弃，读它永远得 0。RISC-V 的 32 个寄存器里 x0 同样恒 0，这条约定直接继承到真芯片。

| 周期 | PC | 指令 | 效果 |
| --- | --- | --- | --- |
| 1 | 0 | addi x1, x0, 0 | x1 = 0 |
| 2 | 1 | addi x2, x0, 5 | x2 = 5 |
| 3 | 2 | add x1, x1, x2 | x1 = 5 |
| 4 | 3 | addi x2, x2, -1 | x2 = 4 |
| 5 | 4 | bne x2, x0, 2 | 跳回 PC = 2 |
| $\cdots$ | 2 至 4 循环 | 共循环 5 轮 | x1 依次到 15，x2 递减到 0 |
| 18 | 5 | sw x1, 12(x0) | 内存[3] = 15 |
| 19 | 6 | lw x3, 12(x0) | x3 = 15 |

19 拍跑完：x1 = 15、x2 = 0、x3 = 15、内存[3] = 15，与手算的 $5+4+3+2+1 = 15$ 一致。模拟器每个周期只推进一次 PC、只写一次寄存器堆，正是 §9.1「一拍走完一条指令」的行为级复述；它与真实电路差在时间（行为级没有延迟账），不差在「发生了什么」。

**本节小结**：模拟器把「每拍取指、走通路、改一次状态」跑成了循环计数，19 拍的逐拍表与手算对上号——纸上拼的通路经了一段真实程序的检验。

## $\rm \S \, 9.7$ 本章自测答案

> 先闭卷作答 §9.5 与 §9.6，再核对。

### $\rm \S \, 9.7.1$ 关键概念回顾答案

1. 取指用指令存储器，译码用位字段切开，执行用 ALU，访存用数据存储器，写回走寄存器堆写端口。PC 是一排 D 触发器组成的寄存器，属于本册 §6.4 的器件。（§9.1）
2. ALUSrc（add 为 0、lw 为 1）、MemRead（add 为 0、lw 为 1）、MemToReg（add 为 0、lw 为 1）。ALUSrc 选「立即数还是寄存器」进 ALU，MemToReg 选「ALU 结果还是存储器数据」写回。（§9.2）
3. ALU 做减法、零标志进 PCSrc：为零则下一拍 PC 取分支目标，否则加 4 顺序执行。判零由 ALU 干，改 PC 在边沿发生。（§9.2）
4. 被最长路径（lw）卡死。约束式 $T_{clk} \ge T_{clk \to q} + T_{logic} + T_{setup}$ 里的 ${T_{logic}}$ 对 lw 要包含五站的全部延时，其他指令的 slack 全是正的也救不了它。（§7.2、§9.3）
5. 差在时间：行为级不付门延迟的钱；一致在行为：每拍取一条指令、改一次状态的状态序列与真实电路相同。（§9.4）
6. 省掉了专门的清零与传值指令、给比较指令提供常数源。常用写法：addi x1, x0, 5 装载立即数（x0 当基址）、beq x2, x0, exit 与零比较判循环终点。（§9.4）

### $\rm \S \, 9.7.2$ 应用与辨析答案

1. sw：RegWrite 0、ALUSrc 1、ALUOp 加、MemRead 0、MemWrite 1、MemToReg 0、PCSrc 0；lw 与它仅 MemRead/MemWrite 互换、MemToReg 与 RegWrite 不同。RegWrite 与 MemWrite 不会同时为 1，存储指令不写寄存器，加载指令不写内存。（§9.2）
2. lw 路径变 $2.25 - 0.60 + 1.20 = 2.85$ ns，频率上限 $1/2.85\,\text{ns} \approx 351$ MHz。（§9.3）
3. 改写：循环体里「x2 减 1 后 bne x2, x0, loop」是标准写法；等价改法是「beq x2, x0, exit 跳出、否则跳回循环头」。beq 分支命中时 PCSrc 为 1、PC 取目标；不命中为 0、PC 加 4，两种情况都在边沿更新。（§9.2、§9.4）
4. 每段只含自己那站的延迟加流水线寄存器开销，最长段约 1 ns 量级，主频能上浮数倍；代价是每条指令要多拍才走完（延迟换吞吐），与计算机系统结构册 §3 的定性结论一致。（§9.3）
5. 立即数在译码站做符号扩展、ALUSrc 选它进 ALU、执行站完成加法，共经取指、译码、执行、写回四站；两个源操作数一个是 x0（恒 0）、一个是立即数，都不需要从寄存器堆读真值，读端口空转。（§9.1、§9.2）
