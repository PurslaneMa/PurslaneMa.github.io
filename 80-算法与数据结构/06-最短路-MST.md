## $\rm \S \, 6.1$ 换一张价目表：边开始按长度计费

先立任务。论文资料管理器迟早长出这两条需求：其一，多机房同步，服务器之间链路延迟不同，一篇新论文要从主库推到每个节点，各节点想知道「总延迟最小的那条路」；其二，机房布线，n 台机器要连成一个内网，线材按米花钱，问「总米数最短的一套连线」。两个任务画在同一种图上，问的却不是同一件事：前者问点到点的路，后者问全图的树。老合同撑不住新任务，因为 BFS 的层号只数跳数：走五条边就是第 5 层，可五条短边加起来可能比三条长边还便宜。跳数少与总长短是两个问题，价目表必须先换。

定义（边权与最短路）：给每条边挂一个数，叫边权（weight），记 $w(u,v)$。一条路径的长度是它沿途各边权之和。$\operatorname{dist}(s,v)$ 定义为从 $s$ 到 $v$ 的所有路径里最短那条的长度，不可达记 $\infty$。本章最短路部分默认有向图（无向图可当双向有向读），且权非负；布线任务用无向图，在 §6.5 出场。

新价目表下，遍历的老动作「访问一个顶点」不够用了，需要一个按边长改账的动作。定义（松弛，relaxation）：维护一张 dist 表，$\operatorname{dist}[s]=0$，其余顶点初始为 $\infty$；对边 $(u,v)$ 做一次松弛，指按下面规则考虑改账：

$$
\operatorname{dist}[v] \leftarrow \min\bigl(\operatorname{dist}[v],\ \operatorname{dist}[u] + w(u,v)\bigr)
$$

读法：已经知道一个到 $u$ 的价，就顺路问一句「经 $u$ 到 $v$ 会不会更便宜」，便宜就改。松弛有一条贯穿全章的底线性质：**dist 表里任意时刻的值，都是某条真实存在路径的长度**。初始 $\infty$ 之外，每个有限值都是某次松弛写下的，而那次松弛的来源 $\operatorname{dist}[u]$ 又是更早的真实路径长，归纳可回溯到 $\operatorname{dist}[s]=0$。于是 dist 的值永不低于真值，算法的全部工作是把它压到真值上。

白话：松弛是会计听说了一条新走法，翻开账本问「照这条路走是不是更便宜」，是就改账；底线性质说账本上写的每个数都真的走得通，绝没有账面价低于市价的空头支票。

> 本节小结：边权把票制从「每边一票」换成按长度计费，BFS 层序合同作废；松弛是按边改账的最小动作，其值恒为真实路径长，这是全章证明的公共地基。

## $\rm \S \, 6.2$ Dijkstra：出袋即封账

松弛给了改账的动作，没给改账的顺序。顺序错了会怎样，§6.3 有一个四顶点反例等着；这里先看正确顺序长什么样。最朴素的想法是每轮从全部未定账顶点里挑 $\operatorname{dist}$ 最小的一个，松弛它的全部出边，做 n 轮，每轮扫一遍顶点，账是 $\Theta(n^2)$。挑最小这件事第 3 章的堆专管：把顶点的当前报价压进小根堆，delMin 出来的就是全场最便宜的未定账顶点。这就是 Dijkstra 算法（Dijkstra's algorithm）。

定义（Dijkstra）：起点 $s$ 入堆（报价 0）；每轮 delMin 取出报价最小的顶点 $u$，查封账名册，已封账的报价是陈旧副本，跳过；未封账者「出袋即封账」，把它记入已定账集合 $S$，并松弛它的全部出边，改账成功的顶点以新报价再次入堆。同一顶点堆里可能同时躺着多份旧报价，靠名册过滤，这就是第 3 章事件模拟里用过的惰性删除。

先把骨架写成十行（标准库 `heapq` 就是 §3.2 的二叉堆）：

```python
import heapq

def dijkstra(n, adj, s):
    """adj[u] 是 (v, w) 列表；返回 dist 与 prev 两张表"""
    INF = float("inf")
    dist = [INF] * n
    prev = [None] * n
    dist[s] = 0
    done = [False] * n
    pq = [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if done[u]:            # 陈旧报价：封账名册过滤
            continue
        done[u] = True         # 出袋即封账
        for v, w in adj[u]:    # 松弛全部出边
            if d + w < dist[v]:
                dist[v] = d + w
                prev[v] = u
                heapq.heappush(pq, (dist[v], v))
    return dist, prev
```

把它存成 `dijkstra_demo.py`，喂入 §6.4 exp1a 的图（生成器见 `expAD06/exp.py`），输出的 dist 表与同图 Bellman–Ford 的结果逐顶点一致，这组双算法对拍在每轮实验里都跑了一遍。顺带说 `prev` 表的用处：同步任务要的不只是「最低延迟多少」，还要「走哪条路」；沿 $\operatorname{prev}[v]$ 一路回溯到 $s$ 再倒序，就是那条最短路。把每个顶点的 $\operatorname{prev}$ 边抽出来，恰好构成一棵以 $s$ 为根的树，叫最短路树（shortest-path tree）：每个顶点的树路径就是它的最短路，这是「单源最短路」这个名字里「单源」两字的兑现。

算法的灵魂是一条不变量：**任何顶点出袋时，它的 $\operatorname{dist}$ 已经是真值。** 证明用归纳法。首个出袋的是 $s$，$\operatorname{dist}[s]=0$ 即真值。归纳假设：排在 $u$ 之前出袋的顶点，账都已封死为真值。反证：设 $u$ 出袋时 $\operatorname{dist}[u]$ 大于真值，取一条真最短路径 $P$，它从 $s$ 出发，途中必有一条边 $(x,y)$ 是「离开已封账集合」的第一条边：$x$ 已出袋，$y$ 未出袋。由归纳假设 $\operatorname{dist}[x]$ 是真值，且 $x$ 出袋时松弛过 $(x,y)$，所以 $\operatorname{dist}[y]$ 此刻不超过 $P$ 走到 $y$ 为止的前缀长度；权非负，$P$ 从 $y$ 继续到 $u$ 的后缀只会加价不减价，于是 $\operatorname{dist}[y]$ 不超过 $\operatorname{dist}(s,u)$ 的真值。$y$ 此刻还在堆里报价，而堆按报价出袋，$u$ 能先于 $y$ 出袋，说明 $\operatorname{dist}[u]\le\operatorname{dist}[y]$。串起来：$\operatorname{dist}[u]\le\operatorname{dist}[y]\le$ 真值；再由底线性质 $\operatorname{dist}[u]\ge$ 真值，两端夹死，$\operatorname{dist}[u]$ 恰为真值。$\square$

账目按票清算：每个顶点至多封账一次，n 次 delMin；每条出边在封账时被检查一次，全部成功松弛至多 m 次，每次 push 一份新报价。二叉堆每次操作 $O(\log n)$ 票，合计 $\Theta((n+m)\log n)$；对比朴素版 $\Theta(n^2)$，稀疏图上堆版全胜。合同里有一条明示的适用条件：权非负。证明里「后缀只加价不减价」那一步用足了它，§6.3 会看到抽掉这一步合同怎么撕。

白话：Dijkstra 是一位按报价封账的会计，全城顶点排队竞标，谁报价最低谁先定账；轮到某人时，其余所有还在场内的报价比他都高或相同，而任何没被发现的走法都绕不开这些已定账的中转站，不可能更便宜，账可以封死。

> 本节小结：Dijkstra 用堆把「挑全场最便宜的未定账顶点」压到 $\log$ 级，出袋即封账的不变量靠归纳加反证成立，权非负是论证里「后缀不加价」的前提；账为 $\Theta((n+m)\log n)$，陈旧报价由封账名册过滤。

## $\rm \S \, 6.3$ 负权边：合同里没写的条款与 Bellman–Ford

权非负不是排版习惯，是合同的承重墙。现实里确有负权边：汇率图上走一圈钱变多对应负权环路，任务调度里「做完 A 再做 B 反而省时」也建模成负权边。看 Dijkstra 的论证在哪一步塌。四顶点有向图：$A\to B$ 权 $2$，$A\to C$ 权 $3$，$C\to B$ 权 $-2$，$B\to D$ 权 $0$，源点 $A$，真值 $\operatorname{dist}[A]=0$、$\operatorname{dist}[C]=3$、$\operatorname{dist}[B]=3-2=1$、$\operatorname{dist}[D]=1$。逐轮跟踪堆版 Dijkstra 的动作：

1. $A$ 出袋（报价 0），松弛两条出边：$\operatorname{dist}[B]=2$、$\operatorname{dist}[C]=3$，两份报价入堆。
2. 堆顶是 $B$（报价 2），先于 $C$ 出袋，封账名册记下「$B$ 已定账 $2$」；出袋时松弛 $B\to D$，$\operatorname{dist}[D]=2$，入堆。
3. $C$ 出袋（报价 3），松弛 $(C,B)$：$3+(-2)=1<2$，改账成功，$B$ 以新报价 $1$ 重新入堆。
4. $B$ 的新报价出袋，但封账名册上 $B$ 已打勾，这份报价被当陈旧条目丢弃；$D$ 也无人再去告诉它真值是 $1$。

最终 $\operatorname{dist}[D]=2$，真值是 $1$：算法交出了错账。$\operatorname{dist}[B]$ 的表值碰巧被第 3 步的改账救回，但这救不回来的是后果：$B$ 已经按错价 $2$ 兑现过一次封账，它出袋时用错价喂给了下游，$D$ 从此拿不到 $1$。注意出错的环节不是实现：惰性删除按合同把「已封账顶点的再报价」一律当陈旧副本，而负权后缀让这份再报价恰恰是真改进。封账论证里「真最短路径的后缀只加价不减价」那一步被抽掉，已出袋顶点的账再也保不住。还有一句值得记下的观察：若把 $A\to C$ 的权改成 $1$，负权松弛恰好赶在 $B$ 出袋之前发生，堆版侥幸答对。负权边上 Dijkstra 的对错全看出袋顺序的运气，合同没保的它就不该承诺。

不挑顺序的替代方案是 Bellman–Ford 算法（Bellman–Ford algorithm）：不封账，只改账；把全部边排成一份固定清单，对清单整体做一轮松弛称为一轮；一轮一轮做下去。它的正确性押在一个逐轮推进的命题上：**第 $k$ 轮结束后，每个 $\operatorname{dist}[v]$ 都等于「跳数不超过 $k$ 的路径」里的最短真值。** 归纳证明。$k=0$ 时只有 $\operatorname{dist}[s]=0$，成立。设第 $k-1$ 轮末命题成立，考虑跳数恰为 $k$ 的真最短路径 $P$，取它最后一条边 $(x,v)$：$P$ 去掉这条边的前缀跳数 $k-1$，由归纳假设第 $k-1$ 轮末 $\operatorname{dist}[x]$ 已是该前缀真值；第 $k$ 轮松弛 $(x,v)$ 时把 $\operatorname{dist}[v]$ 压到不超过真值，而底线性质保证压不破真值，于是取等。两个方向闭合。$\square$

命题一立，账目自动出来：无负环时最短路是简单路径，跳数至多 $n-1$，故 $n-1$ 轮内全部真值落定，总账为松弛 $n-1$ 轮、每轮 $m$ 条边，$\Theta(nm)$。这份合同还附赠一张检测券：再做第 $n$ 轮，若仍有边能改账，说明存在跳数超过 $n-1$ 仍在变短的路，只可能是可无限绕行的负权环。工程上 $\Theta(nm)$ 常常付不满：若某一整轮没有任何改账发生，真值已全部落定，可以停机，这叫早期停止；实付轮次由图上「最长的那条最短路要走几跳」决定，§6.4 两种图各付一次给你看。实现连注释十四行：

```python
def bellman_ford(n, arcs, s):
    """arcs 是 (u, v, w) 有向弧列表；返回 dist，None 表示存在可达负环"""
    INF = float("inf")
    dist = [INF] * n
    dist[s] = 0
    for _ in range(n - 1):
        improved = False
        for u, v, w in arcs:
            if dist[u] != INF and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                improved = True
        if not improved:       # 早期停止：整轮无改账，真值已落定
            return dist
    for u, v, w in arcs:       # 第 n 轮：负环检测券
        if dist[u] != INF and dist[u] + w < dist[v]:
            return None
    return dist
```

`dist[u] != INF` 那道闸值得一秒：没有它，从 $\infty$ 出发的 $\infty+(-2)<\infty$ 这类算术会把不可达顶点的账污染成伪有限值。存成 `bf_demo.py` 喂入 §6.4 的两张图，exp1a 返回 10 轮后的完整 dist，链图返回 1200 轮后的完整 dist，与 `expAD06/result.txt` 一致。

白话：Bellman–Ford 是不问青红皂白的抄表员，每轮把全城每条路都听一遍、该改就改；第一轮保一跳的准，第二轮保两跳的准，抄满 $n-1$ 轮天下太平；第 $n$ 轮还在改，就是有让人越走越富的环形路在捣乱。

> 本节小结：负权后缀撕毁「出袋即封账」；Bellman–Ford 以轮为单位松弛，第 $k$ 轮保跳数 $\le k$ 的真值，$n-1$ 轮收敛、第 $n$ 轮可测负环，合同 $\Theta(nm)$，早期停止按图的直径打折。

## $\rm \S \, 6.4$ 实测一：稀疏对垒与稠密兑现

两组实验，脚本与完整输出在 `expAD06/result.txt`（exp1a、exp1b、exp2），计时多轮取最速。票种声明：边检查指看一条邻接表条目或一条弧一次，成功松弛指一次真实的改账，上滤比较指堆内一次报价比较。第一组对比 Dijkstra（二叉堆）与 Bellman–Ford 在同一张稀疏图上的耗时与松弛账：

| 图与算法 | 用时 | 边检查 | 成功松弛 | 轮次或入袋 |
| --- | --- | --- | --- | --- |
| exp1a 随机稀疏 $n=1200$、$m=3600$，Dijkstra | 4.30 ms | $7200=2m$ | 1895 | 入袋 1896 |
| 同图，Bellman–Ford | 15.44 ms | 72000 | 4449 | 10 轮（上界 $n=1200$） |
| exp1b 链图 $n=1200$、$m=1199$，Dijkstra | 0.35 ms | $2398=2m$ | 1199 | 入袋 1200，上滤比较 0 |
| 同图，Bellman–Ford | 577.67 ms | 2877600 | 1199 | 1200 轮（打满上界） |

1. 随机稀疏图上 Bellman–Ford 只付了 10 轮：早期停止条款兑现，轮次由图的直径决定，$\Theta(nm)$ 是上界不是实付。即便如此，每轮 7200 次松弛尝试的底盘仍使它以 15.44 ms 输给堆版 4.30 ms，两算法算出的 dist 表逐顶点完全一致。
2. 链图把上界打满：源点放在链的远端、边按升序供给，每轮松弛只把真值向前推一跳，1200 轮共 288 万次松弛尝试，用时 577.67 ms，是同图 Dijkstra 的约 1650 倍。Bellman–Ford 的合同里白纸黑字写着「存在图要付全款」，链图就是那种图。
3. Dijkstra 在链图上省到极致：2m 次边检查之外，堆里常年至多一份报价（上滤比较 0 次），把「挑最小」的税几乎降到零。
4. 同一批实验还在稠密图上兑现了 §3.5 欠的账：$n=400$ 的完全图 $m=79800$，Dijkstra 换 d 叉堆，d=2、4、8 的用时为 46.81、21.53、29.01 ms（各 3 轮取最速），三份 dist 完全一致。这张负载的特点是成功松弛只有约 2200 次：15.96 万次边检查里 98.6% 改账失败，堆内存货少，delMin 的层数账说了算。d 从 2 到 4 层数近半、用时也近半；d 到 8 层数再降，但每层要在 8 个孩子里挑最小，单价税把优势吃回去。§3.5 说的「d 的最优值由负载配比决定」，在这张真实负载上应验，本负载的最优在 d=4。

> 本节小结：稀疏图上堆版 Dijkstra 以 4.30 ms 对 15.44 ms 胜出；链图让 Bellman–Ford 付满 1200 轮、577.67 ms，合同上界照章兑现；稠密图上 d 叉堆把 Dijkstra 从 46.81 ms 压到 21.53 ms（d=4），§3.5 的权衡表在真实负载下成立。

## $\rm \S \, 6.5$ 割性质：贪心取边的安全证书

布线任务换个问法就换了张合同：不要点到点的路，要一套连通全图的边，总权最小。定义（生成树与 MST）：无向连通图中，取 $n-1$ 条边且保持连通、无环的边子集叫生成树（spanning tree），三个条件两两互推；边权和最小的生成树叫最小生成树（Minimum Spanning Tree，MST）。下一节的两个算法都是贪心：一条一条挑边，每条都宣称「这条不拿亏了」。贪心的合法性由一张证书统一签发。

定义（割与横割边）：把顶点集分成两半 $S$ 与 $V\setminus S$，叫一个割（cut）；两端各在一侧的边叫横割边（crossing edge）。

命题（割性质，cut property）：对任意割，其中权最小的横割边 $e$ 属于某棵 MST。证明用交换论证。取一棵不含 $e$ 的生成树 $T$（若含 $e$ 已完成）。把 $e$ 加入 $T$，树上两点之间原有一条树路径，现在出现唯一的环；$e$ 是横割边，而这个环从 $S$ 出发回到 $S$，沿途必再跨割奇数次，故环上除 $e$ 外还有至少一条横割边 $f$，且 $f$ 在树里。权最小性给出 $w(f)\ge w(e)$。从 $T$ 里删去 $f$ 再加入 $e$：删一条树边把树断成两截，环的存在保证 $e$ 恰好把两截重新接上，所得仍是一棵 $n-1$ 条边、连通、无环的生成树，权变化 $w(e)-w(f)\le 0$。于是含 $e$ 的生成树权不增，取权最小者即含 $e$ 的 MST。$\square$

推论（贪心合法性）：从空集开始，只要每一步取的边都是「当前某个割的最小横割边」，取满 $n-1$ 条就得到一棵 MST。Prim 与 Kruskal 的全部正确性都挂在这条推论上，它们只是挑割的角度不同。

白话：割是一条河，横割边是过河的桥；任何一张总账合理的布线图里，全河最便宜的那座桥都值得保留，把它换成更贵的桥或干脆不修河，只会多花钱或者断路。

> 本节小结：MST 是无向连通图上总权最小的 $n-1$ 条边；割性质经交换论证证明「任意割的最小横割边总在某棵 MST 里」，由此签发贪心合法性证书，Prim 与 Kruskal 共用。

## $\rm \S \, 6.6$ Prim 与 Kruskal：两台取边机器

Prim 算法（Prim's algorithm）挑的割最顺手：$S$ 取已入树的顶点集合。从任一起点入树开始，每步取 $S$ 与外界之间最便宜的横割边，把它的外界端点拉进树。实现照抄 §6.2 的堆骨架：堆里存 $(w,v)$ 报价；一个顶点入树时，把它的全部出边中指向树外者的报价压堆；delMin 出袋时查封账名册，已在树内的是陈旧条目，跳过。

```python
def prim(n, adj):
    """adj[u] 是 (v, w) 列表；返回 MST 总权与树边集"""
    in_tree = [False] * n
    total, edges = 0, []
    pq = [(0, 0, -1)]          # (权, 顶点, 树侧父结点)
    while pq:
        w, u, par = heapq.heappop(pq)
        if in_tree[u]:         # 陈旧报价：两端均已入树
            continue
        in_tree[u] = True      # 出袋即入树
        total += w
        if par != -1:
            edges.append((par, u, w))
        for v, wv in adj[u]:
            if not in_tree[v]:
                heapq.heappush(pq, (wv, v, u))
    return total, edges
```

正确性两段：其一，堆顶恰为当前割的最小横割边，因为每条跨割边恰有一份有效报价在堆里（树侧端点入树那一刻压入），底线与 Dijkstra 的名册论证同款；其二，割性质保证每步取边安全。账与 Dijkstra 同款，$\Theta((n+m)\log n)$；陈旧条目是这张表的暗税，§6.7 会在稠密图上称出它的分量。

Kruskal 算法（Kruskal's algorithm）连割都不挑：全部 $m$ 条边按权升序排队，逐条过堂，两端点尚未连通就取入树，已连通（会成环）就跳过。裁判工作交给并查集（union-find）结构：一个 parent 数组，$\operatorname{find}(x)$ 沿父链找到根，根相同即已连通；$\operatorname{union}$ 把两棵树接成一棵，接时把矮树挂到高树下，叫按秩合并（union by rank）。路径压缩（path compression）是 $\operatorname{find}$ 的顺手优化：走过的每个结点直接改挂到根，第一次走通的链变成第二次的直达电梯。

```python
def kruskal(n, edges):
    """edges 是 (w, u, v) 列表；返回 MST 总权"""
    parent = list(range(n))
    rank = [0] * n

    def find(x):               # 沿父链找根，返回路上顺手压缩
        root = x
        while parent[root] != root:
            root = parent[root]
        while parent[x] != root:
            parent[x], x = root, parent[x]
        return root

    total = 0
    for w, u, v in sorted(edges):
        ru, rv = find(u), find(v)
        if ru == rv:
            continue           # 两端已连通：加边成环，跳过
        if rank[ru] < rank[rv]:
            ru, rv = rv, ru
        parent[rv] = ru        # 矮树挂高树：按秩合并
        if rank[ru] == rank[rv]:
            rank[ru] += 1
        total += w
    return total
```

正确性：设某时刻考虑边 $e=(u,v)$，取割 $S$ 为此刻 $u$ 在已取森林中的连通块；若有一条比 $e$ 便宜的横割边 $f$，它在更早时已被过堂，当时两端点分属更细的连通块、必然不同块，于是 $f$ 已被取入树；可 $f$ 一旦入树，它的两端在当前森林里就该同块，与 $f$ 跨割矛盾。故 $e$ 是当前割的最小横割边，割性质放行。$\square$ 账目：排序 $\Theta(m\log m)$ 主导；并查集加路径压缩与按秩合并后，均摊每次操作 $O(\alpha(n))$，$\alpha$ 是增长慢到在全宇宙规模下都不超过 5 的反 Ackermann 函数，这条是理论结果，本册引用不证明；§6.7 实测的是它的一个极端切面。两个实现存成 `mst_demo.py`，喂入 §6.7 的两档图（生成器见 `expAD06/exp.py`），总权 388826 与 1344，两算法逐分一致。

白话：Prim 是从一个城市向外修桥的工程队，永远修当前最便宜的下一座，修一座城并一座；Kruskal 是全国桥梁统一招标，便宜的标书先审，审查员拿着连通名录一查，发现两端已通就一票否决；路径压缩是把问过路的人直接记成总部直线电话。

> 本节小结：Prim 维护「树与外界」这个割，堆顶即最小横割边，账 $\Theta((n+m)\log n)$，暗税是陈旧条目；Kruskal 全边排队加并查集判环，账 $\Theta(m\log m)$ 主导，两者合法性都由割性质签发。

## $\rm \S \, 6.7$ 实测二：两档图上的 MST 与并查集的账

两种 MST 在稀疏、稠密两档图上同台（exp3，图用「随机生成树加随机加边」保证连通，计时各 3 轮取最速），另加一组并查集压缩对照（exp4）。两档图上两算法给出的 MST 总权逐分不差（稀疏 388826、稠密 1344），互为对方的对拍：

| 图档 | Prim（堆） | Kruskal（排序＋并查集） |
| --- | --- | --- |
| 稀疏 $n=2000$、$m=6000$ | 2.85 ms，入袋 6001，陈旧出袋 4001 | 2.27 ms，排序 6000 条，find 共 10282 次 |
| 稠密 $n=400$、$m=79800$ | 108.35 ms，入袋 79801，陈旧出袋 79401 | 28.31 ms，排序 79800 条，find 共 2094 次 |

1. 稀疏档两机器同价：2.85 对 2.27 ms。m 小，Prim 的堆税与 Kruskal 的排序税都不重，选谁看顺手。
2. 稠密档 Kruskal 快 3.8 倍，差在暗税与存货：Prim 让 7.98 万条边各进一次堆，出袋 7.98 万次里 7.94 万次是陈旧条目，占 99.5%，堆在为死报价买单；Kruskal 排一次序就完事，取边阶段的 find 总跳数只有 1891，裁判近乎免费。稠密图选 Kruskal，这份实测就是理由。
3. 并查集的压缩对照（exp4）：3000 个结点排成一条深链（结点 $i$ 深度为 $i$），做 2000 次随机 find。不压缩：总跳数 2955300，平均每次约 1478 跳，恰在 $n/2$ 量级，用时 130.70 ms；压缩：总跳数 4996，平均每次约 2.5 跳，用时 0.56 ms。跳数差约 591 倍，用时差约 233 倍。第一次 find 走通一条链，沿途全部改挂根结点，此后这条链上的查询都是一步直达；链是并查集最坏的形状，压缩专治这种形状。

> 本节小结：稀疏档两机同价（2.85 对 2.27 ms），稠密档 Kruskal 以 28.31 对 108.35 ms 胜出，胜因是 Prim 的 99.5% 陈旧出袋；链上 2000 次 find 的总跳数由 2955300 压到 4996，路径压缩把重走链变成直达电梯。

4. 割性质的交换论证中，边 $f$ 是怎么找到的？为什么删 $f$ 加 $e$ 之后仍是生成树？

## $\rm \S \, 6.10$ 本章自测答案

概念回顾答案：

1. 封账证明里，底线性质提供 $\operatorname{dist}[u]\ge$ 真值这一侧，与堆序给出的 $\operatorname{dist}[u]\le$ 真值夹出等号；Bellman–Ford 归纳里，它保证松弛压出的新值不超过真值，使归纳能取到等号（来源：§6.2、§6.3）。
2. 用在「真最短路径从 $y$ 继续走到 $u$ 的后缀只会加价」，于是 $\operatorname{dist}[y]\le$ 真值可传给 $u$。反例中 $A\to C\to B$ 的后缀含权 $-2$ 的边，$B$ 先出袋封账 $2$ 之后，$C$ 的松弛仍能以 $1$ 改进它，已封的账被证明不是真值（来源：§6.2、§6.3）。
3. 归纳设第 $k-1$ 轮末跳数 $\le k-1$ 的真值已落账，归纳步取真最短路最后一条边 $(x,v)$，松弛把它压到真值；反向靠底线性质压不破真值。第 $n$ 轮仍能改账说明存在跳数超过 $n-1$ 且总权还在下降的路，只能是绕环亏损，即可达负环（来源：§6.3）。
4. 把 $e$ 加入不含它的生成树 $T$ 产生唯一环，环从 $S$ 出发回 $S$ 必再跨割，环上另一条树内横割边即 $f$；删 $f$ 断树成两截，$e$ 跨割恰能重接，$n-1$ 条边、连通、无环齐备，且 $w(e)-w(f)\le 0$（来源：§6.5）。
5. 每条跨割边在树侧端点入树那一刻被压堆一次，此后两端都在树内时不再新压，故跨割边与有效报价一一对应；陈旧条目对应两端均已入树的边，入堆时有效、出袋时已死（来源：§6.6）。
6. 过堂按权升序，$f$ 在 $e$ 之前；当时 $u$ 所在连通块是当前块的子集，$f$ 的两端此刻分属割两侧、当时分属更细的块，必然不同块，于是 $f$ 当场入树；而 $f$ 入树后其两端在当前森林同块，与「$f$ 跨割」矛盾，故更便宜的横割边不存在（来源：§6.6）。

应用与辨析答案：

1. 负权边撕毁 Dijkstra 的封账合同（§6.3 四顶点反例同款）。改用 Bellman–Ford：$n-1$ 轮、每轮 $m=2000$ 条边，账 $\Theta(nm)=10^6$ 次松弛量级，实测同尺度链图 1200 轮才 577.67 ms，这张图 499 轮毫秒级可完；负环检测券顺带免费（来源：§6.3、§6.4）。
2. 不是并查集的错，Prim 根本不用并查集。按 §6.7，稠密图上堆版 Prim 的 99.5% 出袋是陈旧条目，慢是实现形态的已知代价。改法一：换 Kruskal，排序加并查集，稠密档实测快 3.8 倍；改法二：稠密图上放弃堆，用朴素「每轮扫全顶点挑最小」版 Prim，$\Theta(n^2)$ 且无堆税，$n=1000$ 时约 $10^6$ 票，比堆版的堆操作更省（来源：§6.7）。
3. 把 3000 个结点排成深链做随机 find（exp4 同款输入）：不压缩 2000 次 find 总跳数 2955300、130.70 ms，压缩后 4996 跳、0.56 ms，差距 591 倍的跳数藏不住。按秩合并只保证树高 $O(\log n)$，救不了「同一深链被反复查询、每次都从底走到顶」的负载；压缩直接把走过路径改挂根，查询成本塌到常数（来源：§6.7 exp4）。
