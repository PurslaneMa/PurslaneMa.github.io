## $\rm \S \, 3.1$ 问题：读完再决定

LL 的每一步是选一条产生式把非终结符展开，难在开口相同的候选分不清。反过来走：手里攥着记号流，每一步把一段已读的记号**收拢**成一个非终结符，这叫**规约**（reduction），规约就是推导的逆步。对 `id + id * id`，最先读到的 `id` 定不了案：它可能就此是 `F -> id`，也可能是乘法的一半。LR 的做法是等 `id * id` 与后面的 `$` 全部到位，才把 `T -> T * F` 收拢。**读完再决定**，五个字就是自底向上的全部秘密。

机器形状：一个栈，两种动作。**移进**（shift）把下一个记号压栈；**归约**把栈顶按某条产生式 ${A\to\beta}$ 的右部弹掉、压入 $A$；栈里只剩开始符号且输入读尽即接受，对不上即报错。每一步的真问题是：此刻该不该归约、用哪条产生式。为此先给「该归约的那段」起名字。设 $\Rightarrow_{rm}$ 表示最右推导，若

$$
S\Rightarrow_{rm}^{*}\alpha A w\Rightarrow_{rm}\alpha\beta w
$$

则 $\beta$ 连同它在句型中的这个位置叫**句柄**（handle）。读法：最右推导的每一步都会替换掉一段，这段就是句型 $\alpha\beta w$ 的句柄，也是一次合法规约能吃下的东西；所以规约序列倒放恰好是最右推导，本章实验对每一步做了逐步校验（§3.3）。栈为什么装得下这场戏：最右推导的句柄总出现在尚未规约部分的左端附近，栈顶正是那个位置。

白话：LL 像落子前把整步棋想清楚，LR 像先把棋子一颗颗码上桌，码齐完整的一手才合拢归位；同一盘棋，语法树都会到手，只是生长方向相反。

> 本节小结：自底向上 = 规约（推导的逆步）；句柄由最右推导定义；移进-归约机器只缺一个「何时归约、归约成谁」的决策器，本章其余篇幅都在造它。

## $\rm \S \, 3.2$ LR(0) 自动机：把「路上的可能」记成状态

决策器得回答「栈顶这一段是不是某条产生式的右部」。程序化的思路与 §1.4 同源：**集合当状态**。先把文法增广（augment）：加一条 ${S'\to S}$，${S'}$ 不再出现在别处，「接受」因此成为唯一确定的终态；G1 增广后共 7 条产生式。再定义 **LR(0) 项**（item）：在产生式右部某处点一个点，如 `E -> E . + T`。点前是已经读到的，点后是还没读的；一个状态就是一批项的集合，含义是「此刻栈里可能正躺着这些前缀」。

两个算子把集合串成自动机。闭包（closure）把「马上要展开的」抄进来：

$$
\mathrm{closure}(I)=I\ \cup\ \{\,B\to\cdot\gamma\ :\ A\to\alpha\cdot B\beta\in I,\ B\to\gamma\in P\,\}
$$

读法：若某个项的点后站着非终结符 $B$，栈里接下来既可能直接出现完整的 $B$，也可能正躺着 $B$ 某条产生式右部的开头，于是把 $B$ 的每条产生式配上「点在最左」抄进来；抄进来的项自己又可能点出新的 $B$，反复到不再新增，又是不动点。转移把点推过一格：

$$
\mathrm{goto}(I,X)=\mathrm{closure}\bigl(\{\,A\to\alpha X\cdot\beta\ :\ A\to\alpha\cdot X\beta\in I\,\}\bigr)
$$

读法：把 $I$ 中点后是 $X$ 的项统统把点移过 $X$，再求闭包，得到「多读了一个 $X$ 之后」的新状态。构造三步，与子集构造同款：1. 初始状态取 $\mathrm{closure}(\{S'\to\cdot S\})$；2. 对每个状态与它项内点后的每个符号算 goto，新集合立为新状态；3. 重复到没有新状态。对 G1 跑出来 12 个状态、22 条转移、合计 34 个项（实验原样输出）：

```text
I0: 核 1 项, 闭包后 7 项 :: E' -> . E ; E -> . E + T ; E -> . T ; T -> . T * F ; T -> . F ; F -> . ( E ) ; F -> . id
I1: 核 2 项, 闭包后 2 项 :: E' -> E . ; E -> E . + T
I2: 核 2 项, 闭包后 2 项 :: E -> T . ; T -> T . * F
I3: 核 1 项, 闭包后 1 项 :: T -> F .
I4: 核 1 项, 闭包后 7 项 :: F -> ( . E ) ; E -> . E + T ; E -> . T ; T -> . T * F ; T -> . F ; F -> . ( E ) ; F -> . id
I5: 核 1 项, 闭包后 1 项 :: F -> id .
I6: 核 1 项, 闭包后 5 项 :: E -> E + . T ; T -> . T * F ; T -> . F ; F -> . ( E ) ; F -> . id
I7: 核 1 项, 闭包后 3 项 :: T -> T * . F ; F -> . ( E ) ; F -> . id
I8: 核 2 项, 闭包后 2 项 :: F -> ( E . ) ; E -> E . + T
I9: 核 2 项, 闭包后 2 项 :: E -> E + T . ; T -> T . * F
I10: 核 1 项, 闭包后 1 项 :: T -> T * F .
I11: 核 1 项, 闭包后 1 项 :: F -> ( E ) .
```

手推核对 $I_0$：核 1 项 ${E'\to\cdot E}$；点后是 $E$，抄 $E$ 的两条；`E -> . T` 又点出 $T$，抄 $T$ 的两条；再点出 $F$，抄 $F$ 的两条；闭包 7 项，与机器一致。$I_2$ 来自 $\mathrm{goto}(I_0,T)$：两项的点后分别是空与 `*`，无需再抄，闭合为 2 项。

冲突可以精确定义了。同一状态里，「点已到头」的项想归约，「点后是终结符」的项想移进，若抢同一列，叫**移进-归约冲突**（shift-reduce conflict，S/R）；两个点已到头的项抢同一列，叫**归约-归约冲突**（reduce-reduce conflict，R/R）。G1 实测 2 格 S/R：$I_2$ 的 `*` 列是 `s7` 对 `r2`（${E\to T}$），$I_9$ 的 `*` 列是 `s7` 对 `r1`（${E\to E+T}$）。看 $I_2$ 的处境：栈顶形状对应 $T$、下一记号是 `*`。归约 ${E\to T}$ 是错的：`*` 根本不能跟在 $E$ 后面，乘法归项层管，$E$ 层收不了这个尾。移进、让 `T -> T . * F` 继续走才对。LR(0) 的状态不带「下一个记号」的信息，两可局面分不出来。

白话：LR(0) 自动机是一本「读到哪、哪些剧情还接得上」的地图，每个状态是一页分支表；冲突格就是同一格写着两种下一步，机器自己把矛盾钉到了具体的状态和记号上。

> 本节小结：项 = 产生式加读入进度点；closure 与 goto 两个不动点算子加 BFS 即程序化构造；G1 实测 12 状态、22 转移、34 项、2 格 S/R，病根是状态不含向前看信息。

## $\rm \S \, 3.3$ SLR：用 FOLLOW 砍掉不靠谱的归约

$I_2$ 那步错误规约有个可观察的破绽：${E\to T}$ 归约完，$E$ 的合法后邻必须落在 $\mathrm{FOLLOW}(E)$ 里（§2.3 的算法），而 `*` 不在。**SLR**（simple LR）就砍这一刀：归约 ${A\to\alpha}$ 只填进 $t\in\mathrm{FOLLOW}(A)$ 的列，其余列留白；移进照旧。对 G1 的账：实验值 `FOLLOW(E) = {+, ), $}`，`*` 缺席，于是 $I_2$、$I_9$ 的 `*` 列只剩 `s7`，2 格冲突全消。整张表（`s`/`r` 后接状态号/产生式号，实验原样输出）：

```text
st |    +    *    (    )   id    $ |   E   T   F
 0 |             s4        s5      |   1   2   3
 1 |   s6                      acc |
 2 |   r2   s7        r2        r2 |
 3 |   r4   r4        r4        r4 |
 4 |             s4        s5      |   8   2   3
 5 |   r6   r6        r6        r6 |
 6 |             s4        s5      |       9   3
 7 |             s4        s5      |          10
 8 |   s6            s11           |
 9 |   r1   s7        r1        r1 |
10 |   r3   r3        r3        r3 |
11 |   r5   r5        r5        r5 |
```

第 2、9 行正是 LR(0) 出冲突的两行：归约只占 FOLLOW 列（第 2 行的 `*` 列没有 `r2`），移进原样保留。全表 ACTION 非空格 36/72、GOTO 非空格 9。拿它跑 `id + id * id`，栈轨迹实验原样输出（左列栈、底 `0` 在最左；中列剩余输入；右列动作；共 14 步 = 移进 5 + 归约 8）：

```text
0                      | id + id * id $   | s5
0 id 5                 | + id * id $      | r6
0 F 3                  | + id * id $      | r4
0 T 2                  | + id * id $      | r2
0 E 1                  | + id * id $      | s6
0 E 1 + 6              | id * id $        | s5
0 E 1 + 6 id 5         | * id $           | r6
0 E 1 + 6 F 3          | * id $           | r4
0 E 1 + 6 T 9          | * id $           | s7
0 E 1 + 6 T 9 * 7      | id $             | s5
0 E 1 + 6 T 9 * 7 id 5 | $                | r6
0 E 1 + 6 T 9 * 7 F 10 | $                | r3
0 E 1 + 6 T 9          | $                | r1
0 E 1                  | $                | acc
```

第 11 行是「读完再决定」的现场：`T * id` 凑齐、`$` 也看到了，机器才敢归约 `T -> T * F`。把 8 次归约按时间顺序抄出来再倒放，就是最右推导，实验逐行校验通过：

```text
E
E + T
E + T * F
E + T * id
E + F * id
E + id * id
T + id * id
F + id * id
id + id * id
```

`( id + id ) * id` 同样接受：19 步、11 次归约、最右校验通过。喂非法输入 `id + * id`：SLR、LALR、LR(1) 三张表（后两张见 §3.4–§3.5）都在记号下标 2 停机、报错前归约 3 次、可接受记号只剩 `(` 与 `id`，与第 2 章 LL 的报错位置一致。

FOLLOW 这把刀也有砍不动的场合。悬挂 else 的语言（§2.7 谈过）写成直接形式 G4：

```text
S -> if S | if S else S | a
```

实测 LR(0) 与 SLR 各剩 1 格 S/R：状态 $I_4$ 同时装着点已到头的 `S -> if S .` 与 `S -> if S . else S`，`else` 列上是 `s5` 对 `r1`。砍不动的账：`FOLLOW(S) = {else, $}`（实验值），`else` 在册，因为 $S$ 后面确实可能合法地跟着外层 if 的 `else`。刀钝在分不清「这个 `else` 归谁」，这不是文法写法能改的（§2.7 已论证歧义是语言性质）。工程处理沿用约定，但 LR 家族里它有个顺口的名字：**冲突默认移进**（yacc/bison 的缺省规则），移进等于把 `else` 判给最近的 if。选择有代价，实测两种裁决跑 `if if a else a`：移进裁决接受、配出内层；归约裁决直接判非法。对长度 0–8 的全部 9841 个 `if/else/a` 串，移进裁决与一份 SLR 零冲突的无歧义文法 G6（§3.6 末尾给出）判定一致 9841/9841，归约裁决只接受 8 个。约定不是推导出来的正确，是语言标准的官方裁决，与第 2 章同构。

> **竞赛生迁移提示**：你写过的双栈表达式计算器（《形式语言与自动机》§3.5 的 calc）其实是一台手写移进-归约机器：数栈对应符号栈，运算符栈顶的优先级比较就是在裁决「移进还是归约」，只是当时裁决靠手扒的优先级表，本章之后靠自动机加声明。

白话：SLR 给自动机配了副 FOLLOW 做的粗框眼镜，多数模糊能滤掉（G1 全消），滤不掉的是悬挂 else 这种先天歧义，只能按行规拍板。

> 本节小结：SLR = LR(0) 自动机加 FOLLOW 过滤归约列；G1 从 2 格冲突到 0、`id + id * id` 实测 14 步且规约倒放即最右推导；悬挂 else 的冲突 FOLLOW 消不掉，按默认移进（就近配对）处理。

## $\rm \S \, 3.4$ 规范 LR(1)：把向前看刻进状态

SLR 的刀还有更伤脑筋的钝口。文法 G7（赋值与左值，`*` 是解引用）：

```text
S -> L = R | R
L -> * R | id
R -> L
```

实测 LR(0) 状态 10 个、SLR 冲突 1 格：状态 $I_2$ 装着 `S -> L . = R` 与 `R -> L .`，`=` 列上是 `s6` 对 `r5`。按 SLR 规矩查 FOLLOW：`FOLLOW(R) = {=, $}`（实验值；`=` 在册是因为 `L -> * R` 里 $R$ 的后邻可以是 `=`），刀砍不动。可直觉上这是假冲突：栈里躺着一个能按 `R -> L` 归约的 $L$ 时，它要么是赋值语句的左值（后面跟 `=`），要么就是整句话本身（后面跟 `$`）。以 $R$ 的身份归约时，后面只能是 `$`。这个区分 FOLLOW 做不到：它把 $R$ 在全语言各种位置的后邻一锅端了。

**规范 LR(1)**（canonical LR(1)）把「此刻归约合不合法」直接刻进状态。LR(1) 项在点串后面挂一个向前看记号，记作 $[A\to\alpha\cdot\beta,\ a]$，含义是：栈里已有 $\alpha$，读完 $\beta$ 之后**当且仅当**下一个记号是 $a$，才允许按 ${A\to\alpha\beta}$ 归约。闭包规则随之升级：

$$
\bigl[A\to\alpha\cdot B\beta,\ a\bigr]\ \text{生成}\ \bigl[B\to\cdot\gamma,\ b\bigr]\quad\text{对每个 } b\in\mathrm{FIRST}(\beta a)
$$

读法：$B$ 归约完之后紧跟着的是 $\beta$，$\beta$ 读完才轮到归约 $A$、见到 $a$，所以 $B\to\gamma$ 的合法归约记号是 $\mathrm{FIRST}(\beta a)$；$\beta$ 推得空时 $b$ 就是 $a$ 自己。这与 §2.3 FOLLOW 规则 2、3 是同一套逻辑，只是从全局统计换成此刻局部。goto 不变：点推过一格，带着向前看走。

对 G1 重跑：状态 12 涨到 22，冲突 0（SLR 已消的冲突不会复活，能 SLR 的文法必是 LR(1) 文法）。涨在哪：$I_0$、$I_1$ 保持单份，其余 10 个状态各分裂成两份（实验核对）。以 $I_2$ 为例，两份的向前看分别是 `{$, *, +}` 与 `{), *, +}`：顶层的 $T$ 归约后可能整句结束，括号里的 $T$ 出门必撞 `)`，LR(1) 把「同一形状、不同处境」分开记账。对 G7：状态 14 个、冲突 0，假冲突消失，因为那里 `R -> L .` 的向前看只有 `$`（实测状态内容 `S -> L . = R, $ ; R -> L ., $`），`=` 列只剩移进；同核分身实测 4 组、每组 2 份，全语言里只有这一个处境真的需要区分。

白话：SLR 的 FOLLOW 是按户口本查后邻，LR(1) 是把后邻写在每个人工牌上；工牌多印了一倍，但真假冲突当场分清。

> 本节小结：LR(1) 项 = 点串加向前看；闭包生成规则用 $\mathrm{FIRST}(\beta a)$ 把归约条件局部化；G1 实测 22 状态 10 组分身，G7 的假冲突被项内向前看消掉。

## $\rm \S \, 3.5$ LALR：把同核状态合并回来

LR(1) 消歧干净，代价是状态翻倍、表占内存翻倍。观察分裂的形状：两份状态的**核**（core，项去掉向前看）完全相同，只差向前看。**LALR**（lookahead LR）把它们合并回来：同核状态并成一组，向前看取并集，转移边重接。G1 实测 22 状态合回 12，冲突仍 0；$I_2$ 两份的并集 `{+, *, ), $}` 恰好是 $\mathrm{FOLLOW}(T)$，可见 SLR 相当于对所有同核状态无差别预支并集，LALR 只在真分裂处并。表的行为经得起查：对长度 0–6 的全部 19531 个 `id + * ( )` 串（合法 15 个），SLR、LALR、LR(1) 三张表与一份手写判定器的接受判定完全一致（19531/19531）；19516 条非法串上三表报错的记号下标全部相同，但其中 934 条报错前的归约次数不全相同，SLR 的粗向前看偶尔多绕几步无用的归约再死，不冤枉好人，只是绕路。

合并有一条精确的边界：**从无冲突的 LR(1) 表出发，合并只会新添冲突，且新添的只能是 R/R**。理由两句：移进列由核决定，核不变，移进列不动；归约列在并集下只增不减，若新增的归约与移进同列相撞，那个 LR(1) 原状态早就冲突了，与出发点矛盾，所以能撞上的只剩另一个归约。G8 是现成的反例文法：

```text
S -> a A d | b B d | a B e | b A e
A -> c
B -> c
```

LR(1) 实测 14 状态、0 冲突：$I_6$ 是 `A -> c ., d` 与 `B -> c ., e`，$I_9$ 是 `B -> c ., d` 与 `A -> c ., e`，两份各管各的句子，清清楚楚。LALR 合并后两个状态并成一份，四个项同室（`A -> c ., d ; B -> c ., e ; B -> c ., d ; A -> c ., e`），`d`、`e` 两列各爆出一格 R/R（`r5` 对 `r6`），实测 LALR 冲突 2 格；SLR 也是这 2 格（FOLLOW 一锅端同病），LR(0) 更早爆出 6 格 R/R。LALR 弱于 LR(1) 的价签就挂在这里：合并免费拿回空间，代价是可能把 LR(1) 分清的账重新搅浑。

四个家族在状态数上的实测对比（LR(0)/SLR/LALR/LR(1)）：G1 是 12/12/12/22，G4 是 7/7/7/12，G7 是 10/10/10/14，G8 是 13/13/13/14。SLR 与 LALR 表一样大，消歧能力介于 LR(0) 与 LR(1) 之间；工程工具选 LALR，消歧接近 LR(1)、房租停在 LR(0)。

白话：LALR 是把 LR(1) 那些只差工牌的分身合住一间房，房钱省一半；偶尔两拨人合出矛盾（R/R），但绝不会把原来不冲突的屋子挤出新旧之争（S/R）。

> 本节小结：LALR = 同核合并、向前看取并；G1 实测 22 合回 12 且 19531 串行为与 LR(1) 一致；合并只能新添 R/R，G8 实测合并出 2 格 R/R。

## $\rm \S \, 3.6$ 歧义文法：不修文法，修表

第 2 章为了让 LL(1) 收下四则运算，把文法改写成三层（§2.5 的 G3）。LR 有省事的出口：文法不改，用**声明**教表做事。先看不改的下场，歧义表达式文法 G5：

```text
E -> E + E | E - E | E * E | ( E ) | id
```

实测 SLR 冲突 9 格：状态 $I_8$、$I_9$、$I_{10}$（分别含点已到头的 `E -> E + E .`、`E -> E - E .`、`E -> E * E .`）在 `+`、`-`、`*` 三列上都是移进对归约。$I_8$ 的处境：栈里已有完整的 `E + E`，下一记号是 `+`，先算还是接着吃？这语言有两棵树（§3.2 的老朋友），谁也救不了：LR(1) 实测 18 格（状态分裂让每格记两遍账）、LALR 回到 9 格。注意这不是失败而是移交：优先级与结合律本来就是语言设计者的决定，冲突格把决定权送到了台面上。

yacc/bison 的声明语法接住决定权：`%left '+' '-'` 声明同级左结合，下一行 `%left '*'` 声明乘法优先级更高（声明顺序即优先级从低到高）。表构造时的裁决规则三条：1. S/R 比优先级，产生式的优先级取它最右终结符的优先级，产生式高则归约、记号高则移进；2. 同级看结合律，左结合归约、右结合移进、声明为非结合则报错；3. 双方都没有优先级则默认移进，R/R 一律取写得早的产生式。实测按 `%left + -; %left *` 裁决：9 格全消，分布是同级左结合归约 5 格、记号优先级高移进 2 格（$I_8$、$I_9$ 的 `*` 列）、产生式优先级高归约 2 格（$I_{10}$ 的 `+`、`-` 列）。这套表算 `8 - 3 - 2` 得 3、`2 + 3 * 4` 得 14、`2 * 3 + 4` 得 10，与 Python 逐一相同；随机生成 2000 条含括号的表达式，声明表与 Python 求值一致 2000/2000，G1 的分层文法加 SLR 在同样 2000 条上也三方一致。殊途同归：一条靠文法分层，一条靠声明裁决。

悬挂 else 的无歧义化同属「修表不修语言」：§3.3 的 G4 若嫌约定含糊，可以改写成 SLR 零冲突的 G6（实测状态 11、冲突 0）：

```text
S -> M | U
M -> if M else M | a
U -> if S | if M else U
```

`M` 管「配平的 if」，`U` 管「有一段悬空 else 的 if」，歧义被写进文法结构里，解析器不再需要拍板。实测它对 `if if a else a` 给出内层配对的树，与 G4 加默认移进的判定在 9841 串上完全一致（§3.3）。

白话：冲突格是机器递过来的请示条：「这两步都对，听谁的？」声明就是批复；批复合理，表就把语言的语义决定执行到位。

> 本节小结：歧义文法在四张表上都留冲突（G5 实测 9/18/9 格），工程出口是优先级与结合律声明加三条裁决规则，实测 9 格全消且 2000 条随机求值与 Python 一致；无歧义改写 G6 是另一条路。

## $\rm \S \, 3.7$ 一个真实错误：把减号声明成右结合

声明是给人写的接口，写错照样产出会算错的表。实验故意把减号声明成右结合（效果同 `%right '-'`）：`8 - 3 - 2` 算出 7，正确答案是 3。两棵归约树一对照就现形：

```text
正确:  E[E[E[id] - E[id]] - E[id]] = 3        右结合:  E[E[id] - E[E[id] - E[id]]] = 7
```

左树是 ${(8-3)-2}$，右树是 ${8-(3-2)}$。随机 2000 条表达式里这套错表算错 531 条。诊断链：症状是求值错且不报任何冲突（声明的职责就是消冲突，错了也消得干干净净）；定位是把同一输入的树形打印对比；病根是同一优先级的运算符必须同结合律，`-` 单独右结合，算的就不是减法；修复是把 `-` 与 `+` 放进同一个 `%left`；验证是 2000/2000 复跑全对。姊妹错误同样实测：`*` 不升级优先级（与 `+` 同级声明），`2 + 3 * 4` 算出 20，2000 条里错 768 条。bison 手册反复叮嘱「同级必须同结合、层级必须拉开」，对应的就是这两笔账。

白话：优先级声明像给机器印发操作手册，手册印错页机器照翻不误；冲突消失不等于语义正确，声明层的对错要靠求值对账来抓。

> 本节小结：错误的声明静默地产出错误的优先级，右结合减号实测错 531/2000、同级乘号错 768/2000；修复与验证都落在随机对账上。

## $\rm \S \, 3.8$ bison 思想：表是生成物，动作是挂件

把零件拼回工程视图。bison（yacc 的 GNU 实现）吃一份 `.y` 文件，三段式：声明段放记号与 `%left` 这类优先级声明；文法段写产生式，每条后面可挂语义动作（C/C++ 代码）；尾段是词法器接口等杂项。产出是一个内嵌 LALR(1) 表的 C 文件，只暴露一个 `yyparse()` 驱动器，逻辑就是 §3.3 那台栈机器。语义动作搭在**值栈**上：归约弹掉 $k$ 个符号时同时弹它们的语义值，动作算出一个新值压回，`E -> E + E` 的动作就一句话：左部语义值取第 1 个与第 3 个子符号语义值之和。本章实验的 `evaltree` 正是值栈的玩具版：归约时把子树合成父树，最后吐出整棵树并求值，与 Python 对账 2000/2000。冲突报告同款：bison 编译文法时打印的 shift/reduce 警告，就是本章表格里那格 S/R 的机器可读版，数一数行数就知道声明没写全。bison 用的正是 LALR(1)，这解释了它为什么收得下歧义文法（声明消解）也解释了它偶发的 reduce/reduce 警告（§3.5 的合并边界）。

白话：bison 是「文法进、解析器出」的自动售货机：投进文法与优先级声明，掉出一台驱动器加一张表，语义动作是你挂在每个出口上的小钩子。

> 本节小结：bison = LALR(1) 表生成器 + 固定驱动器 + 值栈语义动作；冲突报告与本章的冲突定位一一对应，声明错误由求值对账兜底。

## $\rm \S \, 3.11$ 本章自测答案

1. 句柄定义见 §3.1 公式：最右推导的一步 ${S\Rightarrow_{rm}^{*}\alpha Aw\Rightarrow_{rm}\alpha\beta w}$ 中被替换的 $\beta$ 及其位置。规约是推导的逆步，而自底向上每步吃下的正是当前句型的句柄，句柄又由最右推导定义，故倒放必是最右推导；实验对 `id + id * id` 的 8 次归约逐行回放校验（§3.3）。
2. 项是产生式右部加进度点；闭包把点后非终结符的产生式「点在最左」抄进来直到不动；goto 把点推过一格再闭包（§3.2 两个公式）。$I_0$：核 ${E'\to\cdot E}$，抄 $E$ 两条，点出 $T$ 抄两条，再点出 $F$ 抄两条，共 7 项，与机器输出一致。
3. 归约动作只填 $t\in\mathrm{FOLLOW}(A)$ 的列。有效的原因：$I_2$、$I_9$ 的错误归约（${E\to T}$、${E\to E+T}$）要求后邻 `*`，而 `*` 不在 $\mathrm{FOLLOW}(E)=\{+,\ ),\ \$\}$ 里（§3.3）。
4. 多了一个向前看记号，语义是「读完右部后下一个记号是它才许归约」（§3.4）。生成规则 $b\in\mathrm{FIRST}(\beta a)$ 的理由：$B$ 归约完后面紧跟着 $\beta$，$\beta$ 读完才轮到归约 $A$、见到 $a$；$\beta$ 推空时 $b$ 取 $a$。
5. 同核状态合并、向前看取并集（§3.5）。理由：移进列由核决定、合并后不变；归约列只增不减，若新增归约与移进同列相撞，则 LR(1) 原状态早已冲突，矛盾，故只能新增 R/R。实证是 G8：LR(1) 的 $I_6$、$I_9$ 合并后在 `d`、`e` 两列各爆一格 R/R（§3.5）。

应用与辨析答案：

1. 歧义是语言性质，G7 的语言并不歧义，冲突是 SLR 的 FOLLOW 太粗：$\mathrm{FOLLOW}(R)$ 把 $R$ 作整句收尾（后邻 `$`）与作 `* R` 内部（后邻 `=`）两种处境混为一谈；LR(1) 状态里 `R -> L .` 的向前看只有 `$`，`=` 列只剩移进，同一文法 LR(1) 零冲突、14 个状态（§3.4）。
2. ① ${E\to E+E}$ 的优先级取最右终结符 `+` 的优先级；② `%left '+' '-'` 把 `+` 与 `-` 声明为同级左结合，产生式与向前看 `-` 同级；③ 同级左结合的裁决是归约。于是 `E + E` 先收拢，树向左长，得 ${(8-3)-2=3}$（§3.6、§3.7）。
3. 状态数（LR(0)/SLR/LALR/LR(1)）：G1 是 12/12/12/22，G4 是 7/7/7/12，G8 是 13/13/13/14；冲突格：G1 是 2/0/0/0，G4 四表全是 1，G8 是 6/2/2/0（§3.3、§3.5）。悬挂 else 四表同冲突，因为歧义是语言性质，任何确定性自动机都得在「`else` 归谁」处卡住（§2.7）；G8 的 R/R 只在合并后出现，因为 LR(1) 靠向前看把 `A -> c` 与 `B -> c` 的合法后继分开，合并把并集搅回一起（§3.5）。

**你现在能做什么**：给一份中小型文法，程序化构造 LR(0) 自动机、报出 S/R 与 R/R 冲突格；用 SLR 消掉能消的、指出消不掉的属于哪类歧义；写一组正确的优先级声明，让歧义表达式文法的求值与 Python 一致。

第 2、3 章合起来办完了语法级的事：LL 靠改写文法，LR 靠自动机加声明，产物都是一棵唯一的语法树。但树还不是机器的形状：名字在哪里声明、类型配不配、这棵树对应哪几条三地址指令，树自己说不出口。下一章把树降级成中间表示，顺手把符号表与类型检查做掉。
