# $\rm Chapter \, 2$ 计算图与反向模式微分

上一章造出了带形状的运算对象，但每个运算算完就忘：`c = a * b` 执行完，`c` 不知道自己来自乘法，`a` 也不知道自己被用过。本章给对象装上记忆：计算图（computational graph）记下「谁由谁算出」，反向模式微分（reverse-mode differentiation）让梯度沿图自动流回来。两件事合起来叫自动微分（automatic differentiation，autograd），是 PyTorch 那行 `loss.backward()` 的全部内容。

## $\rm \S \, 2.1$ 为什么需要自动微分：一项爆炸的手推

第 4 章已经手推过 MLP 的反向传播，那时的结论是「分层结构让中间结果可复用」。这里把账算得更细。取一个 2-3-3-1 的网络（输入 2 维，两层隐层各 3 个单元，输出 1 个），对全部 25 个参数（${6+3+9+3+3+1}$）用链式法则：如果把每个参数的求导式**完整展开**（不共享任何中间结果），展开式的项数等于该参数到损失之间的路径数。逐个数：第一层 6 个权重各有 3 条路径（经任一第二隐层单元到输出），第二层 9 个权重各 1 条，偏置 3 条、3 条、3 条、1 条，合计 39 项，每项 3 个局部导数因子，共 117 次乘法；换个网络结构，全部重推。反向传播的算法：对图上 25 条边各算一次局部导数，中间结果全部复用。

| | 链式法则全展开 | 反向传播（记忆化） |
| --- | --- | --- |
| 2-3-3-1 网络的求导代价 | 39 项，每项 3 因子 | 25 个局部导数各算一次 |
| 换网络结构 | 全部重推 | 零改动：图变了，规则不变 |
| 本质 | 重复子问题暴力重算 | 记忆化：每个子问题算一次 |

展开式的长相抽一项出来看。第一层权重 ${w^{(1)}_{ij}}$ 经第 ${k}$ 个第二隐层单元的那条路径，展开后就是一个三因子乘积：

$$
\frac{\partial o}{\partial h^{(2)}_k}\cdot\frac{\partial h^{(2)}_k}{\partial h^{(1)}_j}\cdot\frac{\partial h^{(1)}_j}{\partial w^{(1)}_{ij}},
$$

39 项里每一项都长这样，项与项之间大量共享同一些因子，展开式却没有共享机制；反向传播的共享机制就是记忆化本身。

竞赛生视角：这就是「暴力枚举 vs 记忆化搜索」的差距。自动微分做的事，是把记忆化搜索从「手推一次的网络」变成「对任意计算图自动执行」。

## $\rm \S \, 2.2$ 前向模式 vs 反向模式：一笔代价账

自动微分有两大模式。前向模式（forward mode）给每个数配一个对偶分量 ${(v,\,v')}$，运算规则同步传播值与导数（${{(uv)}'=u'v+uv'}$）：一遍前向得到输出对**一个**输入方向的导数，术语叫 JVP（Jacobian-vector product）。反向模式先跑前向记账，再从输出端反向扫一遍，得到损失对**所有**中间量的梯度（VVP）。代价规则由此而定：前向按方向数（输入维数）计价，反向按输出数计价。训练的场景是 1 个 loss 对上百万参数：反向一遍完事，前向要跑上百万遍。两种模式并排放：

| | 前向模式 | 反向模式 |
| --- | --- | --- |
| 每个数携带 | 一个方向导数分量 | 一个输出端梯度 |
| 一遍得到的 | 输出对**一个**方向的导数（JVP） | 损失对**全部**中间量的梯度（VVP） |
| 代价按什么计 | 方向数（输入维数） | 输出数 |
| 典型用武之地 | 雅可比矩阵、灵敏度分析 | 训练：1 个 loss 对全部参数 |

实测这笔账（${d=256}$ 的三层 tanh MLP，${P=196608}$ 个参数；反向用 torch autograd，前向模式用复步法实现单方向 JVP，复步法即算 ${f(x+\mathrm{i}h)}$ 取虚部，精度到机器级）：

| 量 | 实测（单次） |
| --- | --- |
| 反向传播一次，得全部 ${P}$ 个梯度 | 35.1 ms |
| 前向模式一个方向（复步 JVP） | 9.2 ms |
| 前向模式拿全部梯度的推算代价 | ${P\times 9.2\,\mathrm{ms}\approx 30}$ 分钟 |
| 两者之比 | 约 5 万倍 |

复步 JVP 的正确性有对照：同一方向上它与 torch autograd 算出的投影梯度相差 ${4.4\times10^{-15}}$（float64 机器级）。前向模式不是没用，输出维数小于输入维数时它更快；只是训练恰好是最不利于它的场景。

## $\rm \S \, 2.3$ 计算图：以 ${z=x\cdot y+w}$ 手推全流程

计算图是一张流水记账：节点是运算，边是中间值的流向。以 ${z=x\cdot y+w}$ 为例，取 ${x=2}$、${y=3}$、${w=1}$，图的文字版：`x, y → [乘法节点] → p = 6`，`p, w → [加法节点] → z = 7`。反向传播从输出端出发，规则只有一条：**局部导数乘下游梯度**。

1. 输出端：${\partial z/\partial z=1}$；
2. 加法节点：局部导数对两个输入都是 1，把下游梯度原样分发，得 ${\partial z/\partial p=1}$、${\partial z/\partial w=1}$；
3. 乘法节点：局部导数 ${\partial p/\partial x=y=3}$、${\partial p/\partial y=x=2}$，各乘上从下游收到的 ${\partial z/\partial p=1}$；
4. 收账：${\partial z/\partial x=1\cdot 3=3}$，${\partial z/\partial y=1\cdot 2=2}$，${\partial z/\partial w=1}$。

每一步只用两类东西：前向存下的值（乘法节点要用 ${x}$ 和 ${y}$ 的值）与下游传来的梯度。顺序必须从输出端往输入端走：一个节点要乘的「下游梯度」必须是收齐了的最终值，所以得先算完所有下游节点。这个顺序就是图的拓扑序的逆序，第 3 章的引擎会显式地做这个排序。

> **引擎视角**：前向存的每个中间量，反向都会被用到恰好一次：乘法节点用 ${x}$ 与 ${y}$ 的值本身，加法节点什么都不用。「该存什么」由局部导数公式决定，第 4 章的三个层会把这个规则再列一遍（Linear 存输入、ReLU 存掩码）。

## $\rm \S \, 2.4$ PyTorch 对照：grad_fn 链与逐数梯度

同一张图让 PyTorch 建一遍：

```python
xt = torch.tensor(2.0, requires_grad=True)
yt = torch.tensor(3.0, requires_grad=True)
wt = torch.tensor(1.0, requires_grad=True)
z = xt * yt + wt        # z = 7.0
z.backward()
```

每个运算的返回张量都带一个 `grad_fn`，指向记账本里的自己这一页。链不用手翻，五行代码走完（对照实验真跑所用）：

```python
node, chain = z.grad_fn, []
while node is not None:
    chain.append(type(node).__name__)
    nxt = node.next_functions
    node = nxt[0][0] if nxt else None
```

打印出的链是：

```text
AddBackward0 -> MulBackward0 -> AccumulateGrad
```

`AddBackward0` 是加法节点，`MulBackward0` 是乘法节点，`AccumulateGrad` 是叶子（`x`、`y`、`w` 这类原始张量）的梯度收集器：链的末端就是图的三片叶子。`backward()` 执行的正是 §2.3 那四步，梯度写进每个叶子的 `.grad`。逐数对照：

| 变量 | §2.3 手推 | torch autograd | 差 |
| --- | --- | --- | --- |
| ${\partial z/\partial x}$ | 3.0 | 3.0 | 0 |
| ${\partial z/\partial y}$ | 2.0 | 2.0 | 0 |
| ${\partial z/\partial w}$ | 1.0 | 1.0 | 0 |

验证环境：WSL Ubuntu，PyTorch 2.14.1+cpu，float64。手推与引擎完全一致并不奇怪：引擎只是把 §2.3 的四步写成了对所有图都成立的循环。下一章就把这个循环写出来。

## $\rm \S \, 2.7$ 本章自测答案

### $\rm \S \, 2.7.1$ 关键概念回顾答案

1. 手推要对每个参数展开链式法则且换个结构全部重推；自动微分把「展开」变成「对任意图自动执行的记忆化」，代价从 39 项降到 25 个局部导数。（§2.1）
2. 前向按方向数（输入维数）、反向按输出数；训练是 1 个 loss 对百万参数，反向一遍、前向百万遍，实测差距约 5 万倍。（§2.2）
3. 节点是运算（乘法、加法），边是中间值流向；${z=x\cdot y+w}$ 有乘法、加法两个运算节点与 ${x,y,p,w,z}$ 五个值。（§2.3）
4. 局部导数由前向存下的值决定（如乘法节点用 ${x,y}$ 的值），下游梯度由反向传上来；所以前向必须保存中间量。（§2.3）
5. 节点的 `_backward` 要读收齐的下游梯度，逆拓扑序保证处理到它时所有下游都已算完；反着走会把没收齐的部分梯度当最终值传上去，得到错梯度。（§2.3）

### $\rm \S \, 2.7.2$ 应用与辨析答案

1. 图：`x, y → [乘] → p`，`p → [tanh] → q`，`q, w → [加] → z`；局部导数依次为 ${y}$ 与 ${x}$（乘）、${1-\tanh^2(p)}$（tanh）、两个 1（加）。（§2.3）
2. 前向模式按方向计价：约 5 百万遍；反向按输出计价：1 遍（对 100 维输出求和后回传）。（§2.2）
3. 对解析函数，${f(x+\mathrm{i}h)=f(x)+\mathrm{i}h f'(x)+O(h^2)}$，虚部除以 ${h}$ 取 ${h\to 0}$ 无截断误差；在 `abs`、比较、取整等非解析运算上失效。（§2.2）
4. 只有 `wt.grad` 有值（等于 1）；图照样记（`z.grad_fn` 链完整），只是 `xt`、`yt` 不是叶子收集器，它们的梯度停在中间量上不落地。（§2.4）
