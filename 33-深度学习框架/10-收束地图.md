# $\rm Chapter \, 10$ 收束地图：从迷你框架读进 PyTorch

九章造完一整个框架：张量、计算图、引擎、层、损失、优化器、循环、数据管道、设备与精度、分布式与存档。本章不添新零件，做三件收尾事：一张组件对照总表、三条主线的收束、一条从迷你框架通往真实源码的阅读路线，最后把本册接到本站的其他册上。

> **开始前自检**：本章假设你已经会：
>
> 1. □ 本册 §1–§5 的五大组件（Tensor、Value、Module、损失、优化器）；
> 2. □ 本册 §6–§9 的工程层（循环、数据、设备、分布式、checkpoint）；
> 3. □ Reverse mode 自动微分的定义（本册 §2）。

## $\rm \S \, 10.1$ 组件对照总表

| 迷你框架（章） | PyTorch 对应物 | 它解决了什么 |
| --- | --- | --- |
| `Tensor`（§1） | `torch.Tensor` | 多维数组与形状三件套，全部计算的载体 |
| `Value` 与闭包回传（§2–3） | `autograd` 计算图引擎 | 不必手推每层梯度，反向自动算 |
| `Linear`/`ReLU`/`Module`（§4） | `torch.nn` 与 `nn.Module` | 层复用、参数按名字收集、递归组合 |
| `softmax_ce`、`sgd_step`（§5） | `nn.functional` 与 `torch.optim` | 数值稳定的损失与带状态的更新式 |
| 训练循环（§6） | `loss.backward()` + `optimizer.step()` | 前向、反向、更新按时序粘成一步 |
| `DataLoader`（§7） | `torch.utils.data` | 采样、组批、拼接与训练循环解耦 |
| `device` 字段（§8） | `.to('cuda')` 与设备分派 | 同一份代码跑在不同硬件上 |
| dtype 选择（§8） | `autocast` + `GradScaler` | 低精度换速度，小梯度不失真 |
| 梯度平均（§9） | `DistributedDataParallel` | 多卡各算各的 batch，梯度汇成一份 |
| `np.savez` 字典（§9） | `torch.save`/`state_dict` | 训练现场可中断、可恢复、可搬运 |

这张表同时是全书的目录倒放：从上到下正好是九章的顺序。读它的方法是问「没有它会怎样」：没有 Tensor 则没有形状规则，没有引擎则每换一层就手推一遍导数，没有 Module 则层无法组合成网络，没有 DataLoader 则采样逻辑焊死在循环里，没有 device 则代码与硬件绑死，没有 state_dict 则训练一次就得从头再来。

表的第二种用法是把报错翻译回组件。训练里遇到报错，先别搜文档，先问它属于哪个组件的职责范围；下表是十个最常见的症状与归属：

| 报错或症状 | 归属组件 | 回读 |
| --- | --- | --- |
| `shape mismatch` | Tensor 与广播 | §1.2 |
| `grad is None` | 计算图没挂上 | §2.4 |
| `_backward` 被漏调 | 引擎的回传顺序 | §3.3 |
| `parameters()` 是空表 | Module 的递归收集 | §4.2 |
| loss 出现 `nan` | log-sum-exp 或精度 | §5.1、§8.4 |
| 评估时显存暴涨 | 忘了 `no_grad()` | §6.4 |
| batch 内容永远是同一类 | 忘了 shuffle | §7.3 |
| `expected device cuda:0` | 数据与模型不同地 | §8.1 |
| 参数一万步不动 | float16 下溢 | §8.3 |
| loss 不降反升 | 优化器与学习率 | §5.2 |
| `KeyError: 'l1.W'` | state_dict 的名字对不上 | §9.4 |
| 每 epoch 时间忽长忽短 | 数据管道喂不上 | §7.4 |

调试 torch 代码时先做这个翻译：把报错归到左列的某一组件，再回读对应章节，比在文档里乱翻快得多。这个表的用法练熟之后，读第三方的训练代码也一样：先把陌生的工程代码归到十行总表的某一格，读不懂的部分往往是它在自己造某一格的轮子。

## $\rm \S \, 10.2$ 三条主线的收束

1. **自动微分 = 计算图 + 拓扑序**。§2 建图、§3 引擎里 `topo` 排序后逆序回传，这两件事就是 Reverse mode 微分的全部算法内容。拓扑序防的是「依赖没算完就动手」的乱序错误：一个节点的梯度要等全部下游回传完才齐，排序保证这一点。同一规则在册内三次换装：标量闭包（§3）、层矩阵公式（§4）、关闭记账的 `no_grad`（§6.4）。
2. **训练循环 = 十行胶水**。§6 的骨架十章不变：清、前向、损失、反向、更新。§7 换数据来源、§8 换设备与精度、§9 加 all-reduce 与存档，五个动作一个没动过。判断一条工程改动是否「只动工程不动算法」，就看它是否插在五动作之间的缝隙里：§9 的 all-reduce 插在反向与更新之间，§8 的 loss scaling 插在损失与反向之间，都是缝隙里的手术。
3. **工程层 = 让同一份循环在更大的资源上跑**。设备抽象管「在哪算」，dtype 管「用什么算」，DataLoader 管「喂多快」，DPP 管「几双手一起算」，checkpoint 管「算崩了怎么办」。五样工程的共同敌人是「同一份循环在不同资源上的错位」：数据错位、设备错位、精度错位、卡间错位、断点错位，各自的接口都是为消掉一种错位而设计的。

三条主线在 §10.1 的表上各有落点：主线一占前两行，主线二占第五行，主线三占后五行。表、主线、九章，三套索引指向同一批知识，闭卷时能互相推出，就算收束完成。

## $\rm \S \, 10.3$ 源码阅读路线

| 项目 | 规模 | 看什么 | 读完的收获 |
| --- | --- | --- | --- |
| micrograd | 约 300 行 | `Value._backward` 闭包、`backward()` 里的拓扑排序 | 「引擎没有更多东西了」 |
| tinygrad | 数千行 | 一个算子（如 `add`）的 CPU 与 GPU 两份实现 | 设备分派在真实代码里的长相 |
| PyTorch `autograd` | 数万行 | `variable.py` 的 `Function` 节点、`engine.cpp` 的多线程反向调度 | 单线程拓扑序如何扩成并行引擎 |

1. **micrograd**：本册 §2–§3 的同源实现。重点盯两处：`Value._backward` 闭包怎么把「本节点的回传规则」记在图上（§3.1 的空 lambda 被运算符重载覆盖），以及 `backward()` 里 `topo` 列表怎么用 DFS 一次性排好。
2. **tinygrad**：把 micrograd 的思路做成能跑 GPU 的张量库。看同一个 `add` 如何有 CPU 与 GPU 两份实现、按 `device` 字段查表调用（§8.1 的「标签」升级成「分派」），以及 lazy execution 与本册记账方式的异同。
3. **PyTorch 的 autograd 目录**：`variable.py` 与 `engine.cpp`。看 `Function` 与反向图的节点表示，以及多线程执行反向任务队列的调度：§3 的单线程拓扑序如何扩成并行的引擎。

三段路线的纵深递增：第一段读完懂算法，第二段读完懂分层，第三段读完懂工程。读不动第三段是正常的，它依赖 C++ 与多线程。自检读没读懂的办法有三：

1. 合上源码，能在 §10.1 的表里指出每个看到的类对应哪一行；
2. 能对别人讲清「micrograd 的 `_backward` 为什么是闭包而不是方法」；
3. 能说出 torch 引擎与 §3.3 的实现差在「并行调度」而不在「微分的数学」。

## $\rm \S \, 10.4$ 与本站其他册的接口

1. **深度学习分册**：那边讲「为什么这样训」（损失怎么选、正则为什么、学习率怎么调），本册讲「框架怎么把它变成代码」；那边 §4 的反向传播手推与本册 §4.1 的层反向公式是一对一翻译。
2. **机器学习与凸优化分册**：SGD 的收敛率与随机性分析（那边 §6）是本册 §7.3 无偏性论证的理论后方；本册的对照实验是那些定理的数值前台。
3. **计算理论册**：Reverse mode 的复杂度论证（自动微分一节）给本册 §2–§3 提供「为什么反向只需一次扫描」的根据；前向与反向模式的代价账两边各算一遍，口径一致。
4. **计算机系统结构册**：GPU 章（SIMT、显存层级、带宽账）是本册 §8 设备层的硬件下方；本册说「规格口径」的地方，去那一册找机制解释。

## $\rm \S \, 10.7$ 本章自测答案

### $\rm \S \, 10.7.1$ 关键概念回顾答案

1. 见 §10.1 表；最不能缺的是 Tensor 与计算图引擎（没有载体与导数规则，其余组件都没有挂靠点）。（§10.1）
2. 自动微分的不变量是拓扑序回传，循环的不变量是五动作顺序，工程层的不变量是「算法不动」；五样东西（数据、设备、精度、多卡、存档）一个动作都没动。（§10.2）
3. micrograd 懂算法（闭包回传与拓扑排序）、tinygrad 懂分层（算子的多设备实现）、PyTorch autograd 懂工程（并行反向引擎）；「看什么」见 §10.3 的表。（§10.3）
4. 深度学习分册讲「为什么这样训」，本册讲「框架怎么把它变成代码」；那边 §4 的反向传播手推与本册 §4.1 的层反向公式一对一翻译。（§10.4）
5. 本册是 `for v in reversed(topo)` 的代码形态，计算理论册是「按反拓扑序扫描 DAG」的复杂度形态；两边都算「一次前向加一次反向、常数倍于前向的代价」。（§10.2、§10.4）
6. 看改动是否插在五动作之间的缝隙里；§9 的 all-reduce 插在反向与更新之间，§8 的 loss scaling 插在损失与反向之间。（§10.2）

### $\rm \S \, 10.7.2$ 应用与辨析答案

1. 属于优化器与 Module 的交界：`zero_grad` 是 Module 的方法（§4），调用时机是胶水的第一个动作（§6）；表上落在「训练循环」一行。（§10.1）
2. 训练循环主线：§7 把手写切片换成 DataLoader、§9 在反向与更新之间插 all-reduce；证据是 §9.3 的同步梯度实验（${2.2\times10^{-16}}$）与 §7.4 的 DataLoader 逐数一致（${\max|\mathrm{diff}|=0}$）。（§10.2）
3. 挂在自动微分主线：前向存中间量的地方改成存检查点、反向时重算；动 §3 的引擎与 §4 的层，循环五动作不变（重算藏在 `backward` 内部）。（§10.2）
4. 同一件事的两档深度：`assert` 是「只报错不实现」，真分派要给每个算子配各设备的实现并按 `device` 字段查表调用，即 tinygrad 的做法。（§10.3）
5. §5.3 三优化器对照（${10^{-16}}$ 级）、§6.2 二十 epoch 训练对照（${6.7\times10^{-16}}$）、§9.3 梯度同步（${2.2\times10^{-16}}$）；共同构成是「同一输入、两实现、逐元素差在机器精度级」。（§10.4）
