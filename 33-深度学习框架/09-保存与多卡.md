# $\rm Chapter \, 9$ 保存与多卡：检查点与数据并行

## $\rm \S \, 9.1$ 保存与加载：状态字典里装了什么

要解决的问题：训练几小时后进程意外退出，怎样把训练现场写到磁盘、下次原样读回？PyTorch 把模型里所有参数打包成一个字典，键是名字、值是张量（tensor），叫状态字典。存档、读回、打印键名三步：

```python
torch.save(model.state_dict(), 'ckpt.pt')          # 存：名字 → 张量
state = torch.load('ckpt.pt')                      # 读：拿回同一个字典
model.load_state_dict(state)                       # 按名字填回模型
for k, v in model.state_dict().items():            # 打印一遍看清有哪些键
    print(k, tuple(v.shape))
```

打印得到 `l1.weight (32, 8)`、`l1.bias (32,)`、`l2.weight (2, 32)`、`l2.bias (2,)` 四行（验证环境：WSL Ubuntu，PyTorch 2.14.1+cpu）。这里的 `model` 是 §6.1 的 `MLP`（`l1`：${8\to32}$、`l2`：${32\to2}$）。键名是「模块（module）名 + 参数名」：`l1.weight` 是第一层的权重矩阵；§4.5 的手写框架给同一批参数起的点分名字 `l1.W`、`l1.b` 是同一套思路。读盘默认会严格比对键名与形状，对不上就报错（§9.7 逐条翻译），所以跨机器读盘要写 `torch.load(path, map_location='cpu')` 把张量映射到指定设备；`torch.save(model, ...)` 则把类的定义路径一起序列化，恢复时那份 `class MLP` 改名或搬目录就抛 `ModuleNotFoundError`，只存状态字典才是可移植的写法。

## $\rm \S \, 9.2$ 断点续训：checkpoint 里放什么

要解决的问题：只存参数够不够？不够。优化器（optimizer）自己也有状态：momentum 存着惯性的 ${v}$（§5.5），Adam 存着 ${m,s,t}$，中断后不还原，续训的轨迹与没断过就不是一条线（§9.6 把这条差量出来）。完整的检查点（checkpoint）是四样：模型参数、优化器状态、当前进度、当前最好指标。

```python
ckpt = {'model': model.state_dict(),        # 参数
        'opt':   optimizer.state_dict(),    # 优化器状态（动量、步数）
        'epoch': epoch,                     # 进度：恢复到第几轮
        'best':  best_acc}                  # 最好指标：选模型与早停用
torch.save(ckpt, 'ckpt.pt')
ckpt = torch.load('ckpt.pt', map_location=device)
model = MLP().to(device)                    # 先重建同结构的模型
optimizer = torch.optim.SGD(model.parameters(), lr=0.1, momentum=0.9)
model.load_state_dict(ckpt['model'])        # 再按名字填回
optimizer.load_state_dict(ckpt['opt'])      # 优化器状态同样按结构填回
```

真跑一眼（环境同上）：`ckpt.keys()` 是 `['model', 'opt', 'epoch', 'best']`，`opt.keys()` 是 `['state', 'param_groups']`，`opt['state'].keys()` 是 `[0, 1, 2, 3]`。优化器要先于 `load_state_dict` 用同样的 `model.parameters()` 与超参构造好，否则参数组对不上；`map_location=device` 让存盘时在 GPU 上的张量读回 CPU 或另一张卡（本机无 GPU，此句按规格口径写）。`opt` 里 `state` 是「参数编号 → 动量与步数张量」、`param_groups` 存学习率与动量系数，编号 `[0, 1, 2, 3]` 正对应 §4.5 按顺序收集的四个参数。

## $\rm \S \, 9.3$ 多卡：数据并行的分工与最小写法

要解决的问题：单卡算不动、显存也喂不饱时，一张卡上的循环怎样摊到多张卡上。数据并行（data parallelism）的分工：每张卡放一份完整模型，大批量切成 ${N}$ 份，每卡吃自己那份小 batch、各自前向反向得一份梯度，再把所有卡的梯度做一次全归约（all-reduce，求平均），每卡拿到相同的平均梯度后各自走一步；参数起点、梯度、更新都相同，所以各卡永远同步。PyTorch 用 `DistributedDataParallel`（DDP）实现这件事，只改模型一行与启动方式：

```python
import os, torch, torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP
dist.init_process_group(backend='nccl')          # 建立卡间通信组
local_rank = int(os.environ['LOCAL_RANK'])       # torchrun 注入的本进程编号
torch.cuda.set_device(local_rank)
model = DDP(model.cuda(), device_ids=[local_rank])   # 反向时自动同步梯度
for xb, yb in loader:                            # loader 见 §7，每卡只吃自己的 1/N 份
    xb, yb = xb.cuda(), yb.cuda()
    optimizer.zero_grad()
    loss = criterion(model(xb), yb)
    loss.backward()                              # 返回时梯度已平均，循环里看不到通信
    optimizer.step()
```

```bash
torchrun --nproc_per_node=4 train.py             # 本机起 4 个进程，各占一张卡
```

`torchrun` 自动注入 `LOCAL_RANK`、`RANK`、`WORLD_SIZE`，脚本据此知道自己用哪张卡、吃哪份数据。`rank`（全局进程编号）、`world_size`（进程总数）、`DistributedSampler` 如何保证各卡数据不重叠，以及多机与 Slurm 调度，都在主线第 44 章 [§44](../06-编程语言/44-多GPU分布式训练与任务管理.md) 讲透了，本节只留原理与最小写法。

## $\rm \S \, 9.5$ 打开盖子：数据并行与环形 all-reduce 的通信账

不打开盖子，你会缺一块判断力：`DDP(model)` 加得很轻松，却说不出它凭什么与「单卡用大批量训练」等价，也算不出每步多花多少通信。分工的迷你版就是 §6.1 的循环里多插一行：

```python
for xb in batches_of_rank(rank):          # 每卡只吃自己的 1/N 份
    z = model(xb)
    loss.backward()                        # 各卡各自的反向
    all_reduce_average(model.grads)        # 全体参数：求和再除 N
    optimizer.step()                       # 各卡拿同一份平均梯度
```

数学上这就是 §7.5 的无偏性换了个用法：${N}$ 份小 batch 梯度的平均等于大批量梯度（线性性），所以数据并行的 ${N}$ 卡一步，数学上等价于单卡用大批量走一步。torch 把 `all_reduce_average` 挂进反向传播本身，`loss.backward()` 返回时梯度已经平均完，循环里看不到通信那一行；挂进反向是精心设计：平均能在反向收尾阶段与最后几层的计算重叠，通信被算力藏掉一部分。代价是每步多传一遍全体参数：模型多大，每步就传多大。

all-reduce 的朴素实现是参数服务器：每卡把梯度发给服务器，服务器求和再发回。按模型大小记 ${S}$，每卡发 ${S}$、收 ${S}$，共 ${2S}$；服务器的网卡要同时接 ${N}$ 份 ${S}$，成了瓶颈。环算法（ring all-reduce）让每卡只与左右邻居通话：梯度切成 ${N}$ 块，第一圈做归约散射（reduce-scatter，每卡收到 ${S/N}$ 并转发出 ${S/N}$，走 ${N-1}$ 步后每卡各持一块完整和），第二圈做全收集（all-gather，把 ${N}$ 块完整和传遍全网）。每卡总通信量：

$$
2\,(N-1)\cdot\frac{S}{N} \;=\; \frac{2(N-1)}{N}\,S \;\xrightarrow{N\to\infty}\; 2S
$$

每卡的账封顶在 ${2S}$，与卡数无关，这正是它胜过朴素实现的点。逐卡通信量对照（单位 ${S}$，真跑算术验证）：

| ${N}$ | 朴素（每卡 ${2S}$） | 环形 ${2(N-1)/N}$ | 环形/朴素 |
| --- | --- | --- | --- |
| 2 | 2.00 | 1.0000 | 0.500 |
| 4 | 2.00 | 1.5000 | 0.750 |
| 8 | 2.00 | 1.7500 | 0.875 |
| 16 | 2.00 | 1.8750 | 0.938 |
| 64 | 2.00 | 1.9688 | 0.984 |

读法要诚实：环算法省的是服务器的集中瓶颈与卡数增长时的扩展性，单看每卡总量它并不比朴素少多少（大 ${N}$ 时趋近 ${2S}$）；它的赢在带宽被均摊到 ${N}$ 条链路上，全网总速率随卡数线性涨。数据并行的核心动作（分块算梯度、平均、同步）在 CPU 上用两个线程就能演。实验：400 个样本分给 2 个 worker 各 200 个，各自算完整的前向反向得一份梯度，平均后与「一次性算全量 400 样本的梯度」对照（验证环境 WSL Ubuntu，NumPy 2.5.4）：

| worker 数 | ${\max\big|g_{\mathrm{sync}}-g_{\mathrm{full}}\big|}$ |
| --- | --- |
| 2 | ${2.2\times10^{-16}}$ |
| 4 | ${5.6\times10^{-16}}$ |

差在机器精度级，且这个差不为零是浮点求和顺序不同造成的：${\frac{1}{2}\big(\mathrm{mean}_1+\mathrm{mean}_2\big)}$ 与 $\mathrm{mean}_{400}$ 在数学上全等（线性性），在浮点里差最后一个位。DDP 不是近似，是精确的代数恒等式加上浮点的尾数噪声。

## $\rm \S \, 9.6$ 打开盖子：np.savez 往返与丢优化器状态的分叉

不打开盖子，你会缺一块判断力：知道 checkpoint 要连优化器一起存，却看不到「只存参数」会把轨迹带偏多远。手写框架的参数表在 §4.5 就有名字（`l1.W`、`l2.b`），存盘就是把名字映射到数组，一行 `np.savez` 就够：

```python
params = {"l1.W": net.l1.W, "l1.b": net.l1.b, "l2.W": net.l2.W, "l2.b": net.l2.b}
np.savez("mini_ckpt.npz", **params)
loaded = np.load("mini_ckpt.npz")            # loaded["l1.W"] 即参数
```

真跑往返：存了再读，四个数组 ${\max|\mathrm{diff}|=0}$，逐数一致；torch 侧同一实验也真跑过，`state_dict` 存盘再读 `max|diff| = 0.0`。只存参数、丢掉优化器状态会发生什么，真跑对照：momentum（$\beta=0.9$，$\mathrm{lr}=0.1$）训练 10 步，存档；第 11 步起两条恢复路线，一条带 ${v}$ 恢复、一条把 ${v}$ 清零，与「不中断连跑 20 步」对照（第 11 步损失相同，因为损失在更新前记录）：

| 步 | 连续 20 步 | 带状态恢复 | 丢状态恢复 |
| --- | --- | --- | --- |
| 11 | 0.0577 | 0.0577 | 0.0577 |
| 12 | 0.0506 | 0.0506 | 0.0563 |
| 14 | 0.0404 | 0.0404 | 0.0507 |
| 16 | 0.0330 | 0.0330 | 0.0433 |
| 18 | 0.0274 | 0.0274 | 0.0360 |
| 20 | 0.0230 | 0.0230 | 0.0295 |

带状态恢复与连续训练逐数一致（${\max|\Delta L|=0}$）；丢状态从第 12 步起分叉，10 步后损失 0.0295 对 0.0230，差 ${1.1\times10^{-2}}$。机制：momentum 的 ${v}$ 是过去梯度的累积（§5.5），清零等于宣布惯性从零开始，更新方向与幅度全变；Adam 的账更重，${m}$、${s}$ 外加步数计 ${t}$（偏置校正靠它），一样都不能丢。存盘代码相应扩一圈：

```python
state = {"l1.W": net.l1.W, "l1.b": net.l1.b,      # 模型参数
         "l2.W": net.l2.W, "l2.b": net.l2.b,
         "v.l1.W": v["l1.W"], "v.l1.b": v["l1.b"],  # momentum 的速度
         "v.l2.W": v["l2.W"], "v.l2.b": v["l2.b"],
         "epoch": 10}                               # 进度：恢复时知道从哪继续
np.savez("mini_ckpt.npz", **state)
```

torch 的 `torch.save({'model': model.state_dict(), 'opt': optimizer.state_dict(), 'epoch': e}, path)` 是这一段的成品版，见 §9.2。

## $\rm \S \, 9.7$ 常见错误与报错翻译

| 症状 | 原因 | 怎么改 |
| --- | --- | --- |
| `KeyError: 'model'` | 存档是裸状态字典，读盘时却按带键字典索引 `['model']` | 统一存成 `{'model': ...}` 再读，或直接 `load_state_dict(torch.load(path))` |
| `RuntimeError: Error(s) in loading state_dict`（`size mismatch` / `Missing key(s)`） | 模型结构与存档不一致，或键名对不上 | 打印两边 `state_dict().keys()` 逐对；迷你框架是 `l1.W`、torch 是 `l1.weight`（§4.5） |
| 续训后 loss 曲线跳一下（Adam 或 momentum 尤甚） | 只存了 `model.state_dict()`，优化器状态丢了 | 按 §9.2 的四样一起存，§9.6 的分叉表量化了代价 |
| 换了层宽或加了新层，旧存档加载失败 | 键集合变了 | 用 `load_state_dict(sd, strict=False)` 只填同名同形的层，返回 `_IncompatibleKeys` 供核对 |

`strict=False` 用在承认识别到的不一致、只填能填的那部分：迁移学习里给预训练骨干加新分类头，新头的键是意外的、旧骨干的键是齐的；反过来若主干层都没加载上，它也会静默放过，所以加载后要打印返回值核对缺了哪些键。

## $\rm \S \, 9.10$ 本章自测答案

### $\rm \S \, 9.10.1$ 关键概念回顾答案

1. 名字到张量的字典；它只存数值、与类定义解耦，换代码目录也能读回，而 `torch.save(model, ...)` 把类路径一起序列化。（§9.1）
2. 优化器状态、当前进度、最好指标；丢了优化器状态（momentum 的 ${v}$、Adam 的 ${m,s,t}$），续训轨迹会分叉，§9.6 里 10 步后差距 ${1.1\times10^{-2}}$。（§9.2、§9.6）
3. 每卡一份模型、各吃一份小 batch、梯度 all-reduce 平均后同步更新；靠梯度对 batch 分解的线性性（求和的平均等于平均的和）。（§9.5）
4. ${2(N-1)S/N}$；省的是服务器的集中瓶颈与扩展性（带宽均摊到全网链路），不省单卡总量（大 ${N}$ 时同样趋近 ${2S}$）。（§9.5）
5. 浮点求和顺序不同：分块平均再平均与一次全量平均数学全等，浮点里差最后一个位。（§9.5）

### $\rm \S \, 9.10.2$ 应用与辨析答案

1. ${128}$；线性缩放规则建议学习率乘卡数（${\mathrm{lr}\propto}$ 等效 batch），否则大批量的梯度平均会稀释有效步长。（§9.3）
2. 数据并行切样本维、模型并行切参数（层或矩阵维）；单卡装不下的参数量（embedding 巨表、超宽 FFN）迫使人切模型。（§9.3）
3. ${N=2}$ 时每卡既是发送方也是接收方，一轮 reduce-scatter 加一轮 all-gather 各传半份模型（${S/2}$），合计 ${S}$。（§9.5）
4. SGD 无状态（只有 $\mathrm{lr}$），参数加进度就够，无影响；Adam 的 ${m,s,t}$ 丢了等于优化器失忆，分叉同 momentum 实验。（§9.6）
5. 参数、优化器状态、step 计数、数据置换的种子（§6.3 的 ${123+e}$）、随机层的种子（dropout）、超参快照；少一样，续训就只是近似重启。（§6.3、§9.2）
