# $\rm Chapter \, 3$ 哈希与生日攻击

第 2 章立起了保密性，但位翻转攻击说明偷看与篡改是两回事。验证「这段数据没被改过」需要一个定长指纹：数据动一点，指纹就变。本章主角是密码学哈希函数，先定义它的三条性质与强弱关系，再用抽屉原理算出它躲不开的统计极限（生日攻击），然后看最常见的内部结构为什么藏着长度扩展的坑，最后用 Merkle 树回答「怎么只下载一点数据就验证海量文件」。

## $\rm \S \, 3.1$ 问题：完整性的指纹

下载一个 $2\,\text{GB}$ 的文件，怎么确认它没坏、没被替换？全文件重新比对需要另一份完整副本。需要的工具是**密码学哈希函数（cryptographic hash function）** $H$：任意长输入压成定长输出（如 SHA-256 给出 $256$ 位），并且满足三条性质：

1. **抗原像性（preimage resistance）**：给定 $y$，找 $m$ 使 $H(m) = y$ 不可行，从指纹反推数据难；
2. **抗第二原像性（second-preimage resistance）**：给定 $m$，找 $m' \ne m$ 使 $H(m') = H(m)$ 不可行，给定数据伪造同指纹的假货难；
3. **抗碰撞性（collision resistance）**：找任意一对 $m \ne m'$ 使 $H(m) = H(m')$ 不可行，凭空造一对同指纹数据难。

三者强弱关系是链：抗碰撞最强、抗第二原像居中、抗原像最弱，能找碰撞的算法稍加固定输入就能找第二原像，能伪造第二原像的输入对本身也是碰撞。§3.2 会给这条链定量的价格差。工程上还有两个可观察的性质：**雪崩效应（avalanche effect）**：输入改一位，输出约一半的位翻转，指纹面目全非；输出是一串定长比特，可以直接当 $256$ 位整数参与模运算，第 7 章的签名和第 9 章的承诺都会这么用。

三条性质与三类应用一一对应，先钉住这张表，后文引用时不再展开：

| 应用 | 对手能力 | 依赖的性质 |
| --- | --- | --- |
| 下载校验（文件已定） | 替换文件凑指纹 | 抗第二原像 |
| 数字签名（先哈希再签，第 6 章） | 自由挑两条消息骗签名 | 抗碰撞 |
| 承诺（第 9 章） | 反推被承诺的值 | 抗原像 |

顺带一句边界：哈希不是加密。它把消息压成指纹但不可还原，「不可逆」不等于「保密」，对低熵输入（比如少量候选密码），攻击者把候选逐个哈希比对就能反推，密码存储里给哈希加盐防的就是这个，本册不展开。

## $\rm \S \, 3.2$ 生日攻击：$2^{n/2}$ 的天花板

哈希输出 $n$ 位，值域只有 $2^n$ 个。按**抽屉原理（pigeonhole principle）**，只要消息数超过 $2^n$，碰撞必然存在，所以抗碰撞从来不是「没有碰撞」，而是「找碰撞的代价高到不可行」。这个代价由**生日攻击（birthday attack）**定标：从值域中随机抽 $m$ 个值，期望碰撞对数约为

$$
\frac{m(m-1)}{2^{n+1}}
$$

令它等于 $0.5$（即「很可能出现至少一对」），解出 $m \approx 2^{n/2}$。分子 $m(m-1)/2$ 就是 $m$ 个值两两配对的对数：每一对撞上的概率是 $2^{-n}$，对数乘概率即期望，抽屉原理给了「碰撞必然存在」的存在性，这个乘法给的是「多久撞上一次」的定量价签。数值验证（`python`）：

```python
import math
for n in (64, 128, 256):
    m = math.isqrt(2 ** n)                      # 取 2^(n/2) 条消息
    print(n, m * (m - 1) / 2 / 2 ** n)          # 期望碰撞数 ≈ 0.5
```

| 输出位数 $n$ | 取 $2^{n/2}$ 条消息的期望碰撞对数 | 约 $50\%$ 概率出碰撞所需消息数 |
| --- | --- | --- |
| $64$ | $0.5$ | $2^{32.2}$ |
| $128$ | $0.5$ | $2^{64.2}$ |
| $256$ | $0.5$ | $2^{128.2}$ |

这张表给出 §3.1 那条链的价格差：碰撞攻击只要 $2^{n/2}$ 次哈希，第二原像攻击仍要约 $2^n$ 次。于是设计守则成对出现，若只需要抗第二原像（每个对象已有既定的原文），$128$ 位输出够用；若对手可以自由挑选两条消息再拿出来对比（数字签名场景，第 6 章），必须抗碰撞，输出 $256$ 位起步，把碰撞代价顶回 $2^{128}$（按第 1 章的换算约 $1.3\times10^{22}$ 年）。

## $\rm \S \, 3.3$ Merkle–Damgård 与长度扩展攻击

主流哈希（MD5、SHA-1、SHA-256）同属一个模板：**Merkle–Damgård 结构**。取一个定长压缩函数 $h$，把消息切成分块、补齐长度，从初始值开始链式推进：

$$
H_0 = \text{IV}, \qquad H_i = h(H_{i-1} \,\|\, m_i), \qquad H(m) = H_L
$$

$\|$ 表示拼接。末尾附上消息长度这一步是安全证明的要求：不带长度时，`m = ab` 与 `m' = abc` 的链可能停在同一个中间态，证明拧不紧。填充的格式也值得看一眼：先补一个 `0x80`，再补零，最后 $64$ 位写消息的比特长度，长度信息本身就在链上，这是攻击者能「续链」的前提之一。但它救不了另一个洞：消息在链上滚动，链的最后一格停在 $H_L$如果攻击者已知 $H(k \| m)$（$k$ 是不知道的密钥）和 $k$ 的长度，就能从 $H_L$ 继续往后滚动，算出 $H(k \| m \| \text{pad} \| \text{任意后缀})$ 的合法值。这就是**长度扩展攻击（length-extension attack）**：附加的后缀不同，但指纹是「真钥匙算出来的」。

后果直接指向第 4 章：把 $H(k \| m)$ 当消息认证码用是错的，攻击者截获一条合法消息 $m$ 与它的指纹，就能给任意后缀造出同样合法的指纹，而接收方无从分辨后缀不是原话。修补的思路也在此埋下：让密钥在两个方向上都隔离于消息，具体构造叫 HMAC。

## $\rm \S \, 3.4$ Merkle 树：一个哈希验证一堆数据

哈希只验证单个对象；数据有 $8$ 个分块时，逐块存指纹要 $8$ 个哈希，块再多就线性膨胀。**Merkle 树（Merkle tree）**把哈希叠成树：叶子存每个数据块的哈希，每个内部节点存两个孩子的哈希拼接后再哈希，全树收缩成一个根哈希。验证叶子 $4$（下标 $3$，$0$ 起）只需要它到根的兄弟路径，$3$ 个哈希，与树高对数同阶。实际跑一遍（`python`，输出截断为 $16$ 位十六进制）：

```python
import hashlib
H = lambda b: hashlib.sha256(b).hexdigest()[:16]
lv = [H(b"block%d" % i) for i in range(1, 9)]          # 8 片叶子
while len(lv) > 1:
    lv = [H(bytes.fromhex(lv[i]) + bytes.fromhex(lv[i + 1]))
          for i in range(0, len(lv), 2)]
print(lv[0])                                           # 根：fc86d92eaa4ee387
```

各层算出的节点：

| 层 | 节点（前 $10$ 位） |
| --- | --- |
| $0$（叶） | `9a59c5f822` `6d0b07ee77` `7e56ddaff5` `215008ba41` `2e13467597` `90e0b521b8` `929945245a` `40d56ca52b` |
| $1$ | `9a1ad5f24a` `d571616b70` `5194b33d4d` `d727231da0` |
| $2$ | `aa449482a5` `bf1ed7a31e` |
| $3$（根） | `fc86d92eaa4ee387` |

验证叶子 $4$（叶哈希 `215008ba41…`）：取兄弟叶 `7e56ddaf…`（在左），算出父亲 `d571616b70…`；取叔父 `9a1ad5f24a…`（在左），算出祖父 `aa449482a5…`；取兄弟祖父 `bf1ed7a31e…`（在右），得根 `fc86d92eaa4ee387`与整树算出的根一致即叶子没被换。把这条验证路径也写成脚本（叶哈希与三个兄弟哈希是下载得到的全部材料）：

```python
import hashlib
H = lambda b: hashlib.sha256(b).hexdigest()[:16]
cur = H(b"block4")                                    # 待验证的叶子：215008ba416eb06b
path = [("7e56ddaff5ff44d9", "L"), ("9a1ad5f24ac4ecb3", "L"), ("bf1ed7a31e97130f", "R")]
for s, side in path:                                  # 自底向上，side 标兄弟在左还是在右
    cur = (H(bytes.fromhex(s) + bytes.fromhex(cur)) if side == "L"
           else H(bytes.fromhex(cur) + bytes.fromhex(s)))
print(cur)                                            # fc86d92eaa4ee387，与公布的根一致
```

反过来，改任何一个叶子，从它到根的 $3$ 个节点全要重算，其余子树的哈希一字不动，脚本把这条重算路径也验证过。这个「改一处、只需对数条路径」的性质就是三个工程的共同骨架：下载校验（文件清单只公布一个根，分块哈希随数据走；区块链），每个区块头存交易列表的 Merkle 根，轻节点只收路径即可验证一笔交易而不下载全链；Git，对象库按内容哈希寻址、树对象层层嵌套，Git 提交＝带父指针的快照（本站全书锚点比喻），这一说法里的快照，其内容寻址正是 Merkle 结构。

## $\rm \S \, 3.7$ 本章自测答案

> 先闭卷作答上面两节，再核对。

### $\rm \S \, 3.7.1$ 关键概念回顾答案

1. 抗原像防「从指纹反推数据」，抗第二原像防「给既定原文造同指纹假货」，抗碰撞防「凭空造一对同指纹数据」；强弱：抗碰撞最强、第二原像居中、原像最弱。（§3.1）
2. $m$ 个值两两配对共 $m(m-1)/2$ 对，每对撞上 $n$ 位值域的概率 $2^{-n}$，故期望碰撞对数为 $m(m-1)/2^{n+1}$；令其为 $0.5$ 得 $m \approx 2^{n/2}$。抗碰撞代价 $2^{n/2}$，$256$ 位输出顶回 $2^{128}$；第二原像仍要 $2^n$，$128$ 位输出已够。（§3.2）
3. 分块、补长度，$H_i = h(H_{i-1} \| m_i)$ 滚动到 $H_L$；攻击利用「链条任意中间态可继续滚动」：拿 $H(k \| m)$ 当新链条起点，附任意后缀算出合法指纹。（§3.3）
4. 叶子本身加上到根的兄弟哈希路径（$8$ 叶树为 $3$ 个），自底向上重算与根比对；改动一个叶子后重算的是它到根路径上的全部节点，兄弟子树不动。（§3.4）
5. 雪崩效应保证「先哈希再签」时攻击者无法定向拼出想要的指纹值（第 6 章）；「输出当整数用」出现在椭圆曲线签名的 $z$ 与第 9 章的承诺值（第 7、9 章）。（§3.1）

### $\rm \S \, 3.7.2$ 应用与辨析答案

1. 防中途损坏与第三方替换，只要哈希值来自可信渠道。站点被攻破时攻击者可以连文件带哈希一起换，哈希由同一渠道发布就失去裁决力；防住的是「传输损坏」而非「发布源作恶」。（§3.1）
2. 验单个文件：存每个文件的哈希（$10^6$ 个，各 $32$ 字节），验证传「文件＋一个哈希」。验整个集合：存 Merkle 根（一个），验证单个文件传「文件＋$20$ 个兄弟哈希」，存储从 $10^6$ 降到 $1$，传输从 $O(1)$ 涨到 $O(\log n)$，两个方向各取所需。（§3.4）
3. 截获 $(m, \text{tag})$，若已知或可猜出 $\text{len(key)}$，从 $\text{tag}$ 出发滚动哈希，对任意后缀 $\text{suffix}$ 造出合法的 $H(k \| m \| \text{pad} \| \text{suffix})$；单向性只防「从指纹反推 $k \| m$ 全文」，防不住「从链条中间继续向前滚」。（§3.3）

---

指纹解决了「怎么发现数据被改」，但有一个前提没说出口：指纹必须由可信渠道发布。要是消息和指纹都来自同一条不可信信道（比如都出自对话的另一方）攻击者连消息带指纹一起换，哈希全程蒙在鼓里。给消息盖上「只有密钥持有者能造、任何人拿钥匙能验」的戳，就是下一章的 MAC 与 AEAD。
