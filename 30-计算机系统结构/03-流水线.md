## $\rm \S \, 3.1$ 五级流水线：5 倍从哪来

洗衣店提供了唯一需要的类比：洗衣、烘干、熨烫、折叠、归柜五道工序。第一批衣服走完全程后，第二批不必等第一批归柜，它在第一批烘干时就进了洗衣机。五台机器同时在忙五批衣服，完工节奏从「每 50 分钟一件」变成「每 10 分钟出一件」：每件衣服仍是 50 分钟，产能 5 倍。CPU 的五道工序：

| 级 | 全称 | 干什么 |
| --- | --- | --- |
| IF | Instruction Fetch | 取指：按 PC 取一条指令（定长 4 字节在这里还债，一取一个准） |
| ID | Instruction Decode | 译码，读寄存器堆 |
| EX | Execute | ALU 运算或算访存地址 |
| ME | Memory | load/store 访问数据缓存 |
| WB | Write Back | 结果写回寄存器堆 |

每级一拍，流水填满后每拍完成一条：吞吐率 5 倍于非流水，单条指令仍走 5 拍（第 1 章 §1.1 延迟与吞吐的分家在这里重现）。理论 CPI 是 1，加速比约等于级数，前提是每一拍都有新指令喂进来。砸这个前提的惯犯叫**冒险（hazard）**，共三类：数据冒险（指令等着用还没算完的数）、控制冒险（分支不知道该取哪条）、结构冒险（两个级抢一个部件）。

## $\rm \S \, 3.2$ 数据冒险：转发与 load-use

重点是 **RAW（read after write）**：后一条指令要读的寄存器，前一条还没写回。手算这段序列（`t0` 即 `x5`，编号对应 RISC-V）：

```asm
I1: lw   x5, 0(x6)     # 取数
I2: add  x7, x5, x1    # 用 x5：RAW，且生产者是 load
I3: sub  x8, x7, x9    # 用 x7：RAW，生产者是 ALU 指令
I4: and  x10, x11, x12
I5: or   x13, x10, x2  # 用 x10：RAW
```

不加任何措施时，I2 在 ID 级读 x5（第 2 拍起），而 I1 的 x5 第 5 拍才写回，读到的是旧值。**转发（forwarding，前递）**的做法是拉旁路线：EX/MEM 与 MEM/WB 级间寄存器里躺着的现成结果，直接送到 EX 级的输入，不绕道寄存器堆。ALU 型生产者（I3 等 I2、I5 等 I4）经转发零等待。唯独 I2 救不了：`lw` 的数据第 4 拍末才从存储器出来，I2 的 EX 若排在第 4 拍则转发线也来不及接，必须**停一拍（stall）**。这叫 load-use 冒险，是转发救不了的一拍。逐拍时序表（手算，与程序输出逐位一致）：

| 指令 | c1 | c2 | c3 | c4 | c5 | c6 | c7 | c8 | c9 | c10 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| lw x5, 0(x6) | IF | ID | EX | ME | WB |  |  |  |  |  |
| add x7, x5, x1 |  | IF | ID | ID（停） | EX | ME | WB |  |  |  |
| sub x8, x7, x9 |  |  | IF | IF | ID | EX | ME | WB |  |  |
| and x10, x11, x12 |  |  |  | IF | IF | ID | EX | ME | WB |  |
| or x13, x10, x2 |  |  |  |  | IF | IF | ID | EX | ME | WB |

核对四个细节：I2 在 ID 级多停一拍（c4），等 `lw` 的 ME 结束；I3 停在 IF（c4），因为 ID 被 I2 占着；I3 与 I5 的 RAW 靠转发解决，EX 紧贴生产者的 EX/ME 之后；总计 10 拍，$\text{CPI} = 10/5 = 2.0$。对照组：把 I2 改读 `x1, x2`（无 load-use），I2 的 EX 提前到 c4，全程只要 9 拍（CPI 1.8）：转发让普通 RAW 不花一分钱，账上只剩 load-use 的那一拍。编译器也来帮忙：把独立指令挪进 load 后面的洞里，那拍就白捡了。

**本节小结**：数据冒险的本体是 RAW——后一条要读的数前一条还没写回；转发把 ALU 型等待降为零，load-use 因数据 ME 末才就绪仍欠一拍，这一拍可以由编译器调度拿独立指令填掉。

## $\rm \S \, 3.3$ 控制冒险：分支预测的账

分支指令到 EX 级才揭晓方向，而取指每一拍都在往前跑：揭晓前取进流水线的指令全是要冲掉的水。这就是**控制冒险（control hazard）**。最朴素的**静态预测（static prediction）**固定猜一边（如「向后跳就猜跳」，照顾循环）；**动态预测（dynamic prediction）**记住每个分支的历史，主力是 **2 位饱和计数器（2-bit saturating counter）**：

| 状态 | 编码 | 预测 | 实际跳 | 实际不跳 |
| --- | --- | --- | --- | --- |
| 强跳 | 11 | 跳 | 11 | 10 |
| 弱跳 | 10 | 跳 | 11 | 01 |
| 弱不跳 | 01 | 不跳 | 10 | 00 |
| 强不跳 | 00 | 不跳 | 01 | 00 |

两位的妙处在容忍一次反转：偶尔不跳一次（11 → 10），预测仍是「跳」，下次照旧命中。实跑三种序列（Python 实跑，Windows 10 / Python 3.12.10，随机序列固定 `random.seed(7)`）：

```python
def pred(seq, bits, init=0):
    c, miss = init, 0
    for t in seq:
        if (c >= (1 if bits == 1 else 2)) != bool(t): miss += 1
        c = min((1 << bits) - 1, c + 1) if t else max(0, c - 1)
    return 1 - miss / len(seq)
```

| 序列 | 1 位计数器 | 2 位计数器 |
| --- | --- | --- |
| 循环型：9 跳 1 不跳 × 100 轮 | 80.0% | 89.8% |
| 交替型：跳、不跳严格交替 | 0.0% | 50.0% |
| 随机型：50% 抛硬币，1000 次 | 50.1% | 48.3% |

读法有三条。1. 循环型 2 位 89.8% 恰好等于分支自身的跳转率：每圈只错退出那一次（计数器在强跳被唯一的不跳拽到弱跳，下一圈开头预测依旧正确），预测器没法更好，除非换专门照顾循环的结构；1 位在 80.0%，多赔的 10 个点在每圈入口：退出把它的计数器砸到 0，下一圈第一跳也跟着错。2. 交替型 1 位计数器全错：每次反转都踩在它的预测上；2 位靠容忍一次反转，保住 50%。3. 随机型没有历史模式可学，两位也好多位也罢都是 50% 上下的听天由命。预测的价值按这笔账算：

$$
\text{CPI} = 1 + \text{分支频率} \times \text{误预测率} \times \text{误预测代价}
$$

手算：分支占 20%，误预测率 10%，深流水线代价 15 拍，则 $\text{CPI} = 1 + 0.2 \times 0.1 \times 15 = 1.3$；换成 50% 的误预测率，$\text{CPI} = 1 + 0.2 \times 0.5 \times 15 = 2.5$，吞吐率差近一倍。链表遍历、平衡树这类分支密集的程序对预测器最敏感。

一句与操作系统的接口：上下文切换把整条流水线连同分支历史一起冲掉（操作系统册 §2.1 保存的寄存器现场只是架构状态，预测器里学到的历史不在其中），这也是切换贵的原因之一。

## $\rm \S \, 3.4$ 结构冒险与实验代码

第三类是**结构冒险（structural hazard）**：两个级同拍抢同一个部件。典型冲突是 IF 与 ME 同拍都要访问存储器，工业界的解法是让指令缓存与数据缓存分家（第 5 章你会看到 L1 确实分成两块）；寄存器堆同理，ID 级读与 WB 级写同拍发生，就把寄存器堆做成读写双端口。三类冒险里它最像工程杂活，设施到位即消失。

两组实验的完整复现代码如下（10 行流水线模拟 + 8 行预测器；与 §3.2、§3.3 正文数字逐位一致）：

```python
def pipeline(plist):                        # plist: [{op, rd, rs}, ...]，lw 消耗 3 拍可用
    ifc = [i + 1 for i in range(n)]; idc = []; exc = []
    for i in range(n):
        d = ifc[i] + 1
        if i: d = max(d, exc[i - 1])        # 前一条离开 ID，本条才能进 ID
        idc.append(d); e = d + 1
        if i: e = max(e, exc[i - 1] + 1)
        for j in range(max(0, i - 2), i):   # 转发窗口：前两条
            if plist[j]["rd"] in plist[i]["rs"]:
                e = max(e, idc[j] + 3 if plist[j]["op"] == "lw" else exc[j] + 1)
        exc.append(e)
    return max(e + 2 for e in exc)          # 最后一条 WB 结束的周期
```

运行输出即 §3.2 的逐拍表（含 I2 在 c4 的 ID 停留、I3/I4 在 IF 的按停）与「总周期 10，CPI 2.00；无 load-use 对照 9」；预测器输出即 §3.3 表中三行六个数。手算表与程序互为验算。

**本节小结**：结构冒险是两个级同拍抢一个部件，解法全是工程设施——指令/数据缓存分家、寄存器堆双端口。至此三类冒险收齐：数据靠转发与停顿，控制靠预测，结构靠硬件设施，各自的花销都已入账。

## $\rm \S \, 3.7$ 本章自测答案

> 先闭卷作答 §3.5 与 §3.6，再核对。

### $\rm \S \, 3.7.1$ 关键概念回顾答案

1. 每级一拍、流水填满后每拍出一条，产能 5 倍；单条指令仍走完五级。前提是每拍有新指令、数据随时可用、方向已知：数据/控制/结构冒险逐一破坏。（§3.1）
2. 转发给 ALU 型 RAW 提供旁路，结果不绕寄存器堆直达 EX。load 的数据 ME 末才出现，紧邻消费者的 EX 等不到转发线，必须停一拍。（§3.2）
3. $\text{CPI} = 1 + \text{分支频率} \times \text{误预测率} \times \text{代价}$；0.2×0.1×15 = 0.3，CPI 1.3；50% 时 0.2×0.5×15 = 1.5，CPI 2.5，差近一倍。（§3.3）
4. 容忍一次反转：偶发一次反方向不改变预测，1 位计数器在交替序列上全错而 2 位保住 50%。无历史模式的随机分支谁也预测不了。（§3.3）
5. IF 与 ME 抢存储器：指令/数据缓存分家；ID 读与 WB 写抢寄存器堆：双端口。L1 分成 I/D 两块正是前者的遗产。（§3.4）

### $\rm \S \, 3.7.2$ 应用与辨析答案

1. `and` 与 `or` 无依赖，挪前填洞后 load-use 那拍被独立工作盖住：I2 的 EX 推到第 5 拍期间 I4 已在跑，总周期回到 9 拍（即对照组数字）。这个手法叫指令调度（编译器层面的延迟槽填充）。（§3.2）
2. 级数翻倍，load-use 与误预测的代价（冲掉的拍数）跟着翻倍；深流水还拉高分支误预测率的结构性成本，§3.3 的账 0.2×0.5×15 会变成 0.2×0.5×30。频率涨、CPI 也涨，第 1 章的三因子相乘不一定赚。（§3.2、§3.3）
3. $\text{CPI} = 1 + 0.3 \times 0.1 \times 15 = 1.45$；消掉一半分支后 $1 + 0.15 \times 0.1 \times 15 = 1.225$，快约 15%。（§3.3）
4. 流水线被整条冲掉（重新填满要几拍），分支历史清零（前几十次分支预测变差）：两者都是切换的隐性税。（§3.3、§3.4）
