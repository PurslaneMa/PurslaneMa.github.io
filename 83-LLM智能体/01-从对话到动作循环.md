整册只有一句主线：**agent 就是把 LLM 的下一词预测变成对世界的动作循环，感知、决策、行动、反馈四步首尾相接**。本章把这个循环最小化地立起来：先看单轮问答到底缺什么（§1.1），再定义循环本身并把它对齐到你学过的 MDP 框架（§1.2），然后给循环填上两块骨头，ReAct 的思考-行动-观察轨迹（§1.3）与工具调用的解析-执行-回填协议（§1.4），最后在规则世界里把同一任务交给单轮和循环各跑一遍，量出能力跳变有多大（§1.5）。学完本章你能亲手驱动一个无模型的 agent 循环，并知道它的每一步消息是怎么长的。

LLM 本身怎么训练、怎么推理，本册不重讲，需要时指回《LLM从零构建》册；模型在对话任务上的行为与工具调用接口见《自然语言处理》册 §12。

## $\rm \S \, 1.1$ 问题：下一词预测没有手

把 LLM 当成一个函数看：输入一串文本，输出一串文本，调用返回即结束。它有三个写死在机制里的性质，每个都有可直接观察的后果。

1. **模型本身无状态**。两次调用之间互不相识，所谓记忆只是这次调用时上下文窗口里摆着的文本。后果：想让模型「记得」三分钟前查到的引用数，唯一的办法是把那个数字写进本轮的输入里。
2. **它只能产文本**。输出再像命令，也不会有任何一个字节被世界里执行。后果：模型写出一条完美的 `SELECT` 语句，查询不会自己发生；写出一段「先拿钥匙再开门」，钥匙不会自己进兜。
3. **一次输出内无法获得新信息**。生成第 100 个词时，模型知道的不会比生成第 1 个词时更多，因为没有任何新输入进来。后果：凡是「先查一个数、再按结果决定下一步」的任务，一次生成在原理上就不够用。

拿一个真实任务对照。「把这份 30 篇的论文列表里每篇的引用数查出来，填进表格，超过 500 的标红。」单轮 LLM 能写一段「假如我要做这件事」的漂亮说明，却完成不了它：查引用数要访问外部世界（性质二撞墙），网页打不开要换渠道重试（性质一撞墙），填表时发现两条数据打架要回头核对（性质三撞墙）。注意这三个障碍都不是「模型不够聪明」，而是这个函数接口根本没有给聪明留出用武之地的通道。

顺便澄清一个常见误会。聊天产品里「模型记得三分钟前说过的话」，并不是模型有了记忆，而是客户端把历史全文重新发了一遍：每一轮请求里，你这句话前面都拖着之前的全部对话文本。记忆住在客户端维护的那个列表里，不住在模型里。这也是长对话越聊越慢的原因之一：每次请求的输入都在变长，处理前缀的开销跟着涨（《LLM从零构建》§12.3 的 KV cache 只省计算，不省这份上下文本身的存在）。记住这一点，§1.2 循环里的 `context` 就不陌生了，它就是这个列表的正式化。

所以在 LLM 之上还需要一层东西。它要能把模型的文本输出变成对世界的真实动作，要把动作的结果送回给模型，要允许「试、错、再试」这个过程发生。这层东西就是本章的主角。

白话：单轮 LLM 是一支好笔，但手被绑在背后：它能写出「应该先拿钥匙再开门」，却碰不到任何一扇门。缺的不是智力，是一个能把手松开的循环。

> 本节小结：LLM 是无状态、只产文本、单次调用内无新信息的函数；记不住事、动不了手、补不了信息三类日常动作恰好分别踩在这三条性质上，这就是要在模型之外补一层循环的原因。

## $\rm \S \, 1.2$ 新概念：agent 是一个 while 循环

定义（agent，智能体）：以 LLM 为决策器、以某个外部环境为作用对象、按固定控制流反复执行「感知-决策-行动-反馈」四步的系统。写成最小骨架：

```python
context = [task]                     # 感知：任务与历史都住在上下文里
while not done and steps < BUDGET:   # 终止条件必须显式给出
    text = llm(context)              # 决策：模型读上下文，产出思考与动作文本
    action = parse(text)             # 解析：从文本里抠出结构化的动作
    obs = env.execute(action)        # 行动：对世界真正执行这一步
    context += [text, obs]           # 反馈：把输出与观察回填进上下文
```

用记号压紧：设 $c_t$ 是第 $t$ 轮的上下文，$E$ 是环境，$\pi$ 是模型，则循环就是

$$
a_t=\pi(c_t),\qquad o_{t+1}=E(a_t),\qquad c_{t+1}=c_t\,\Vert\,a_t\,\Vert\,o_{t+1}
$$

读法：$\Vert$ 表示文本拼接，$a_t$ 是模型从上下文 $c_t$ 里产出的动作文本，环境 $E$ 执行后返回观察 $o_{t+1}$，三者拼进上下文供下一轮使用。

这个形状《强化学习》§1.2 的读者会眼熟，逐项对齐如下：

| 《强化学习》§1.2 的对象 | agent 循环里的对应物 | 关键差别 |
| :--- | :--- | :--- |
| 状态 $s_t$ | 上下文文本 $c_t$ | 不是马尔可夫状态，是一段可长可短的文本 |
| 动作 $a_t$ | 工具调用 | 从模型输出的文本里解析而来 |
| 转移 $P(s'\mid s,a)$ | 工具运行时或真实世界 | 规则不可写全、转移不可枚举 |
| 奖励 $r_t$ | 无显式奖励，用成功条件加预算代替 | 稀疏且外置于模型 |
| 策略 $\pi(a\mid s)$ | LLM 权重加提示 | 权重全程冻结，「知识」全在上下文里 |

最后一行值得多看一眼。RL 的策略靠梯度训练进参数里，训练完就刻在权重上；agent 的 $\pi$ 权重一个字都不动，每一轮的全部依据都摆在 $c_t$ 里：提示是操作手册，观察是实时路况。这也解释了为什么第 2 章整章都在讲上下文：对 agent 来说，上下文不是辅助材料，它就是策略的本体。

现在可以精确说「能力跳变」跳在哪。单轮是把全部决策压缩进一次前向：模型必须一次性猜对整条动作序列，猜错没有任何补救。循环把决策摊到每一步，每步做完都强制塞进一条新观察，错误的代价从「整局崩盘」降为「多走几步」。跳变的来源不是模型变聪明了（权重与单轮时是同一份），而是控制流从一次函数调用换成了带反馈的迭代，迭代让错误变得可恢复。

白话：单轮像闭卷一口气默写整张地图，错了就交卷；agent 像带着 GPS 开车，走错一个路口，下一条语音提示立刻把你拉回来。车技没变，变的是有了实时反馈。

循环也开出一张新账单：每个动作都是一次完整的模型调用，世界 #1 的 14 轮就是 14 次前向，延迟与费用都按轮数线性涨，这笔账在第 8 章成本一节细算。本册后面各章都沿着这个骨架逐件加装：第 2 章管上下文，第 3 章管工具协议的工程细节，第 4 章管决策质量，第 5 章把多个循环接在一起。骨架立稳了，后面的每件设备都有地方安装。

> 本节小结：agent ＝ 以 LLM 为策略 $\pi$、以工具运行时为环境 $E$、以上下文为唯一状态的 while 循环；与 MDP 逐项对齐后差异集中在两点，环境不可枚举、策略靠上下文而非权重；能力跳变来自控制流（反馈迭代），不来自模型本身。

## $\rm \S \, 1.3$ ReAct：把思考写进轨迹

§1.2 的骨架里，模型每轮产出一段文本。ReAct（Reasoning plus Acting）给这段文本规定了形状：它必须由两类行交替组成，**Thought** 行写「我现在处于什么状态、下一步为什么这么走」，**Action** 行写结构化的动作；环境回话用 **Observation** 行。三种行在轨迹里逐轮交替，直到任务完成或预算耗尽。完成的标志也是一个动作：真实实现里常见一个专门的 `final_answer` 工具，调用它即宣告循环结束；本章网格世界里，观察返回「任务完成」就是终止信号。终止动作和普通动作走同一条协议通道，没有特权路径。

锚点实验世界 #1 的前两轮与最后一轮长这样（完整轨迹见 `_uni5_work/expEA01/result.txt`）：

```text
Thought: 手里没有钥匙，当前在 (0, 0)，目标是 (5, 3)；查表选 S 方向，
         走完这步离目标还剩 7 步。
Action: {"name": "move", "arguments": {"dir": "S"}}
Observation: moved to (1, 0)，holding=False

（第 2 至 9 轮同形，位置沿最短路推进，第 9 轮抵达钥匙格 (5, 3)）

Thought: 手里有钥匙，当前在 (2, 3)，目标是 (2, 1)；查表选 W 方向，
         走完这步离目标还剩 1 步。
Action: {"name": "move", "arguments": {"dir": "W"}}
Observation: moved to (2, 1)，holding=True
```

读这段轨迹注意两处。其一，第 9 到 10 轮之间有一个**阶段切换**：拿到钥匙那一刻起，同一个查表器的目标从钥匙格换成了终点格，轨迹里 Thought 的措辞随之从「手里没有钥匙」变成「手里有钥匙」。任务里嵌套的子目标（取钥、送达）就是这样靠上下文里的一行观察自然切换的，不需要任何额外的控制代码。其二，每轮 Thought 都复述了位置与剩余距离，这正是观察回填的直接产物：没有第 $t$ 轮的 Observation，第 $t{+}1$ 轮的 Thought 就无从写起。

为什么值得把思考写出来而不是直接给动作？在真实 LLM 里，Thought 是上下文的一部分，它改变下一步生成时每个词的条件概率：模型读到「目标是先取钥匙」之后，续写出「去终点」方向动作的概率就被压低了。这个效应本册在第 4 章规划方法（CoT、ToT）里展开。这里必须先说清模拟器的边界：本章伪 LLM 是查表机，思考文本是查表时顺带吐出的固定字符串，**并不参与决策**，动作在查表那一刻已经定了。我们的模拟器复现的是轨迹的**形状**与协议的**行为**，不复现「思考影响分布」这一真实机制；这是用表驱动模拟换无 API 实验付的租金，后面所有结论的适用范围都受这条限制。

白话：Thought 是把心里话写在便签上贴回桌面。真人贴便签会提醒自己，我们的查表机器人贴便签纯属走流程；但走完流程，轨迹长什么样、协议怎么应答，和真的一模一样。

> 本节小结：ReAct 规定了 Thought/Action/Observation 三类行交替的轨迹形状；嵌套子目标靠观察回填自然切换阶段；真实模型中 Thought 参与决策而模拟器中它只是记录，这条差异是本章全部模拟结论的边界。

还有一个隐蔽的收获藏在轨迹里：整条轨迹是**可读的**。出了错，你打开消息列表就能看到模型每一轮「想了什么、做了什么、世界回了什么」，排障的对象是一段文本而不是一次黑盒函数调用。这个性质在工程上叫可追溯性，第 3 章的错误处理和第 6 章的评测都会反复用到它。

## $\rm \S \, 1.4$ 工具调用协议：解析-执行-回填

循环骨架里的三行代码 `parse`、`execute`、回填，合起来是工具调用协议（tool calling protocol）的三拍。逐拍走查每拍发生了什么，数据来自锚点世界 #1 的真实输出。

1. **解析**：模型吐出的文本形如 `Action: {"name": "move", "arguments": {"dir": "S"}}`，解析器用正则从中抠出工具名与参数。抠不出来（比如少个右括号）不算异常，算一条观察。
2. **执行**：运行时按工具名查到 `move` 的实现，传入方向参数，改动世界状态，得到观察文本如 `moved to (1, 0)，holding=False`。
3. **回填**：把模型的原始输出与执行观察按 `assistant` 和 `tool` 两种角色追加进消息列表。上下文是循环的**唯一**状态：没有数据库、没有隐藏变量，掉电后只要消息列表还在，任务就能续跑。这两类角色的命名与《LLM从零构建》§4.2 里模型的输入侧一致：对模型而言，一切历史都是「已经写出的文本」，`tool` 观察与用户的任务在机制上并无不同。

回填有一个可以逐轮验证的算术性质：初始 1 条 user 消息，此后每轮恰好加 1 条 assistant 加 1 条 tool，所以第 $t$ 轮结束时列表长度是

$$
L_t=1+2t
$$

世界 #1 走了 14 轮，$L_{14}=29$，与实测的 29 条消息（1 条 user、14 条 assistant、14 条 tool）吻合。把这段生长过程挑几个关键轮列表：

| 轮次 | assistant 消息 | tool 消息（Observation） | 列表长度 |
| :--- | :--- | :--- | :--- |
| 0 | （尚无） | 任务：拿到钥匙并走到终点 | 1 |
| 1 | Thought＋Action(S) | moved to (1, 0) | 3 |
| 3 | Action JSON 少右括号 | 解析失败，请按协议重发 | 7 |
| 4 | 按正确格式重发 S | moved to (3, 0) | 9 |
| 14 | W 至 (2, 1) | holding=True，任务完成 | 29 |

第 3 轮是特意安排的一次协议事故：伪 LLM 吐出的 Action JSON 少了右括号，解析器返回「解析失败，请按协议重发」，这条**错误提示本身作为 Observation 回填**，第 4 轮模型按正确格式重发同样方向的动作，任务照常完成，总代价是多烧一轮（14 轮里 13 步有效移动加 1 轮纠错）。这正是协议设计的要害：坏输出进入循环而不是打断循环，格式错误就成了一种普通的、可反馈可修正的世界状态。

白话：协议三拍就是收快递，拆包（解析）、试用（执行）、把体验写进备忘录（回填）；连「包裹是空的」也要记进备忘录，这样下一轮才知道要投诉。

> 本节小结：解析-执行-回填三拍把文本变成动作、把动作变成观察、把观察变成下一轮的上下文；列表长度 $L_t=1+2t$ 可逐轮对账；解析失败也回填，错误因此可自愈，代价是多一轮。

## $\rm \S \, 1.5$ 锚点实验：同一任务，单轮对循环

实验要量出 §1.2 说的跳变。任务设在 $8\times 8$ 网格世界：起点 $(0,0)$，先走到钥匙格、拿到钥匙，再走到终点格才算成功；墙格不可通行，撞墙原地不动但消耗一步；每个世界按墙密度 0.12 随机生成，生成时用 BFS 验证「起点到钥匙、钥匙到终点」两段都连通才收货，共 50 个世界，预算 64 步，种子 20261108。§1.3、§1.4 引用的世界 #1 是这 50 个里的第一个：6 堵墙，钥匙在 $(5,3)$，终点在 $(2,1)$。

两个条件用的是同一个执行器、同一个预算，差别只在决策侧。ReAct 条件的伪 LLM 是表驱动的：预先生成真实地图的 BFS 距离场，运行时按「位置＋是否持钥」查表，返回一条固定格式的 Thought 和贪心最优动作，每步都是真实最短路。单轮条件用一个**故意带缺陷的表**：它不知道墙在哪，按空棋盘规划，一次输出「取钥匙到送终点」的完整动作序列，输出后不许改，模型侧从此再无输入。脚本与完整输出在 `_uni5_work/expEA01/exp.py` 与 `result.txt`。

| 条件 | 成功率 | 平均步数 | 平均浪费动作（撞墙） |
| :--- | :--- | :--- | :--- |
| 单轮一次性输出 | 34%（17/50） | 10.88（仅成功世界） | 3.44 步/世界 |
| ReAct 循环 | 100%（50/50） | 12.60（全部世界） | 0 |

两个条件跑在同一批 50 个世界上，世界与世界的难度差异因此被配平，剩下唯一的变量就是控制流：有没有反馈。这正是对照组实验的安排方式，和《LLM从零构建》§11.6 讲统计显著性时「除待测变量外其余不动」的原则同源；样本量 50 是为了把「34% 不是 20% 也不是 45%」这种量级判断站稳，而不是为了给出窄置信区间。

读这张表有三层。第一层是成功率：34% 对 100%。单轮的失败机理很具体：它按空棋盘规划，撞上第一堵墙后既不绕路也不改计划，浪费动作越积越多，预算耗尽即死局；平均每个世界白白撞墙 3.44 步。第二层是步数：循环的 12.60 步是全部 50 个世界「先取钥后送达」真实最短路的平均（这批世界的最短路最短 4 步、中位 13 步、最长 23 步），一步不多走。第三层最容易误读：单轮的 10.88 步**看起来更快**，但它是只在 17 个成功世界上算的平均，那些恰好是路径短、路上没墙的容易世界，困难世界全部阵亡后不进分母。这是评测里的幸存者偏差：失败者被剔除后，剩下的人平均成绩当然好看；对照《LLM从零构建》§11.3 讲下游基准打分时会遇到同一类陷阱。

白话：单轮考生只会在简单卷子上交卷，还顺手把难题考生的成绩单撕了；循环考生每题都答，平均用时自然长一点，但 50 张卷子一张不空。

> 本节小结：50 个随机网格世界上，单轮成功率 34%、平均浪费 3.44 步，ReAct 100% 且步数即最优（均值 12.60，min/median/max 为 4/13/23）；10.88 对 12.60 的步数对比是幸存者偏差，不能当作「单轮更快」的证据。

## $\rm \S \, 1.6$ 常见错误与证据式排查

错误一：观察不回填，agent 变复读机。有人把循环写成只追加模型输出、不追加工具观察，于是上下文永远停在第一轮，模型每轮读到同样的输入、产出同样的动作，直到预算烧光。排查方法：打印消息列表的角色序列，健康的循环是 `user, assistant, tool, assistant, tool, …` 成对生长（锚点世界 #1 是 1 条 user 配 14 对），且长度逐轮满足 $L_t=1+2t$；若 `tool` 消息不出现或不再增长，先查回填那行代码。

错误二：没有显式终止条件。§1.2 骨架里 `steps < BUDGET` 不是装饰：任务不可解、模型陷入重复、环境永不给成功信号，任何一种都会让无上限的循环无限烧钱。锚点实验给两个条件同一个 64 步预算，失败的世界在预算处分出高下，而不是在电费账单上。排查方法：任何 agent 上线前先问「什么条件下它会停」，答不出来就是缺陷；想验证预算真的在起作用，把 `BUDGET` 压到 3 重跑一遍，两个条件都应当截断失败，而不是抛异常或死循环。

错误三：把解析失败当异常抛出。§1.4 第 3 轮的演示里，少一个右括号的世界照常完成，因为解析错误被当成观察回填；若实现成抛异常终止，一次格式抖动就杀掉整个任务。排查方法：在解析器里对失败路径打日志，确认它走的是「生成观察」分支而不是「终止」分支。

错误四：把模拟器的结论外推成真实模型的行为。本章模拟器中 Thought 不影响动作、动作永远最优、环境规则全知，三者都比真实世界乐观（真实模型的 Thought 参与决策、动作带采样噪声、环境有未知部分）。34% 对 100% 的差距量级可以定性迁移，具体数字不能；凡是真实系统上的声称，须按第 6 章评测方法另测。

> 本节小结：四个高频坑，观察不回填成复读机（查消息角色序列与 $L_t$ 对账）、无预算上限烧钱（查终止条件）、解析失败当异常（查失败分支）、模拟结论外推（数字不可迁移）；每个都有明确的检查动作。

## $\rm \S \, 1.7$ 动手实践：十分钟手摇一个循环

前置条件：装了 python3 的终端（WSL 或 Linux/macOS 均可）；在用户主目录新建练习目录，不碰已有文件。

```bash
mkdir -p ~/ea01-practice && cd ~/ea01-practice
```

读法：新建目录 `ea01-practice` 并进入；`-p` 让目录已存在时不报错。把下面 11 行存成该目录下的 `loop.py`（对象：新建文件），运行 `python3 loop.py`。

```python
pos, key, goal = 0, 3, 5     # 一维走廊：0 1 2 3 4 5，钥匙在 3，终点在 5
holding, log = False, []
while not (holding and pos == goal):
    stage = "取钥" if not holding else "送达"
    d = 1 if (pos < key or (holding and pos < goal)) else -1
    pos += d
    holding = holding or pos == key
    log.append((stage, d, pos, holding))
for row in log:
    print(row)
```

成功验证：输出 8 行，依次为 5 步「取钥」（位置 1 到 5）接 2 步「送达」（位置 4 到 5），最后一行 `(送达, 1, 5, True)`。这就是 §1.2 骨架的最小版：`stage` 是决策、`d` 是动作、`log` 里每条都是回填的观察。若输出变成同一行无限重复，多半是把 `d` 的条件写成了只看 `pos < goal` 而忘掉 `holding`，agent 拿到钥匙后折返，这正是错误一的 miniature：决策没吃到最新状态。按 `Ctrl+C` 停掉后对照第 4 行修正即可。把走廊改成环（位置 5 向右走回 0）再跑一遍，观察循环会不会停不下来，是这十分钟的进阶题。

> 本节小结：11 行走廊脚本验证取钥 5 步加送达 2 步；漏读 `holding` 状态即复现「复读机」症状，说明回填与决策共用同一份状态。

## $\rm \S \, 1.10$ 本章自测答案

概念回顾答案：

1. 感知是上下文里摆着任务与历史，决策是 $\pi$（LLM）读上下文产出动作文本，行动是环境 $E$ 执行，反馈是观察拼回上下文（§1.2）。「唯一状态」指循环不依赖消息列表之外的任何记忆，掉电后凭列表可续跑（§1.4）；限制是这只描述本章的循环，第 2 章会引入上下文之外的记忆层（检索、压缩），状态就不再唯一了。
2. Thought 写当前状态与下一步理由，Action 写结构化动作，Observation 是环境的回话（§1.3）。真实模型里 Thought 是上下文的一部分，改变后续词的条件概率分布，参与决策；伪 LLM 是查表机，Thought 是随动作一起吐出的固定字符串，不参与决策（§1.3）。因此模拟器只复现轨迹形状与协议行为，不复现思考效应。
3. 解析从文本抠出工具名与参数，执行按名调用实现并改动世界，回填把输出与观察按角色追加进消息列表（§1.4）。解析失败回填后，下一轮模型读到错误提示即可按协议重发自愈（世界 #1 第 3 轮，代价一轮）；抛异常则把一次可修复的格式抖动升级成整个任务的死亡（§1.6 错误三）。
4. 单轮按空棋盘一次输出全序列、撞墙不修正，浪费动作积到预算耗尽，平均每世界浪费 3.44 步（§1.5）。10.88 是只在 17 个成功世界（恰好路径短、无墙挡道）上算的幸存者平均，12.60 是全部 50 个世界的真实最短路平均，分母不同不可比（§1.5）。

应用与辨析答案：

1. 检查一：打印消息列表角色序列。健康应为 `assistant, tool` 成对生长；若只有 `assistant` 在长，是观察没回填（§1.6 错误一），模型每轮读同样的输入自然做同样的事。检查二：核对动作解析与执行之间是否真的改了世界状态。若 `tool` 观察永远是「blocked」一类，是执行器没吃动作参数或动作本身非法，循环在原地撞墙（§1.5 单轮失败的机理同款）。
2. 单轮先崩。它按空棋盘规划，成功世界是路径短且无墙的，平均 10.88 步意味着预算 12 时已有一批成功世界被砍；墙多的世界本来就靠撞墙耗尽预算，降预算只是死得更快，34% 只会向下走。ReAct 的 12.60 是全部世界的最优路径平均，最短路中位数是 13 步（§1.5），预算 12 已容不下半数世界，成功率同样下降，但循环只会因预算截断而失败、不会因浪费而失败，且每一步都沿真实最短路走，同预算下它的成功率始终高于单轮。定性结论：预算收紧时两个条件都崩，单轮崩得更快。
3. 不成立。两个平均数的分母不同：10.88 只在单轮恰好成功的 17 个简单世界上统计，34% 的失败世界被剔除了；12.60 覆盖全部 50 个世界且是真实最短路（§1.5）。比较效率要先定共同口径，同样的任务集、同样的成功率口径，否则就是在拿幸存者和全体比，这正是 §1.5 与《LLM从零构建》§11.3 指出的评测陷阱。
